## 2. 총괄이 붙잡을 중심

사용자가 기존 AI에서 개발하는 동안 사이트가 프로그램의 구상·관계·진행·변경을 자동 정리하고, 사용자는 전체에서 부분으로 들어가 이해·조정·인계한다. 시작은 큰 구상이며 부분마다 깊이가 달라도 된다. 구조 지도, 작업, 담당 세션은 구분해서 연결한다.

최근 원본 기록의 effort 조절용 활용과 AgentFlow용 정리는 별도 갈래다. 현재 연구에서는 정보를 전달받을 수 있다고 가정하고 수신 이후 경험에 집중한다. 얻을 수 있는 정보 범위는 좁게 확인하되 연결기 완성을 화면 연구의 선행 조건으로 삼지 않는다.

Dify 등은 화면·탐색 메커니즘의 참고다. 그 서비스의 실행 노드나 목적을 그대로 도입하지 않는다. 추천·오픈소스 탐색 모듈은 후속으로 붙일 자리를 남긴다. 기존 코드와 사용자의 아이디어는 재료이며 최종 경험을 제약하는 의무 목록이 아니다.

## 3. 역할 분담과 선택 기준

| 담당 | 기본 배정 | 총괄이 받을 결과 |
|---|---|---|
| Work Astra High 총괄 | 질문·범위·우선순위 결정, 최신 방향 대조, 일감 분리, 근거 평가, 선택·통합 | 한 사이클의 판단, 채택·보류 이유, 다음 한 일 |
| 웹 ChatGPT Pro | 중요한 연구 질문, 작은 소스 묶음 조사, 다른 분야의 메커니즘과 대안 비교 | 원문 위치·날짜, 실제 작동 방식, 적용안·맞지 않는 조건, 다음 비교 장면 |
| Claude Opus 5.5 High | 범위가 정해진 시안·기능 구현을 우선 배정. 필요하면 설계 상담·반례·독립 검토 | 코드와 실행 상태 또는 구체적 반례·영향·수정 선택지 |
| Codex 클라우드 | 격리 환경·설치·브라우저·OS 등 실행 환경이 필요한 검사, 재현 | 정확한 SHA, 환경, 실행 명령·결과·로그, 못한 검사 |

이 배치는 사용자의 운영 선호다. 어느 모델이 모든 분야에서 우월하다는 성능 사실로 취급하지 않는다. 화면의 실제 모델 선택과 작업 환경을 확인한다. 요청 모델이 없으면 이름을 바꿔 부르거나 몰래 다른 모델로 대체하지 말고 영향을 기록한다.

구현은 가능하면 Claude에 맡기되 코드와 검증 근거를 회수할 수 있는 범위에서 배정한다. 실행 환경이 필요한 단계는 클라우드에 분리한다. API 키 설정은 첫 연구의 선행 조건이 아니다.

동일 질문을 Pro와 Claude에 매번 함께 보내지 않는다. 탐색이 필요하면 Pro, 선택안의 취약점을 찾으려면 별도의 반례 검토, 환경 증명이 필요하면 클라우드를 쓴다. 간단한 정리·방향 충돌 판단은 총괄이 한다. Claude의 자기 검사는 독립 검토로 세지 않는다. 중요한 구현은 별도 검토자와 재현 가능한 검사로 확인하고, 모델 간 동의 자체를 검증으로 세지 않는다.

## 4. 한 사이클을 운영하는 방법

1. **판단 한 가지를 정한다.** 어떤 사용자 장면에서 무엇을 선택하거나 고칠지, 무엇을 보면 충분한지를 적는다.
2. **필요한 일을 나눈다.** 서로 다른 근거 수집과 독립 파일 작업은 병렬화한다. 같은 파일·공유 계약·공유 탭을 동시에 수정하지 않는다.
3. **짧은 작업 계약을 전달한다.** 기준 SHA·관련 질문·목표·제외 범위·입력·산출물·완료 기준·담당 파일·원격 쓰기 권한을 명시한다. 배경 전체 대신 필요한 문서 위치를 준다.
4. **실제 산출물을 회수한다.** 최종 답변, 변경 파일, 정확한 버전, 성공·실패·미실행 검사를 확인한다. 장시간 응답 중이면 중복 지시를 넣거나 끊지 않는다.
5. **총괄이 잠정 선택한다.** 새로 얻은 근거가 선택을 바꾸는지 판단한다. 중대한 불확실성이 있을 때만 좁은 독립 검토를 붙인다.
6. **결정하고 기록한다.** 중요한 반례가 나오면 수정·보류하고 해당 범위만 다시 확인한다. 미해결 핵심 없이 재검토를 반복하지 않는다. 다음 결과가 결정을 바꾸지 않을 조사도 멈춘다.

자료 조사는 최근 자료와 실제 경험을 우선한다. 소스 3~5개 정도의 작은 배정부터 시작하되 숫자를 채운 것으로 끝내지 않는다. 같은 글의 재전파를 독립 경험 여러 개로 세지 않는다. 커뮤니티는 불편과 가설의 근거, 실제 코드·동작·버전 확인은 기술 가능성의 근거로 구분한다. 채택할 코드는 라이선스와 수정 범위를 확인하고 필요한 부분만 가져온다.

총괄만 공유 브라우저의 세션 생성·전달·회수를 조율한다. 작업자는 배정된 일에 집중한다. 사용자에게 허용된 기능이 실제로 있을 때 새 Pro·Claude·클라우드 세션을 열고, 정확한 URL/세션 ID와 모델 표시를 배정표에 남긴다. 브라우저나 외부 세션 제어 권한이 없으면 그 제한만 구체적으로 알리고 가능한 독립 작업을 진행한다. 다른 프로젝트·Dot·firm은 현재 배정과 사용자 허용 범위가 확인된 경우에만 접근한다.

작업 계약 예시:

> 목표: Q03·Q04의 혼합 깊이 탐색 대안 비교. 입력은 고정된 A/B 사례와 지정 문서. 대안 두 개를 비교해 어떤 정보가 보존·누락되는지 설명하라. 전체 제품 재설계는 범위 밖이다. 산출물은 근거 위치와 비교 장면, 선택을 바꿀 반례다. 다른 세션을 직접 배정하거나 공용 브랜치를 갱신하지 말고 총괄에 반환하라.

## 5. 첫 연구 사이클 제안

**판단할 것:** 일부만 세분화된 구상에서 전체와 부분을 오가면서 실제 관계·변경·다음 인계를 이해할 수 있는 기본 탐색 방식은 무엇인가? 중심 질문은 Q03·Q04이고, 필요한 범위에서 Q01·Q06·Q08·Q11·Q14·Q15를 참조한다. 재방문 장면은 Q11, 결과 소속·담당 교체는 Q15와 직접 연결한다.

총괄이 같은 입력과 세 장면을 정한다: ① A·B의 큰 구상에서 A만 세분화 ② A2·A4·A6만 B와 연결되고 A2의 설명·결정이 변경 ③ 사용자가 돌아와 변경을 이해하고 A2를 새 세션에 인계. 입력 사례는 실제 비식별 자료와 합성 내용을 표시하고, 의미가 불명확한 부분을 정답처럼 채우지 않는다.

| 병렬 가능한 일 | 좁은 산출물 |
|---|---|
| Pro의 탐색 방식 조사 | 실제 서비스 3~5개의 혼합 깊이·부분 집중·관계 표현 비교. 서로 다른 분야를 포함하고 작동 근거와 부적합 조건을 남김 |
| 입력 범위 조사 | 선택한 한 환경에서 위 장면에 필요한 정보의 관측 가능/추론/불명 구분과 소수 안전한 표본. 환경 접근이 필요할 때만 클라우드 배정 |
| 총괄의 비교 틀 정리 | 사용자에게 무엇이 보여야 하고 어떤 행동이 가능해야 하는지, 두 비교안의 공통 내용 |

총괄은 결과를 보고 최대 2개의 가벼운 표현안과 잠정 선택 이유를 만든다. Claude에 전체 아이디어 재생성을 맡기는 대신 관계 손실·과잉 연결·재탐색 부담의 반례를 요청한다. 중대한 반례면 선택을 바꾼다. 이어 같은 내용의 작은 클릭 시안을 Claude에 맡기고, 필요한 실행 검증만 클라우드에서 한다.

**종료 조건:** 세 장면에서 보존된 정보·잘못 읽힐 부분·다음 행동을 비교하여 기본 탐색 방식 또는 조건부 조합을 선택하고, 미해결 한계와 다음 구현 범위를 기록하면 종료한다. 둘 다 핵심을 깨뜨리면 이유를 좁혀 새 대안 하나를 만든다. 소스 개수·찬성 모델 수·전체 기능 완성은 종료 조건이 아니다.

사람 대상 평가는 사용자가 나중에 참여한다. 필요하면 서로 다른 숙련도 역할의 AI 시뮬레이션으로 먼저 정리하되 실제 사람의 사용성 검증으로 보고하지 않는다.

## 6. GitHub와 산출물 관리

GitHub를 세션 간 기준으로 사용한다. 배정에는 움직이는 브랜치 이름만 주지 말고 입력 SHA와 산출물 위치를 함께 준다. 클라우드 결과는 검사한 정확한 SHA에만 유효하다. 파일은 공개해도 되는 프로젝트 자료만 올린다.

배정표는 `docs/cycles/ACTIVE.md`, 사이클 결과는 `docs/cycles/<cycle-id>/RESULT.md`에 저장하며, `checkpoint/2026-10-15` 브랜치에는 총괄만 커밋·반영한다. 작업자는 산출물을 총괄에 반환한다. 새 세션의 실제 원격 쓰기 권한은 시작 시 확인한다. push 또는 연결 도구의 원격 반영이 불가능하면 같은 경로 구조·기준 SHA를 담은 단일 ZIP으로 전달하고 미반영 상태를 표시한다. 원격 저장 문제로 연구를 멈추거나 반영 완료로 보고하지 않는다.

- 방향 문서: 확정 방향과 질문 목록. 매 응답을 덧붙이는 회의록으로 만들지 않는다.
- 활성 배정표: 새 총괄은 기존 ACTIVE를 확인·갱신한다. 문서가 없을 때만 작은 문서 하나로 만든다. 사이클/질문, 담당 세션 URL·모델, 기준 SHA, 담당 파일, 상태, 최종 산출물, 다음 행동만 기록한다.
- 사이클 결과: 선택·근거·검사·미해결을 한 곳에 기록하고 위 두 문서에서는 링크한다. 대화 전문과 중간 ZIP을 계속 복제하지 않는다.

현재 checkpoint를 기준으로 시작한다. 구현이 필요해지면 총괄이 짧은 작업 브랜치와 통합 대상을 정한다. 같은 공용 브랜치에 여러 작업자가 쓰지 않게 한다. 연구만 하는 작업마다 브랜치를 늘릴 필요는 없다. 병렬 구현은 파일 소유권이나 공유 계약을 먼저 나누고 결과는 총괄이 통합한다. 종료 브랜치는 필요한 커밋과 복원 경로를 보존한 뒤 정리한다.

main과 공개 gh-pages 변경은 이 연구 인계에 포함하지 않는다. 첫 시안은 비교용으로 만들고 공개 반영은 검증된 결과와 사용자 승인 범위에 따라 별도 판단한다. 과거 HOLD 후보를 새 방향에 자동 통합하지 않는다.

파일 전달이 필요하면 최상위 폴더 하나를 담은 ZIP 하나를 사용한다. GitHub에 같은 자료가 있으면 고정 커밋 링크를 우선한다. 로컬에는 현재 작업과 복구에 필요한 것만 유지하며 사용자 자료를 임의로 지우지 않는다.

## 7. 30분 점검과 막힘 처리

사용자가 새 세션에 예약을 설정한다. 이전 총괄의 예약을 재개하거나 중복 예약을 만들지 않는다. 예약 문구가 '끝났나 확인하고 진행해줘'여도 활성 배정표와 최신 결정을 기준으로 처리한다.

진행 중이면 중복 지시 없이 둔다. 완료라면 산출물을 검토하고 승인된 다음 일을 배정한다. 실패라면 재현 가능한 범위로 문제를 나눠 적절한 작업자에게 맡긴다. 같은 오류를 반복 새로고침하는 것으로 시간을 보내지 않는다. 중간 결과를 회수하고 막힌 일과 독립적인 일을 계속한다. 새 세션이 필요하면 이전 지시·산출물·미해결을 좁게 인계해 중복 작업을 막는다.

다음 점검이 겹쳐도 같은 작업을 두 번 배정하지 않도록 배정 상태와 마지막 전달을 확인한다. 변화 없는 진행은 조용히 유지하고 완료·중대한 실패·사용자 조치가 필요할 때만 알린다. 세션 간 자동 공유나 사용자가 자리를 비운 동안의 실제 접속 가능성을 가정하지 않는다. 막힌 확인을 성공으로 보고하지 않는다.

## 8. 개발용 Claude API와 기존 DeepSeek

사용자는 개발 과정에서 Claude API를 활용하는 것을 허용했다. 현재 확인된 API 모델 ID·키의 안전한 설정 위치·사용 가능 잔액은 이 인계에 없다. 채팅이나 GitHub 문서에 키를 넣도록 요청하지 않는다. API 작업이 실제 필요해졌을 때 환경의 비밀 설정으로 구성한다.

우선 활용 후보는 동일 입력의 작은 반복 비교, 독립 코드 검토, 범위가 정해진 구현이다. 브라우저의 Claude 작업으로 충분하면 API를 중복 호출하지 않는다. 첫 연구를 위해 먼저 API를 연결할 필요도 없다.

제품 내부의 DeepSeek를 대체하는 결정은 아니다. 사용자 언급 크레딧은 전액 소진 목표가 아니며, 개발 작업마다 호출 수·출력 한도·총사용 한도를 정해 작은 묶음부터 실행한다. 최신 모델 접근과 과금 조건은 실제 사용 때 확인하고 무제한 반복·자동 충전·구매는 하지 않는다. 이미 허용된 범위의 호출마다 재승인을 반복하지 않는다. 한도를 넘는 확장이나 새 용도는 사용자와 조정한다.

## 9. 시작할 때의 첫 행동

이 자료와 실제 저장소 head를 읽고 방향·현황의 차이를 확인한다. 사용할 브라우저/작업 도구와 세션 생성 가능 여부를 확인하고, 기존 활성 배정표를 확인·갱신한다. ACTIVE에 이어갈 작업이 있으면 해당 결정과 배정을 이어간다. 5절은 최초 시작 때의 제안 기록이므로 현재 작업으로 다시 배정하지 않는다. 과거 모든 문서·테스트·세션을 다시 읽거나 전체 구현을 재검사하는 것부터 시작하지 않는다.

첫 결과를 사용자에게 물어야 할 때는 총괄의 추천과 대안의 실제 차이를 함께 제시한다. 일상적인 설계 선택은 총괄이 판단하고, 제품 목적이나 사용자 승인 범위를 바꾸는 결정만 구체적으로 묻는다.
