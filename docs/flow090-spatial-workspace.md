## 최소 계약 (구현 전 정리)
| 구분 | 어디에 | 무엇 | 바꾸는 행동 |
|---|---|---|---|
| 프로젝트 목적 | `Project.space.brief` `{text, at, previous[]}` | 사용자가 쓴 ‘만들 것’ 원문. 요청·작업이 아니다(인계문에 요청으로 들어가지 않음) | 목적 입력, 목적 고치기. 고치면 이전 원문을 `previous`에 남김 |
| 영역 ID | `Project.space.areas[]` `{id:'A_…', name, note, archived, createdAt}` | 사용자가 나눈 큰 영역. `note`가 비면 ‘구상 미기재’(FLOW091에서 ‘미정’을 바꿈) | 영역 추가, 이름·설명 수정, 보관·되살리기(삭제 없음) |
| 영역 관계 | `Project.space.relations[]` `{id:'L_…', from, to, kind, note}` | 유형(흐름·먼저 필요·같은 요구 공유·관련)과 설명. 실행 순서나 실행 선이 아니다 | 관계 추가·삭제(관계는 기록이 아니라 배치 정보) |
| 작업 참조 | `Task.areaId`(요청 작업에만, 선택 키) | 요청 작업이 속한 영역. 반환(보고·자료) 작업은 저장하지 않고 부모 작업의 영역을 따른다 | 영역 화면에서 새 요청, 이어 쓴 요청(현재 작업의 영역 상속), ‘영역 미지정’ 정리 |
| 공유 요구 참조 | 기존 `Project.bases`(프로젝트 전체) | 기준은 영역에 복제하지 않는다. 영역 화면은 그 영역 요청에서 나온 기준과 나머지(‘다른 영역·미분류 기준’, FLOW091) 기준을 구분해서 보여줄 뿐이다 | 기존 기준 기록·정정 그대로 |
| 뷰 선택 | 탭별 sessionStorage `agentflow.workspace.place` | 지금 보는 화면(전체 공간 / 영역 / 영역 미지정 / 작업)과 영역. 프로젝트 데이터 아님 | 화면 이동. `currentTaskId`(사용자가 이어가는 작업)를 바꾸지 않는다 |
| 이어서 작업 | 기존 `currentTaskId` + `focusTask` | 사용자가 이어가는 작업 | ‘이어서 작업’ 버튼(명시 행동)과 요청 작성만 |
| 초안 대상 | `Project.space.draftTarget` (`null`=지금 작업을 따라감, `{area:null}`=영역 없이, `{area:id}`) | 작성 중인 새 요청이 들어갈 영역. 초안 의미의 일부라 초안 원문(`Project.draft`)과 함께 저장·백업된다. 보낸 뒤 비운다. 보관된 영역을 가리키면 그대로 보여 주고 보내기를 막는다(자동으로 바꾸지 않음) | 빈 초안에서 ‘이 영역에 새 요청’, 입력창의 영역 선택(R1) |
| 배치 | `Project.space.layout` `{version:'layout.1', positions:{영역ID:{x,y}}}` (B1) | 지도 위 영역 위치(표현 데이터). 저장 위치가 없는 영역은 목록 순서로 정해지는 고정 기본 위치를 쓴다 | 손잡이 끌기·방향키 이동, 새 영역 추가(빈 자리), 위치 되돌리기. 자세한 내용은 `flow090-map-operations.md` |

## 이번 배치에서 동작하는 경로 (실제 저장 데이터)
1. **빈 첫 방문.**
   - 서비스 목적 한 줄 아래에 ‘무엇을 만드나요?(프로젝트 목적 · 작업 요청과 따로 보관)’ 입력이 있고, ‘영역 나누러 가기’ 버튼이 있다.
   - 그 아래 입력창은 ‘또는 바로 첫 요청 쓰기’로 남아, 영역 없이 시작할 수도 있다.
2. **전체 공간.**
   - 목적과 목적 고치기(이전 원문 보관)를 보여준다.
   - 영역 카드에는 이름, 설명(비면 ‘구상 미기재’), 요청 수, 돌아온 결과 수와 ‘앱 미검증’, ‘앱에서 이어갈 작업’(FLOW091에서 이름 바꿈)을 표시한다.
   - 영역 추가, 영역 미지정 작업 카드, 영역 사이 관계(유형+설명, 실행 순서 아님 안내), 보관한 영역(되살리기)이 있다.
3. **영역 화면.**
   - 경로는 ‘전체 공간 › 영역’이다. 이름·설명 고치기와 보관(삭제 없음)이 있다.
   - ‘이 영역의 요청과 작업’ 목록에는 상태(기존 정직한 문구), 돌아온 결과, ‘원문 보기’가 있다. 원문을 열어 봐도 현재 작업은 바뀌지 않는다.
   - ‘이어서 작업’(명시 행동)이 있다. 기준은 이 영역의 기준과 ‘다른 영역·미분류 기준’으로 나눠 보여준다.
4. **이 영역에 새 요청.**
   - 기존 입력창이 열리고, 위에 ‘이 요청의 영역’ 선택이 표시된다(지금 작업 따라감 / 각 영역 / 영역 없이).
   - 제출하면 그 영역의 요청이 되고, 그 영역의 최근 작업에 이어진다. 다른 영역의 열린 작업에는 이어 붙지 않는다.
   - 이후 MOCK 정리, 작업문, 보고 붙여넣기·결과 파일은 기존 그대로다. 보고는 부모 작업의 영역을 따른다.
   - 작업 화면 위에 ‘전체 공간 › 영역 › 지금 이어가는 작업’ 경로가 보인다.
5. **복원.**
   - 탭별로 마지막 화면(전체 공간 / 영역 / 작업)을 새로고침 뒤에도 복원한다.
   - 목록 카드에 ‘영역 n개’를 표시하고, 목록에서 열면 공간 화면으로 간다.
   - 백업 저장·불러오기(사본)는 목적, 영역, 관계, 작업의 영역을 보존한다.
6. **기존 프로젝트.**
   - project.3 저장값은 열 때 다시 쓰지 않는다. 첫 변경을 저장할 때 v4로 쓴다.
   - 모든 원문·작업·보고가 그대로 열린다. ‘영역 미지정 작업’에서 영역으로 옮길 수 있다(반환 작업은 부모를 따르므로 옮길 수 없다).
- 저장, 잠금, 다른 탭의 늦은 저장, 휴지통·복원, 새 프로젝트 전환 보호는 기존 commit/persist 경로를 그대로 쓴다. 공간 편집도 같은 경로로 저장된다.

## R1 — 독립 검토 회귀 4건
1. **(P1) 영역 복귀 시 늦은 옛 보고가 최신 좁은 요청을 우회.**
   - 원인: 영역 대상이 정해진 새 요청의 부모를 그 영역의 마지막 작업(보고 포함)으로 골랐다.
   - 수정: 그 영역의 최신 사용자 요청을 고르고, 그 요청에 반환이 있으면 그 요청의 최신 반환에 잇는다.
   - 유지: 사용자가 옛 작업을 명시적으로 이어가면(현재 작업이 그 영역) 그 작업에 잇는다.
2. **(P1) 보고 초안이 사용자 요청으로 재분류.**
   - 수정: ‘이 영역에 새 요청’은 초안이 비어 있을 때만 종류(요청)와 대상(그 영역)을 바꾼다.
   - 작성 중인 보고·요청이 있으면 종류, 연결 대상, 요청의 영역을 그대로 두고 기존 초안을 열어 짧게 안내한다.
3. **(P2) 영역 편집 초안 혼입.**
   - 원인: 미저장 입력을 DOM ID만으로 보존해, 모든 영역이 같은 편집칸 값을 공유했다.
   - 수정: 미저장 입력을 프로젝트 ID와 영역 ID 키로 보존한다. 저장·취소(새 버튼) 뒤에는 그 영역의 초안을 지운다.
4. **(P2) 백업 사본에서 미제출 요청의 영역 대상 소실.**
   - 원인: 초안 대상이 탭 상태(`composeArea`)에만 있었다.
   - 수정: 대상을 `space.draftTarget`으로 옮겨 초안과 함께 저장한다.
   - 기존 형식의 기본값은 ‘따라감’(`null`)이다. project.1~3과 공개되지 않은 첫 v4 후보 모두 해당한다.
   - 잘못된 영역 ID는 읽기에서 거절한다. 보관된 대상은 보내기를 막고 안내한다.
