## 최소 계약 (구현 전 정리)
| 구분 | 어디에 | 무엇 | 바꾸는 행동 |
|---|---|---|---|
| 프로젝트 목적 | `Project.space.brief` `{text, at, previous[]}` | 사용자가 쓴 ‘만들 것’ 원문. 요청·작업이 아니다(인계문에 요청으로 들어가지 않음) | 목적 입력, 목적 고치기. 고치면 이전 원문을 `previous`에 남김 |
| 영역 ID | `Project.space.areas[]` `{id:'A_…', name, note, archived, createdAt}` | 사용자가 나눈 큰 영역. `note`가 비면 ‘미정’ | 영역 추가, 이름·설명 수정, 보관·되살리기(삭제 없음) |
| 영역 관계 | `Project.space.relations[]` `{id:'L_…', from, to, kind, note}` | 유형(흐름·먼저 필요·같은 요구 공유·관련)과 설명. 실행 순서나 실행 선이 아니다 | 관계 추가·삭제(관계는 기록이 아니라 배치 정보) |
| 작업 참조 | `Task.areaId`(요청 작업에만, 선택 키) | 요청 작업이 속한 영역. 반환(보고·자료) 작업은 저장하지 않고 부모 작업의 영역을 따른다 | 영역 화면에서 새 요청, 이어 쓴 요청(현재 작업의 영역 상속), ‘영역 미지정’ 정리 |
| 공유 요구 참조 | 기존 `Project.bases`(프로젝트 전체) | 기준은 영역에 복제하지 않는다. 영역 화면은 그 영역 요청에서 나온 기준과 나머지(공통) 기준을 구분해서 보여줄 뿐이다 | 기존 기준 기록·정정 그대로 |
| 뷰 선택 | 탭별 sessionStorage `agentflow.workspace.place` | 지금 보는 화면(전체 공간 / 영역 / 영역 미지정 / 작업)과 영역. 프로젝트 데이터 아님 | 화면 이동. `currentTaskId`(사용자가 이어가는 작업)를 바꾸지 않는다 |
| 이어서 작업 | 기존 `currentTaskId` + `focusTask` | 사용자가 이어가는 작업 | ‘이어서 작업’ 버튼(명시 행동)과 요청 작성만 |
| 초안 대상 | 탭별 place의 `composeArea` | 작성 중인 새 요청이 들어갈 영역. 입력창 위에 표시하고 해제할 수 있다. 초안 원문 자체는 기존 `Project.draft`에 하나 | 영역 화면의 ‘이 영역에 새 요청’, 입력창의 영역 해제 |
| 배치 | 영역 배열 순서 | 이번 배치는 저장 좌표 없이 순서대로 자동 배치. 좌표·드래그·팬줌·되돌리기는 편집 canvas 조사 후 다음 배치 | — |

- 저장: `idea015.project.4`. project.1·2·3은 읽을 때 빈 공간(`brief:null, areas:[], relations:[]`)으로 변환된다. 원문·작업·보고는 그대로다. 백업 저장·불러오기는 v4로 공간과 참조를 보존한다. 읽기에 실패하면 초기화하지 않는다(기존 envelope 규칙).
- 예제와 내 프로젝트는 분리한다. 시안 샘플 영역은 사용자 프로젝트에 넣지 않는다.

## 이번 배치에서 동작하는 경로 (실제 저장 데이터)
1. **빈 첫 방문.**
   - 서비스 목적 한 줄 아래에 ‘무엇을 만드나요?(프로젝트 목적 · 작업 요청과 따로 보관)’ 입력이 있고, ‘영역 나누러 가기’ 버튼이 있다.
   - 그 아래 입력창은 ‘또는 바로 첫 요청 쓰기’로 남아, 영역 없이 시작할 수도 있다.
2. **전체 공간.**
   - 목적과 목적 고치기(이전 원문 보관)를 보여준다.
   - 영역 카드에는 이름, 설명(비면 ‘미정’), 요청 수, 돌아온 결과 수와 ‘앱 미검증’, ‘지금 이어가는 작업’을 표시한다.
   - 영역 추가, 영역 미지정 작업 카드, 영역 사이 관계(유형+설명, 실행 순서 아님 안내), 보관한 영역(되살리기)이 있다.
3. **영역 화면.**
   - 경로는 ‘전체 공간 › 영역’이다. 이름·설명 고치기와 보관(삭제 없음)이 있다.
   - ‘이 영역의 요청과 작업’ 목록에는 상태(기존 정직한 문구), 돌아온 결과, ‘원문 보기’가 있다. 원문을 열어 봐도 현재 작업은 바뀌지 않는다.
   - ‘이어서 작업’(명시 행동)이 있다. 기준은 이 영역의 기준과 프로젝트 공통 기준으로 나눠 보여준다.
4. **이 영역에 새 요청.**
   - 기존 입력창이 열리고, 위에 ‘이 요청의 영역’ 선택이 표시된다(지금 작업 따라감 / 각 영역 / 영역 없이).
   - 제출하면 그 영역의 요청이 되고, 그 영역의 최근 작업에 이어진다. 다른 영역의 열린 작업에는 이어 붙지 않는다.
   - 이후 MOCK 정리, 작업문, 보고 붙여넣기·결과 파일은 기존 그대로다. 보고는 부모 작업의 영역을 따른다.
   - 작업 화면 위에 ‘전체 공간 › 영역 › 지금 이어가는 작업’ 경로가 보인다.
5. **복원.**
   - 탭별로 마지막 화면(전체 공간 / 영역 / 작업)을 새로고침 뒤에도 복원한다.
   - 목록 카드에 ‘영역 n개’를 표시하고, 목록에서 열면 공간 화면으로 간다.
   - 백업 저장·불러오기(사본)는 목적, 영역, 관계, 작업의 영역을 보존한다.
6. **기존 프로젝트.**
   - project.3 저장값은 열 때 다시 쓰지 않는다. 첫 변경을 저장할 때 v4로 쓴다.
   - 모든 원문·작업·보고가 그대로 열린다. ‘영역 미지정 작업’에서 영역으로 옮길 수 있다(반환 작업은 부모를 따르므로 옮길 수 없다).
- 저장, 잠금, 다른 탭의 늦은 저장, 휴지통·복원, 새 프로젝트 전환 보호는 기존 commit/persist 경로를 그대로 쓴다. 공간 편집도 같은 경로로 저장된다.

## 미완료 (이번 배치 아님)
- 지도 연결선 그리기, 좌표 저장, 드래그, 팬·줌, 되돌리기 등 편집 canvas. 지금은 카드 격자와 관계 목록으로 된 읽기 지도다. Pro의 Dify 조사 뒤 다음 배치에서 한다.
- AI 구상 생성(목적에서 영역 제안). 공급자 연결 시에도 이번에는 없다. Pages에서는 수동 추가만 가능하다. 예제 프로젝트에 영역 체험은 넣지 않았다.
- 영역별 진행 표시는 기존 작업 상태 문구와 ‘돌아온 결과 · 앱 미검증’뿐이다. 완료 색칠은 하지 않는다.
- 공유 요구를 여러 영역에 명시적으로 연결하는 기능은 없다. 기준은 프로젝트 전체에 있다.
- 목적 입력창의 작성 중 내용은 저장되지 않는다(제출한 목적만 저장).
- 관계 삭제는 바로 지운다. 관계는 배치 정보라 되돌리기가 없다.
- 실제 사용자 사용성 확인은 하지 않았다.
