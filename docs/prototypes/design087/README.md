- 기준 커밋: `5f3dd88`. `app/continuity`와 생산 코드는 바꾸지 않았다.
- 이 폴더만 추가했다: `index.html` 하나, `check.py`, 이 문서, `CHECK.md`.
- **가상 비교자료다.** AI 연결이 없고, 아무것도 실행·전송·저장하지 않는다. CSP `default-src 'none'`로 네트워크도 막았다.

## 여는 법
- `index.html`을 브라우저로 직접 연다. 설치나 빌드는 필요 없다.
- 상단에서 A/B/C를 전환한다. 선택한 영역과 탭은 전환해도 유지된다.
- 주소 해시(`#v=B&a=booking&t=work`)에 위치가 남아, 브라우저 뒤로가기가 동작한다.
- ‘변경 확인’과 ‘초안’은 메모리 상태다. 새로고침하면 초기화된다.

## 공정성
세 안은 같은 데이터, 같은 문구, 같은 표시 배지, 같은 상세 탭을 쓴다(공통 렌더러). 다른 것은 전체 탐색 방식과 관계를 보여주는 방식뿐이다.

공통 요소:
- 상세 탭: 구상·요구 / 작업·세션 / 결과·검증 / 변경.
- 목록 대체 보기, 뒤로가기, 선택 유지.
- 키보드: 노드·카드·칩은 버튼이다. 탭은 ←/→/Home/End로 이동하고, Esc는 전체로 돌아간다.
- 다크 모드, 375px 폭.

## 핵심 경로 (세 안 모두 실제 클릭 동작)
1. 전체 → **예약** 선택 → 작업·세션 탭에 ‘옛 결정 기준으로 보낸 지시예요’(Codex API 담당, 로그인 필수 지시, 실행 상태 알 수 없음).
2. ‘변경 확인하기’ → 변경 탭에서 결정 변경(로그인 필수 → 비회원 허용)을 보고 ‘이 변경을 확인했어요’.
3. ‘이 작업만 다음 지시 초안 만들기’ → API 작업 하나의 초안이 나온다. ‘초안 · 어디에도 보내지 않음’이고, 복사만 된다. 확인 전에는 버튼이 비활성이다.
4. **취소** 선택:
   - 구상·요구 탭: ‘버튼 문구만’이 현재 요청으로 유지된다.
   - 결과·검증 탭: 늦게 온 전체 문구·배치 보고는 ‘이전 요청에 대한 보고 · 최신 요청보다 늦게 도착’으로 붙는다. ‘최신 요청과 비교’ 표로 비교할 수 있다.

Claude 화면 담당의 비회원 반영 보고는 ‘보고만 있음 · 직접 확인 안 함’으로만 표시한다. 검증 완료처럼 보이는 표시는 없다.

## 반영한 수용 조건 (5f3dd88 평가 / Sol 확인 → 새 시안 조건)
- **최신 의도·보고 대상·검증 상태를 따로 표현한다.** 결과마다 ‘대상 요청 / 확인 / 최신 요청과의 관계’ 3칸을 둔다.
- **늦은 이전 보고가 최신 요청을 밀어내지 않는다.** 관련 결과로만 붙인다.
- **초안에도 같은 분리를 담는다.** 기준 결정, 이전 지시 실행 여부 모름, 보고할 때 대상 요청과 확인 여부를 나눠 적어 달라는 요청을 넣는다.
- **영역 ≠ 세션.** 영역(회원·예약·취소·알림), 역할(화면 담당·API 담당), 세션(Claude 세션 1 → 2 교체, Codex 세션 1), 작업 기록은 서로 다른 엔티티다. 세션이 교체돼도 작업 기록은 그대로 남는다.
- **평소 화면에는 내부 ID와 정책 설명이 없다.** ‘옛 결정 기준’ 판정 근거는 접힌 ‘이 표시는 어떻게 정해졌나요?’에만 있다. 이 근거는 ‘기록된 연결로 계산한 가상 표시, 코드 검사나 자동 충돌 검출 아님’이다.

## 미구현·한계
- 실제 데이터 모델과 연결이 없다. 데이터는 `index.html` 안 `/* Synthetic data */` 블록의 상수다.
- 자동 배치가 없다. A는 넓은/좁은 두 좌표 세트를 손으로 배치했다. 영역 수는 4개로 고정이다.
- ‘옛 결정 기준’은 합성 데이터의 기록 연결에서 계산한다. 실제 제품이라면 결정↔작업 연결을 누가 기록하는지 정해야 한다.
- 상태를 저장하지 않는다. URL에는 선택(시안·영역·탭·목록)만 남는다.
- 다음은 하지 않았다: 스크린리더 실기, 터치 기기 실기, 인간 사용성 관찰.
- Pro의 별도 3소스 조사는 아직 반영하지 않았다. 데이터 블록과 시안별 렌더러(`variantA/B/C`)가 분리돼 있어, 조사 결과는 렌더러 단위로 교체·추가할 수 있다.
