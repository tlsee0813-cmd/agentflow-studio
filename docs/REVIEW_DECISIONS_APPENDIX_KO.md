# AgentFlow Studio 검토 반영 기록

개정 3 부록 · 판단 이유와 코드 근거를 찾을 때 읽는다. 현재 연구 주제의 단일 목록은 [방향 문서 6절](PRODUCT_DIRECTION_AND_RESEARCH_PLAN_KO.md)이다. 이 부록은 작업 배정표가 아니다.


## A1 전체 판단

외부 검토는 자동으로 갱신되는 지도에서 빠지기 쉬운 동일성·출처·변경 충돌·인계 연결을 잘 짚었다. 이들은 표현 연구에서도 다뤄야 할 핵심이다. 다만 부품 목록은 구현 명세나 착수 순서가 아니다. 필요한 제품 동작을 먼저 받아들이고, 그것을 구현하는 엔진·형식·화면 조작은 비교 대상으로 둔다.

사용자의 전제는 그대로 유지한다. 최근 원본 기록은 effort 조절과 AgentFlow용 정리로 별도 활용할 수 있고, 현재는 정리된 정보를 전달받을 수 있다고 놓고 수신 이후의 경험을 설계한다. 아래의 정보 보존 원칙은 연결 가능성을 다시 입증하라는 선행 과제가 아니다. 정리 담당의 정확한 역할과 출력 형식은 사이트가 필요로 하는 정보를 정한 뒤 맞춘다.

## A2 입력과 지도 뼈대

| 제안 | 판단과 반영 |
|---|---|
| 기록 어댑터·공통 이벤트 | 도구와 화면의 결합을 줄이는 후보 구조로 보존한다. 2A에서는 접근 가능한 정보와 비교용 표본을 확인한다. 정식 이벤트 규격이나 모든 도구의 어댑터를 지금 만들지는 않는다. |
| 원본은 기기에, 사이트에는 파생물·포인터 | 유력한 보관 방향이다. 다만 원본이 삭제되거나 접근 불가능하면 포인터만으로 재분석할 수 없다. 보존된 상태를 재구성하는 것과 원본을 새 모델로 다시 해석하는 것을 구분한다. 언제든 전체 지도를 다시 계산할 수 있다는 보장은 채택하지 않는다. |
| 비밀 가리기 | 연구용 기록 공유 전 적용한다. 필요한 관계를 잃지 않도록 경로·이름은 일관된 별칭으로 바꿀 수 있다. 원본·키를 공개하거나 대화에 옮기지 않는다. 모델의 요약만으로 비밀 제거가 보장된다고 보지 않는다. |
| 발언 등급 | 제안·결정·질문, 채택·보류·대체, 주장·관측 근거를 데이터에서 구분한다. 서로 겹치는 속성을 하나의 배타적 등급으로 묶지는 않는다. 테스트 출력도 특정 검사 결과이며 전체 기능 완료와 동일하지 않다. |
| 안정 ID·별칭 | 같은 부분이 시간에 따라 다른 이름으로 언급되는 장면을 핵심 연구에 추가한다. 이름 일치만으로 병합하지 않고 프로젝트 범위·문맥·출처를 함께 본다. 불명확한 언급은 후보로 둘 수 있으나 사용자가 후보 정리에 매달리게 만들지 않는다. |
| 포함 구조·관계 그래프 분리 | 의미상 분리한다. 물리적으로 별도 DB를 요구하는 것은 아니다. 부모 필드 외에도 순환·이동·폐기·공유 참조를 다뤄야 하므로 필드 하나로 끝난다고 보지 않는다. |
| 관계 접기 | 알려진 구체적 관계를 유지하고 상위 화면에서 묶어 표현하는 방향을 수용한다. 상위 관계만 알려졌다면 하위 관계를 만들어내지 않는다. 집약된 연결에서 실제 연결 대상을 확인할 수 있어야 한다. |
| 구성부분·작업·세션과 배정 | 분리 원칙을 수용한다. 한 작업이 여러 부분을 건드리거나 담당이 교체·병렬화될 수 있다. 카드의 담당 표시는 실제 배정과 상태에 근거하며 임의의 단일 담당값으로 고정하지 않는다. |
| 렌즈·상세 슬라이더·펼침 고정 | 비교 시안의 후보다. 한 번에 관점 하나만 허용하거나 전역 슬라이더를 반드시 두지는 않는다. 기본 진행 표시를 유지하면서 관점을 바꾸는 안, 부분별 펼침을 우선하는 안을 비교한다. 상세 수준과 확대축소는 구분한다. |

## A3 자동 갱신과 사용자 수정

**의미 있는 변경을 추적할 수 있어야 한다는 요구는 수용한다. 정리 모델의 출력이 반드시 지도 패치여야 한다는 결정은 보류한다.** 이름 변경·분할·병합·관계 변경 같은 임시 변경 사례를 시안 전에 작성하면 충분하다. 정리된 이벤트를 사이트가 변환하거나, 상태 차이를 계산하거나, 정리 담당이 변경안을 보내는 방법 모두 비교할 수 있다. 최종 전달 규격은 후속 단계에서 정한다.

| 제안 | 판단과 반영 |
|---|---|
| 필드별 출처·사용자 고정 | 사용자 수정 보호와 변경 이유 추적은 수용한다. 모든 편집을 영구 잠금으로 처리하지 않는다. 명시적 고정, 나중의 사용자 결정, AI 제안, 계산 상태를 구분한다. 화면 좌표 선호와 제품의 사실·결정도 같은 잠금 규칙으로 묶지 않는다. |
| 예외만 묻는 보관함 | 해결이 필요한 충돌·불확실성을 좁혀 보여주는 원칙을 수용한다. 모든 최상위 추가·분할·병합을 자동으로 승인 대기에 넣지는 않는다. 영향·되돌릴 수 있는 정도·사용자 의도에 따라 결정하고, 해당 부분 안의 표시와 통합 보관함을 비교한다. |
| 변경 피드·마지막 열람 이후 | 재방문 경험의 핵심 후보로 수용한다. 최근 변경을 이해하고 근거로 이동할 수 있어야 한다. 시간 이동·전체 복원은 피드만으로 완성되지 않으며 상태 버전과 보존 정책이 필요하다. 되돌리기도 후속 변경에 미치는 영향을 고려한다. |
| 점진 배치 | 기존 위치와 탐색 맥락을 최대한 보존한다. 절대 움직이지 않는 규칙은 겹침과 과밀을 만들 수 있으므로 필요 시 사용자가 선택하는 정돈과 부분 재배치를 비교한다. 사용자가 옮긴 위치는 존중한다. |

외부 검토에 더해 **반복 수신·늦게 도착한 기록·누락 후 재수신**을 비교 장면에 추가한다. 같은 기록이 두 번 왔다고 노드나 변경이 두 번 생겨서는 안 되고, 늦은 기록이 최신 결정을 조용히 되돌려서도 안 된다. 향후 구현에서는 대상 ID·출처 식별·기준 버전·변경 묶음의 일관성을 다뤄야 한다. 지금 정확한 프로토콜을 고정하지는 않는다.

겹치는 작업은 모두 충돌이 아니다. 두 세션이 같은 부분을 서로 다른 목적으로 다룰 수 있으므로 활동의 중첩과 실제 결정·변경의 충돌을 구별한다. 폐기·대체된 부분은 활성 지도에서 정리하되 이전 근거와 인계에서 참조할 수 있어야 한다. 공유 부분은 복제본의 상태가 따로 변하지 않도록 참조 관계를 연구한다.

## A4 다음 행동과 인계

맥락 묶음·범위 선택·결정과 미정 대장·자료 포인터는 수용한다. 사용자 목적, 선택한 부분, 관련 결정과 미정, 필요한 관계, 최근 변화, 이전 담당의 미완 항목을 작업에 맞게 추린다. 관련 자료를 전부 넣어 문맥을 다시 과밀하게 만들지 않는다. 자료에는 위치와 읽는 이유를 함께 제공한다.

- 인계 식별자는 어느 범위와 기준에서 시작한 작업인지 연결하는 유용한 후보다. 토큰이 언급됐다는 사실만으로 새 세션을 자동 확정 연결하지는 않는다. 과거 인계문 인용·다른 프로젝트 복사·범위 변경을 구분하고 연결 오류를 고칠 수 있어야 한다. 식별자는 인증 수단이나 완료 증거가 아니다.
- 수신 재진술은 세션이 이해한 범위와 부족한 입력을 기록하는 후보다. 모든 작업의 추가 승인 단계로 만들거나 올바른 이해·성공을 보증하는 것으로 취급하지 않는다.
- 결정에는 대체·철회와 관련 부분을 표현할 필요가 있다. AI가 결정이라고 요약한 것과 사용자가 실제 확정한 것을 구별한다.
- 자료 포인터는 가능하면 버전이 있는 위치를 사용한다. 파일 이동·삭제·접근 불가를 구분하며 줄 번호만으로 내용의 동일성을 보장하지 않는다.

## A5 연구 순서와 평가

8절의 **1 → 2A·2B 병렬 → 3 → 4 → 5 → 6** 순서를 유지한다. 2A의 첫 결과는 정보 범위와 안전하게 공유할 수 있는 소수 기록 묶음이다. 재생기·별칭 엔진·정식 패치 규격의 완성을 3단계 화면 비교의 선행 조건으로 삼지 않는다. 반복 비교에 실익이 생기면 최소한의 재생 도구를 만든다.

실제 기록은 표현의 흔들림과 맥락을 연구하는 데 쓰고, 합성 사례는 실제 표본에 없는 동시 작업·누락·폐기 등 경계를 보완한다. 정답 지도 하나를 강제하기보다 중요한 결정·관계·출처가 보존되는지, 사용자가 변경과 다음 행동을 찾을 수 있는지를 비교한다. '두 단계 안에 찾기' 같은 기준은 중요한 행동별 목표 후보이며 모든 항목에 일괄 적용하지 않는다.

정리 실행 시점은 후속 설계 항목으로 둔다. 턴 종료·유휴 경계·묶음 처리를 검토하되, 파일 변경이나 명시적인 결정 표현이 없다는 이유만으로 이벤트를 버리지는 않는다. 질문·실패·목표의 수정·보류에도 지도에 필요한 정보가 있을 수 있다.

## A7 두 번째 검토의 반영 결정

- 형태 제안 수용: 질문 목록은 본문 6절, 연구 순서는 8절, 과거 판단은 이 부록으로 분리했다. 본문 질문마다 질문·이유·비교안을 기록했다.
- 추가 주제 수용: 원본과 재구성(Q05), 첫 연결(Q06), 되묻기·주의·반복 시도(Q10), 신선도(Q11), 비활성(Q12), 역방향 전달(Q09), 순서·의존(Q16), 비어 있음(Q07), 인계 크기(Q14), 이름의 발언 근거(Q02). 새 독립 기능 목록으로 늘리지 않고 관련 질문에 합쳤다.
- 수정한 해석: 원본이 기기에 있다고 지도 상태만 유일하게 남는 것은 아니다. 파생 기록·사용자 변경·상태 사본의 보존 범위에 따라 복원 가능성이 달라진다. 과거 상태 복원과 원본 재해석을 분리해서 연구한다.
- 수정한 해석: 오래 조용함·담당 없음·반복 시도만으로 문제를 확정하지 않는다. 프로젝트 의도와 작업 상태에 따라 주의를 계산하며 원인을 설명하고 해제할 수 있게 한다.
- 수정한 해석: 사용자 발언을 무조건 결정으로, AI 발언을 무조건 낮은 가치로 다루지 않는다. 명시적 사용자 선택을 존중하면서 인용·질문·제안·관측을 구분한다.
- 참고만 유지: 기존 질문 수 제한은 현재 구현의 선택이다. 새 제품의 모든 되묻기에도 질문 하나 규칙을 강제하지 않는다.
- 인계 묶음은 시작 안내·현재 방향·이 부록으로 구성한다. 대표 기록 묶음은 아직 새 연구용으로 선정·비식별화하지 않았으므로 준비된 산출물처럼 인계하지 않는다.
