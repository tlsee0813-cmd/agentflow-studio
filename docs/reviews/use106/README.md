# USE106 — 첫 요청의 목적 보존과 검토 위계

첫 화면의 목적을 입력하고 바로 첫 요청을 제출하면 목적이 빠지던 경로를 고쳤다. 기존 `space.brief`에 목적을 반영한 후보 상태에서 요청을 검증·제출하므로, 같은 제출의 `background` 사본과 전달문에도 목적이 들어간다. 목적은 선택 사항이고 요청 원문·확정 기준으로 승격되지 않는다. 이미 만들어진 작업의 배경 사본은 그대로다.

이번 작업은 구현 회귀검사와 AI 소스 검토다. 사람 대상 사용성 평가나 실AI 의미 품질 평가가 아니다. 합성 자료와 MOCK만 사용했으며 외부 개발 도구로 작업을 보내지 않았다.

## 재현과 수정

기준 소스에서 목적과 첫 요청을 입력한 뒤 목적 폼을 따로 제출하지 않고 ‘작업문 준비하기’를 눌렀다. 새 회귀검사는 `space.brief`가 null이어서 실패했다([실패 로그](logs/baseline-failure.log)). 기존 handler는 목적 입력을 읽지 않았다.

수정 후에는 보이는 첫 목적과 요청을 로컬 후보 상태에서 함께 검증하고 한 번 commit한다. 첫 요청의 보이는 문자열이 마지막 유효 draft와 다를 때도 재검증하여, 잘못된 입력 대신 이전 유효 요청을 제출하지 않는다. 이름 자동 지정도 이 검증 이후에만 반영된다. 빈 목적은 허용한다. 미제출 목적의 DOM 값은 프로젝트 전환 때 초기화하여 다음 프로젝트에 섞이지 않게 했다.

검증 오류는 입력칸 두 개와 이전 저장 상태를 보존한다. 저장 용량 오류는 기존 저장본을 덮어쓰지 않으며, 수락된 요청 원문·목적·배경을 현재 탭의 메모리와 JSON 복구 사본에 보존한다. 이 경우 입력칸은 이미 수락된 요청으로 전환되므로, **입력칸에 그대로 남는다는 뜻은 아니다**. 중복 제출은 새 요청을 만들지 않는다. 저장 복구 전 탭을 닫으면 메모리 변경은 잃을 수 있으며 기존 ‘저장되지 않은 변경’ 경고·백업 경로를 사용한다.

## 제한된 UI 개선

1. 결과 상세에서 개별 원문 수정·삭제·제외·연결 해제를 지원하지 않는다는 사실을 밝힌다. 현재 작업의 ‘방향 수정 / 다음 요청’으로 작업 번호와 정정 내용을 남길 수 있지만, 기존 결과와 연결은 남으며 전달문에 포함될 수 있다고 안내한다. 초안 비우기는 저장 결과에 영향을 주지 않고 휴지통은 프로젝트 전체에 적용됨을 구분한다.
2. 기존 기록에서 ‘이번 요청 / 별도 조건란 / 열린 질문·보류·모름 / 현재 단계의 다음 행동’을 먼저 보여준다. 원문·현재 기준 값을 구분하고 긴 내용은 ‘앞부분’이라고 명시한다. active 질문과 원문만 보관 상태를 포함해 기존 `stageOf`에 맞춘 안내를 쓴다. 실제 질문이 없는 원문의 미정 표현을 새로 추출했다고 주장하지 않는다.
3. 빈 별도 조건란은 ‘원문 속 조건·금지가 없다는 뜻이 아님’으로 표시한다. 전체 전달문의 추적 ID·근거·권한·원문은 유지하고, 복사/Markdown 전체 내용 일치를 검사했다. MOCK은 규칙 기반이며 의미 이해·질문 완전성을 제공하지 않는다고 입력 안내에 명시한다.

USE106의 11개는 직접 첫 제출의 실제 HTTP background, 영역 경유와 옛 작업 사본 불변, 빈 목적·빠른 이중 제출, 목적/요청 유효성 오류와 재시도, quota 실패 시 기존 저장 문자열·복구 사본·중복 방지, 결과 안내의 비변경성, 전문 복사·다운로드·좁은 화면, 프로젝트 경계, active 질문/보류, 정정한 현재 기준 표시, 원문만 보관 상태를 검사한다. 여러 합성 요청을 사용하며 제품 코드에 예제별 분기를 추가하지 않았다.

maxlength 우회, `Storage.prototype.setItem` quota 오류, 빠른 `requestSubmit()` 두 번, 호출 꺼짐 config는 **명시적 fault injection**이다. config fault 검사 외 통신은 브라우저→실제 localhost HTTP→MOCK이며 DOM bridge를 사용하지 않는다. static 비교는 API 없는 browser MOCK이다. 전체 localStorage 임의 교체는 하지 않았다.

기존 테스트 assertion을 수정·완화하지 않았다. 최초 SPATIAL102 실행은 ‘연결만 표시하는 section’에 새 일반 안내의 ‘전달’ 문구가 섞여 실패했다. 일반 정리 안내를 연결 사실 section 밖으로 옮겨 원래의 검사를 통과시켰다. 새 검사의 selector 한 곳을 실제 `new-project` ID로 바로잡았고, 원문 보관 검사는 실제로 숨겨진 버튼을 강제 클릭하지 않고 기존 호출 꺼짐 config 경로로 진입한다.

새 검사만 기존 Verify workflow에 추가했다. 원격 CI 결과는 정확한 커밋을 대상으로 실행한 Actions 링크와 인계 BUILD에서 따로 확인한다. 위 표는 로컬 결과이며 원격 통과를 대신하지 않는다.

## 독립 diff 검토와 반영

새 독립 에이전트에 `fork_turns=none`, 요청 모델 `gpt-6.1-sol`, reasoning `high`로 좁은 diff 검토를 맡겼다. 도구는 해당 모델 요청을 수락했다. 별도 backend 모델 식별을 증명하는 자료는 없으며 다른 모델로 바꾸지 않았다. [검토 원문](independent-review.md)은 수정 전 diff의 소스 분석으로, 브라우저 재현을 수행했다는 주장이 아니다.

검토의 세 P2를 모두 반영했다: 프로젝트 사이 미제출 목적 잔존값 초기화(test 08), 정정 기준의 ‘원문’ 오표기 수정(test 10), active 질문 및 준비 전 상태에 맞는 안내(test 09/11). 총괄이 해당 브라우저 회귀검사를 실행했다. 반복 평가나 추가 기능 개발로 확대하지 않았다.

## 남은 제약

- 개별 결과 정리 기능은 없다. 정정 요청을 추가해도 잘못된 원본과 연결이 남는다.
- MOCK의 의미 오해, 본문 속 조건/미정 자동 추출은 이번 범위 밖이다. 실제 AI/외부 도구 실행과 사람 사용성 개선 효과는 미검증이다.
- 미제출 목적은 프로젝트 간 보존되는 별도 draft가 아니다. 프로젝트 전환 시 초기화한다. 같은 프로젝트에서 유효성 오류가 발생하면 입력은 유지한다.
- quota 오류 후에는 현재 탭의 복구 파일을 저장하거나 저장 가능 상태로 복구해야 한다. 메모리만 남은 변경의 영구 보존을 약속하지 않는다.
- 미리보기 ZIP은 정적 browser MOCK이며 공개 배포가 아니다. 최상위 폴더 하나와 BUILD의 소스/실행산출물별 SHA256으로 인계한다.
