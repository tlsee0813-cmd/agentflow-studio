# USE105 독립 첫 사용 평가 — 주니어 역할

## 평가 조건과 결론

- 실제 사람이 아닌 AI 역할 시뮬레이션이다. 작은 단일 기능을 구현해 본 주니어로, 공방 수업 안내의 첫 기능을 정리해 외부 개발 도구에 전달할 자료를 찾았다.
- 요청된 모델 조건은 `gpt-6.1-sol high`이다. 이 에이전트가 실제 어떤 모델 식별자·추론 설정으로 배정됐는지 확인할 플랫폼 메타데이터는 제공되지 않았다. 요청 조건을 실제 실행 증명으로 주장하지 않는다.
- 전용 junior 프로필, 조작 포트 8802, 1280×900 화면만 사용했다. 도구가 보고한 앱 주소는 `http://127.0.0.1:8765/agentflow-studio/`였다. 지정된 정적 로컬 배포 평가이며 공개 호스트 접속 검증이 아니다. 파일 해시 일치는 평가 조건으로 전달받았고 이 에이전트가 독립 검증하지 않았다.
- 다른 평가자, 다른 프로필, 이전 평가, 앱 소스, 개발 문서, 테스트, 앱 내부 상태나 localStorage를 읽지 않았다. UI 명칭이나 해결 순서를 사전에 받지 않았다. browser.py/action.py는 지정된 도구로 실행했고 그 내용을 읽지 않았다.
- 총 **20개 본 행동**(입력 5, 클릭 14, 재시작 1), 보조 snapshot 1회, 스크롤 0회. 각 행동의 자동 스냅샷·jpg는 별도 증거다. 01·07·16·21.jpg를 이미지 뷰어로 직접 확인했다. 도구 시작과 보고서 작성은 사용자 행동 수에서 제외했다.
- 전체 목표 **부분 완료**. 프로젝트·첫 요청·영역·이전 기록·재시작 복귀는 완료. 요청과 결과 구분은 화면에서 이해했다. 실수 결과의 안전한 개별 정리/복구는 미도달이다. 외부 도구 전달, AI API 호출, 실제 구현·검증은 수행하지 않았다.

## 실제 입력 원문

**P — 프로젝트 목적**

소규모 공방의 원데이 클래스 일정과 예약 방법을 안내하는 페이지를 만들고 싶어요. 첫 기능은 날짜별 수업과 남은 자리를 보여주는 안내입니다. 결제와 회원 기능은 아직 정하지 않았어요.

**R — 첫 요청**

공방 수업 안내 페이지에 날짜별 클래스 이름, 시작 시간, 남은 자리를 목록으로 보여주세요. 우선 샘플 데이터 3개로 만들고 휴대폰에서도 읽기 쉽게 해주세요. 예약은 전화 문의 문구만 넣고 결제와 회원은 아직 미정이니 구현하지 마세요.

**E — 의도적으로 잘못 붙인 합성 결과**

[합성 실수 기록] 다른 프로젝트인 카페 메뉴 페이지 작업 결과를 잘못 붙였습니다. 메뉴 카드 3개를 만들었다는 보고이며 실제 실행이나 검증은 하지 않았습니다. 이 공방 요청의 완료 결과가 아닙니다.

## 문제, 장점, 재현과 반례

### 1. 잘못 보관한 결과를 개별 정리하는 길을 찾지 못함

- **관찰:** 행동 17에서 실수 결과를 기존 작업에 보관했다. 행동 18의 보고 자료 펼침과 행동 19~20의 이력/원문 펼침에서 개별 삭제·연결 해제·정정 제어를 찾지 못했다. 프로젝트 전체 휴지통 버튼은 있었지만 원래 요청과 영역을 함께 잃을 수 있다고 생각해 누르지 않았다.
- **재현한 경로:** 첫 요청 준비 → 결과 붙여넣기 → E 입력 → 결과에서 이어가기 → 보고 자료 펼침 → 지난 요청과 결과 → 해당 결과의 입력 원문 펼침. 증거 16~21.
- **예상:** 엉뚱한 결과 한 건만 잘못 붙였을 때 원래 요청을 보존하며 제외하거나 되돌릴 수 있을 것으로 기대했다.
- **판단 한계/반례:** 앱 전체에 복구 기능이 없다는 증거는 아니다. 현재 화면과 두 개의 자연스러운 상세 경로에서 찾지 못했다는 발견성 문제다. 다른 메뉴나 텍스트 정정 흐름은 더 탐색하지 않았다. 보고를 완료로 바꾸지는 않았고, 미검증 상태와 원문은 명확히 남아 있어 피해를 줄이는 표시가 있었다.
- **필요한 도움:** 특정 보고만 제외/정정/연결 해제하는 위치 또는 가능한 정리 방법 안내가 필요하다. 이 평가 종료 시 합성 실수 결과는 여전히 프로젝트에 남아 있다.

### 2. 전달문은 찾기 쉬우나 본문을 소화하기 어려움

- **관찰:** 준비 직후 복사·저장·전체 보기 버튼이 눈에 띄었다. 전체 문서에는 첫 요청과 목적뿐 아니라 긴 프로젝트/작업/입력 식별자, r 기준, 보존 기준, 관련 입력 등이 들어 있었다. 화면 제목은 쉽게 읽혔지만 전체 본문은 단일 기능에 비해 길었다.
- **예상/주관 반응:** 세 문장 요청을 짧게 정리해 주거나 질문을 받을 것을 생각했으나, 원문 유지 중심의 전달문이었다. 단일 기능 경험 역할에서는 어느 부분을 검토해야 할지 도움이 필요하다.
- **재현:** 행동 5~7, 증거 06~08. 한 번 확인했고 여러 요청 크기로 반복하지 않았다.
- **반례/장점:** 원문을 그대로 보존했고 결제·회원 미정 및 구현 금지를 누락하지 않았다. 화면에 MOCK은 의미를 해석하지 않는다고 명시되어 있어 실제 AI 요약 품질 문제로 해석하지 않는다. 전체 문서가 필요한 외부 실행 도구에는 유용할 수 있으며 실제 외부 도구의 수용성은 미확인이다.

### 3. 재시작 후 목록 복귀는 성공

- **관찰:** 재시작 후 곧바로 내 프로젝트 목록과 저장된 카드가 보였다. 이어서 하기를 누르면 전체 공간으로 복귀했고 이름·목적·영역·첫 요청이 남아 있었다. 좌측의 임시 `나의 프로젝트` 표시는 목록 상태에서 보였지만 실제 카드와 복귀 후 프로젝트는 맞았다.
- **기대/한계:** 직전 이력 화면으로 복원될 수도 있다고 생각했으나, 목록에서 한 번 눌러 돌아오는 방식도 이해할 수 있었다. 같은 프로필에서 1회 재시작만 확인했다. 장기 보관, 다른 기기, 백업 왕복은 미확인이다.

### 4. 요청·결과·실행 상태 구분은 강점

- **관찰:** 입력 탭과 결과 전용 제목, `내 요청`/`가져온 결과 · 구현 보고`, `미실행`/`앱 미검증` 문구가 반복되어 표시됐다. 결과를 넣어도 원래 공방 요청을 카페 작업 목표로 교체하지 않았다.
- **자동 실행 기대:** 첫 화면의 AI 연결 없음·복사/붙여넣기 설명을 읽은 후 자동 개발 실행을 기대하지 않았다. 준비 버튼은 문서 작성, 결과 버튼은 보고 저장/후속 초안으로 이해했다. 이후 UI도 그 이해와 일치했다. 네트워크나 외부 실행을 기술적으로 검사한 것은 아니므로 화면 관찰 범위로만 주장한다.
- **반례/한계:** 결과 보관이 작업 02 초안을 생성하여 처음엔 새 요청을 만든 듯 보일 여지가 있었지만 제목이 후속 확인 초안임을 설명했다. 실제 두 번째 새 요청을 제출하고 두 종류의 이력을 교차 비교하지는 않았다.

## 목표별 결과와 도움 필요

| 목표 | 결과 | 범위 |
|---|---|---|
| 작은 합성 프로젝트 만들기 | 완료 | 이름·목적 저장 |
| 첫 요청 정리와 전달 자료 찾기 | 완료 | 본문과 복사/저장 위치 확인. 실제 복사·파일 저장·외부 전송은 안 함 |
| 영역 하나 추가 | 완료 | 예약 문의 안내, 설명 미기재, 요청 없음 |
| 기존 요청 확인 | 완료 | 이력 및 복귀 후 현재 작업에서 확인 |
| 새 요청과 이전 결과 구분 | 부분 완료 | 요청/결과 입력 선택과 이력의 서로 다른 표시는 이해. 후속 새 요청 제출 비교는 미실행 |
| 중단 후 돌아오기 | 완료 | 동일 프로필 브라우저 재시작 1회 |
| 실수 기록 안전 복구/정리 | 미도달 | 자연스러운 보고 상세와 이력에서 개별 정리 제어를 찾지 못함. 도움 필요 |

추가로 작업문에서 사용자가 꼭 검토할 핵심 부분에 대한 설명이 있으면 좋겠다고 느꼈다. 실제 개발 도구 사용, AI 응답, 파일 가져오기, 백업 왕복, 휴지통 복구, 모바일 크기는 확인하지 않았다.

## 독립성 한계

평가자는 실제 주니어가 아닌 AI이며, UI 문구를 빠르게 읽고 접근성 트리를 이용한다. 접근성 트리에는 화면 밖 요소도 포함돼 실제 사람보다 발견에 유리하다. 주요 4개 jpg를 직접 봤지만 모든 행동 전 화면 영역을 스크롤하며 검증한 것은 아니다. 20행동 한도와 실수/복귀를 시도하라는 상위 과제 때문에 자연 발생 사용과 다르다. 다른 평가 결과나 소스는 참조하지 않았으며, 보고서의 어려움과 기대는 이 역할 시뮬레이션의 반응이다. 단일 합성 프로젝트·단일 세션 결과로 일반 사용자 전체의 성공률을 추정하지 않는다.

행동 종료 후 공통 도구는 native confirm/prompt를 자동 취소한다는 기술 보정을 전달받았다. 이번 20행동에서는 확인창을 여는 삭제·휴지통·초기화 조작을 하지 않아 이 제약으로 판정한 앱 무반응은 없다.
