# USE105 독립 첫 사용 평가 — 초보 역할

## 범위와 판정

- 실제 초보 사람이 아닌 AI 역할 시뮬레이션이다. 코딩 경험이 거의 없는 사용자의 관점으로 작은 합성 프로젝트를 조작했다.
- 요청 모델 표기: `gpt-6.1-sol`, reasoning `high`. 이 실행에서 실제 모델 식별자와 reasoning 설정을 독립적으로 확인할 수 있는 플랫폼 정보는 받지 못했다. 따라서 요청한 설정이 실제 적용됐다고 검증해 주장하지 않는다.
- 전용 novice 프로필과 조작 포트 8801만 사용했다. 브라우저가 표시한 페이지 주소는 `http://127.0.0.1:8765/agentflow-studio/`였다. 제공받은 동일 해시 정적 배포의 localhost 평가이며 공개 호스트 접속 검증이 아니다. 해시 일치 자체도 이 평가자가 재검증하지 않았다.
- 다른 평가자, 이전 평가, 제품 소스, 개발 문서, 테스트를 읽지 않았다. 환경 사용에 필요한 런타임 스킬만 읽었다. 앱 JS, 내부 상태, localStorage를 검사·수정하지 않았다.
- 상호작용 20개로 종료했다. 명백한 막힘은 없었다. 초기 브라우저 실행과 보조 snapshot 1회는 행동 수에서 제외했다. 매 행동에서 도구가 자동 생성한 접근성 트리·스크린샷은 보조 증거다. 명시적 스크롤 0회. 도구의 클릭에 따른 자동 스크롤은 있었다.
- JPG 직접 확인: 01, 10, 13, 14, 18, 21. 나머지는 접근성 트리 중심으로 관찰했다. 전체 트리에 화면 밖 항목도 포함되므로 실제 시각적 발견 난이도보다 쉽게 찾았을 수 있다.

전체 목표는 **부분 완료**다. 프로젝트 및 첫 요청을 만들고 외부 도구에 전달할 작업문 위치를 찾았다. 영역 추가, 기존 요청 확인, 재시작 후 복귀, 잘못 분류한 초안의 안전한 정정까지 했다. 새 요청의 최종 제출, 이미 제출한 잘못된 기록의 삭제·복구, 백업·복사·다운로드의 실제 성공은 확인하지 않았다. 외부 전송이나 AI API 호출은 하지 않았다.

## 실제 입력

아래 행동 표의 입력 A~E는 다음 문자열 전체를 뜻한다.

- A: `소규모 공방 예약 안내`
- B: `작은 도자기 공방의 수업과 예약 방법을 휴대폰으로 볼 수 있는 안내 사이트를 만들고 싶어요. 결제와 회원 가입은 아직 정하지 않았어요.`
- C: `공방의 도자기 수업 이름, 소요 시간, 가격과 전화 예약 방법을 보여주는 첫 화면을 만들어 주세요. 휴대폰에서 글씨를 읽기 쉽게 해 주세요. 결제와 회원 가입은 아직 미정이라 넣지 말아 주세요.`
- D: `찾아오는 길`
- E: `추가로 공방 주소와 주차 안내도 첫 화면 아래에 넣어 주세요.`

## 행동 기록

행동 번호와 자동 증거 번호는 1 차이가 난다. 예를 들어 행동 1은 02.jpg 및 대응 JSON이다. 초기 01은 보조 snapshot이다. ‘기대’는 역할의 예상이며, ‘관찰’은 이번 실행에서 화면·트리로 확인한 사실이다.

| 행동 | 실제 조작 | 화면·증거 | 기대·오해 / 관찰 | 완료 여부 |
|---|---|---|---|---|
| 1 | `프로젝트 이름`에 A 입력 | 시작 화면, 02 | 기대: 내 프로젝트 제목이 바뀐다. 관찰: 상단·왼쪽 제목과 저장 상태가 갱신됐다. | 완료 |
| 2 | `무엇을 만드나요? 프로젝트 목적 · 작업 요청과 따로 보관해요`에 B 입력 | 시작 화면, 03 | 기대: 만들려는 전체 목적을 저장한다. 관찰: 목적과 작업 요청이 따로라는 문구가 있고 `영역 나누러 가기`가 활성화됐다. | 완료 |
| 3 | `영역 나누러 가기` 클릭 | 전체 공간, 04 | 기대: 예약 같은 큰 부분을 만들 수 있다. 관찰: 목적이 표시되고 영역 이름·설명 입력칸이 나왔다. 자동으로 영역을 제안하지 않았다. | 완료 |
| 4 | `영역 이름`에 `예약 안내` 입력 | 전체 공간, 05 | 기대: 첫 영역의 이름을 정한다. 관찰: 이름 입력만 되고 아직 영역은 0개다. | 완료 |

| 6 | `이 영역에 새 요청` 클릭 | 첫 요청 화면, 07 | 기대: 예약 안내를 위한 요청을 쓴다. 관찰: 영역 선택이 예약 안내로 되어 있다. | 완료 |
| 7 | `요청 또는 돌아온 결과 원문`에 C 입력 | 첫 요청 화면, 08 | 기대: 평소 말로 필요한 첫 화면과 미정 범위를 설명한다. 관찰: 입력과 작업문 준비 버튼이 유지됐다. | 완료 |
| 8 | `작업문 준비하기 ↗` 클릭 | 현재 작업, 09 | 기대: 외부 개발 도구에 전달할 글을 정리한다. 관찰: `이제, 작업문을 전달하세요.`와 복사·Markdown 저장·전체 보기 버튼이 나타났다. 실제 웹사이트가 만들어진 화면은 아니었다. | 첫 요청 준비 완료 |
| 9 | `전달할 작업문 전체 보기` 클릭 | 전체 문맥 입력상자까지 자동 이동, 10 | 기대: 어떤 글을 전달하는지 읽는다. 관찰: C와 B, 미정인 부분을 임의 확정하지 말라는 안내가 포함됐다. 식별자·기준·근거 설명이 길어 초보에게 부담스럽다. | 자료 위치 발견 완료; 복사·저장은 미시도 |
| 10 | 왼쪽 `전체 공간 1` 클릭 | 전체 공간, 11 | 기대: 다른 영역을 추가한다. 관찰: 원래 목적·예약 안내와 영역 추가 입력이 남았다. | 완료 |
| 11 | 영역 추가 폼의 `영역 이름`에 D 입력 (`nth: 0`) | 전체 공간, 12 | 기대: 찾아오는 길 영역을 만든다. 관찰: 같은 이름의 필드가 속성 패널에도 있어 폼의 첫 필드를 지정했다. | 입력 완료 |
| 12 | `＋ 영역 추가` 클릭 | 전체 공간, 13 | 기대: 두 영역이 함께 보인다. 관찰: 영역 수 2, 찾아오는 길 카드와 속성이 나왔다. `화면 밖 영역 1개 · 모두 보기`가 표시됐고 실제 JPG에는 예약 안내가 보이지 않았다. | 영역 추가 완료; 전체 지도 맞춤 미시도 |

## 기대와 관찰

자동 실행에 대한 기대: 처음에는 이름에 AI 개발 도구가 들어 있어 준비 버튼이 사이트 제작까지 시작할 가능성을 떠올릴 수 있다. 그러나 첫 화면에 `AI 연결 없음`, `규칙으로 흉내 내는 체험판`, `작업문을 복사·저장해도 개발 도구가 실행되지는 않아요`가 명시돼 있었다. 이후에는 준비 버튼을 문서 정리로 기대했다. 결과 화면에서도 실제 사이트 미리보기는 나오지 않았고, 역사 화면은 미실행이라고 표시했다. 이 흐름에서는 자동 실행으로 오해하지 않았다. 실제 외부 실행 여부를 기술적으로 검사한 것은 아니다.

요청과 결과의 구분: 버튼과 제목·placeholder가 바뀌어 차이를 이해할 수 있었다. 실제 결과를 받은 적이 없으므로 결과로 들어갈 사실 자료는 없었다. E는 의도적인 오분류 초안이며 외부 구현 보고로 주장하지 않는다. 잘못된 입력 종류를 누른 뒤에도 문장을 잃지 않고 전환한 것은 좋았다. 제출된 잘못된 결과를 수정하거나 삭제하는 기능을 확인한 것은 아니다.

초보 도움 필요: 첫 요청 작성과 영역 추가에는 별도 설명 없이 도달했다. 하지만 Claude Code·Cursor를 처음 쓰는 역할이라면 어느 도구를 준비하고 어디에 붙여넣어야 하는지는 이 화면만으로 끝내기 어렵다. 전체 문맥을 봤을 때 긴 UUID, r 번호, D1, requested, CLI/MCP, 기준 비교라는 표현의 필요성을 판단하기 어렵다. 이 내용은 개발 도구용 자료라는 점을 이해하더라도, 초보가 수정해야 할 글인지 그냥 복사하면 되는 글인지 한 번 더 확인받고 싶다.

## 문제·반례·장점

1. **전체 작업문이 읽기 부담스럽다.** 재현 경로는 행동 8→9, 증거 10이다. 짧은 수업 안내 요청 뒤에 식별자와 기준 설명이 긴 문서가 나타났다. 이는 주관적 이해 부담이며 기능 고장이라고 주장하지 않는다. 반례로 상단의 `작업문 복사`·`Markdown 저장`은 명확해서 전문 내용을 모두 읽지 않고 전달할 경로는 있다. 실제 복사 결과는 미확인이다.
2. **영역 두 개만 추가했을 때도 하나가 지도 밖으로 나갔다.** 행동 10→11→12, 증거 13에서 `화면 밖 영역 1개 · 모두 보기`와 하나의 카드만 보였다. 영역 두 개가 나란히 보이길 기대했다. 반례로 바로 `모두 보기`, `전체 맞춤` 수단이 제공돼 막힘은 아니었다. 눌렀을 때의 동작은 미확인이다.
3. **재시작 후 마지막 입력까지 곧바로 돌아오지 않는다.** 행동 17→18→19로 목록→전체 공간→현재 작업을 거쳤다. 목록의 이어서 하기가 마지막 초안을 여는 줄 기대했지만 전체 공간으로 갔다. 반례로 프로젝트, 원래 요청, 영역, 결과 모드, 초안 문장은 모두 유지됐고 두 클릭으로 찾았다. 데이터 손실을 관찰하지 않았다.
4. **결과로 잘못 적은 요청도 제출 버튼이 활성화된다.** 행동 15→16에서 관찰했다. 문장 의미를 이해하지 않는 MOCK 안내와 일치하므로 의미 검증 결함으로 단정하지 않는다. 반례로 선택된 모드·제목·placeholder가 분류를 알렸고 행동 20에서 손실 없이 전환됐다.
5. **장점:** 첫 화면의 자동 실행·외부 전송 안내, 목적과 요청의 분리, 영역 설명을 선택으로 둔 점, 미정인 결제·회원 내용을 작업문에서 임의 확정하지 않게 다룬 점, 역사 화면의 요청·미실행 표시, 자동 저장과 초안 복원, 입력 종류 전환 중 내용 보존이 도움됐다.
