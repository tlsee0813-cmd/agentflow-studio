# USE105 독립 첫 사용 평가 — 미들 역할

## 평가 조건과 판정

- 실제 사람이 아닌 AI 역할 시뮬레이션이다. 여러 기능과 변경 관리 경험이 있는 미들 사용자의 관점으로 화면에서 다음 행동을 정했다.
- 총괄의 실행 기록에는 `fork_turns: none`, model `gpt-6.1-sol`, reasoning_effort `high`로 생성 요청이 수락되었다고 되어 있다. 나는 역할·공통 목표·기술 도구 안내만 받았다. 실제 backend 모델 식별자나 추론 설정은 독립적으로 조회·확인하지 못했으므로, 요청 설정과 실제 실행 모델의 일치를 보증하지 않는다.
- 지정된 middle 프로필과 조작 포트 8803만 사용했다. 페이지에 표시된 URL은 `http://127.0.0.1:8765/agentflow-studio/`였다. 1280×900 Chromium 화면이다.
- 공개 URL은 직접 검증하지 않았다. 지정 배포와 해시가 일치한다는 상위 작업의 조건으로 제공된 로컬 정적 배포를 사용했다. 이 보고서는 공개 호스트의 동작 검증이 아니다.
- 앱 소스, 개발 문서, 테스트, 다른 평가자 기록이나 프로필을 읽지 않았다. 앱 내부 JS, 상태 및 localStorage를 조회·수정하지 않았다.
- 환경 런타임 안내 skill과 환경 상태만 확인했다. 제품 솔루션 설명은 받지 않았다. 실제 외부 개발 도구로 전달하지 않았으며 AI API를 호출하지 않았다.
- 주요 행동 20개. 보조 snapshot 2개(01, 17), 별도 scroll 0개. 화면 JPG는 01, 10, 15, 16을 직접 보았다. 각 행동의 자동 JPG·JSON은 같은 디렉터리에 있다.
- **전체 목표: 부분 완료.** 합성 프로젝트 생성, 영역 1개 생성, 첫 요청과 전달 작업문 발견, 가상 결과 보관, 새 요청과 이전 결과 구분, 브라우저 재시작 후 복귀는 완료했다. 실수한 기록의 안전 복구/정리는 시도했지만 확인하지 못했다.

## 실제 입력 원문

이름: `소규모 공방 예약 안내`

목적: `동네 소규모 도예 공방의 수업 일정과 예약 방법을 안내하는 웹사이트를 만들고 싶습니다. 방문자는 수업과 날짜별 잔여 자리를 확인하고 예약을 문의합니다. 결제와 회원 가입 도입 여부는 아직 미정입니다.`

영역: `수업·예약 안내` (설명은 선택 입력이라 비워 둠)

첫 요청: `첫 화면에 도예 수업 소개와 날짜별 정원·잔여 자리를 보여 주세요. 날짜를 고르면 예약 문의 방법과 준비물이 보이게 해 주세요. 모바일에서도 읽기 쉽게 구성하고, 결제와 회원 가입은 아직 미정이므로 구현 전에 질문으로 남겨 주세요.`

가상 결과: `평가용 가상 보고입니다. 개발 도구가 수업 소개와 날짜별 잔여 자리 목록을 구현했다고 보고했습니다. 모바일 검사는 아직 하지 못했습니다. 결제와 회원 가입은 미정으로 남겼습니다. 실제 구현·검증 증거는 없습니다.`

다음 요청: `다음 변경 요청입니다. 만석 날짜에는 예약 문의 대신 다음 수업 일정 안내를 보여 주세요. 기존 수업 소개와 준비물 안내는 유지하고, 결제와 회원 가입은 계속 미정으로 남겨 주세요.`

## 문제, 반례, 장점

1. **질문·정리 기대와 MOCK 동작의 차이.** 홈과 입력 아래에 ‘필요한 질문만 받고’라는 안내가 있었지만, 결제·회원 도입을 미정으로 넣고 작업문을 준비하자 질문이 나오지 않고 원문 유지형 작업문이 생성됐다(08→09). 다만 ‘브라우저 MOCK · AI 아님’, ‘규칙으로 흉내 내는 체험판’, ‘MOCK은 요청의 의미를 해석해 할 일을 정하지 않습니다’라는 반대 근거도 명시돼 있다. 따라서 유료 AI 기능 결함이나 실제 AI 질문 품질로 일반화할 수 없다.
2. **영역 나누기는 직접 만드는 흐름.** ‘영역 나누러 가기’ 이후 자동 영역 후보가 아니라 빈 추가 폼이 나왔다(04). 막히지는 않았고, 1개 생성 후 즉시 ‘이 영역에 새 요청’이 나와 연결은 쉬웠다. 버튼이 자동 분류를 보장한다고 단정하지 않는다.
3. **복구는 관찰 공백.** 휴지통 버튼을 한 번 눌렀으나 16·17에서 아무 변화가 보이지 않았다. 재현 범위는 ‘해당 이력 화면에서 한 번 클릭하고 snapshot으로 다시 확인’까지다. 앱 버그라고 확정하지 않는다. 20행동 종료 뒤 총괄이 공통 harness의 native confirm/prompt 기본 자동 취소를 알려 주었다. 앱의 확인창을 도구가 전달하지 않은 한계이므로, 안전 복구 미검증으로 기록한다. 총괄의 별도 재현 결과나 정답 경로는 제공받거나 읽지 않았다.
4. **전달 문맥은 충실하지만 길다.** 실제 전달 텍스트에는 프로젝트/작업/기준 식별자와 많은 기록·권한·범위 설명이 있었다(10). 미들 사용자로서 원 요청·미정 사항의 보존은 신뢰에 도움이 됐으나, 한 번에 검토할 분량과 제품 내부 용어가 많았다. 복사 버튼이 상단에 있어 전체 문맥을 읽지 않고도 전달 가능하다는 장점도 있다.
5. **요청과 구현 보고의 구별은 강점.** 결과 붙여넣기 직후에는 연결 대상과 내보낸 기록 없음이 보였고, 처리 후에는 앱 미검증과 후속 초안이라는 설명이 앞에 나왔다. 이력의 ‘내 요청’과 ‘가져온 결과 · 구현 보고’도 구별하기 쉬웠다(12, 14, 15, 22).
6. **자동 실행 기대는 해소됐다.** 처음에는 AI 개발 도구에 맡기는 서비스로 보고 실행 연결이 있을 수도 있다고 생각했지만, 첫 화면에서 복사·붙여넣기 방식과 자동 실행 아님을 읽었다. 이후 작업문 준비·결과 가져오기는 외부 도구 실행을 시작하지 않을 것으로 기대했다. 관찰상 화면은 작업문 준비와 기록만 바뀌었고, 실제 외부 실행 여부는 네트워크 감시로 검증하지 않았다. 앱이 외부 진행을 알지 못한다는 이력 안내도 일관됐다.

## 도움 필요·미확인과 독립성 한계

- 휴지통 이동 확인창과 복원 UI 검증에는 네이티브 대화상자를 전달하는 중립 조작 도구가 필요하다. 현재 도구가 확인창을 자동 취소했으므로 이 경로의 사용성 판정은 보류한다. 이번 결과를 ‘안전 복구 성공’으로 세지 않는다.
- 첫 작업문은 찾았지만 클립보드·Markdown 파일 내용, 백업 내보내기/복원, 실제 외부 개발 도구의 동작, 실제 AI 모드는 검증하지 않았다.
- 20개 행동 한도로 두 번째 영역 추가, 개별 잘못된 원문의 정정, 휴지통 재시도는 하지 않았다. 생성한 1개 영역과 미완료 항목을 구별해야 한다.
- 실사용 인간의 독립 평가가 아니다. 상위 에이전트가 역할·목표·종료 한도·격리 도구를 정했고 나는 화면에서 순서를 선택했다. 제품 명칭·클릭 순서·정답은 사전에 제공받지 않았다. 종료 후 받은 유일한 보정은 native confirm/prompt가 공통 harness에서 자동 취소된다는 기술 정보이며 이를 복구 미검증의 원인 설명에 반영했다.
- 화면 밖 콘텐츠까지 포함하는 accessibility snapshot을 사용하므로 인간이 현재 뷰포트만 훑을 때보다 탐색에 유리하다. 버튼 클릭 시 도구의 자동 스크롤도 개입했다. screenshot을 일부 직접 확인했지만 모든 행동 직후의 화면을 시각적으로 검토하지는 않았다.
- 다른 평가자와의 비교, 반복 실험, 사용자 통계는 없다. 여기서 ‘쉬웠다’나 ‘기대했다’는 지정된 역할 시뮬레이션의 판단이다.
