# USE105 독립 첫 사용 평가 — 기존 코드와 제약을 중시하는 시니어 역할

이 문서는 실제 사람이 아닌 AI 역할 시뮬레이션의 기록이다. 요청된 모델은 `gpt-6.1-sol`, reasoning `high`다. 이 실행에서 모델 식별값과 reasoning 설정을 확인하는 플랫폼 메타데이터는 제공되지 않아 실제 적용을 독립 검증하지 못했다. 일반적인 시스템 설명의 GPT-6 계열 안내를 특정 모델 적용 증거로 삼지 않았다.

전용 프로필 `senior`, 조작 포트 8804, 화면 1280×900을 사용했다. 화면 URL은 `http://127.0.0.1:8765/agentflow-studio/`였다. 제공받은 기술 조건은 공개 프록시 장애로 동일 해시의 정적 배포를 로컬에서 평가한다는 것이며, 해시를 직접 검증하거나 공개 호스트를 검증했다는 주장은 하지 않는다.

## 목표와 결과

- 합성 프로젝트 ‘소규모 공방 예약 안내’를 만들고 첫 개발 요청을 준비해 전달할 자료 찾기: **완료**. 전체 작업문, 복사, Markdown 저장 버튼을 찾고 전체 문맥을 읽었다. 실제 복사·다운로드·외부 전달은 하지 않았다.
- 영역 하나 추가: **완료**. ‘운영 안내’와 제외 범위를 추가했다. 기존 요청은 영역 미지정으로 남았다.
- 기존 요청 확인: **완료**. 이력에서 ‘내 요청’, ‘작업문 준비됨 · 미실행’을 확인했다.
- 새 요청과 이전 결과 구분: **부분 완료**. 별도 입력 종류와 연결 대상을 이해하고 합성 결과를 이전 작업에 연결했다. 실제 두 번째 새 요청 작성·제출은 하지 않았다.
- 중단 후 돌아오기: **완료**. 브라우저 재시작 뒤 목록에서 프로젝트를 찾고 ‘이어서 하기’로 진입했다. 영역·요청·결과 수가 유지되었다. 이전 작업 화면 그대로가 아니라 전체 공간으로 열렸다.
- 실수한 기록 안전 복구/정리: **부분/복구 미도달**. 프로젝트를 잘못 정리하는 상황을 의도적으로 모의해 ‘휴지통으로’를 클릭했다. 이동 또는 확인창이 관찰되지 않았고 복구 경로까지 도달하지 못했다. 행동 종료 뒤 전달받은 기술 보정에 따르면 공통 조작 도구가 native confirm/prompt를 기본 자동 취소하며 확인창을 전달하지 않는다. 따라서 안전 복구는 도구 제약으로 미검증이다. 개별 요청·보고의 삭제/수정은 확인하지 않았다.

총 사용자 행동 **17개**. 보조 snapshot **2회**(01, 18), 명시적 scroll **0회**, JPG 직접 확인 **8장**(01, 05, 07, 13, 15, 16, 17, 19). 클릭 도구가 대상을 화면 안으로 가져온 것은 별도 스크롤 행동으로 세지 않았다. 브라우저 시작, 도구 프로세스 대기, 파일 작성은 사용자 행동에서 제외했다.

## 주요 문제, 반례와 장점

### 목적 입력과 첫 요청의 저장 기대 차이

**예상:** 첫 화면에 프로젝트 이름 자동 저장과 목적 입력이 함께 있어, 목적을 쓴 뒤 아래에서 첫 요청을 준비하면 목적도 배경으로 남을 것으로 생각했다.

**관찰:** 03에서 입력된 목적은 05·06의 ‘작업문에 넣을 프로젝트 배경 · 요청 당시 저장된 구상 없음’과 대비되었다. 07·10·19 전체 공간도 ‘목적 적기’ 상태였다.

**재현 절차:** 새 브라우저 상태에서 이름과 목적을 입력 → ‘영역 나누러 가기’를 누르지 않고 아래 첫 요청 입력 → 작업문 준비 → 배경 및 전체 공간 목적 확인. 이 세션에서 한 번 관찰한 절차이며 별도 재현 반복은 하지 않았다.

**반례/한계:** ‘영역 나누러 가기’를 거쳤을 때 저장되는지는 미확인. 목적이 입력만으로 저장된다고 UI가 명시적으로 보장했다고 단정하지 않는다. 핵심 제약은 첫 요청에도 다시 적었으므로 작업문에서는 잃지 않았다. 처음 쓴 목적만의 배경 보존 기대가 어긋났다.

### 재개 후 확인 초안 상태 문구의 해석 난점

**관찰:** 15는 ‘후속 확인 작업문 초안’이 준비되었다고 명시했다. 재시작·재진입 후 19의 전체 공간은 ‘구현 보고 도착 · 앱 미검증 · 아직 다음 요청이나 확인 작업문 없음’이라고 표시했다. 동시에 사이드바에는 작업 2 ‘후속 확인 작업문 초안’이 남았다.

**예상:** 준비된 확인 초안이 있다면 전체 공간에서도 그 존재나 다음 단계가 대응될 것으로 기대했다.

**재현 절차:** 미실행 첫 작업에 합성 결과를 붙여넣어 ‘결과에서 이어가기’ → 확인 초안 생성 → restart → 이어서 하기. 한 세션 관찰이며, 복사·저장된 확인 작업문만 세는 정책 등은 미확인이다. 상태 손실이나 버그로 확정하지 않는다.

### 휴지통 이동과 복구 확인 미도달

**관찰:** 목록에서 ‘휴지통으로’를 한 번 클릭했지만 17과 보조 18의 이미지·접근성 트리에는 변화가 없었다. 화면에 보이는 복구나 휴지통 목록도 없었다.

**예상:** 이동 확인 또는 이동 후 복구 위치를 발견할 수 있을 것으로 기대했다. **재현:** 저장된 합성 프로젝트 목록 → 휴지통으로. 동일 클릭 반복은 하지 않았다.

**기술 보정/한계:** 행동 종료 뒤 총괄로부터 공통 Playwright harness에 native confirm/prompt 핸들러가 없어 기본 자동 취소되며, 확인창을 평가자에게 전달하지 않는다는 기술 설명을 받았다. 이는 나의 화면 관찰과 별개로 전달된 도구 정보다. 휴지통 클릭 뒤 동일 화면이었던 것을 앱의 무반응이나 확인창 부재로 판단하지 않는다. 프로젝트는 이후 정상 진입 가능했다. 안전 복구는 도구가 확인창을 전달하지 않아 미검증이며, 대화상자를 보존하는 환경에서 추가 확인이 필요하다. 다른 프로필의 재현 결과는 읽지 않았다.

### 장점

- 첫 화면의 ‘AI 연결 없음’, ‘브라우저 MOCK · AI 아님’, 복사·저장해도 실행되지 않는다는 설명이 눈에 보였다. 처음부터 자동 실행을 기대하지 않았으며, 이력의 ‘미실행’도 기대와 맞았다. 네트워크 감사를 하지 않았으므로 실제 호출 부재를 시스템 수준에서 증명한 것은 아니다. AI API·외부 도구 실행 버튼은 의도적으로 호출하지 않았다.
- 기존 코드 보존, 요청 범위, 미확인 값을 전달문에서 확인할 수 있었다. 실제 코드 파일이 포함되지 않는다는 설명은 외부 개발 도구에 무엇을 준비해야 하는지 이해하는 데 유용했다.
- 사용자 요청을 ‘의도’, 구현 보고를 ‘주장’으로 구분하고 결과를 ‘앱 미검증’으로 남겼다. 합성 결과도 구현 완료로 오해하지 않도록 하는 표시가 구체적이었다.
- 영역 추가는 이름·선택 설명·추가 동작이 한 화면에 있어 독립적으로 수행할 수 있었다. 기존 요청이 자동으로 새 영역에 배정되지 않은 것도 화면에서 확인할 수 있었다.

## 도움 필요와 독립성 한계

사용 흐름과 클릭 순서에 대한 설명자의 도움은 받지 않았다. UI 명칭과 클릭 순서는 매 화면에서 스스로 골랐다. 행동 종료 뒤 받은 유일한 후속 보정은 위의 확인창 자동 취소라는 기술 정보이며, 이후 추가 UI 행동은 하지 않았다. 목적 저장의 경계, 확인 초안과 전체 공간 상태 문구의 관계, 휴지통 확인/복구는 추가 확인이 필요하다. 백업 내보내기·복원, Markdown 다운로드 내용, 새 두 번째 요청 제출, 개별 기록 수정/취소, API 연결 모드와 실제 개발 결과는 확인하지 않았다.

소스·개발문서·테스트·이전 평가·다른 평가자의 증거 또는 프로필은 읽지 않았다. 도구 실행 지침과 관리형 환경 런타임 스킬만 기술 설정에 사용했고, 앱 내부 JS·상태·localStorage를 검사·수정하지 않았다. 화면 접근성 트리는 화면 밖 콘텐츠까지 포함할 수 있어 일반 사용자의 실제 시선 순서와 다르다. 주요 화면 JPG도 직접 보았지만 모든 행동 직후 이미지를 직접 확인하지는 않았다. 역할 설정 자체가 기존 코드·제약을 강조했고 AI인 만큼 실제 사람의 망설임·피로·시각 탐색 비용을 그대로 대표하지 못한다.
