# USE105 독립 첫 사용 평가 — 스태프/리드 역할

## 범위와 판정

- 실제 사람이 아닌 AI 역할 시뮬레이션이다. 병렬 작업을 나누고 다음 담당자에게 맥락을 인계하려는 스태프/리드 관점으로 진행했다.
- 요청 모델 설정: `gpt-6.1-sol`, reasoning `high`. 평가자에게 전달된 요청값이며, 플랫폼에서 실제 적용된 모델 ID와 reasoning 수준을 별도 조회하거나 검증하지 않았다. 이 보고서를 특정 모델의 실제 사용자 연구 결과로 읽으면 안 된다.
- 전용 `staff` 프로필, 제어 포트 8805, 화면 1280×900만 사용했다. 브라우저가 연 대상은 `http://127.0.0.1:8765/agentflow-studio/`이다. 지정 배포와 해시가 일치하는 정적 파일이라는 실행 조건을 전달받았으며 직접 해시를 검증하지 않았다. 공개 호스트 접속·가용성 검증이 아니다.
- 앱 소스, 개발 문서, 테스트, 다른 평가자와 다른 프로필 증거는 읽지 않았다. 화면 접근성 트리와 내 JPG만 관찰했다. 앱 JS·상태·localStorage를 조회하거나 수정하지 않았다.
- 주 행동 20회에서 종료했다. 보조 snapshot 2회(01, 18), JPG 직접 열람 4회(01, 10, 17, 22). 별도 scroll·resize 없음. 클릭 도구가 대상 요소로 화면을 이동시키는 경우가 있었다. 브라우저 시작은 준비 작업으로 별도 집계했다.
- 전체 목표는 **부분 완료**. 프로젝트 생성, 첫 요청 정리, 전달 자료 위치 발견, 추가 영역 생성, 기존 요청 확인, 재시작 후 복귀는 완료했다. 새 요청과 돌아온 결과의 입력 모드 차이는 확인했으나 결과 저장 후 이력 분리는 미확인이다. 저장된 기록의 삭제·복구는 도구 제약으로 미검증이며, 잘못 적은 결과 초안 비우기만 완료했다.

## 실제 입력 원문

P — 프로젝트 목적:

> 소규모 공방의 수업 일정과 예약 방법을 안내하는 웹사이트. 방문자가 수업 종류, 소요 시간, 예약 가능 시간을 확인하고 전화로 문의한다. 결제와 회원 기능은 아직 미정이다. 안내 화면과 운영자 정보 관리를 나누어 병렬로 검토하고 싶다.

R — 첫 요청:

> 첫 요청: 공방 수업 안내 첫 화면을 만들어 주세요. 도자기·목공 수업 카드에 소요 시간과 예약 가능 요일을 보여 주고, 전화 문의 버튼을 둡니다. 모바일에서도 읽기 쉬워야 합니다. 결제·회원 기능은 아직 미정이므로 구현하지 말고 확인할 항목으로 남겨 주세요. 운영자 정보 관리 작업과는 분리하고, 샘플 데이터만 사용하세요. 완료 기준과 다음 담당자에게 넘길 내용을 포함해 주세요.

M — 일부러 잘못 붙인 합성 결과 초안:

> 잘못 붙인 합성 메모: 결제와 회원 구현까지 완료. 실제 구현이나 검사는 하지 않았으며 이 내용은 저장하지 않고 지울 예정.

## 기대, 관찰, 재현을 구분한 평가

### 인계 자료: 목표 완료, 내용 품질은 제한적

- **예상:** 리드로서는 작은 작업을 분리하고 실행 범위·미정 사항·완료 기준을 담은 전달 자료를 얻고 싶었다.
- **관찰:** 클릭 8~9에서 전달 자료와 복사/Markdown 저장 버튼을 쉽게 찾았다. 원문에 쓴 결제·회원 미정 및 구현 금지, 샘플 데이터, 운영자 작업과 분리하는 조건은 전체 텍스트에 남았다. 프로젝트 배경을 지시와 구분하고 뒤에서 바뀐 구상은 당시 사본에 들어가지 않는다는 안내가 있어 인계 시점의 맥락을 이해하는 데 도움이 된다.
- **한계:** 체험판은 요청을 해석해 구체적인 할 일과 완료 조건을 만들지 않고 원문 및 일반 지시를 둘러싼다. 내가 쓴 완료 기준 요청이 구체적인 체크리스트로 발전하지 않았다. 전체 자료는 ID·기준·주의문이 길어서 수신자가 실제 요청을 빠르게 파악하는 데 부담이 있을 수 있다. 전달문 중 `유지할 조건: 명시된 추가 조건 없음`은 R 안에 금지가 여러 개 있는데도 표시되어 잠깐 상충한다고 느꼈다. **조건이 유실됐다는 주장은 아니다:** 같은 자료 위쪽에 R과 금지가 온전히 남았고 원문 범위를 따르라고 반복한다.
- **재현 범위:** 1개의 요청만 관찰했다. 실제 개발 도구에 붙여넣거나 상대 도구가 이를 얼마나 잘 수행하는지는 시험하지 않았다.

### 영역·병렬 업무: 나누기는 완료, 실제 병렬 실행은 미검증

- **관찰:** 안내와 운영자 정보 관리 두 영역을 독립적으로 만들었고 첫 요청은 안내 영역에 연결됐다. 카드가 요청 수와 앱에서 이어갈 작업을 구분해 표시한다. 후자의 의미가 외부 실행 상태가 아니라는 설명이 유용하다.
- **예상 조정:** 나는 병렬로 처리할 범위를 나누는 역할이지만, 관찰한 관계 설명은 메모라고 명확히 밝혔다. 자동 의존성 실행이나 병렬 에이전트 실행을 기대하지 않게 됐다.
- **미확인:** 담당자 배정, 실제 다중 사용자 공동 작업, 영역 간 충돌 감지, 외부 작업 동시 실행은 시험하지 않았다. 기능 유무도 단정하지 않는다. 두 번째 영역은 이름만 만들었고 요청은 아직 없다.

### 요청·결과 구분: 화면 이해 완료, 실제 저장 흐름은 부분

- **관찰:** 처음부터 요청/다음 변경과 돌아온 결과가 나뉘며, 기록은 내 요청·미실행으로 표시했다. 결과 입력에는 어떤 작업에 연결할지와 내보낸 기록 없음·비교 불가 상태를 따로 보여 줬다. 결과 보고를 검증 완료와 같게 취급하지 않는다는 문장은 분명하다.
- **미확인:** 실제 결과를 제출하지 않아 저장된 결과 카드, 새 요청과 이전 결과가 함께 있는 이력, 잘못 연결된 결과의 수정·삭제는 보지 못했다. 초안 입력만으로 전체 기록 처리의 성공을 주장하지 않는다.

### 중단·복귀: 완료

- **관찰:** 재시작으로 프로젝트 목록에 돌아왔으며 이름, 영역 2개, 요청 1개가 유지됐다. 이어서 하기 한 번으로 지도에 재진입했다. 이전에 열었던 기록 화면은 복원되지 않았지만 기존 작업은 좌측 현재 작업에서 다시 찾았다.
- **재현 범위:** 같은 프로필의 브라우저 재시작 1회. 다른 기기, 백업 불러오기, 저장소가 지워진 경우는 미확인이다.

### 안전 복구: 초안 정리 완료, 저장 기록 복구는 도구 제약

- **관찰:** 행동 16은 휴지통 이동 클릭 뒤 반환 화면 변화가 없었다. 삭제 성공이나 복원 성공은 확인하지 못했다.
- **기술 보정:** 이 시도 후 총괄이 중립 도구에 native confirm/prompt 처리기가 없어 브라우저 확인창을 자동 취소한다는 기술 정보를 전달했다. 따라서 이 사례를 앱 무반응, 확인창 부재, 삭제 버그의 증거로 사용할 수 없다. 이는 화면으로 스스로 발견한 앱 기능이 아니며, 평가 독립성에 영향을 주는 사후 기술 설명으로 명시한다. 복구의 다음 클릭 경로는 전달받지 않았다.
- **관찰:** 행동 19~20에서 잘못 붙인 결과 초안은 제출 전에 비울 수 있었다. 이것은 이미 저장된 결과의 복구와 다르다.
- **필요한 도움:** 브라우저 native 확인창을 사용자에게 그대로 전달하는 도구로 휴지통·복구만 재검증해야 한다. 저장된 잘못된 결과의 정리도 이번 결과로 판정할 수 없다.

## 자동 실행에 대한 판단

첫 화면에서 복사·붙여넣기 방식, 브라우저 MOCK·AI 아님, AI 연결 없음, 작업문 복사·저장도 실행되지 않는다는 안내를 보았다. 행동 8의 준비는 내부 규칙 기반 정리로 이해하고 눌렀다. 전체 전달문과 기록 화면도 CLI/MCP 연결·자동 실행 없음, 외부 실행 여부를 알 수 없음이라고 설명한다. 따라서 작업문 준비가 실제 구현을 시작했다고 생각하지 않았다. 외부 도구에 보내거나 AI API를 직접 호출한 행동은 하지 않았다. UI 문구에 근거한 판단이며 네트워크 트래픽이나 앱 내부 구현을 검사한 결과는 아니다.

## 도움 필요와 독립성 한계

- 기본 프로젝트·첫 요청·인계 자료 탐색에는 사람 도움 없이 진행했다. 이름을 중복한 추가 폼과 속성 패널 입력란은 도구에서 순서 선택으로 처리했다.
- 복구 시도는 도구가 native 확인창을 전달하지 않아 미검증이다. UI의 복구 가능성을 평가하려면 해당 도구 기능이 필요하다.
- 행동 상한 20회에서 종료했다. 실제 결과 제출, 두 번째 요청, 백업 저장·복원, 수신 개발 도구의 구현 품질은 미확인이다.
- 평가의 목표와 역할, 합성 주제, 행동 수, 브라우저 실행 방식은 사전에 전달받았다. 구체적인 앱 명칭과 클릭 순서에 대한 정답은 받지 않았다. 클릭은 화면에서 스스로 골랐다.
- 같은 앱을 처음 보는 실제 사람의 심리나 시간은 대체하지 못한다. 접근성 트리는 화면 밖 콘텐츠까지 포함하므로 육안 사용자보다 정보를 빨리 찾을 수 있다. JPG도 4회 직접 보았지만 모든 화면을 육안으로 검사하지 않았다.
- 환경 시작 지침을 위해 cloud-environment-runtime 스킬을 읽고 환경 상태를 확인했다. 이는 앱 제품 문서가 아니며 기능·클릭 경로를 제공하지 않았다. 그 외 타 평가자·소스·개발 문서·테스트·타 프로필 증거는 읽지 않았다.
