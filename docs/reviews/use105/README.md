# USE105 — 공개 체험판 독립 역할 사용성 시뮬레이션

2026-10-15 (Asia/Seoul). **실제 사용자 평가가 아닌 AI 역할 시뮬레이션 한 사이클**이다. 역할 이름·행동 수·완료 표시는 사람의 성공률, 신뢰도, 숙련도 효과를 증명하지 않는다. 구현·배포는 수행하지 않았다.

첫 작업문을 찾는 길은 다섯 세션에서 발견됐다. 다음 개선은 기능 확대보다 **목적이 언제 저장되는지, 잘못 붙인 결과를 어떻게 정리하는지, 전달 전에 무엇을 확인해야 하는지**를 화면에서 알리는 데 우선순위를 둔다. 가장 강한 재현은 목적을 입력한 뒤 바로 첫 요청을 준비하면 그 목적이 배경에 반영되지 않는 흐름이다. 개별 보고 정리는 한 평가자의 제한된 탐색 결과이며 기능 부재를 확정하지 않는다.

## 독립성·모델·관찰 방식

AI 역할 에이전트 5개를 각각 `fork_turns: none`, 요청 모델 `gpt-6.1-sol`, 추론 `high`로 생성했고 도구가 모두 수락했다. 모델을 바꾸지 않았다. 실제 backend 식별자를 독립 조회한 것은 아니다. 단순 방법·환경 정리는 별도 `gpt-6-luna / max`가 작성했고 총괄이 사실 표현을 검토했다.

공통 목표는 소규모 공방 예약 안내 프로젝트(결제·회원 미정)를 만들고 첫 요청과 외부 도구로 전달할 자료를 찾는 것이었다. 이어 영역 추가, 기존 요청 확인, 새 요청과 이전 결과 구분, 중단 후 복귀, 실수 기록 정리를 요청했다. 역할·목표·기술 도구·행동 한도만 주었고 솔루션 설명, 이전 평가, 정답 클릭 순서, UI 명칭은 미리 주지 않았다. 구체적인 요청 문구는 각 평가자가 만들었다. [공통 과업과 운영 기록](protocol.md) 참조.

각 평가자가 새 Chromium 프로필과 전용 포트에서 UI로 직접 행동을 골랐다. 네이티브 브라우저 도구 대신 중립 Playwright 도구를 exec로 사용했다. 총괄이 대신 클릭을 선택하거나 다른 평가자의 관찰을 전달하지 않았다. 프로필·스토리지는 분리했지만 같은 파일시스템에 접근할 수 있는 논리적 격리이며 보안 격리는 아니다. 전원 다른 평가자의 증거·앱 소스·개발문서·테스트를 읽지 않았다고 기록했다. 평가 중 localStorage 조작은 없었다. 총괄도 원인 진단용 앱 소스 읽기를 추가하지 않았다. 최초에는 배포 파일을 기계적으로 전송·해시 확인했고 소스 커밋 metadata만 확인했다.

**독립성의 예외와 도구 한계:** 전체 접근성 트리에는 화면 밖 항목이 포함되며 locator 클릭은 자동 스크롤한다. 시각적 발견 난이도를 낮출 수 있다. 모든 행동의 스크린샷은 저장했지만 평가자가 전부 육안 확인한 것은 아니다. 주니어·미들·시니어·스태프에는 종료 무렵 native confirm 자동 취소라는 기술 보정을 전달했다. 해결 순서나 다른 역할 결과는 전달하지 않았다. 시니어는 이 제약을 기록하고 17행동에서 종료했고 나머지는 20행동에서 종료했다. 역할 간 결과 공유를 금지했고 전원 다른 역할 자료를 읽지 않았다고 기록했다. 공유 파일시스템 접근을 독립 감사하지 않았으며 일부 역할에는 확인창 도구 제약을 전달했다. 완전 독립된 사람 실험이라고 주장하지 않는다.

## 가장 먼저 고칠 최대 3개

### 1. 목적 입력의 저장 경계를 첫 요청 전에 명확히 알리기

**관찰·재현:** 시니어는 첫 화면 목적을 입력하고 아래 첫 요청을 준비했다. 이후 ‘요청 당시 저장된 구상 없음’, 전체 공간의 빈 ‘목적 적기’를 보았다([03](evidence/senior/03.json), [05](evidence/senior/05.json), [07](evidence/senior/07.json)). 총괄이 평가 종료 뒤 새 프로필에서 목적에만 별도 조건을 넣어 같은 경로를 한 번 재현했다. 첫 요청 준비 뒤 배경 없음이 표시되고, 목적 편집칸도 비었다([02](evidence/purpose_check/02.json) → [04](evidence/purpose_check/04.json) → [06](evidence/purpose_check/06.json)).

**문제:** 자동 저장 안내와 목적·첫 요청이 한 화면에 있지만, 목적 입력 후 바로 요청하면 어떤 내용이 저장·포함됐는지 예측하기 어렵다. 목적에만 적은 제약을 전달했다고 믿을 위험이 있다. 이 경로의 배경 미반영은 재현됐지만 다른 저장 상태나 모든 데이터의 영구 소실을 주장하지 않는다.

**먼저 바꿀 설명:** 목적 입력 옆에 현재 저장 여부와 저장 행동을 명시하고, 바로 요청하는 경로에서 ‘프로젝트 배경에 포함된 내용’을 짧게 보여 주기. 영역 화면으로 이동하는 버튼에 목적 저장 역할도 있으면 이를 드러내기. 어떤 저장 동작으로 구현할지는 다음 사이클에서 결정한다.

**반례:** 목적을 입력하고 ‘영역 나누러 가기’를 거친 다른 세션에서는 목적이 작업문 배경에 남았다. 모든 첫 요청 경로의 결함은 아니다.

### 2. 잘못 붙인 결과 한 건을 정리할 다음 행동을 알려 주기

**관찰:** 주니어는 의도적으로 다른 프로젝트의 합성 결과를 보관했다. 보고 자료와 이력 원문을 펼쳤지만 개별 정정·제외·연결 해제 방법을 찾지 못했다([18](evidence/junior/18.json)–[21](evidence/junior/21.json), [화면](evidence/junior/21.jpg)). 보이는 프로젝트 전체 휴지통은 범위가 커서 누르지 않았다.

**문제:** 오류를 발견한 결과 상세에서 안전하게 다음에 무엇을 해야 하는지 알기 어렵다. **한 세션의 두 상세 경로에서 발견하지 못한 사실**이며, 앱 전체에 복구 기능이 없다는 결론은 아니다. 다른 역할의 프로젝트 휴지통 시도와 합산하지 않는다.

**먼저 바꿀 설명:** 결과 상세에 ‘잘못 가져온 결과인가요?’와 현재 가능한 정리 방법·영향 범위를 안내하기. 개별 정리가 지원되지 않으면 그 한계와 가능한 대안을 정직하게 표시하기. 새 삭제 기능 자체를 이번 근거만으로 확정 요구하지 않는다.

**반례:** 요청/보고의 원문과 ‘앱 미검증’ 표시는 유지됐다. 총괄의 별도 확인에서는 프로젝트 단위 확인창, 이동 후 ‘되돌리기’, 목록 복구가 관찰됐다([confirmation_check 04](evidence/confirmation_check/04.json) → [05](evidence/confirmation_check/05.json) → [06](evidence/confirmation_check/06.json)). 이는 개별 잘못된 결과 정리의 성공을 뜻하지 않는다.

### 3. 전달문에서 사람이 확인할 내용과 다음 행동을 먼저 보여 주기

**관찰:** 초보·주니어·미들·스태프는 전체 전달문에서 긴 프로젝트/작업/입력 ID, 기준 번호, 보존·권한 안내를 읽는 부담을 보고했다. 실제 문서에 이런 항목이 있는 것은 화면으로 확인됐다([초보 10](evidence/novice/10.jpg), [주니어 08](evidence/junior/08.json), [미들 10](evidence/middle/10.json), [스태프 10](evidence/staff/10.json)). 스태프는 요청 안에 금지가 있는데 ‘유지할 조건: 명시된 추가 조건 없음’이라는 문구가 함께 있는 점도 해석하기 어려웠다고 기록했다. 원문 속 금지가 유실된 것은 아니다.

**문제:** 복사 위치는 찾았지만 사용자가 무엇을 검토·수정해야 하는지 확신하기 어렵다. 문서 길이와 문구는 관찰 사실, 부담과 수신자 혼선은 AI 역할의 해석이다. 실제 개발 도구의 수용성·사람의 이해 실패는 검증하지 않았다.

**먼저 바꿀 위계:** ‘이번 요청 / 보존할 조건·미정 / 아직 모르는 것 / 다음 행동: 쓰던 도구에 붙여넣기’를 사람 검토용 짧은 요약으로 먼저 제시하고, 추적용 세부 근거는 상세로 유지하기. MOCK에서는 의미 기반 질문이나 정리가 자동 생성되지 않는다는 기대도 ‘필요한 질문만 받고’ 같은 안내와 맞추기. 조건이 없다는 포괄 문구 대신 어떤 별도 입력란에 관한 상태인지 한정하기.

**반례:** 상단의 ‘이제, 작업문을 전달하세요’, 복사·Markdown 저장 버튼은 명확했고 모든 역할이 자료 위치를 찾았다. 원문·미정·범위 보존은 장점이므로 근거 내용을 무조건 삭제하자는 제안이 아니다.

## 공통점·차이와 그대로 둘 장점

공통으로 프로젝트·첫 요청·자료 위치·기존 기록을 찾았고 같은 프로필 재시작 후 내용을 다시 확인했다. 역할별 차이는 역량 순위가 아니라 선택한 경로의 차이다. 초보는 잘못 분류한 초안을 바꾸었고, 주니어는 잘못 저장된 보고를 정리하려 했다. 미들은 보고 후 새 요청까지 이어갔다. 시니어는 목적과 요청을 한 화면에서 입력해 저장 경계와 재개 상태 문구를 문제 삼았다. 스태프는 두 영역과 전달문 범위·조건의 일관성을 보았다. 역할 프롬프트가 이 관심사를 유도했다.

- 첫 화면의 MOCK·AI 연결 없음·복사해도 자동 실행되지 않음, 이력의 미실행·앱 미검증 표시를 유지한다. 다섯 세션에서 **지속적인 자동 실행 오해는 관찰되지 않았다**. UI 밖 실제 호출을 네트워크 감사로 검증한 결과는 아니다.
- 원문과 보고, 요청 의도와 검증되지 않은 구현 주장을 구별하는 표시는 유지한다. 미들의 세 이력 카드가 이를 뒷받침한다([22](evidence/middle/22.json)).
- 목적·영역·요청의 구분, 선택적인 영역 설명, 영역 생성 후 바로 요청할 수 있는 안내는 유용했다.
- 초보의 초안 모드 전환·복귀와 스태프의 초안 비우기는 관찰된 장점이다. 총괄의 별도 합성 프로젝트에서 휴지통 이동 후 ‘되돌리기’로 프로젝트가 목록에 다시 나타난 것도 관찰했다. 재진입 후 전체 내용 대조는 수행하지 않았으며 백업 왕복이나 개별 보고 복구까지 확장하지 않는다.

후순위 후보도 남긴다. 초보·스태프는 두 영역 중 하나가 화면 밖이라는 안내를 보았지만 ‘모두 보기/전체 맞춤’은 시도하지 않았다. 재시작 후 ‘이어서 하기’가 마지막 편집 위치 대신 전체 공간을 여는 것은 복귀 기대 차이였으며 데이터 손실은 관찰하지 않았다. 시니어의 후속 확인 초안이 있는데 ‘아직 다음 요청이나 확인 작업문 없음’이라는 전체 공간 문구는 상태 의미 설명 후보다([15](evidence/senior/15.json), [19](evidence/senior/19.json)); 저장·내보내기 정책을 확인하지 않아 버그로 단정하지 않는다.

## 1280px·좁은 화면

총괄 별도 프로필에서 1280×900과 390×844의 시작·첫 요청 준비·이력 화면을 비교했고 **관찰한 화면에는 심각한 겹침이 없었다**. 390px에서는 상단 탐색 일부가 가로 화면 밖으로 밀렸다. 접근성 이름으로 클릭하면 보이도록 이동했으므로 영구 접근 불가로 판정하지 않는다. 가로 이동 발견성은 사람 검증이 필요하다. 전체 작업문 편집란의 좁은 화면 가독성과 복잡한 캔버스·휴지통 등 모든 상태를 검증한 것은 아니다. [화면별 증거와 한계](layout.md).

## 미확인·도구 보정·종료 조건

- 공개 호스트의 현재 배포, 실제 AI/외부 세션, 실제 외부 도구 전송, 복사·다운로드 내용, 백업 왕복, 장기 저장, 다중 사용자·병렬 실행은 미확인이다. 역할 평가에서 실제 외부 실행·키·유료 API는 사용하지 않았다.
- 공통 도구가 native confirm을 자동 취소한 것은 평가 도구 결함이다. 미들·시니어·스태프의 휴지통 클릭을 앱 무반응·복구 실패로 해석하지 않는다. 총괄이 평가 종료 후 확인창을 기록하는 도구로 새 합성 프로젝트에서 한 번만 이동·되돌리기를 검증했다. 역할 세션 성공으로 소급 합산하지 않는다.
- 총괄의 목적 재현·확인창 재현은 독립 첫 사용 세션이 아닌 사후 확인이다. 새 프로필이며 다른 역할 스토리지는 건드리지 않았다.
- 보고서·증거만 `docs/use105-persona-review`의 `docs/reviews/use105/`에 기록한다. 앱 소스·다른 브랜치·PR 병합·배포는 변경하지 않는다.
- 새 독립 비평자(gpt-6.1-sol / high 요청·수락)가 과장·반례를 한 번 검토했다. 독립성 확정 표현과 프로젝트 되돌리기 범위를 좁히라는 두 지적을 반영했다. [비평과 반영](critique.md)에 원문과 수정 결과를 기록했고 이 사이클은 종료한다. 추가 사용자 연구나 구현은 다음 사이클로 남긴다.

각 역할 폴더의 `actions.jsonl` 및 번호별 JSON은 실제 조작·접근성 화면·오류를 담고, 같은 번호 JPG는 당시 화면이다. 모든 데이터는 합성이다. [증거 파일 해시](evidence-manifest.sha256)로 파일을 대조할 수 있다. 브라우저 프로필은 임시환경에만 남기며 커밋에 포함하지 않는다.
