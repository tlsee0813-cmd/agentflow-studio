# 방법 및 환경 기록

이 문서는 USE105 관찰에 사용한 대상, 실행 환경, 절차와 기록상의 한계를 정리한다. 기능 동작에 대한 평가나 결론은 포함하지 않는다.

## 대상과 아티팩트 확인

- 공개 대상 URL: https://tlsee0813-cmd.github.io/agentflow-studio/
- 배포 커밋: `d7b0bf8541ba0b5ecca914f8d6f412f44af24127`
- 소스 커밋: `2931b50938af037a43e20ed7aba69b96ab79843d`
- GitHub connector를 통해 배포 커밋의 blob 16개를 가져와 Git blob SHA-1을 대조했다. 확인된 blob SHA-1은 모두 일치했다.
- `BUILD.txt`의 SHA-256은 `53456b07d1b729369e8665ca84cd214b80a858a261644337b2a301aede979f47`이며, 문서에 기재된 정적 asset 15개의 SHA-256도 모두 일치했다. 이 해시 대조는 총괄 측에서 프로그램으로 수행했다.
- `BUILD.txt`에는 정적 빌드가 깨끗한 `2931b50` 트리에서 `continuity/scripts/build-static.mjs`를 실행해 만들어졌다고 기록되어 있다. CI 실행 `38689525012`에는 Ubuntu 24.04와 Windows 2022 검증 작업의 성공 상태가 기록되어 있다.

## 네트워크와 실행 환경

- 클라우드 HTTP 허용목록에 공개 대상 호스트가 없었다. 기본 sandbox 실행에서는 소켓 연결이 허용되지 않아 proxy 연결 실패 및 Chromium 실행 실패가 발생했다.
- 정식 권한 승격 뒤에는 localhost HTTP 서버와 Chromium을 실행할 수 있었다. 공개 `BUILD` 파일을 대상으로 한 `curl` 요청은 `CONNECT HTTP 403 Forbidden`을 반환했다.
- 공개 호스트로 우회 접속하지 않았다. 지정된 정적 파일을 `http://127.0.0.1:8765/agentflow-studio/`에서 제공해 관찰했다. 따라서 이 세션의 화면 관찰은 공개 호스트에서 직접 얻은 결과가 아니다.
- 기존 설치 환경의 Node v24.19.0, Python 3, Chromium 154, Playwright를 재사용했고 소프트웨어를 설치하지 않았다.

## 평가자 구성과 작업 절차

- 평가자는 novice, junior, middle, senior, staff의 다섯 역할이었다. 각 역할은 `fork_turns=none`으로 생성했고, 요청 모델은 `gpt-6.1-sol`, 요청 추론 수준은 `high`였다. 다섯 생성 요청은 모두 수락되었다.
- 각 평가자는 별도 브라우저 프로필과 포트(8801–8805)를 사용했다. 평가자끼리 결과를 공유하지 않도록 했고, 이전 평가 결과·앱 소스·정답 경로를 제공하지 않았다.
- 공통 과업은 결제와 회원 정책이 정해지지 않은 소규모 공방 예약 안내를 준비하는 상황이다. 첫 요청을 정리하고 전달 자료를 찾은 다음, 영역 추가·기존 요청 확인·새 요청과 이전 결과 구분·중단 후 복귀·실수 복구를 다루도록 했다.
- 각 세션은 12–20개의 행동을 수행하거나 진행이 막히면 종료하도록 했다. `snapshot`과 `scroll` 호출은 보조 행동으로 별도 집계했다.
- 네이티브 browser 도구 대신 각 평가자가 `exec`에서 자신의 Playwright 프로필을 직접 제어했다. 총괄은 평가자 대신 클릭 대상을 선택하지 않았다. 총괄의 `environment_check`는 별도의 반응형 점검이며 역할별 관찰 데이터에 합산하지 않았다.
- 평가자에게 지정한 모델과 추론 수준, 그리고 생성 요청의 수락 상태를 기록했다. 실제 실행 backend가 요청된 모델과 독립적으로 일치하는지는 검증하지 못했다. 이 문서 작성 agent의 요청 모델·수준은 `gpt-6-luna`·`max`였고 생성 요청은 수락되었다.

## 브라우저 기록과 한계

- 브라우저 harness는 역할별 persistent Chromium 프로필을 열고, 초기 viewport를 1280×900으로 설정한다. 각 행동 뒤 페이지 URL, viewport, 오류 문자열, 전체 body의 접근성 트리(`aria_snapshot`)와 현재 화면의 JPEG 스크린샷을 저장한다.
- 동작 인터페이스는 click, fill, press, select, scroll, reload, restart, resize, snapshot을 지원한다. 요청과 결과는 역할별 JSON 및 JSONL 기록에 보관된다.
- 접근성 트리에는 화면 밖 요소도 포함될 수 있고 스크린샷은 현재 viewport만 보여준다. 따라서 이 기록 방식은 사람이 화면을 보고 조작하는 조건과 다르며, 각 자료가 나타내는 범위도 서로 다르다.
- 역할별 프로필과 포트는 논리적 분리다. 전체 filesystem의 보안 격리를 뜻하지 않는다. 브라우저의 localStorage를 직접 수정하지 않도록 했다.
- 앱의 실제 AI API·유료 AI 호출 및 외부 개발 도구로의 작업 전달은 사용하지 않았다. 배포 파일 읽기와 허용된 증거 커밋에는 GitHub 커넥터/API 및 Git을 사용한다. 사용자 비밀은 읽거나 기록하지 않았다.
- 총괄은 소스 커밋의 metadata를 확인했지만, 그 내용은 평가자에게 전달하지 않았다.

HTTP 응답 증거의 헤더 내용은 그대로 보존했고, 저장본 public-headers.txt는 문서 diff 검사를 위해 CRLF를 LF로 정규화하고 끝의 빈 줄을 제거했다. 브라우저 행동 JSON/JPG는 원래 기록을 보존했다.
