# USE105 새 독립 비평 — 한 번의 문서·증거 검토

2026-10-15. 실제 사람 연구의 타당성을 평가한 것이 아니라, AI 역할 시뮬레이션 보고서의 주장과 저장된 UI 증거 사이의 범위를 검토했다. 이전 대화·평가 이력을 상속하지 않고 전달받은 검토 과제에서 시작했다. 앱 소스·개발문서·테스트·브라우저 프로필은 읽지 않았고 UI 추가 실험도 하지 않았다. 원래 보고서는 수정하지 않았다.

검토 자료는 README.md, method-environment.md, protocol.md, layout.md와 다섯 evidence/*/review.md다. 핵심 주장은 목적 재현 02/04/06, 시니어 03/05/07, 주니어 18–21, 확인창 재현 04–06의 JSON으로 대조했다. 역할별 번호 JSON의 action을 집계했고, 스태프 10의 전달문 및 화면 크기 점검 JSON을 확인했다. environment_check 06/09/10과 junior 21의 JPG를 직접 보았다. 해시 manifest와 critique.md는 최종 포장 때 생성할 예정이라는 조건이므로 현재 부재를 결함으로 세지 않았다.

## 판정

상위 세 우선순위는 **다음 사이클에서 설명을 개선할 후보**로 유지할 수 있다. 저장 경계는 한 역할 세션과 총괄의 새 프로필 사후 확인에서 같은 방향으로 관찰됐다. 개별 결과 정리는 한 역할의 두 상세 경로 탐색 한계이며, 긴 문서 부담은 AI의 주관이다. 이 세 근거를 동일한 강도로 취급하거나 실제 사람의 실패·기능 부재로 확대하면 안 되지만, 현재 본문은 그 차이를 대부분 명확하게 적었다.

공개 호스트 직접 검증, 5명의 사람 연구, 모든 과업 완료, 외부 전달 완료, native confirm의 앱 결함이라는 중대한 과장은 발견하지 못했다. 다만 다음 두 표현은 증거가 보증하는 범위로 바꿔야 한다.

## 반드시 바꿀 표현

### 1. 독립성을 결과로 단정하는 문장

- 위치: README.md 「독립성의 예외와 도구 한계」의 “역할별 학습 오염은 피했으나”.
- 이유: fork_turns none, 역할별 프로필, 결과 미공유 지침 및 각 역할의 미열람 진술은 독립적인 선택을 뒷받침한다. 그러나 protocol.md 자체가 파일시스템 공유와 OS 수준 접근 감사 부재를 명시한다. ‘오염을 피했다’는 확정은 이 증거보다 강하다. 또한 총괄의 기술 보정이 일부 역할에 전달된 예외도 있다.
- 교체 예: “역할 간 결과 공유를 금지했고 전원 다른 역할 자료를 읽지 않았다고 기록했다. 공유 파일시스템 접근을 독립 감사하지 않았으며, 일부 역할에는 확인창 도구 제약을 사후 전달했다.”
- 유지 가능: ‘대화 이력 없이 생성한 다섯 AI 역할 세션’, ‘브라우저 프로필·스토리지 분리’, ‘총괄이 클릭 경로를 선택하지 않았다는 운영 기록’. 통계적·인간 실험의 독립성 보증으로 읽지 않는다.

### 2. 프로젝트 전체 복구 범위를 넓힐 수 있는 요약

- 위치: README.md 「공통점·차이와 그대로 둘 장점」의 “전체 프로젝트 되돌리기는 실제 관찰된 장점”.
- 이유: confirmation_check/04.json은 확인창 문구와 dismiss, 05는 accept 후 휴지통 이동과 되돌리기 버튼, 06은 목록 재등장 및 요청 1개·결과 0개를 확인한다. 복구 뒤 재진입해 모든 내부 원문·기준·영역·저장된 결과를 대조한 기록은 이 재현에 없다. 특히 이 합성 프로젝트에는 저장된 결과가 없으므로 잘못 보관한 결과의 복구를 반증하지도 입증하지도 않는다.
- 교체 예: “총괄의 별도 합성 프로젝트에서 휴지통 이동 후 ‘되돌리기’로 프로젝트가 목록에 다시 나타난 것은 관찰된 장점이다. 재진입 후 전체 내용 대조까지 수행한 것은 아니다.”
- 유지 가능: 상위 2번의 이미 좁게 쓴 “이동 후 ‘되돌리기’, 목록 복구가 관찰됐다”. 역할 세션의 성공으로 소급하지 않는 현재 구분도 유지한다.

## 상위 세 우선순위에 대한 반례

| 우선순위 | 가장 강한 반례·대안 해석 | 증거가 지지하는 결론 |
|---|---|---|
| 1. 목적 저장 경계 | 초보·주니어·미들·스태프는 ‘영역 나누러 가기’를 거쳐 목적이 작업문 배경에 남았다. 시니어는 핵심 제약을 첫 요청에도 다시 적어 해당 제약이 전달문에서 실제 유실된 사례는 아니었다. 목적 입력 자동 저장을 명시적으로 보장한 문구도 확인되지 않았다. | 같은 첫 화면에서 목적을 입력한 뒤 영역 버튼을 거치지 않고 바로 첫 요청을 준비하는 경로에 한정하면, 배경 없음 표시와 이후 빈 목적 편집칸이 관찰됐다. purpose_check의 목적에만 둔 휠체어 안내 조건은 이 경계의 위험을 더 선명하게 한다. 1역할+1사후 재현이며 빈도·영구 소실·모든 경로 결함은 아니다. |
| 2. 잘못 붙인 결과 개별 정리 | 주니어는 보고 자료 펼침과 이력 원문 두 경로만 확인했고, ‘정리 바로잡기’, ‘이번 요청 바로잡기’, ‘이 입력 다시 정리’ 등 다른 제어는 추가 탐색하지 않았다. 이들이 해당 보고의 정정을 지원하는지는 미확인이다. 원문과 ‘앱 미검증’ 표시는 유지됐다. 프로젝트 목록 되돌리기는 개별 보고 정리와 대상이 다르다. | “한 AI 역할이 두 상세 경로에서 개별 결과를 정리할 다음 행동을 찾지 못했다”는 발견성 후보는 성립한다. “개별 삭제/정정 기능이 없다”, “앱에 복구가 없다”는 결론은 성립하지 않는다. 현재처럼 가능한 방법·영향 범위 안내를 우선 제안할 수 있다. |
| 3. 전달문 검토 위계 | 모든 역할이 자료 위치와 복사·저장 버튼을 찾았다. 긴 ID·근거·권한 안내는 추적성과 범위 보존에 도움이 될 수 있고, 수신 개발 도구에는 유용할 수 있다. staff 10의 원문 금지는 그대로 남아 있어 ‘추가 조건 없음’이 금지 유실의 증거는 아니다. | 본문에 긴 식별자·기준 안내가 있다는 것은 관찰 사실이다. 네 역할의 부담·혼선 평가는 AI의 해석이며 사람의 이해 실패나 수신 도구 성능 저하를 입증하지 않는다. 앞에 사람 검토용 짧은 요약을 두는 후보는 가능하되, 그 효과는 아직 입증되지 않았다. |

## 요청된 일곱 점검의 결과

1. **공개 호스트와 로컬 배포:** README와 방법 문서는 지정 파일 해시 대조와 localhost 관찰을 구분하고, 공개 호스트의 현재 내용·캐시·헤더 미확인을 명시한다. 현재 제목의 ‘공개 체험판’은 평가 대상의 성격으로 읽을 수 있으며, 본문은 공개 호스트 검증을 주장하지 않는다. 해시 검증 자체는 총괄이 수행했다는 보고와 근거 연결을 검토한 것이고 이 비평자가 재계산한 것은 아니다. BUILD/CI 내용 역시 이 검토에서 독립 실행 검증하지 않았다.
2. **목적 저장 경계:** senior 03→05→07과 purpose_check 02→04→06은 서술과 일치한다. 목적에만 적은 조건이 있는 사후 확인과 빈 목적 편집칸은 단순히 접힌 요약만 잘못 읽은 설명보다 강하다. 다만 백업·저장소 내부·장기 보존을 검사하지 않아 영구 삭제 판정은 할 수 없다. 현재 제한 문구를 유지한다.
3. **개별 결과 탐색 실패:** junior 18–21에서 실제 합성 보고 보관과 두 상세 경로 탐색을 확인했다. 다른 역할의 초안 정리나 프로젝트 휴지통을 같은 성공/실패로 합산하지 않은 것은 정확하다.
4. **긴 전달문 부담:** README는 AI 역할 해석과 실제 문서 내용을 구분하며 실제 사람·수신 도구 미검증을 명시한다. 이 구분은 충분하다. “사용자가 무엇을 검토할지 확신하기 어렵다”는 문장은 해당 절의 AI 해석 한정과 함께 읽어야 하며 일반 사람의 입증된 반응으로 인용하면 안 된다.
5. **다섯 역할·수치·모델:** 번호별 JSON action 집계는 초보 20+snapshot 1, 주니어 20+1, 미들 20+2, 시니어 17+2, 스태프 20+2와 일치한다. 주 행동은 합계 97, 보조 snapshot은 8이며 효율·성공률은 아니다. 모델은 요청 gpt-6.1-sol/high와 spawn 수락 수준의 근거만 있다. backend 확인 불가를 명시한 현재 서술은 적절하다. ‘평가자 5명’보다 ‘AI 역할 에이전트 5개’가 더 명료하지만 첫 문장의 AI 한정이 있어 필수 오류로 세지는 않는다. 독립성 확정 표현은 위 1번대로 고친다.
6. **native confirm 보정:** 미들·시니어·스태프의 무변화 화면을 앱 무반응으로 판정하지 않은 것은 타당하다. 당시 JSON만으로 native dialog를 직접 확인한 것은 아니며 원래 도구 제약은 총괄의 기술 보정이다. 별도 confirmation_check는 실제 confirm과 dismiss/accept 후 상태 차이를 기록하므로 프로젝트 휴지통 경로에 확인창이 있다는 반증은 제공한다. 이를 역할 첫 사용 성공이나 개별 결과 복구로 소급하지 않는다. 목록 복구를 넘는 요약만 위 2번대로 좁힌다.
7. **부분 완료·미도달·화면 크기:** README의 다섯 전체 과업 부분 완료, 미들의 두 번째 영역 미도달, 초보/스태프의 초안과 저장 기록 구분, 미들만 새 요청 제출 후 3개 이력 비교가 역할 기록과 맞는다. 390px에서 가로 탐색이 잘리지만 locator 클릭 후 이동한 화면과 09의 전체 작업문 입력란 미도달 한계를 구분한 layout.md도 적절하다. 일부 화면에서 심각한 겹침을 관찰하지 못한 것을 전체 모바일 대응 보증으로 확대하지 않았다.

## 유지할 결론과 종료

첫 작업문과 전달 버튼은 다섯 AI 역할 모두 찾았고, 목적·영역·요청·합성 결과·미검증 표시와 같은 프로필 재시작 복귀가 관찰됐다. 이는 실제 사람의 성공률이나 숙련도 차이를 뜻하지 않는다. 우선순위 1의 경로별 저장 경계, 2의 제한된 개별 결과 정리 발견성, 3의 사람 검토용 요약·표현 위계 후보를 유지한다. 새 기능을 확정 요구하거나 추가 실험으로 이번 사이클을 확대할 필요는 없다.

위 두 표현과 최종 링크·manifest 포장만 총괄이 정리한 뒤 종료할 수 있다. 이 리뷰는 한 번의 검토이며 수정 후 두 번째 평가를 요청하지 않는다.

## 총괄 반영 기록

독립 비평은 fork_turns none, gpt-6.1-sol / high 요청으로 생성·수락됐다. 실제 backend 모델은 별도 확인하지 않았다. 비평자의 원문은 위에 그대로 보관했다. 총괄은 README에서 (1) 학습 오염 회피 확정을 미공유 지침·미열람 자술·접근 감사 부재로 바꾸고, (2) 전체 프로젝트 되돌리기를 합성 프로젝트의 목록 재등장 관찰로 좁히며 복구 후 전체 내용 대조 미실행을 명시했다. 상위 3개 후보와 반례는 유지했다. 수정 후 추가 UI 평가나 두 번째 비평 없이 사이클을 종료했다.
