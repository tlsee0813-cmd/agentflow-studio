# IDEA014 rev1 — 합성 프롬프트 비교 결과

2026-10-11 Cloud 최종 보고를 요약한다. 기존 공개10사례와 새 합성4사례에 두 전략을 적용한 첫28회, 실제 질문에 연결한 합성 시험답변 후속4회가 완료됐다. 보고상32회 모두 HTTP200 / deepseek-flash / finish=stop이며 자동 재시도와 JSON 수선은 없었다.

## 결과

| 응답 계약 검사 | 기본안 | 개선안 |
|---|---:|---:|
| 기존 공개10사례 | 8/10 | 10/10 |
| 새 합성4사례 | 3/4 | 4/4 |
| 첫 응답 합계 | 11/14 | 14/14 |
| 후속 각2회 | 1/2 | 1/2 |

개선안의 첫 계약 통과 수는 높았지만 의미 우월성은 입증되지 않았다. Cloud의 정성 검토에서는 명확한 문구 수정·CSV 요청에 양쪽 모두 바로 진행했고, 개선안은 삭제 사례에서 명시된 cascade 의도와 미확인 FK 동작을 구분했다. 반면 다음 문제가 남았다.

- **임의 보류:** DEV-03과 원인 미상 결제 사례에서 개선안이 고객 결정 없이 보류했다. 기본안의 사실 질문이 더 유용하다는 관찰이다.
- **질문과 가정의 확대:** 문의 정리에서 개선안의 정책 질문이 늘었고, 공개 범위 사례에서는 제공되지 않은 유형 필드를 가정했다. 재고 사례는 양쪽 모두 사실 확인과 정책 선택을 충분히 분리하지 못했다.
- **후속 상태·출처 실패:** 홀딩 후속은 양쪽 모두 계약에 실패했다. 기본안은 `proceed/deferred`가 충돌했고, 개선안은 합성 시험답변 `F1`을 `requested` 출처로도 기록했다. 자연스러운 문장이 시험답변을 실제 고객 지시로 바꾸거나 상태 보호 실패를 덮어 주지 않는다.

## 한계

위 의미 관찰은 실행한 Cloud 에이전트의 정성 보고다. 전체32응답 원문과 검사 이유는 총괄이 아직 회수 중이며, 이 문서는 독립 원문 재검토 결과가 아니다. 계약 검사 성공과 의미 정확성·질문 부담·실제 사용자 효용은 별개다. 합성 사례의 단일 비교로 통계적 우월성이나 제품 방향을 확정하지 않는다.

공유 소스는 [`b7db132`](https://github.com/tlsee0813-cmd/agentflow-studio/commit/b7db1324794341075b64065cb43464b2bee19415)의 IDEA014 rev1이다. [Actions 실행38128094933](https://github.com/tlsee0813-cmd/agentflow-studio/actions/runs/38128094933)의 성공은 기존 `app/` 검증이며 프롬프트 효용의 증거가 아니다. 실제 API 비교를 기존 앱의 새 기능 완료나 main 병합으로 취급하지 않는다.

## 다음 판단
