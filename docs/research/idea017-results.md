# IDEA017 실제 재평가 결과

2026-10-12 Cloud 완료 보고와 후속 원문 발췌 확인 기준. IDEA016과 같은 합성 고객6흐름을 현재 앱 경로로 평가했다. 실제15회 모두 provider/app HTTP200, `deepseek-flash`, finish stop이며 여섯 계획 흐름이 완료됐다. 전송·계약·보호 오류, 자동 재시도·응답 수리·fallback은0이다. [IDEA016의 baseline14회](idea016-results.md)는 별도 기록으로 보존한다. 완료·계약 수용은 내용 품질 합격이 아니다.

## 관찰한 변화와 남은 문제

| 사례 | 호출 | 관찰 |

| C01 | 2 | 질문 없이 진행하고 구현자 보고와 실제 검증을 구분했다. |
| C02 | 3 | 질문1개에 confirmation만 합성 test_answer로 적용했다. 회신 후 확정은 반영됐지만 선택지의 비교 축·미정 기한·출처 표현은 불명확했다. |
| C03 | 2 | 명시적으로 이어받은 수동 scope·checks가 현재 작업 원문 참조 구역과 현재 checks에 남았다. 입력 원본 불변에 BOM 확인을 추가했고 관측된 범위 확대는 없었다. |

C02는 ‘자동 확정’ 제목과 ‘대기자가 응답하면’ 효과의 축이 어긋나고, 운영자 확인·순번·기한 정책을 선택지에 섞었다. 기한을 제안에서는 제외하면서 next에는 응답 기한을 포함했다. 최종 scope도 실제 test_answer 출처 대신 원래 요청인 D1을 가리켜 수정 부담이 남는다.

C03의 개선은 원본의 완전 유실 복구가 아니라 명시적 이어받기 조건의 현재 적용 우선순위 보완이다. 이전 수동값 참조는 항상 제공하되 적용 지시는 이번 요청의 명시적 재사용 범위에 한정한다. 의미 탐지를 보장하거나 다른 과거 수동값까지 일괄 적용하는 정책은 아니다. C06 baseline도 연락처 제외는 전달·반영했으며, 이번의 새 개선은 ‘별명만’ 원문 전문 전달과 결과 반영이다. C05 baseline의30→60 단계는 미실행이어서 같은 단계의 전후 비교 결과로 취급하지 않는다.

## 구현 검증과 공개 범위

독립 scratch의 신규 경계 검사13/13과 Cloud의 클린 설치·기존/continuity 타입·빌드·신규13/13 검사가 통과했다. Cloud는 Node22.16.0·npm10.9.2·TypeScript5.8.3 및 기존 모델 설정2048토큰·15초·thinking disabled를 유지했다. 기존 전체 Node·브라우저는 이 Cloud 재평가에서 반복하지 않았다. 기준 IDEA015 R3의279/45/13 검증은 [현재 상태](../PROJECT_STATUS.md)에서 별도로 확인한다.

검증 후보는179파일이며 manifest SHA256은 `5c00511bf010b31f9bae7c443221cd3933fe01caff358ef7ac2fcc7c3df04850`다. baseline178파일 중172개 동일·6개 변경·1개 신규다. 작업 브랜치에는 production의 domain·types·request validation·prompt4파일과 검사3파일을 원문대로 반영한다. 신규13검사는 기존 continuity CI glob에 포함되므로 workflow는 변경하지 않았다. ZIP·과거 원문 전사·실제 호출 결과·키는 게시하지 않는다. 종료 시 paid=false였고 Cloud 검증 후 소스와 baseline 기록의 해시는 불변이었다.
