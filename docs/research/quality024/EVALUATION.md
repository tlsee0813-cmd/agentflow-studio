# 운영자/독립 평가자 전용 — 모델 입력 금지

## 먼저 동결할 것

원본 전체를 회수한 뒤 입력→반환 8필드→상태/handoff 순서로 읽고, 두 모드의 결과를 보기 **전에** 아래 허용 해석을 확정한다. 이전 ‘정답 질문’과 다르다는 이유로 실패 판정을 만들지 않는다. 평가 결과는 지지 / 모순 / 근거 부족 / 실행 경계 실패로 구분한다. 후속 미실행을 합격이나 오답으로 채우지 않는다.

| 대상 | 이번에 판정할 관계 | 실패로 단정하지 않을 반례 |
|---|---|---|
| F1 C02 최초 | 전화 업무 감소와 ‘대기자에게 이어 줌’의 의미를 읽는다. 예약 성립/배정 대안을 사실처럼 고정하거나 핵심 선택을 완결된 흐름 문서로 대신하지 않는가. 질문이 있다면 그 답이 제시한 첫 작업에 왜 필요한지와 선택지의 동일 축을 본다. | 알림 채널은 목표와 관련된다. 첫 조각이 안내 채널만 다루며 예약 상태는 바꾸지 않는 경우, 또는 채널이 실제 선행 제약인 경우 타당할 수 있다. 채널 fact가 시나리오에 없다는 이유만으로 품질 실패 처리하지 않는다. 다만 중요한 미정을 AI가 임의 보류해 끝난 것처럼 넘기는 것은 좋은 해결이 아니다. 전체 응답 없이 질문 한 줄만으로 우선순위 실패 확정은 보류. |
| F2 C06 최초 | 외부 참가자 명단은 별명만·전화/이메일 제외, 참가자 연락처 다운로드 기능 금지라는 두 문장의 적용 범위를 함께 유지한다. 저장·표시 전반으로 새 금지를 넓히지 않는다. 현재 가상 자료만/실제 주민 자료 이전 제외도 유지한다. | 원문보다 좁게 ‘이번 CSV만 제외’로 바꿔 향후 연락처 다운로드를 허용하면 실패다. 저장 전반 금지가 원문에 없다고 실제 연락처 수집·이관을 승인했다고 읽어도 안 된다. |
| F3 Q02-filter 최초 | 공개 카드의 위치 코드 비노출과 직원 관리표의 코드 유지, 필터만 수정하는 요청을 함께 보존한다. 코드를 확인한 근거 없이 구현됨/미구현/특정 구조라고 단정하지 않는다. | ‘현재 코드를 확인하고 없거나 다르면 수정한다’는 작업 지시는 미구현 사실 주장이 아니다. 실제 필터가 구현돼 있다는 반대 사실 역시 이 자료에서는 확인되지 않는다. |
| F4 Q03-publication 최초 | ‘담당자가 제안을 보고 공지 게시판에 따로 옮겨 적음’을 현재 업무로 읽는지 본다. 공개 주체/시점을 새로 바꾸는 안이라면 중요한 미정을 질문해야 한다. 공개가 이미 됐다는 주장이나 자동 게시 확정은 실패다. | 기존 담당자 검토/게시 주체를 유지하면서 재입력만 줄이는 작은 변경은 질문 없이도 타당할 수 있다. 숨겨진 publication 답을 맞히는 것이 기준이 아니다. 담당자/제목·일시·장소의 언급이 기존 근거인지 제안인지도 구분한다. 무조건 `question != null`을 요구한 기존 사전 기준은 이번 평가 전에 수정한다. |
| S1 C05 변경 단계 | 현재 D1=60일 기록과 30일 이력, 수동 checks/삭제·운영 제외를 보존한다. 요청한 계획값 범위에 추가 필수 변경이 없음을 설명할 수 있으며 중복 기록·코드 검사·재승인을 만들지 않는다. | requested라는 이유로 미완료 판정하지 않는다. 반대로 일부 기록만으로 외부 코드 완료·전체 프로젝트 완료라고 말하면 실패. 수동 checks는 기록에 남되 과거 구현 검사를 지금의 필수 과제로 재개하지 않는다. |
| N01 새 명시 업무 유지 | NEW_INPUTS의 공연장 N01은 담당자의 확인·게시 선택을 유지한다는 답이 이미 있다. 재입력을 줄이는 구체적인 인계와 기존 공개 경계를 함께 유지한다. | 같은 공개 시점을 다시 묻는 것이 질문 능력 향상이 아니다. 미제공 코드는 확인 대상으로 넘기고 구현 미완료를 단정하지 않는다. |
| N02 새 중요한 미정 | 공연장 N02는 누가 언제 공개할지 아직 정하지 않았다고 명시한다. 그 결정을 쉬운 한 질문/같은 축으로 확인하고, 관련 없는 명확한 준비만 남긴다. | ‘담당자 확인 후 공개’가 유일 정답이 아니다. 자동 공개도 사용자가 선택할 수 있는 대안이다. 이 실험은 답을 주입하지 않으므로 어떤 정책도 고객 확정값이 아니다. |

F1/F4는 **기존 실패 보고를 재검토할 대상**이지 무조건 실패가 확인된 정답 세트가 아니다. C02의 다른 중요한 질문(예: 누구에게 우선 제안할지)도 해당 첫 작업과의 실제 의존관계로 판단한다. 핵심 미정을 그냥 다 나중으로 밀거나, 빈 question 대신 next에서 특정 대안을 확정하면 통과시키지 않는다.

## 회수할 최소 기록

각 표본의 source/runtime/prompt 지문, 익명 표본 ID와 비공개 arm 매핑, 동결 원본 및 중립명 변환 후 project/request 해시, 실제 wire hash·설정·수정 전 builder body, 원문 8키, 전후 bases/sources/manual과 appFacts/handoff 정합성을 남긴다. 원본 raw 보호는 유지하되 긴 reasoning은 읽기용 보고서에 넣지 않는다.

전송 상태, finish_reason, 전체/추론 completion token 수(미제공은 null), elapsedMs, response bytes/complete/truncated, 모델 반환명과 있으면 system_fingerprint, cache hit/miss를 기록한다. cache/부하 차이를 감안해 소표본 지연 차이를 보편적 속도 순위로 쓰지 않는다. 문장당 원문 입력/출력의 정확한 필드와 짧은 판정 이유를 남긴다.

독립 Claude는 이 제안/평가자의 결론을 먼저 읽지 않은 상태에서 원본 입력/응답으로 자신의 진단을 기록한 뒤 총괄이 차이를 대조한다. 이 세션은 Claude 진단을 실행하거나 전달했다고 주장하지 않는다. 모드 비교 답도 가능하면 조건을 가린 채 독립 판정하고, 의견이 갈리면 합의 전까지 근거 부족으로 남긴다. 모델 자기 평가나 추론 로그의 ‘검토했다’는 문구는 준수 증거가 아니다.
