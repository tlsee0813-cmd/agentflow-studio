# QUALITY024 — 원문 보충 재판정과 평가 보완

2026-10-12 별도 Claude 독립 재판정의 프로젝트 사실·판정 요약이다. 네 사례의 sources 전체와 assistant8키를 읽었으며 provider 입력·응답 후 상태·handoff는 보지 않았다. 기존 [평가기준](EVALUATION.md)과 연구8자료는 조사 당시 원문·manifest를 보존하고 아래를 후속 보완으로 사용한다. **이전 응답의 재판정이며 모델 개선이나 새 실험 결과가 아니다.**

| 사례 | 재판정 |
|---|---|
| C02 | 실패. scope는 외부 알림 채널 결정을 제외하면서 question은 채널을 질문하고, 선택지에 채널과 자동 알림을 하지 않는 안이 섞인다. next는 대기 순서를 미정으로 두면서 첫 사람부터 제안하는 흐름을 전제한다. 예약 성립은 다루지 않았지만 자동 확정을 몰래 가정한 것은 아니다. 이후 단계 미실행은 허용 답이 없는 하네스 한계 |
| C06 | 실패. understanding·scope·checks는 원문 제약 대상과 맞고 **next만** 저장·표시·다운로드 전반으로 넓혀 필드 간 모순을 만든다. 실제 개인정보 처리 허가 문장에서 비롯됐다는 원인 가설은 근거가 약해 철회 |
| Q02 | 실패. next가 D2 requested/원문 보관을 코드 미반영으로 바꿔 주장한다. 같은 필드의 ‘이미 있으면 근거 보고’ 조건과도 모순. 앱 기록 상태는 외부 코드 상태 증거가 아님 |
| Q03 | **통과 / 표현 약함**. 담당자가 제안에서 공지로 전환하는 현행 주체를 유지했고 자동 공개를 가정하지 않음. 수작업 전제 유지 표현은 재입력 감소와 혼동 가능하고 ‘등록만으로 공개하지 않음’은 명시하지 않았음 |

## T1에서 구분할 기준

- 결정 처리는 **질문함 / 명시적 기본값 / 다루지 않음 / 묵시적 가정**으로 구분한다. 질문·명시적 기본값은 허용, 묵시적 가정은 실패, 다루지 않음은 별도 표시한다. 특정 질문 한 줄의 존재만으로 점수화하지 않는다.
- scope의 제외와 question·next, next의 자기 모순, 제약 해석의 필드 간 일관성을 별도 판정한다.
- 제약 충실도는 필드별로 기록한다. next·checks의 대상·행동 확대는 다른 필드가 맞아도 없어지지 않는다.
- requested·confirmed 등 앱 기록 상태에서 코드 구현 여부를 단정하면 실패다. 출처가 붙은 사용자 진술과 조건부 확인 지시는 구분한다.
- 질문 선택지가 같은 비교 축인지, 한 선택지가 요청 목적을 버리는지 확인한다.
- 반복 결과가 다르면 불일치로 남기며 단일 OFF/ON 한 쌍으로 효과를 확정하지 않는다. 이력 유도·중립 이름 등 입력 조건도 구분한다.
- C05는 이번 계획값 반영 범위로 보고 내보낸 작업의 연속성은 별도 제품 과제다. 최초 응답 비교이므로 질문 대기 뒤 미실행 단계는 채점하지 않는다.

prompt 필드 순서·제약 인용은 후속 가설이며 이번 T1에 섞지 않는다. 재확인하지 않은 논문·표준 기억은 근거로 인용하지 않는다. T1은 같은 prompt/input의 OFF 대 ON/high 대조 도구 제작 중, 실호출0·제품 변경0이다.
