# UI001에 전달할 참고안 — 지금 적용 후보 최대 3개

상태: **연구 제안 / 미확정 / 미구현**. UI001의 현재 결과물을 읽거나 수정하지 않았다. 기준은 지정 commit의 `app/continuity`다. UI의 기존 수정 허용 범위를 넓히지 않는다. SOURCE_MAP의 원문 열람 수준을 함께 전달한다.

## U21-1 · 현재 작업과 다음 행동 하나를 우선

**불편:** 입력·기준·이력·진행 설명이 동시에 보이면 무엇을 읽고 누를지 고객이 다시 분류해야 한다는 가설.

**기존 해결책:** GOV.UK/DWP의 요약과 국지 수정, 단순 순차 작업에 불필요한 task list를 피하는 지침. [A07][A08][A09]

**최소 범위:** `public/index.html`/`src/client/app.ts`에서 현재 작업을 중앙 우선 영역으로 두고, 그 단계에서 유효한 주요 행동을 앞세운다. 작업문은 직접 편집 가능하게 유지한다. 원문·조건·전체 이력은 접지만 삭제하지 않는다. 필요한 질문이 없을 때 질문 화면을 거치게 하지 않는다. [P06][P07]

**유지 비용/수용 관점:** 질문 필요/초안/인계 후/보고 후 각각에서 주요 행동이 올바른지 UI 상태별 확인. 모든 원문을 반복 출력하지 않아도 전문가가 현재 조건 하나를 찾아 바꿀 수 있어야 한다. 사용자 조사 효과 수치는 TBD다.

**의존성:** 새 데이터 계약 없이 기존 값으로 가능한 화면 작업이다. 큰 작업 그래프를 선행시키지 않는다.

## U21-2 · 수정 지점에서 전후 차이와 근거를 열기

**불편:** 과거 이력을 뒤져야 변경 이유를 알거나, 새 AI 문구가 수동 수정값을 밀어낸 것으로 보임.

**기존 해결책:** Lovable의 편집/미리보기 구분, jsondiffpatch의 식별자 기반 diff·snapshot 원리. [A02][A03][K01][K03]

**최소 범위:** 해당 작업 옆의 상세에 직전 인계와 현재 내보낼 값의 차이, 관련 기준 ID/출처를 둔다. 네 필드 비교에 새 dependency를 넣지 않는다. 아직 저장하지 않은 편집만 취소할 수 있는 경우에는 그렇게 정확히 표시한다. 사용자가 직접 저장한 수정에 동일 의미의 재승인 창을 붙이지 않는다. 현재 `currentWork`의 수동값/낡은 AI 제외 규칙을 UI가 우회하지 않는다. [P04][P05]

**유지 비용/수용 관점:** 긴 텍스트, 다른 필드 수동값, 인계 후 수정, 기준 변경 뒤 늦은 응답에서 비교 대상이 정확해야 한다. 이후 변경이 생긴 상태에서 과거 patch를 단순 반전시키는 범용 Undo는 제외한다.

**의존성:** 새 ‘계획 반영/외부 관측’ 필드는 IDEA020 합의 전 추측 생성하지 않는다. 현재 코드에서 입증되는 source/revision만 보여준다.

## U21-3 · 실패·미검증·재개를 행동과 함께 표시

**불편:** ‘오류’ 또는 ‘완료’만 보이면 데이터가 남았는지, 실행됐는지, 다음에 무엇을 할지 알 수 없음.

**기존 해결책:** Linear의 실행 활동 표시, Lovable의 복원 실패/해결 사례. 현재 앱의 저장 실패·복사 fallback·늦은 응답 보호. [A06][A05][P07][P08]

**최소 범위:** 보고/증거를 수신해도 외부 검증을 자동 완료하지 않는다. 마지막 확인 자료와 대상 인계를 보여주고, 자료가 없으면 ‘구현 안 됨’ 대신 ‘확인 자료 없음’으로 말한다. 저장 실패 시 입력 보존과 백업/복구 선택, 복사 실패 시 기존 텍스트/파일 대안, 재개 시 현재 작업을 제시한다. 자동 재호출·새 비용은 만들지 않는다.

**유지 비용/수용 관점:** 빈 상태, 저장 충돌, 잘못된 import, 복사 실패, 처리 중 수정, 늦은 응답에 대한 기존 의미를 보존해야 한다. 실행 성공을 흉내 내는 애니메이션/녹색 완료는 금지한다.

**의존성:** P07/P08이 제공하는 기존 에러를 표시하는 것은 UI 범위다. 새로운 원자적 저장/협업 병합을 UI001에서 구현하는 것은 아니다.

## 나중으로 미룰 것

상시 전체 캔버스, 모든 이벤트 타임라인, 전체 프로젝트/외부 코드 Undo, 모델·effort 조절판 확대, 새 상태 enum, 실제 실행 버튼을 현 UI 패치에 섞지 않는다. UI001은 코드 근거 없는 완료 표시를 줄일 수 있지만, 없는 외부 관측을 만들어낼 수는 없다.

## 총괄이 반영할 방식

U21-1~3은 배정 변경 명령이 아니라 참고안이다. 현재 UI001 결과와 비교해 이미 해결한 항목은 다시 구현하지 않는다. 실제로 데이터 계약이 필요한 작은 부분만 IDEA020의 결과와 연결한다.
