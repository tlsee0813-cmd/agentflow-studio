# IDEA013 — 실제 합성 프롬프트 비교 결과

2026-10-11. `experiments/idea013/`의 기본안과 개선안을 합성 개발6사례와 별도 작성한4사례에 비교했다. 첫 응답20회와 실제 첫 질문에 연결한 합성 시험답변 후속4회, 총24회 모두 HTTP200 / deepseek-flash / stop으로 종료됐고 재시도는 없었다. 이전 실험14회는 별도 기록이다.

| 제공된 구조·출처 검사 | 기본안 | 개선안 |
|---|---:|---:|
| 첫 응답 | 7/10 통과 | 8/10 통과 |
| 후속 응답 | 2/2 통과 | 2/2 통과 |

이 수치는 형식·일부 출처 규칙의 통과 수이며 의미 품질 점수가 아니다. HTTP 성공, 구조 통과, 사용자 효용은 각각 구분한다.

관찰된 유용한 차이는 개선안이 문구만 바꾼 DEV-06에서 불필요한 정책 질문을 줄이고, 실제 동작 미검증을 남긴 채 좁게 진행한 점이다. DEV-03에서는 실제 화면 값과 기대 값 비교를 더 구체적으로 요청했다. 명확한 CSV 요청은 양쪽 모두 추가 선택 없이 진행했다. 후속에서 명시적인 시험답변은 `test_only`, 모르는 답은 `deferred`로 유지됐다.

남은 문제는 다음과 같다.

- **출처·상태 계약:** 명시된 새 요청과 기존 확정 결정, 현재 동작, 가정을 혼동한다. DEV-02 기본안의 거절은 명시된 요청을 `confirmed`로 쓴 계약 문제이며 없는 요구를 발명했다는 증거는 아니다. 회비·삭제 사례에서는 기존 확정이 아닌 동작이나 가상의 보존 필요를 확정 충돌로 분류했다.
- **선택지의 공정성:** 문의 정리에서 한쪽에만 재등장 불가 조건을 붙이거나, 재고 재업로드·파일에 없는 품목의 미결 규칙을 결과에 채웠다. 구체적인 장면이 이해를 돕더라도 근거 없는 결과로 선택을 유도할 수 있다.
- **미확인 사실과 조치:** 삭제 사례의 invoice FK 동작은 제공되지 않았는데 구체적인 삭제 결과를 가정했다. 명시적 cascade 허용에 추가 승인이 항상 필요하다고 평가하지 않았다. 결제 장애에서는 원인을 미정으로 유지했지만 이미 영향을 받은 고객의 당장 처리 방안이 빠졌고, 후속의 원인 “확정” 표현도 과했다.

검토자는 프롬프트 이름과 사전 관찰 메모를 본 상태였다. 사례·전략마다 첫 응답은 한 번씩이며 가림 평가, 반복 실험, 통계적 우월성 또는 실제 사용자 효용 검증이 아니다. 구조 검사5실패도 포함해 화면에 표시된 비교 응답과 검사 이유를 회수했다. 원본 증거 ZIP은 앱에서 다운로드하지 못했으므로 원본 묶음을 직접 검증했다고 주장하지 않는다.

기준 커밋 [`c6dc5ea`](https://github.com/tlsee0813-cmd/agentflow-studio/commit/c6dc5ea44de628583ae5f34cccadc7c2a398c2e2)의 [Actions 실행](https://github.com/tlsee0813-cmd/agentflow-studio/actions/runs/38123052025)은 총괄이 GitHub API로 completed/success를 확인했다. 이는 기준 코드의 CI 결과이며 프롬프트 내용 품질의 합격 판정은 아니다. 기존 `app/`과 과거 기록은 유지됐고 main 병합은 없었다.

다음 IDEA014에서는 명시 요청·기존 확정·가정의 출처 계약을 정리하고, 대안에 같은 비교 조건을 적용하며, 모르는 사실을 확인하는 질문과 사용자 정책 선택을 분리한다. 기존10사례는 이제 개선 과정에 노출된 개발 자료다. 새 Claude4사례를 미공개로 준비해 첫 프롬프트가 고정된 뒤 비교하고 실패와 누락도 그대로 남긴다. 리허설 방향이나 개선안의 우월성을 이번 결과만으로 확정하지 않는다.
