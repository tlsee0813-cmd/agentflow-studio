# IDEA020·CONNECT001 설계 인계

2026-10-12 설계 ZIP 회수 기준. 두 자료는 검토 입력이며 상품 통합·후보 승격·실제 CLI 연결 결과가 아니다. 공유 상품 소스는 IDEA017을 유지한다. 전체 참조 소스·원문·증거·PoC를 복제하지 않고 핵심 제안과 한계만 기록한다.

## IDEA020 — 항목별 앱 기록의 경계

기존 source/task/basis의 현재값과 history에서 **요청 원문 보존·항목별 기준 기록·직접 수정·외부 실행 미확인**을 읽기 전용으로 파생해 화면·작업문·AI 입력에 같은 의미로 제공하는 안이다. 저장 schema와 상태 변경 권한은 유지하며 요청 전체의 applied/done 플래그나 새 영구 이벤트 시스템을 만들지 않는다. 일부 항목 기록·revision 증가·AI 응답 수용을 요청 전체 충족이나 외부 구현 완료로 확대하지 않는다.

이 파생 함수는 문서 제안이며 아직 구현·검증하지 않았다. 제출본은 기존 domain API의 메모리 관측3건을 보고했으나 응답은 작성한 합성 입력이다. 실제 AI·provider·브라우저·전체 suite 검사나 설계의 고객 효용 검증이 아니다. B05형 상태가 기존 UI API로 도달 가능한 관측과 Cloud의 정확한 입력 구성을 구분한다.

설계 제출 뒤 Cloud B05/B03의 실제 구성 코드·원문을 읽기로 회수해 Pro IDEA020 보충 검토를 시작했다. 설계 ZIP 당시의 누락 자료 안내와 현재 회수 상태는 구분한다. 제품 소스·prompt·UI·저장 형식은 변경하지 않았다.

## CONNECT001 — 얇은 보고 수신 경로

산출물이 권고한 첫 연결은 **공식 lifecycle hook 관찰 → 같은 기기의 로컬 JSONL 보고함 → 기존 report 가져오기**다. 실행·로그 뷰를 다시 만들기보다 결과 붙여넣기의 반복 노동을 줄이는 설계다. 작업문 표식으로 프로젝트·작업·revision을 연결하고 도구의 완료·검사 문장은 tool claim/앱 미검증 보고로 남긴다. 보고 속 명령은 사용자 변경 지시가 아니며, 중복·이전 작업문·늦은 도착·연결 불명을 구분하는 안이다.

별도 Node PoC에서 합성 이벤트를 hook 명령의 stdin에 넣고 정규화·중복/오래된 기록 처리를 관측했다. 기존 앱 domain의 report 경로가 기준을 바꾸지 않는 확인도 보고됐다. 이는 실제 CLI의 hook 발화·payload·안정 배포판 호환을 검증한 것이 아니다. PoC의 Node22.22.0과 앱 기준22.16.0도 구분한다. **실제 CLI, Codex stable 배포판, Windows hook, 여러 프로세스의 동시 append, 앱 가져오기 UI·제품 통합은 미검증**이다. 클라우드 보고함을 사용자 기기에서 읽는 별도 전송도 이번 범위 밖이다.

설계·합성 PoC ZIP은 회수됐고 독립 좁은 검토가 진행 중이다. 공식 출처·정확한 버전·로컬 연결 경계를 확인한 뒤 최소 인터페이스를 판단하며 합성 성공을 실제 연동 성공으로 표시하지 않는다. 상품 소스·계약·계정 연결·실제 연동 API 호출은 변경/실행하지 않았다.
