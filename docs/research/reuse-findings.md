# 재사용 후보 판단 — REUSE010D

2026-10-11 연구 인계의 자체 요약이다. 라이브러리를 설치하거나 제품에 통합한 결과가 아니며,
원본 코드·전체 제삼자 보고서를 포함하지 않는다. 버전/호환성 관찰은 조사 시점의 후보 정보다.
실제 도입 때 해당 pin과 라이선스·런타임 조건을 다시 확인한다.

우선 후보는 작은 변경 계산 어댑터와 기존 평가기의 회귀 비교 보강이다. 목록/단계와 선택 상세를
비교 기준으로 두고 그래프/React가 필요할지는 따로 판단한다. 현재 evaluator가 충분하면 새
평가 프레임워크를 추가하지 않아도 된다.

| 후보·기법 | 가져올 수 있는 아이디어 | 적용 전 경계 |
|---|---|---|
| jsondiffpatch | 좁은 버전별 변경 계산 | 의미상 고객 결과를 diff만으로 확정하지 않음 |
| Promptfoo | 비교 실험 관리 | 조사한0.124.1은 Node>=22.22.0. 제품 기준22.16.0과 호환된다고 단정하지 않음 |
| effortless | 수동 설정 우선, blind A/B 비교 | Claude Code mod 결합. judge JSON 부재를 동점/허용으로 돌리는 fallback과 오류 행 제외는 복사하지 않음 |
| Durable Streams | 재연결·재생 메커니즘 | 조사 pin의 root/client 라이선스 표시가 달라 직접 도입 보류. lastEventId는 영속 반영 ACK가 아님 |
| DeepEval | 대화 품질 지표 후보 | 조사에 TS 경로도 있음. 의존성과 외부 실험 데이터 전송 경계를 확인 |
| Dagre / Yjs | 배치·협업 메커니즘 | 조사 pin은 사전 릴리스. 안정성 검증 완료로 표시하지 않음 |

도입은 현재 계약·상태 보호·fixture와 작은 입출력 대응표를 만든 후 선택한다.
provider 이벤트 읽기, 안정 ID/순번, replay/resume, 완료·실패 상태와 실행 권한은 별도다.
이벤트가 있다는 사실은 실제 클라이언트 연결 또는 model/effort 변경 지원의 증거가 아니다.
오래된 이벤트가 현재 상태를 되돌리지 않도록 revision/epoch/terminal 상태 보호가 필요하다.

현재 저장소에는 이 조사로 인한 새 패키지나 실행 adapter를 추가하지 않았다.
