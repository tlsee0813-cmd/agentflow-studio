# IDEA015 — 반복 사용 가치에 대한 독립 제품 검토

2026-10-11 Claude Opus 5.5 High의 완료된 검토를 총괄이 읽고 정리했다. 검토자는 저장소를 읽지 않았고, 전달한 흐름 설명과 IDEA014 Cloud 관찰 요약만 사용했다. 아래는 제품 가설과 설계 판단이며 사용자 평가 결과가 아니다.

## 핵심 판단

첫 요청이나 작은 수정에 매번 별도 앱을 거치게 하면 전달 비용이 늘 수 있다. 유용성이 생길 후보는 며칠 뒤 다시 시작하거나 목표를 변경할 때, 이번 작업에 필요한 기존 결정과 근거를 다시 설명하지 않아도 되는 순간이다. 기존 도구의 대화 이어쓰기만으로 충분한 경우도 인정한다.

이번 흐름에서 볼 것은 세 가지다.

- **다음 요청에 필요한 문맥:** 관련 결정을 짧게 보여 주되 무관한 결정을 끼워 넣지 않는다. 관련 결정이 없다는 결과도 정상이다.
- **돌아오는 부담과 기록의 신뢰성:** 결과를 붙여넣는 수고를 줄이고, 가져온 실행 보고를 실제 검증 완료로 승격하지 않는다. AI가 제안한 내용과 실제 사용자 행동의 출처·상태를 구분한다.
- **작은 요청의 빠른 진행:** 명확한 수정에 추가 선택·보류·승인 절차를 붙이지 않는다.

결과를 다시 가져오지 않아 기록이 계속 낡거나, 사용자가 관련 결정 표시를 쓰지 않는다면 독립 앱의 가치는 약해진다. 그때는 실행 도구 안에서 쓰는 더 얇은 방식도 검토한다. 커넥터·그래프·effort 조절은 이 판단의 목적이 아니라 후보 수단이다.

## 총괄의 적용 범위

Claude의 제안을 모두 구현 요구로 채택하지 않는다. 특히 다음을 보정한다.

- 화면을 간결하게 만드는 것과 중요한 제약을 작업 문맥에서 누락하는 것은 다르다. 관련 결정 수를 고정 상한으로 잘라 필요한 제약을 버리지 않는다.
- 사용자가 반응하지 않았다는 이유만으로 기존 결정을 삭제하거나 인계문에서 조용히 제외하지 않는다. 낡았을 가능성은 제안으로 표시하고, 명시적 변경은 적용 범위와 과거 기록을 함께 보존한다.
- 모든 상태 변경에 새 확인 버튼을 요구하지 않는다. 명시적인 사용자 입력도 사용자 행동이며, AI가 그 의미를 과장해 확정·대체하는 경우와 구별한다.
