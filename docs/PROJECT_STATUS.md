Cloud는 첫28회·후속4회 실제 호출을 완료했다. 첫 응답 계약검사는 기본11/14·개선14/14, 후속각1/2다. 개선안에도 임의 보류·과다 질문·미제공 필드·시험답변 출처 문제가 남았다. 총괄은 최종보고와 표시된 결과 JSON을 확인했고 전체 원문은 회수 중이다. [결과와 한계](research/idea014-results.md)를 참조한다. 새4사례는 실행 전 Pro에 공개하지 않았으며 모두 합성 사례다. [공유 범위](../experiments/idea014/REPOSITORY_SCOPE.md)를 참고한다.

IDEA015 원본 ZIP과 Opus 첫 수정 ZIP을 회수했다. 원본의 세 manifest와 source167파일을 별도 확인했으며, 기준145파일은 바이트 그대로이고 `app/continuity/`에22파일만 추가됐다. 원본 ZIP SHA256은 `6bf9bdd41f55164a80cdd6ef355f045809024749f1f3b1ed1b2394ac5946a046`, Opus 리뷰 ZIP은 `5fd1537a793ab52f92a2dc23751c5dc6b21c3635c828bb2e828052b0f64b5aa2`다. 신규 코드는 아직 이 저장소에 반영하지 않았다.

Opus는 보고 붙여넣기 뒤 다음 작업에서 수동 제약이 사라지는 문제와 문자열의 `$` 치환 문제를 고쳤다. 기준 수정 뒤 낡은 AI 작업문이 남는 문제는 안내 문구로 완화했으나 완전 해결로 수용하지 않았다. 반복 사용 시 중첩 스냅샷으로 저장·복구 크기 한도를 넘고, 긴 요청 이력으로 AI 정리·내보내기가 막히는 문제도 남았다. 첫 수정은 domain/test 두 파일에 한정된다. Opus 보고상 35/35검사 및 실제 Chromium141 브라우저8/8이 통과했고, 신규 회귀3개는 원본에서 실패했다. 별도 GPT6.1 Sol High의 좁은 독립 검토에서 R1·R2 수정은 실질적이며 R5·R11은 해결이 더 필요함을 확인했다. Opus에 R2 후속 작업으로 오래된 AI 정리의 기준 버전 추적, 모순 지시의 내보내기 방지, 중첩 스냅샷 제거, AI 요청 한도와 로컬 내보내기 분리, 복구 파일의 한도 일관성 및 작은 재시도·안내 결함 수정을 배정했다. 기존 데이터·수동값·기준 이력을 보존하며 원본 ZIP에 한 번에 적용할 통합 패치를 반환하도록 했다.

Cloud는 **원본**에서 클린 설치·기존/continuity 타입·빌드·신규32/32 및 실제 Chromium154 브라우저8/8을 완료했다. 기존 전체검사는277통과/1실패였다. 후속 진단에서 I9.02는 완료 원장이 생성0 no-op을 반환하는데 무조건 거절을 기대하는 테스트 전제로 확인됐다. 부모 mock 환경 오류가 아니다. 기존 원장을 건드리지 않고 임시 합성 자료로 ‘원장 부재 시 거절’과 ‘완료 시 no-op’을 분리하는 좁은 테스트 수정만 GPT6.1 Sol High에 배정했다. 이 테스트 파일 변경은 기존145파일 보존 원칙의 명시적 예외이며 제품 실행·승인 경계는 변경하지 않는다.

영구 프로필 재방문 후 다운로드 실패는 앱 핸들러를 거치지 않는 일반 Blob에서도 Chromium SIGSEGV로 재현됐다. 시스템 Chromium154/Playwright1.57 환경의 브라우저 충돌로 좁혔으나 버전 차이가 원인인지는 미확정이다. 재방문 후 새 다운로드는 여전히 실패다. 재방문 전 실제 받은2,830바이트 백업의 재방문 후 import와 기준·다음 입력 편집 중 실제 HTTP 지연응답 거절은 완료했다. 원본 소스와 과거 원장은 그대로이며 Opus 수정본 검증은 포함하지 않는다.

Opus R2 통합 수정 ZIP `7841e3cdf6efc34f43a758aa072662461a2360fa45cb5b98feb79090b360a717`을 회수했다. 작성자는 새41검사·직접브라우저12검사 통과를 보고했고, 좁은 독립 검토에서는 영속 revision 기반 낡은 AI 문구 제외·수동값 보존·v1 원본 보존을 확인했다. 그러나 짧은 요청1,001건(654,070바이트)은 저장 성공 후 배열1,000건 제한으로 load/import가 INVALID_DATA인 복구 차단이 재현됐다. Opus에 이 경계만 R3 증분 수정하도록 배정했고 통합 Cloud 전달은 수정 후로 미뤘다. I9.02 격리 테스트 수정은 Windows 좁은2검사 통과, Linux 분기 검증은 남아 있다. 신규 코드의 원격 반영·실AI 검증은 아직 하지 않았다.

현재 실질 잔여 결함을 처리 중이며 통합·운영 준비 완료가 아니다. Pro는 대기하고, Opus 수정본과 Cloud 원본 검사 결과를 구별한다. 실제 DeepSeek 검증은 이후 대상 수정본을 정해 진행한다. [제품 검토와 총괄 판단](research/idea015-product-review.md)은 사용자 효용 입증이 아니다.
