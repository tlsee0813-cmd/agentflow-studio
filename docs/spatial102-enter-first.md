## 1. 구현 전 설계 메모

### 클릭 계약

| 대상 | 기본 클릭·Enter | 정보 보기 | 끌기·편집 |
|---|---|---|---|
| 프로젝트 카드 | 카드(이름·요약 부분)와 ‘이어서 하기’ 모두 열기 | 해당 없음 | ‘휴지통으로’·‘되살리기’는 따로 둔 단추. 카드 클릭으로 일어나지 않는다 |
| 지도 영역 카드 | 카드 본문 단추 `node-enter-*` = 영역 열기 | `node-info-*` ‘정보’ = 기존 선택. 오른쪽 패널(좁은 화면은 시트)에서 이름·구상 고치기, 이 영역에 새 요청, 같이 정하기 | ⠿ 손잡이로만 끈다(포인터·방향키). 손잡이는 본문 단추 밖에 있어서, 끌기가 진입 클릭으로 끝나지 않는다. 빈 바탕을 끌면 화면만 이동한다 |
| 영역 목록 줄(좁은 화면·확대 무관) | 줄 본문 `list-enter-*` = 열기 | `list-info-*` ‘정보’ = 지도 선택과 같은 동작 | 해당 없음 |
| 영역 화면의 요청 | 제목 단추 `task-open-*` = 작업 보기(읽기 화면) | ‘원문 보기’ 펼침 | ‘이어서 작업’·‘이 영역으로 옮기기’는 명시 단추 |

- 바뀐 점: 지도 카드와 목록 줄의 본문 클릭이 ‘선택’에서 ‘진입’으로 바뀌었다. 선택은 ‘정보’ 단추로 옮겼다.
- ID를 역할 이름으로 바꿨다. 예전 `node-select-*`·`node-open-*`·`list-select-*`·`list-open-*`를 쓰던 테스트는 조용히 통과하지 않고 실패한다. 테스트는 각 줄에 근거를 남기고 실제 경로로 고쳤다.

### 보는 곳과 이어갈 작업
- 보는 곳: 전체 공간 › 영역 › 작업. 탭 기억이고 프로젝트 데이터가 아니다.
- 이어갈 작업(`currentTaskId`)과 새 요청 대상(`draftTarget`)은 따로 있다.
  - 이어갈 작업은 ‘이어서 작업’·‘작업 화면으로’로만 바뀐다.
  - 새 요청 대상은 ‘이 영역에 새 요청’(`writeInArea`)과 입력창의 영역 선택으로만 바뀐다. 작성 중인 초안이 있으면 대상을 옮기지 않고 그 초안을 연다.
- 새 ‘작업’ 화면(`view='task'`)은 읽기 화면이다. 요청 원문, 상태, 돌아온 결과 원문, 이 작업의 기준이 있다. 연다고 해서 이어갈 작업이 바뀌지 않는다.

### 경로와 층 표시
- 전체 공간·영역·작업 화면 위에 같은 경로를 둔다. 끝에는 층 이름(‘프로젝트 전체’, ‘영역’, ‘작업’)을 붙인다.
- 작업 화면(`work-view`)의 기존 경로는 그대로다.

### 복귀 위치
- 영역에서 전체 공간으로 돌아오면 창 스크롤을 되살리고, 들어갔던 카드에 포커스를 둔다. 지도 보기 위치는 기존 그대로 유지된다.
- 작업에서 영역으로 돌아오면 영역 스크롤과 그 요청에 포커스를 되살린다.
- 이 기억은 탭 메모리에만 있고 프로젝트마다 따로 둔다. 프로젝트를 바꾸면 비운다.
- 새로고침 복원(`agentflow.workspace.place`)에 작업 ID를 더했다. 읽을 때 검증한다.
  - 작업이 없어졌으면 그 작업의 영역으로 간다. 영역도 없으면 전체 공간으로 간다.
  - 보관된 영역은 기존처럼 ‘열어 보기’ 화면으로 연다.

### ‘확인할 일’ (읽기 전용, 저장 안 함)
기존 기록에서 근거가 있는 두 가지만 센다. 완료율과 외부 실행 상태는 계산하지 않는다.
1. **사용자 판단 대기.** 요청 작업의 상태가 ‘사실 확인 항목 있음’ 또는 ‘제품 선택 항목 있음’이다.
   - 기존 `taskStatus` 규칙을 그대로 쓴다. 답했거나, 질문이 낡았거나, 작업문을 내보냈거나, 결과가 왔으면 해당하지 않는다.
   - 그 작업에서 이어 쓴 요청이 있으면 넘어간 것으로 보고 세지 않는다.
2. **앱 미검증 보고.** 요청 작업의 *가장 최근* 보고·자료를 본다. 그 뒤에 아무 행동도 없을 때만 센다.
   - 아무 행동도 없다는 뜻: 그 보고에서 이어 쓴 작업이 없고, 그 보고로 후속 확인 작업문을 내보낸 기록도 없다.
   - 더 새 보고가 오면 예전 보고는 세지 않는다.
   - 보고가 있었다는 사실만으로 다시 미해결로 세지 않는다.

- 합성 시험 문맥은 세지 않는다.
- 보관된 영역의 항목은 ‘보관됨’ 표시와 함께 보여 준다.
- 각 항목의 ‘보기’는 작업 읽기 화면을 연다. 이어갈 작업은 바꾸지 않는다.

### 시작점
- 영역이 없는 프로젝트: ‘영역 추가’(이름 칸으로 이동)와 ‘바로 첫 요청 쓰기’(영역 없이)를 준다.
- 요청이 없는 영역: ‘이 영역에 새 요청’과 ‘무엇을 요청할지 같이 정하기’(기존 안내 패널)를 준다.

### 남은 한계
- 사람 사용성은 시험하지 않았다. 진입 우선이 실제로 덜 헷갈리는지는 나중에 3–5명 시험으로 본다.
- ‘확인할 일’ 규칙의 한계.
  - ‘그 뒤에 행동이 있었다’는 앱 기록(이어 쓴 작업, 후속 확인 작업문)만으로 판단한다.
  - 사용자가 보고를 읽고 앱 밖에서 처리했으면 계속 남는다.
  - 원래 작업문을 다시 내보낸 경우는 처리로 보지 않는다.
- 영역을 나갈 때 스크롤은 그 순간 값으로 기억한다. 보통 위쪽 경로를 눌러 나가므로, 영역→전체 공간→같은 영역 왕복에서는 대개 맨 위로 돌아온다. 복원이 의미 있는 경우는 아래쪽 요청에 들어갔다 오는 경우와, 전체 공간에서 카드에 들어갔다 오는 경우다.
- 작업 읽기 화면은 요청 작업만 연다. 보고의 보고(후속 확인 작업문에 돌아온 결과)는 그 요청의 결과 목록에 직접 나오지 않는다. 원래 화면의 ‘원문 보기’와 같은 범위다.
- 전체 공간에서는 경로 첫 줄과 제목에 ‘전체 공간’이 두 번 나온다. 세 층의 경로를 같게 두려고 남겼다.
