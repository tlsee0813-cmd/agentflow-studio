# 28 지도 제목 읽기 — 구현 전 정적 확인

기준은 `6b96543fdf980ff45f0e1b67f83e8a0a561a1542`. 기존 로컬 Git object에서 app.ts/styles.css 두 파일만 회수하고 Git blob·SHA256을 대조했다. `BASELINE.json`과 `baseline/`에 보존했다. 27 소스·증거는 수정하지 않았다. 구현 후보·실행 결과가 아닌 정적 검토다. 서버·브라우저·빌드·단위 검사·원격 접근·설치는 실행하지 않았다.

## 가능한 범위와 높이 경계

`app.ts:1284 areaNode`, `styles.css:2279–2290,2556–2564`가 카드 내용과 배치를 결정한다. 카드 외곽240×180, border2px, 좌우 padding34/12px로 안쪽 폭192px이고, node-enter 우측44px 예약을 빼면 제목 폭148px다. 세로 안쪽 높이는162px다.

제목은 **font-size24px / line-height27px, 최대2줄**로 해석했다. 제목54px + 직접부모1줄14px 자체는 가능하다. 원문 순서·기존 aria-label을 유지하고 뒤를 줄 제한하는 방식이다. 긴 이름의 중간 차이가 두 줄 바깥이면 여전히 구별되지 않으므로 이를 해결했다고 말할 수 없다.

모든 신호 동시 상태는 단순 제목 확대만으로 보장되지 않는다. 기존 CSS상 이어갈작업 tag는23.5px, 설명갱신은19.8px, 하위 버튼은26px다. 제목/부모/두 신호를 기존 세로 순서로 보존하면 enter 안에 약117.3px가 필요하다. 바깥 하위 버튼26px·gap6px·subtree신호 한 줄18.15px만 더해도 약167.45px로162px를 넘는다. subtree신호가2–3줄이면 더 부족하다. 이 수치는 CSS 산술이며 실제 글꼴/rect 측정은 아니다. 현재 node-enter의 overflow:hidden에 가려진 신호를 합격으로 간주하면 안 된다.

따라서 일반 카드의 두 줄 확대는 가능하지만, **고정 조작 위치·모든 기존 신호 가시성을 포함한 전 상태 합격은 아직 성립하지 않는다.** 여러 신호를 한 줄로 재배치해도 제목 폭148px에서는 이어갈작업+갱신조차 한 줄이 보장되지 않는다. 신호를 생략하거나 제목을 임의로1줄로 줄이는 보완은 제안하지 않는다.

## 승인 후 최소 후보 파일

제품 자동 전환 없이 연구 복사본의 `area-map`에만 명시 연구 클래스 `.reading-probe-b`를 붙인다. A는 원본 그대로다. zoom/threshold/저장 설정은 추가하지 않는다.

- `src/client/app.ts`: areaNode에서 원래 제목 원문과 이벤트는 유지. 비대화형 직접부모 표시만 추가한다. `areaPath(...).at(-2)`의 실제 이름을 쓰며, 깊이3이상은 별도 고정 폭 표식 ‘상위 생략’을 함께 표시해 긴 부모 이름의 말줄임에 생략 사실까지 감춰지지 않게 한다. 원래 전체 경로는 기존 패널에서 읽는다. 원래 full-path span은 A에서 유지하고 B에서만 숨긴다. 일반 요청/결과 집계는 전용 클래스 하나를 붙여 B에서만 숨긴다. 신호의 존재 조건/값과 실제 소속·관계·프레임 계산은 변경하지 않는다.
- `public/styles.css`: `.reading-probe-b .area-node ...` 하위로만 제목24/27·2줄, 구상문장/구상미기재/일반 집계 숨김, 직접부모1줄을 적용한다. 정보/이동/분기 버튼의 위치·크기,240×180·좌표·fit·선·focus/tab 순서는 건드리지 않는다. 기존 신호를 가리기 위한 overflow/clamp 규칙은 추가하지 않는다.

이 두 파일만으로 먼저 정상 조합을 비교할 수 있으나, 모든 신호 동시 상태의 높이 부족은 그대로 명시해야 한다. 그 상태까지 해결하려면 표시 신호의 재배치나 추가적인 공간 배분 결정을 별도로 승인받아야 하며, 기존 버튼 위치 고정과 충돌할 수 있다. 현재 단계에서는 새로운 신호 축약·아이콘 대체·숨김을 구현하지 않았다.
