## 정상 준비와 동일 입력
프로젝트 JSON/저장소 주입 없이 새 프로젝트→P와 실제 자식 Q/S/H 추가. Q는 ‘원인은 아직 모른다’ 정상 MOCK 분기로 **실제 advice.fact 질문**을 만들고 답하지 않음(작성자 코드 제안으로 알게 된 준비법, 사람 발견성 아님). S는 실제 H 기반 합성 return.2 정상 수신 후 S 구상만 편집해 stale, H는 실제 H를 낸 뒤 H 구상을 편집하고 원 anchor 파일을 수신해 plan-changed held. 부모 구상은 바꾸지 않음.

P 실제 요청/H를 만든 뒤 기존 UI로 백업 저장. 기준/후보의 새 격리 context에서 **동일한 실제 백업을 UI 복구**(확인 dialog 정상 수락), 동일 P return.2 파일 정상 수신으로 valid 설명/이번 탭 갱신/P current-group을 만듦. P 집계는 기록된 질문1·현재 설명1·이번 탭 갱신1·보류1·이전기준1. 이를 모든 잎의 신호로 세지 않음. ‘기록된 질문’을 ‘미결’/unread로 바꾸지 않음. 합성 보고는 실제 외부 AI/구현 기록이 아니다.

6/8도 정상 UI 추가와 백업으로 만들었다. 8에는 다른 독립 흐름 아래 **별도 객체이지만 P와 같은 이름인 부모**, 그 아래 Q와 같은 이름인 자식이 있다. 프로젝트 ID/원 H/원자료는 복구 파일 그대로, entry는 새 사본. P 수신 때 새 보고 T ID는 각 context에서 정상 생성되므로 A/B T 문자열 동일을 요구하지 않고 동일 H/본문/정확 P 연결로 비교했다. 시작 파일을 임의로 꾸미지 않았다.

## 실제 관측
- **4카드 양PC**: 기준은 Q/S/H 제목의 ‘질문’/‘표시’/‘요청’을 둘째 줄에서 볼 수 있다. 후보는 24px/27px 두 줄에서 공통 접두사만 주로 남고 구별 단어는 다음 줄 아래로 밀린다. 1280의 후보 해당 글자 Range 중심 y584.9235 > 자기/조상 clip 하단572.6669, 기준 중심547.6998 < 하단556.3248. 1440도 후보700.1907 >683.9906, 기준650.9906 <662.3906. 원본 PNG4와 원시 char/Range/clip을 함께 대조. 이 수치만으로 글자 잉크나 인간 이해도를 판정하지 않는다.
- **P 많은 신호**: 기준에서 ‘설명 갱신’ Range 노출 면적은 약33.6%, 후보는100%로 개선. ‘앱에서 이어갈 작업’은 둘 다 node-enter clip 밖으로 완전히 잘림. P subtree 집계 문구는 양쪽 다 두 줄로 드러나고 대표 hit도 양성. 4카드 정보 버튼은 양쪽 모두 center hit=true. 즉 ‘제목 확대 때문에 모든 신호가 더 나빠짐’이라는 결과가 아니다. **기준도 기록 읽기 전부 성공 아님.**
- 핵심 신호/버튼의 후보 단독 악화로 조기 종료할 조건은 확정하지 못했으므로 **6/8까지 계속**했다. 제목 구별 손실은 유지. 1280에서 6카드의 Q/S/H info 중심은 y723.56으로 viewport720 밖, 8카드의 추가 일반 영역 info 중심도 y751.26으로 밖이다. 양쪽 제품에서 동일하며 map box가 y268.89~972.89(높이704)인 당시 원시 상태다. 해당 초기 상태를 클릭 가능 PASS로 세지 않는다. 임의 fit/좌표 수리하지 않았고, 초기 6카드 후보 PNG를 반례로 보존했다. 이 원인을 후보 CSS 회귀나 fit 전체 고장으로 단정하지 않는다. 1440 해당 초기 info hit는 모두 양성.
- 기본 맞춤/부모 접기/재펼침 3단계를 모든 크기에서 수집. 비교한 초기 카드 raw rect delta는 모두0, computed matrix도 기준/후보 동일. 6/8에서 보이는 작은 글자와 정보 밀도는 그대로 남는다. 자동 배율 추가나 좌표 수정 없음.
- 8의 깊은 자식에는 후보에서 실제 직접 부모와 ‘상위 생략’ 표기가 있음. 그 부모는 동명 P의 다른 객체임. 기존 정보 패널 경로에는 다른 독립 흐름 접두사가 보이며, 기존 **‘영역 이름 전체 보기’**를 정상 열어 자식 전체 이름을 읽었다. 경로 텍스트 자체도 축약될 수 있으므로 모든 경로 전문이 한 화면에 보인다고 하지 않는다. 후보가 기존 전문 기능을 제거하지 않았음을 확인. 6/8 초기에는 containment-frame DOM이 없고 기존 점선 소속선이 사용됨; 이번 입력에서 무관한 카드가 새 부모 프레임에 들어갔다고 주장하지 않는다.
- 원래 **↘는 영역 열기 버튼 안의 같은 이름 뒤 표시**로 남고, 긴 제목에서는 기준/후보 모두 끝 화살표가 clamp 밖인 경우가 있다. 이를 새 관계/소속 표시로 읽지 않는다.

## 종료·오류 구분
정상 수집은 4/6/8 × A/B 각각 양PC 완료: 6개 child0/외부collector0. 이것은 **시각 채택 PASS가 아니라 수집 완주**다. 별도 원시 비교 판정 프로세스는 구별 단어 손실 및 기준/후보의 필수 배지 잘림을 기록하고 **child1/외부1(기대 시각 FAIL)**. 검사 건수나 중복 크기별 관측을 사람 성공률로 합산하지 않음. 정상 실행 console/pageerror/fatal/cleanup0, 서버는 명시 종료 -15로 별도.

첫 준비 오류 4개(백업 ledger의 sha 이름 누락, 복구 확인 dialog 미수락, 복구 시작 화면에서 work 이동 누락, 후보 root build 누락)는 원 코드/traceback/종료/가용 PNG와 분리 보존. 첫 백업 오류 이전에 실제 준비/백업은 끝났으므로 그 **실제 파일을 그대로** 이어 사용했다. 후보 서버의 diagnostics 모듈 누락은 root build 준비 오류, 제품 UI 실패 아님. root/continuity 기존 빌드 경로로 해결했고 설치/제품 수정은 하지 않음. 나중 성공으로 첫 오류를 삭제하지 않았다.

`SOURCE_BINDING.json`은 pinned 입력과 종료후 source, 실제 HTTP body↔당시 disk↔종료후 disk, 실제 버전을 연결한다. 원본 source 전체/빌드/node_modules는 올리지 않음. `result.json`과 JSONL의 측정은 중복될 수 있지만 원본 그대로이며 큰 JSONL만 무손실 gzip. `RAW_INDEX.json` 원본/압축 bytes/SHA와 재해제 일치를 기록. `MANIFEST.tsv`는 자기 자신 제외 정확 payload 집합. `outer-exit.json`은 외부 tool completion 발췌이며 전체 tool transcript가 아니다.
