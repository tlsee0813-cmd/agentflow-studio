# Cycle26 calculation-v1 — 계산 후보 보류

제품 채택을 보류한다. 폭·높이 불악화 조건은 소속을 시각적으로 읽기 쉽게 만든다는 보장이 아니다. 추가 조건이나 큰 배치 알고리즘으로 확대하지 않았다. 제품·원격·v0 원본은 바꾸지 않았다.

## 비교한 작은 규칙

명시 near는 기존 경로 그대로다. 기본 자식 생성에서 기존 오른쪽 아래 시작점과 바로 아래 시작점 각각의 실제 freeSlot 결과를 계산한다. 아래 결과를 넣은 전체 경계의 폭·높이가 모두 기존 결과보다 크지 않고 하나 이상 작을 때만 아래를 선택한다. 동률·축 간 tradeoff는 기존 결과를 유지한다. 면적 최소화나 viewport 전달은 없다. 최종 addArea/setAreaParent는 기존 API로 한 번만 적용한다.

경계 대상은 visibleAreas(p, 빈 collapsed 집합), 즉 보관된 조상 아래까지 제외한 전체 펼침 카드다. 충돌 검사에서는 기존 freeSlot이 보관 카드도 계속 예약한다. 두 대상의 역할을 구분하며, 실제 화면에서 접힌 가지의 fit 경계와 일치한다고 하지 않는다. 현재 고정 카드240×180을 사용하며 프레임은 fit 경계에 포함하지 않는다.

## 결과와 반례

15개 고정 사례에서 아래 선택7개, 기존 선택8개. 양 PC 개선4개, 동일9개,1440만 개선2개, 배율 악화0개다. v0의 왼쪽 외곽 확대 반례는 기존 위치를 유지했고, 세로 tradeoff와 서로 다른 좌표의 bbox 동률도 기존을 유지했다.

그러나 A(0,0), 무관 부모 B(-300,200), B의 자식(0,600)에서는 아래(0,200)가 폭840→540·높이780 동일이어서 선택된다. 그 자리는 B의 기존 파생 프레임 안이다. 현재 생략 정책을 그대로 계산하면 A의 새 자식 때문에 B 프레임이 생략된다. 카드 충돌은0이고 저장된 실제 소속은 A다. 양 PC 모두 높이 제약으로 fit 배율도 오르지 않는다. 이는 DOM 관측이 아닌 고정 카드의 기하 투영이지만, 경계 조건만으로 공간 의미를 보장하지 못하는 구체 반례다.

거리 최소화도 보장하지 않는다. 기존 왼쪽 외곽 반례에서 v1은 부모와 delta(600,200)인 기존 위치를 유지한다. 더 가까운 아래 대안과 bbox 보존이 다른 목적임을 보여준다. 명시 near 먼 위치는 사용자 명시 입력 경로로서 그대로 유지된다.

## 실행과 증거 한계

격리 후보 compile-v1/probe-v1 exit0. Node24.19.0 보조 계산·기존 TypeScript5.8.3이며 설치는 없다. 모든 단계에 대해 원 프로젝트·기존 수동/보관 좌표·다른 field 불변, 기존 schema 저장 왕복, 카드 충돌0·상한 내를 검사했다. 실제 UI 가독성·프레임/제목 배치·native 조작·브라우저·서버·CI·전체 회귀는 미실행이다.

24 실제 저장 자료의 지도/도구 치수에서 도출한 fit 유효면610×389/770×569를 재사용했다. source의 fitViewport를 그대로 호출한다. 깊은 구조에서는 두 시퀀스가 앞선 자식 위치도 다르므로 RESULT의 policyTrace는 각 v1 입력에서 계산한 실제 두 대안을 따로 기록한다. 기존/후보 전체 시퀀스 비교와 한 단계 선택 조건을 혼동하지 않는다.

V0_UNCHANGED.json은 v0 MANIFEST의29개 원 파일 바이트 일치를 확인한다. calculation-v1 최소 공유 파일은 공유 manifest에 지정했다. 중복 src/dist는 로컬 계산용이므로 업로드하지 않아도 된다. 후보 source는689c의 source-tree.json과 candidate-v1.patch로 특정한다. v1 prepare/probe는 로컬 v0의 검증된 baseline-src/dist·24 자료를 재사용한다.
