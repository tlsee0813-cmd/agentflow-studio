## 사실 / 제안 / 합성의 경계
- **원문 계약(사실)**: 관계 6개(R1–R6)와 양끝·종류, 사실 F1–F11 요약. 각 근거 버튼은 원문 줄(고정 commit) 링크. 문장은 이 화면의 요약입니다.
- **AI 제안**: 묶음 5개 이름·나눔·세부 6개. 지도에서 점선 영역으로만 표현(배지 반복 없음). 묶음 자체는 준비문을 만들 수 없게 했습니다(준비는 세부에서만 — 제안 구성이 실행 범위로 바뀌지 않도록).
- **변경 소유**: 작업문과 미리보기 한 곳만 주황. 접힌 ‘전달할 내용’은 ‘안에 바뀐 부분 · 묶음 전체 변경 아님’ 집계만.
- **합성**: MOCK 예시의 ‘합성 목적 1/2’만 합성값. 순서(A→변경→B→늦은 A)와 ‘예약’/‘알림’·null은 원문 검사 보고(L33–41) 재구성. 사용자 발화·날짜·승인·실제 담당자·AI 성공은 만들지 않았습니다.
- 관계가 적혀 있지 않은 부분(요청 범위 구분)은 ‘무관하다는 뜻은 아님’으로 표시.

## 재사용 경계
cycle01–04 코드는 복사하지 않고 새로 작성. 지도 DOM은 한 번 만들고 클래스 토글만(전체 재렌더 없음), 고정 좌표 2벌(1440/390) + native scroll + transform 배율. cycle01의 수동 translate/scale 스냅샷 엔진과 03/04 DOM 보존 엔진을 합치지 않았습니다. 선은 매번 실제 DOM rect에서 계산하고 접힌 끝은 링(◦)으로 집계 표시, 클릭하면 실제 관계·실제 끝을 나열합니다.
