# 추가 순수 fixture 확인

최초 동결 후 총괄의 지시에 따라 준비 자료만 별도로 실행했다. Python AST에서 동결된 `SEED` 문자열을 추출하고, 테스트 모듈을 import하지 않은 채 기존 `product29-author/app` 빌드를 대상으로 Node 인수 배열 `--input-type=module --eval`을 사용했다. 실제 Node는 v24.19.0이며 지원 Node22 검증과 구별한다.

생성 exit0, 순수 전제 검사 exit0이다. currentTask가 B이고 실제 소유 부분이 B임을 확인했다. compose 대상은 A로 별개이며, 선택할 설명은 사용자 정정 r2·valid였다. C는 적용 설명 없이 보류 한 건만 있었다. 다음 파일은 실제 B와 다른 B0 및 `H29_B_NEXT`에 연결됐고 anchor/basedOn은 같은 B 부분의 r2였다. 그 파일을 순수 domain API로 받으면 current B와 기존 tasks 전체를 유지하면서 새 설명 r3가 유효하게 적용됐다.

stdout 전체 원문, stderr, exit, 실제 명령 인수 배열과 Node 버전을 분리 보존했다. fixture 생성 원문은 합성 프로젝트 데이터이며 실제 사용자 발언이나 정상 UI 작성 관측이 아니다. 복구 파일을 실제 UI로 불러오는 과정, 실제 키·휠·초점·기하, 브라우저와 서버는 아직 실행하지 않았다. 제품 및 동결 검사 소스는 변경하지 않았다.
