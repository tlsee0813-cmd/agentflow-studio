# 원격 전달 안내

검사 소스 두 파일과 작성자 증거를 별도 묶음으로 전달한다. 원격 쓰기는 총괄 담당만 한다. 제품 후보는 총괄이 알려 준 `2a7d078124e96243e949244bec945cc8da2c47ec`이며, 이 자료에서 제품 소스를 다시 게시하지 않는다.

새 검사의 준비 입력은 공개 domain API로 만든 합성 회귀 자료다. 브라우저 검사 실행 시 정상 복구 파일 가져오기로 열고, 실제 결과 파일 선택과 키 입력·클릭·휠을 사용한다. 사용자가 빈 프로젝트부터 작성하는 Cloud 정상 UI 관측과는 다른 증거다. 최초 동결은 AST와 변경 바이트 검사만 수행했다. 이후 추가 지시에 따라 동결 Python의 SEED 문자열만 추출해 Node24의 순수 domain 계산으로 생성·검증했다. 이 추가 결과는 `FIXTURE_NOTE.md`와 `FIXTURE_RECEIPT.json`에 구분했다. 서버와 브라우저는 실행하지 않았다.

`static-first.*`는 최초 인코딩 준비 실패다. workflow를 전송하는 도우미가 한글 문자를 잘못 인코딩해 AST 뒤 바이트 범위 검사에서 실패했다. 수정 후 원본 Git blob `319c464422bef913ab4eb33fdd92951101ad1aa8`을 확인했고, 기존 바이트를 유지한 CI 한 단계 추가만 남겼다. 최초 잘못 준비된 workflow 파일 자체는 보존하지 못했으며 원시 stdout/stderr/exit는 남아 있다. 이는 제품이나 브라우저 실행 실패가 아니다.

`static-review.*`는 최종 소스의 AST와 CI 범위 검사 결과다. `second`, `third`, `final`은 그 사이 서로 다른 소스 판본에서 수행한 정적 검사 기록이며 최종 판본 통과로 합산하지 않는다. 브라우저 실행 수는 0이다.

기존 `REPORT.md`와 `RECEIPT.json`은 순수 fixture 실행 전 동결 시점의 원문이다. 그 안의 ‘fixture 미실행’은 당시 상태이며, 이후 허용된 순수 실행 결과는 추가 메모를 함께 읽어야 한다. 원래 동결 보고서나 원시 로그를 사후에 바꾸지 않았다.

제품 전체 소스, frozen-source 중복 사본, 기존 workflow 전체 사본, dist와 의존성은 증거 업로드에서 제외한다. 검토용 patch는 요청한 변경 범위를 보여 주기 위해 남긴다. 테스트 모듈의 최종 원문은 별도 소스 묶음으로 제품 후보에 연결한다.
