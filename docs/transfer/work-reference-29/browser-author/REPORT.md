# 29 읽기 참고 행동 검사

실제 편집 B와 compose/지도 A를 구분하는 장면, 첫 U 입력 뒤 읽기·입력 보존, 새 설명 판본의 명시 재열기, 작업·프로젝트 전환 및 보류만 있는 부분을 네 장면으로 작성했다. 두 PC 크기에서 같은 행동을 확인한다.

나란히 읽기는 실제 N 입력란과 선택한 설명 본문(SUMMARY)의 글줄 기하·clip·hit로 확인한다. 구상·출처·이전 기록의 글줄로 대신 통과하지 않는다. 이 범위는 독립 검토 지적을 반영해 좁혔다. 첫 U 키 입력 직후에는 클릭으로 초점을 보정하기 전에 manual4 DOM 동일성, 실제 초점·선택 범위, 캡처 본문·판본·내부 읽기 위치를 측정한다. 낡은 설명은 기존 전달문의 현재 설명 구역에서 제외됐는지만 확인하며, 원보고 문구가 남는 것은 오류로 세지 않는다.

새 판본은 같은 부분의 다른 작업 B0에 대한 정확한 H 반환을 사용한다. 현재 B에 결과를 받으면 T로 옮기는 기존 정책을 바꾸거나 테스트에서 숨기지 않는다. 준비 자료는 합성 입력이며 정상 복구 가져오기로 열고 저장소나 제품 DOM을 주입하지 않는다.

로컬 AST와 변경 바이트 검사만 실행했다. 최초 workflow 준비 인코딩 검사 실패와 수정 뒤 통과 로그를 각각 보존했다. fixture 생성, 실제 파일 수신, 브라우저/서버는 실행하지 않았다. 실행 시간과 8개 행동의 통과 여부는 Cloud/CI에서 확인해야 한다. 제품 파일은 수정하지 않았다.
