# 30 지도 복귀 순서 — 작성자 v0

정확 aa0938(29 최종 후보) 격리 소스에서 app.ts 한 파일만 수정했습니다. 31 소스는 그대로 동결하며 여기에는 섞지 않았습니다. PhaseA 원제품은27이며 보고서와 gzip 원인표/사건순서의 Git blob을 직접 검증해 핵심 필드를 대조했습니다. 원6영역 깊은 복귀는 기존 카메라를 유지한 채 양PC704/884 높이가 남고, fit만으로 고쳐지지 않으며 resize는 고칩니다. 4목록 native toggle 뒤 자동회복과 무계측 재현도 확인된 원자료 범위입니다. 특정 함수의 실행을 DOM만으로 확정하지 않습니다.

openSpace의 page scroll 복원을 render 뒤에서 render의 최종 단계 앞으로 옮겼습니다. 옵션 beforeWorkspaceSizing은 최종 displayView와 기존 disclosures 복원이 끝난 뒤 실행되고, 그 다음 sizeWorkspace→finishInitialMapFit→panel reading→작업 참고 reading 순서입니다. 이미 있는 카메라는 기존 finishInitialMapFit earlyreturn으로 그대로이며 최초 카메라가 없을 때만 최종 높이에서 fit합니다. 앞선 renderMap/status의 임시 높이가 있을 수 있지만 이 진입의 최종 fit/읽기 복원 전 다시 측정합니다. 기존 render 기본 호출과 restoreOrigin(false,false) 순서는 바꾸지 않았습니다. focus/입력/카메라/프로젝트 자료를 다시 만들거나 글로벌 scroll listener를 추가하지 않습니다.

Cloud 추가 검증은 같은6영역 scroll0/1200의 exact 원본 대조를 우선합니다. 추가 정상 첫 진입은 새 프로젝트에서 목적과 첫 요청을 채우고 구상 시작 버튼 대신 첫 작업을 준비한 뒤, 아직 전체 공간을 열지 않은 상태에서 실제 휠→nav-space로 갈 수 있습니다. 이때 영역은0이며 missing-camera 분기 검증입니다. 6영역 import는 이미 첫 카메라를 만들므로 후속 복귀를 최초 fit이라고 부르지 않습니다. 비어 있지 않은 최초 fit을 억지로 만들기 위해 session/memo를 지우지 않습니다. 기존 import 초기 fit은 별도 비수정 경로입니다.

같은 복귀에서 panel 읽기/열림/초점과 기존 카메라·선택·접힘·좌표·현재 작업·4값·원보고·과거H 불변을 원자료로 확인해야 합니다. 순서 보완만으로 전체 카드 가독성/모든 진입 경로/작은 뷰포트의240최소높이까지 성공이라 말하지 않습니다.

첫 type/build는 격리 준비에 tsconfig가 빠져 TS5058 exit1, diff0입니다. 원 로그를 보존한 뒤 같은 baseline의 tsconfig2개와 app/package.json을 추가했습니다. 존재하지 않는 continuity/package.json 조회 exit128은 준비 조회 오류이며 파일을 새로 만들지 않았습니다. 최종 Node24 보조 type/build/diff 모두0이고 기존 DEP0190 경고는 남겼습니다. 설치/서버/브라우저/단위/원격 쓰기는 실행하지 않았습니다.
