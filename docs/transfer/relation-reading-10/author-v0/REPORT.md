## 설계
1. **목록 — 열기 전 구별.** 묶음(자식 있는 G2·G3·G4)을 고르면 관계를 **실제 이쪽 끝 세부별 머리** 아래에 나눈다.
   - G3를 고르면 `AI 입력 · 이 묶음 안 세부` 아래에 "받음 ← 새 요청의 배경 고정 / 요청 사본 · ‹요청 맥락› 안"이 오고, `작업문과 미리보기 · 이 묶음 안 세부` 아래에 같은 받음 항목과 "넘김 → 저장·복구"가 온다.
   - 같은 보내는 곳·요청 사본이라는 사실은 항목에 그대로 남는다. 각 버튼의 `aria-describedby`가 실제 받는 세부의 머리를 가리킨다.
   - 구별 수단으로 R ID나 색을 쓰지 않았다.
   - G2를 고르면 실제 보내는 세부 머리가 하나(새 요청의 배경 고정)만 나온다. C22에는 원문 관계가 없어 머리를 만들지 않았다.
   - G4를 고르면 일반 보고 연결(R6)과 파일 반환 연결(R5)이 각각 다른 머리 아래로 나뉜다.
   - **세부를 고르면**(C21 등) 상대가 이미 서로 다르므로 fix1 목록을 그대로 둔다. 수신부 문구를 일괄로 덧붙이지 않았다.
2. **열린 참고 — 간결화.** fix1에는 양끝 큰 카드 2개와 화살 줄이 있었다. 이것을 다음 구성으로 바꿨다.
   - 머리: `관계 참고 · 읽기 전용`과 오른쪽 위 `참고 닫기`.
   - 흐름 한 줄: `보내는 끝 → 받는 끝`(실제 양끝과 방향). 그 아래 `전달: 종류`.
   - 소속 두 줄: `보내는 쪽 ‹부모› 안 · 지도에선 접힌 ‹부모› 자리 / · 지금 선택`, `받는 쪽 …`. 최상위 끝은 `보기용 묶음`으로 적는다.
   - 조건 전문.
   - 작은 메타 줄: `지도 선택은 ‹X› 그대로 · 참고는 준비문을 바꾸지 않음`, `근거 FLOW091-C Lxx · 원문 줄 ↗ · 관계 Rn`.
   - 이름을 밝힌 명시 이동 버튼과 "선택만 옮김…" 안내.
   - 참고만 읽어도 실제 양끝·방향·소속·접힌 대표 차이·조건을 알 수 있다. 끝점이나 조건을 "앞에서 봤다"는 이유로 지우지 않았다.
3. **읽기 보조.** 머리와 소속 줄에 실제 공백이나 ` · `를 넣고 화살표를 숨기지 않았다. 스크린리더가 "AI 입력이 묶음…"처럼 붙여 읽지 않게 하기 위해서다. 이 수정은 t03 이후 HTML 변경이다.
