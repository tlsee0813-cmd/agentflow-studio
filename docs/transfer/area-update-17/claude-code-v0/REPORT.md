## 구현 요지 (INPUT 항목 대응)

1. **PlanStamp**
   - 작업별 사용자 작성 값(manual 4필드+목적 정정)은 `작업ID:sha256`(의존성 없는 동기 SHA-256)으로 넣는다. 값 자체는 복사하지 않는다.
   - 따옴표·역슬래시가 많은 6000자 필드 여러 개에서도 stamp는 유효하고 크기가 일정하다.
   - 한 글자 변화도 감지한다. Node crypto와 일치하는지 시험했다.
   - 관련 없는 영역·미전송 초안·좌표 변화에는 반응하지 않는다(기존 검사 유지).
   - 수정 1: 단순 새 요청이 만든 미개정 `requested` 기준은 넣지 않는다. 명시 개정(history)·결정·답·구상·목적·수동 조건 변화는 계속 낡음으로 처리한다.
2. **anchor 불변조건**: 명시 전달된 anchor가 같은 상태에서 계산한 anchor와 다르거나, 텍스트가 그 상태의 `handoffText`와 다르면 `ANCHOR_MISMATCH`. UI는 복사/저장 텍스트와 같은 상태에서 캡처한 anchor를 넘긴다. 기존 project/revision/epoch 보호는 그대로다.
3. **기록 이력 검증**: 적용된 외부 설명은 그 export의 설명 revision 바로 다음이거나, 같은 반환 ID의 직전 수정 해석이어야 한다. 사이에 사용자 정정이 있는 위조 r3은 거절한다.
4. **정정**
   - 낡은(구상 변경 전) 설명은 정정으로 다시 저장할 수 없다(보류 우회 차단).
   - UI 정정 초안은 시작 revision에 묶인다. 새 설명이 도착하면 저장을 거절하고 글은 보존한다(양 PC 브라우저).
   - details ID는 영역별이다(A 근거 펼침이 B로 새지 않음, 브라우저).
5. **기본 읽기**
   - 기본은 짧은 현재 설명·첫 변화·미채택 제안만 보인다. 링크 줄: 설명 전체 보기/근거 보기/설명 오류 고치기/이전 설명.
   - 설명이 없는 영역에는 아무것도 추가하지 않는다.
   - 2000/300×3/1000자 입력의 기본 블록: 패널 382px·266자, 영역 화면 225px(1280×720).
   - 끝 표지는 기본 화면에 칠해지지 않고 펼치면 전부 보인다. 저장 원문은 바이트 그대로다.
6. **위치 보기**
   - 수신만으로는 지도가 움직이지 않는다(카메라 불변 단언).
   - 명시 ‘지도에서 이 부분 보기’는 최소 pan만 한다. 카드가 남은 공간보다 클 때만 그 카드 기준으로 필요한 만큼 축소하고, 전체 맞춤은 하지 않는다.
   - 카드는 패널·도구·복귀 줄에 가리지 않는다.
   - ‘← 위치 찾기 전 보기로’는 영역 화면·작업 읽기·같은 영역의 새 요청(작업 화면)까지 이어진다.
   - 단순 nav-work→nav-space, 다른 영역·프로젝트는 새 출발이다.
7. **인계**: 유효 설명을 사용자 현재 구상 다음에 ‘전달 기록을 정리한 참고 설명 · 앱 미검증’으로 넣는다. 제안은 미채택·실행 금지로만 넣고, 낡은 설명 본문은 제외한다. 실제 clipboard 텍스트·record chars/digest·return.2 template의 anchor 일치를 브라우저에서 확인했다.

## 브라우저 증거 (AREA17, 1280×720 / 1440×900)

`observations/61-90ebf0c-understanding17.jsonl`에 모든 조건이 기록돼 있다. 각 조건은 expected·value(실제 단언 boolean)·detail(측정값)로 나뉜다. 대표 화면은 `screens/`.

- **[수신 카메라 불변]**: 수신 전후 같은 transform/배율/선택. 대상 카드는 여전히 화면 밖이다.
- **[명시 위치 보기 대상 보임]**
  - 대상이 선택되고 지도 안에 있다. 패널·복귀 줄과 겹치지 않고 창 안에 있다.
  - 배율은 카드가 맞지 않을 때만 바뀌고, 그때 화면에 축소했다고 표시한다(product13 1280: 160%→151%).
- **[원래 배율·좌표 복귀]**
  - 시작 보기의 transform·배율·선택·열린 details·초점·스크롤(휠 왕복)이 돌아온다.
  - 패널 직행, 영역 열기→작업→복귀, 이동 경로 crumb, 새 요청→복사 경로를 모두 검사했다.
  - 새 요청 경로는 위 내용이 늘어나므로, 호출 버튼 anchor 분기(문서 끝 clamp 포함)로 단언한다.

- **반례**
  - 정확 중복: 무변경.
  - 같은 반환 ID 수정 해석: r2.
  - r1 정정 초안 중 r2 수신: 저장 거절·글 보존.

## 남은 위험·한계

- 브라우저는 작성자 실행이고, 브라우저 빌드는 1194로 CI의 1200과 다르다. 새 browser 스크립트는 CI 미등록이다.
