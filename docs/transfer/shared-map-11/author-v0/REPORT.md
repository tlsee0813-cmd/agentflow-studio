**조작 방식**
- 클릭은 실제 마우스로 했다. 누르기 전에 지점이 화면 안·대상 위인지 hit로 확인했다.

- 사례 전환만 Playwright `selectOption`(실제 change 이벤트)으로 했다.

**PC 두 폭 × 두 입력, 같은 페이지에서 왕복한 흐름**
1. **처음 보기:** 아래가 입력과 그대로 일치했다.

   - 변경 칩(이름과 라벨)
   - 모든 노드, 선에 담긴 관계 ID 전부
   - 초기 깊이·무선택·100%
   - 지도 스크롤 없음, 카드 겹침 없음
   - 지도 이름과 변경 칩을 글자 단위로 관측(clip·hit)했다.
2. **변경된 한 부분 선택**(FLOW091 작업문과 미리보기 / PowerToys 키 검색·선택)

3. **근거 상세**

   - 원문은 접힌 채 있다가 실제로 펼쳐진다.

4. **관계 참고**(FLOW091 R3 / PowerToys X1)

5. **비초기 보기와 초안**

## 남은 미검증

- **브라우저:** headless Chromium만 썼다. 실제 Windows/Edge·Safari, 스크린리더, 색 대비는 보지 않았다. 사람 이해 효과도 판정하지 않는다.
- **PowerToys 지도 위치 복귀:** 130%에서도 지도가 지도 창보다 작아 스크롤 위치 복귀를 관측하지 못했다. 깊이·배율·선택·카드 복귀만 관측했다.
- **초안 창과 사례 전환:** 초안 창이 열려 있으면 선택기가 비활성(inert)이라 그 상태로는 전환할 수 없다. 그래서 ‘초안이 열린 채 전환’ 경로 자체가 없다. 전환에서 닫힘을 검사한 대상은 근거 상세다.
- **복사:** 권한을 준 headless에서만 확인했다. 권한이 없는 환경에서는 안내 문구가 대신 나온다(실행하지 않음).
- **보존 범위:** 초안과 보기는 메모리에만 있다. 새로고침·다른 세션 보존은 주장하지 않는다.
- **리뷰 댓글:** 본문의 정확한 문장은 입력에 없다(API 접근 불가). 링크로만 확인할 수 있다.
- **index.html:** 기본 입력 목록 두 줄(`data-fixtures`)이 들어 있다. 이는 설정이며 렌더러 분기는 아니다.

## 제품 연결 제안 (잠정)

**(a) 공통 흐름**
- 공간 지도의 달라진 위치에서 한 부분을 고르면, 역할 한 문장과 달라진 점 한 문장(라벨·근거 있음)을 먼저 보여 준다.
- 명시적으로 열면 전/후, 비교 기준, 관계 전체 조건, 근거 종류와 확인 한계가 나온다.
- 닫으면 같은 자리로 돌아간다.
- 두 입력에서 같은 코드로 의미가 유지됐다.

**(b) 보류와 위험**
- 연구용 2층 포함 구조, 집계선, 접힌 대표 끝점
  - 제품 Area는 평면이다.
- 사례 선택기
- 자유문 초안의 메모리 보관
- 리뷰 원문을 인용하지 않는 근거 형식
- 선 방향 표현은 여전히 보류다.

**(c) 제품에서 재사용할 경로**
- 지도 선택(mapSelected)과 이어갈 작업(currentTaskId)을 분리하는 기존 구조
- Task.id별 manual 4필드와 저장 경로
- 연구 초안으로 이것을 대체하지 않는다. 미래 요청은 기존 ‘새 요청’ 경로로 연결한다.

**(d) 한 번에 체험할 최소 범위**
- 현재 영역 카드 → 짧은 역할·변경 읽기 → ‘근거 보기’ 상세(닫기·초점 복귀) → 기존 새 요청/준비 경로 → 원래 지도.
- 데이터는 영역 note와 근거 링크 수준에서 시작한다.
- 이 연구 결과를 제품 반영 완료로 계산하지 않는다.
