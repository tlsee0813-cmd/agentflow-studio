# Cycle22 정상 UI 재입장 선관측

고정 f7b25a586dca42466f07c7db2bedb9c59703deda 제품(5370D0A6/86DDA3/C3981C), 실제 loopback HTTP→system Chromium154/Playwright1.57. 기존 경험이 있는 관측자이며 사람/블라인드 평가가 아니다. 1280×720을 먼저 수행하고 1440×900은 학습 재현했다. 제품·저장소 주입/실제 AI 호출 없음. 정상 새 프로젝트/목적/영역·포함·관계 입력을 사용했다. MOCK 오류 질문 유도는 코드에서 배운 준비법이다.

예약 아래 A=예약 가능 여부, Q=예약 오류 확인; 알림 아래 B=예약 결과 알림을 만들고 A→B 실제 관계를 입력했다. Q를 먼저 만들고 미답 유지. A 실제 H1 설명을 받아 읽은 뒤 H2 설명으로 갱신했다. B는 실제 H를 내보낸 뒤 B 자신의 구상만 UI 수정하고 옛 H의 명시 합성 return.2를 가져와 plan-changed 보류를 만들었다. 준비/판독을 구분하며 현재 A/B/Q 정답을 화면에서 처음 발견했다고 세지 않는다.

홈→같은 프로젝트의 접힌 첫 지도에서 예약 ‘기록된 질문 1 · 현재 설명 1’, 알림 ‘질문 0 · 설명 보류 1’이 보였다. 예약 기록에서 Q의 ‘답변 기록 없음’과 실제 사실확인 질문을 읽고 A 현재 설명/이전 설명을 구별했다. B에는 현재 설명 없음·보류 이유·변경된 사용자 구상과 옛 당시 작업문이 따로 보였다. 보고 선택을 명시한 뒤 당시 사본을 펼쳤다. 보고 본문 물음표를 질문으로 세지 않았다.

같은 자식 A에서 후속 요청을 실제 입력·제출하고 파일용 작업문을 실제 clipboard로 내보냈다. 정확 project/task/H/anchor는 각 FOLLOW-handoff.md와 최종 상태에 보존했다. 유효 A2 설명/외부 귀속이 이어지며 B 보류는 현재 설명이 아니다. 명시 ‘출발한 지도 보기로’로 돌아와 새 current 작업·구상·실제 관계·미답 Q가 유지됨을 확인했다. 이 관측은 모든 원점 수치 동일성/AI 의미판정 성공을 주장하지 않는다.

첫 경험 공백 후보 한 가지: 재입장 개수만으로는 지난 열람 이후 무엇이 새로 달라졌는지 알 수 없다. 현재/보류/질문은 권위 구분이며 unread/lastSeen가 아니다. A의 이전·현재 내용을 추가로 열어 차이는 확인했으나 마지막 열람과 비교하는 기준은 없다. 이는 정직한 정보 한계로 기록하며 기능 결함·정답 우선순위를 강제하지 않는다.

초기 준비 오류 2회와 공식 1280 조작 오류(이름 없는 native group을 이름으로 찾음, 보고 선택 전 사본 찾음, 패널 뒤 버튼 접근)를 원형 보존했다. 정상 UI로 닫기/명시 맞춤 후 회복했다. 준비 오류는 제품 결함이 아니다. 추가 맞춤은 초기 재입장 관측 이후이며 원래 카메라 보존으로 부풀리지 않는다. child=0/외부 launch=0은 세션 정리 종료이며 내부 actionError까지 모두 성공이라는 뜻이 아니다. pageerror/console/HTTP는 runtime 원본 참조. 당시 resource byte 해시는 실행 자원 식별이며 새로운 환경 설치는 없었다.
