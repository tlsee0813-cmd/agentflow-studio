# 전체 훑기와 부분 읽기: 고정 원문 대조

판정은 구현 채택 보류를 지지합니다. 아래 소스는 카메라 조작 방법의 근거이며, 사용자가 왜 전체를 훑어야 하는지 또는 어떤 판단 공백을 해결하는지의 효과 검증은 아닙니다. UI는 실행하지 않았습니다.

1. **Dify: 맞춤·배율·정확 위치가 별개입니다.** [zoom-in-out 121–152](https://github.com/langgenius/dify/blob/9f75925578ecd093ce3d1e30cb4c68f6efb8398c/web/app/components/workflow/operator/zoom-in-out.tsx#L121-L152)는 fitView와 zoomTo(0.25/0.5/0.75/1/2)를 나눕니다. 이 경로는 draft sync도 호출하므로 화면 조작만으로 저장 바이트가 불변이라고 말하지 않습니다. [node-navigation 21–62, 93–101](https://github.com/langgenius/dify/blob/9f75925578ecd093ce3d1e30cb4c68f6efb8398c/web/app/components/workflow/utils/node-navigation.ts#L21-L101)은 선택의 focus 기본값이 false이고, 명시 focus일 때만 지연 위치 이동을 요청합니다. 위치 이동 주석은 fitView라고 하지만 실제 호출은 setCenter(...,{zoom:1,duration:800})입니다. ‘선택하면 항상 전체 맞춤’은 틀립니다.

2. **xyflow: 저장 뷰 복원과 맞춤 계산을 혼동하면 안 됩니다.** [useViewportHelper 34–82](https://github.com/xyflow/xyflow/blob/8523d8dd9f1551954bc221dccabd6a3119ef9e22/packages/react/src/hooks/useViewportHelper.ts#L34-L82)의 getViewport/setViewport는 transform 값을 읽거나 적용합니다. fitBounds는 현재 크기·줌 한도·padding으로 새 viewport를 계산합니다. [graph 344–405](https://github.com/xyflow/xyflow/blob/8523d8dd9f1551954bc221dccabd6a3119ef9e22/packages/system/src/utils/graph.ts#L344-L405)의 기본 fit 대상은 hidden이 아니고 측정 크기가 있는 노드입니다. 전체 자료/모든 숨은 자손이 반드시 맞춤 대상이라는 주장은 부정확합니다. 이 코드가 선택이나 계층을 자동으로 바꾼다는 근거도 없습니다.

3. **tldraw: 임시 개관 후 새 범위 또는 원래 범위로 갑니다.** [ZoomQuick 22–81](https://github.com/tldraw/tldraw/blob/71e9eae0502a06b8299b9a67b881539d28516f0d/packages/tldraw/src/lib/tools/ZoomTool/childStates/ZoomQuick.ts#L22-L81)는 초기 viewport bounds와 포인터를 잡고, 처음 화면과 page 전체 bounds의 합집합을 커서 위치를 고려해 잠시 축소합니다. 줌 하한이 있어 언제나 모든 도형이 들어온다고 보장하지는 않습니다. [84–153](https://github.com/tldraw/tldraw/blob/71e9eae0502a06b8299b9a67b881539d28516f0d/packages/tldraw/src/lib/tools/ZoomTool/childStates/ZoomQuick.ts#L84-L153)에서 cancel은 idle로 돌린 뒤 원 tool로 나가며, onExit의 zoomToBounds(initialVpb,{inset:0})로 원래 범위를 맞춥니다. 저장 camera 사본을 그대로 재대입하는 방식이 아닙니다. 이동 임계값을 넘겨 moving이 된 뒤 놓으면 nextVpb를 맞춥니다. 미세한 모든 포인터 이동이 새 위치 확정인 것도 아닙니다.

4. **키·옵션 명칭을 정정해야 합니다.** [ZoomTool Idle 16–20](https://github.com/tldraw/tldraw/blob/71e9eae0502a06b8299b9a67b881539d28516f0d/packages/tldraw/src/lib/tools/ZoomTool/childStates/Idle.ts#L16-L20)의 실제 진입은 이미 zoom tool의 idle 상태에서 Shift keydown→zoom_quick입니다. Quick의 Shift keyup은 idle로, pointerup/cancel은 원 tool로 돌아갑니다. [ZoomTool 42–47](https://github.com/tldraw/tldraw/blob/71e9eae0502a06b8299b9a67b881539d28516f0d/packages/tldraw/src/lib/tools/ZoomTool/ZoomTool.ts#L42-L47)의 z keyup은 zoom tool 종료 경로입니다. 다른 tool에서 zoom tool로 들어오는 전체 단축키 경로까지 조사한 것은 아닙니다. 지정 고정 파일에는 `quickZoomOn` 키가 없고, 실제 옵션은 [quickZoomPreservesScreenBounds](https://github.com/tldraw/tldraw/blob/71e9eae0502a06b8299b9a67b881539d28516f0d/packages/editor/src/lib/options.ts#L207-L212)이며 기본 true(351행)입니다. 이 옵션은 개관 줌에 따라 목표 brush의 화면 크기를 보존할지 정합니다. 키/활성 모드를 고르는 옵션과 다릅니다. 현재 default-branch 코드검색0건은 참고만 남기며 고정 revision 전체의 부재 증명으로 쓰지 않습니다.

읽은 Quick 경로는 camera/cursor/zoomBrush/tool 전환을 조작하고, 도형 선택이나 계층 구조를 바꾸는 호출은 없습니다. 이는 읽은 경로 안의 정적 범위이며 전체 제품 모든 side effect의 증명은 아닙니다. 수정일 메타데이터를 최초 기능 도입일로 해석하지 않았습니다.
