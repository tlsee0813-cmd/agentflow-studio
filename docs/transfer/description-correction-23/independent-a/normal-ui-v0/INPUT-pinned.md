# 사이클23 — 고친 설명을 다음 작업문 정리에 전달하기
2026-10-23 KST. 21 CI 반례는 별도 처리 중이며22 관측을 통한 우선순위 판단을 이어간다. 이번 범위는 f7b25a586dca42466f07c7db2bedb9c59703deda 제품의 확인된 입력 누락 하나다. 현재 진행은 ACTIVE를 따른다.

## 문제와 선택
사용자가 현재 설명을 명시 정정해도 같은 작업 재정리와 같은 부분의 새 요청에서 AI가 받는 ContextRequest에는 그 설명이 없다. 반면 실제 인계문에는 사용자 정정 설명을 참고로 싣는다. [작은 합성 domain 반례](https://github.com/tlsee0813-cmd/agentflow-studio/tree/28705351c3ac46a966cfbe347e4017c6c71ffd70/docs/transfer/description-correction-23/domain-probe)는 '30일' 정정 설명과 기존 '7일 유지' 합성 작업문이 함께 남는 것을 확인했다. 실제 AI 오판이 아니라 입력·표현 경계의 재현이다.

기존 설명 정정과 ‘이 입력 다시 정리’, 직접 편집을 재사용한다. 먼저 정확한 부분의 유효한 현재 참고 설명을 AI 정리 입력으로 전달한다. 원문 통째 제외·새 보고 정정 상태·자동 모순 판정·미열람 엔진은 이번 선택이 아니다.

## 구현 계약
- 같은 작업 재정리와 같은 부분의 새 요청 모두 현재 유효한 설명을 명시적으로 받을 수 있어야 한다. 부분의 안정 ID, 설명 판본, 외부/사용자 귀속, 정정 대상과 필요한 출처를 구별한다. 모든 프로젝트 설명/과거 이력/보류 원문을 무차별 추가하지 않는다.
- 사용자 구상·요청·확정 조건과 별도의 **앱 미검증 참고 설명**이다. 사용자 정정이 원보고 전체의 폐기나 새 실행 권한·정책 결정으로 승격되지 않는다. AI의 지시 우선순위와 실제 요청 범위는 유지한다.
- 유효하지 않은 설명, 보류 설명, 대상 없는 전역 요청, 다른 부분의 설명을 현재 참고로 보내지 않는다. 입력의 허용 필드·형식·크기를 검증하며 기존 유효 입력의 호환 경계를 명시한다.
- 클라이언트 생성→런타임→서버 검증→provider prompt/정적 MOCK에서 같은 계약을 보존한다. GUIDE107 별도 후보와 실제 AI HOLD·유료 호출은 건드리지 않는다.
- 읽기·정정만으로 기존 네 작업값을 덮어쓰거나 과거 H의 작업문 사본을 바꾸지 않는다. 기존 직접 입력은 재정리 후에도 유지한다. 모든 설명 갱신을 자동 stale로 만들거나 복사를 차단하지 않는다.
- 이번 입력 전달을 완료해도 기존 AI 문구와 현재 설명의 의미 충돌이 자동 해결됐다고 하지 않는다. 정정 후 기존 작업문의 읽기 안내가 필요하면 기존 안내의 좁은 보완만 제안하고 별도 화면/일괄 경고는 만들지 않는다.

## 확인할 것
작은 domain 반례의 같은 작업/새 요청 입력에서 정정문·대상·판본·귀속을 확인한다. 유효 외부 설명, 사용자 정정, 보류/낡은 설명, 다른 부분/전역, 긴 입력·잘못된 귀속의 경계를 의미 있는 검사로 확인한다. 실제 payload와 provider 입력을 대조하며 프롬프트 문장의 존재만으로 의미 품질 성공을 주장하지 않는다.

PC 정상 UI에서는 설명 정정→같은 부분 재정리/새 요청→직접 수정 보존→실제 인계→지도 복귀를 좁게 관측한다. 기존 화면과 처리 경로를 재사용하고 초기 데이터 주입 여부·합성 응답·미실행 경계를 분리한다. 작성자 정적/타입·필요 domain검사, 별도 코드검토, 승인된 Cloud 실제 조작, 최종 CI를 구분한다. 로컬 서버·브라우저 실행은 하지 않는다.

제품 후보는 별도 브랜치에서만 준비하며21 최종 통합 전 선행 병합하지 않는다. checkpoint 통합은 총괄 판단, main/공개 MOCK은 그대로다. 증거는 delivery 새 접두사, 선택·결과는 이 사이클 문서에 남긴다.
