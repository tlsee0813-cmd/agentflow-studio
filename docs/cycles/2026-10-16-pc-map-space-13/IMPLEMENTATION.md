# PC 지도 공간13 구현·검증 계약

2026-10-16 총괄 결정. [BRIEF](BRIEF.md)의 좁은 PC 개선이다. 제품12의 저장·읽기·편집·복귀 계약은 유지한다.

## 비교 결과와 선택

Opus는 지도 우선 세로 재배분과 지도 위 겹침 패널을 비교했다. 총괄은 **기존 지도 옆 선택상세를 유지하고 전체공간의 상단을 줄이는 안**을 선택한다. 겹침은 카드 가림과 fit/offscreen 계산, 새 내부 스크롤의 복귀 문제를 동시에 만든다. 기존 지도 높이 규칙이 충분하면 그대로 사용한다. 초기 y200~260이라는 제안은 추정이므로 결과로 기록하지 않는다.

읽기 담당 Pro는 최초 요청·한 번 재시도 모두 Unknown error로 실패했다. 다른 Pro창의 사람 확인을 우회하지 않았다. Astra High가 기존 코드에 근거해 별도로 읽기 표현을 검토했다. **프로그램의 목적·영역 구상을 기본에 남기고, 앱의 질문·보고 기록은 종류를 보이는 펼침으로 이동**한다. ‘확인할 일 N건’이라는 숙제/중요도 표현을 그대로 접는 것만으로 해결하지 않는다. 보고가 남아 있다는 이유로 미완료·결함·사용자 의무를 만들지 않는다.

총괄은 Dify의 [선택 패널 코드](https://github.com/langgenius/dify/blob/b18624fc1c700cd6f4ee7ef77c9c11d05e60e296/web/app/components/workflow/panel/index.tsx#L110)와 [폭 예약 함수](https://github.com/langgenius/dify/blob/b18624fc1c700cd6f4ee7ef77c9c11d05e60e296/web/app/components/workflow/panel/panel-width.ts), [React Flow Panel](https://github.com/xyflow/xyflow/blob/3d35b57317576b0916c0bfeaaedd573aaacc2839/packages/react/src/components/Panel/index.tsx#L39)을 원문 대조했다. 선택에 따라 상세를 여는 기제는 참고하지만 Dify의 폭 계산은 preview용 최대 폭이며 그 값을 우리 선택패널 폭으로 복제하지 않는다. 현재 Dify 사용자 창은 로딩 화면에 머물러 선택/닫기 실조작은 미실행이다. 두 서비스와 현 사용자 창이 같은 빌드라는 주장도 하지 않는다.

## 고정 기준과 변경 범위

- 코드 기준 `9613208f40f1f7f8506504ac6025f06e421edd4d`. 제품12는 PR3으로 checkpoint에 이미 통합됐다.
- 대상: 전체 공간(overview)의 배치와 기존 선택상세·질문/보고 펼침·영역 추가. 새 파일이 필요하면 검사 파일을 우선한다. app.ts/styles.css/index.html의 필요한 최소 변경과 기존/새 브라우저 검사·CI만 허용한다.
- domain/schema/server/provider/의존성·작업 화면의 전체 재설계·실제 AI·공개 배포는 제외한다. 로컬 영구저장 구조와 기존 프로젝트를 바꾸지 않는다.
- 루트가 제품 diff를 검토해 후보 브랜치/PR을 만든다. 작성자는 ZIP에 diff·변경 파일·검사·대표PNG2~4·원시·manifest를 담되 전체 저장소/캐시를 넣지 않는다.

## 화면과 행동

1. 전체공간의 프로젝트 도구/목적/공간 제목 중복과 간격을 줄인다. 프로젝트 이름과 필요한 조작은 찾을 수 있어야 한다. 전체공간 전용으로 제한하며 작업/요청/새 프로젝트 화면의 전역 상태나 오류를 감추지 않는다.
2. 프로그램 목적 한 줄과 영역 이름·사용자 구상을 기본에 남긴다. 전문과 편집은 기존 경로로 열 수 있다.
3. 질문/보고는 기존 집계 함수를 그대로 쓰되, 펼침 줄에 ‘이어 볼 기록 N개’와 실제 존재하는 종류/건수를 드러낸다. 예: ‘답 기다림1 · 후속 작업문 없는 보고1’. 이것은 프로그램 미결·외부 실행 상태·완료 여부가 아니다. 펼치면 기존 대상·상태·보기 버튼이 그대로 있고, 0건도 거짓 완료 주장을 하지 않는다. 단순 안내문을 늘리지 않는다.
4. 영역 추가 입력은 명확한 ‘영역 추가’ 펼침으로 옮긴다. 정상 입력·추가·초안 보존을 유지한다.
5. 지도와 선택상세의 기존 나란한 배치, 카드·관계·배율·맞춤·화면 밖 표시를 재사용한다. 상세를 열고 닫을 때 임의 auto-fit/재배치를 하지 않는다. 패널에 새 독립 스크롤을 도입하지 않는다.
6. 선택상세는 영역 구상 먼저, 관련 요청은 그 아래에서 고른다. 읽기만으로 현재 작업/초안/선택된 반환 대상/수동값을 바꾸지 않는다. A를 읽고 R을 편집하는 차이를 유지한다.
7. 새로 접는 details에는 안정된 ID를 주고 제품12의 출발 상태 저장과 함께 복귀를 확인한다. 펼침 클릭 자체와 키보드 조작도 정상이어야 한다.

## 합격과 관측

기본 fixture는 프로그램 목적·구상이 짧은 합성3영역 + 답 대기 질문/후속 작업문 없는 보고를 포함한다. 긴 구상/요청/제목은 별도 경계다. 기존 제품12 stress fixture만으로 기본 디자인을 평가하지 않는다. 합성 전달 이력은 실제 전달 성공으로 쓰지 않는다.

- PC1280×720·1440×900 각각 기본 전체공간과 선택상세 열림을 실제 브라우저로 비교한다. 초기 정상 장면에서 지도 중 보이는 세로 길이가 뷰포트 높이의40% 이상이고 첫 지도 카드의 제목/핵심조작에 접근할 수 있어야 한다. 이는 최소 공간 기준이며 시각적 품질 수용 전체를 대신하지 않는다.
- ‘안내 없음’과 정상 가져오기 안내1개 있는 장면을 구분한다. 오류/저장 실패를 없애서 공간 기준을 맞추지 않는다. 오류 장면은 오류의 실제 가시성과 조작 접근을 우선 확인한다.
- 질문과 보고가 함께/각각/0인 상태의 집계·기본 종류·펼침 목록/대상 이동을 확인한다. 데이터에 없는 미결/완료 문구가 없어야 한다.
- 읽기→직접 보고R 편집→복귀, 다른 보고RB→A 편집→복귀를 두 PC폭에서 확인한다. 기본 접힘과 새 펼침 열린 출발을 모두 포함한다. 현재 작업/수동4/미전송보고/명시 반환 대상은 기존 기준을 유지한다.
- 지도 transform·카드 실제좌표·선택·호출 위치/초점·펼침과 필요한 창 스크롤을 출발·즉시복귀 값으로 비교한다. 내용 높이 변화는 제품12의 의미 있는 호출 위치 보존 계약을 따른다.
- 선택상세 개폐·영역 추가·확대/맞춤은 기존행동을 유지한다. CSS폭1024의 재배치 관측을 실제 브라우저125%확대와 혼동하지 않는다. 실제 확대가 가능한 환경에서는 별도로 수행하고 아니면 미실행을 명시한다.
- 390은 접근/닫기/가로넘침 최소만 확인한다. 새 전체 모바일 합격으로 확대하지 않는다.
- 기존 check/build/domain 및 pc12/spatial102/flow090, 새13검사를 실행하고 실제 종료값·실패기록을 남긴다. 새 검사를 CI에 연결한다. 최종 후보를 독립 Cloud가 고정SHA로 검증하기 전에는 수용하지 않는다.
