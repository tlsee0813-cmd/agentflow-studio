## Dify를 기준으로 무엇을 비교하는가
사용자의 최신 요청에 따라 사람 사용 기록 제출을 기다리지 않는다. Dify는 실행 워크플로를 편집하는 서비스, AgentFlow는 프로그램 구성·변경·외부 작업 맥락을 이해하고 이어가는 서비스다. 공통 조작을 비교하고 결과 명칭은 ‘Dify 대비 조작 평가’로 쓴다.

| 비교 장면 | AgentFlow의 판단 기준 |
|---|---|
| 첫 전체 화면 | 목적·주요 부분·관계가 먼저 보이고 PC 두 크기에서 실제 지도 가시 높이 최소40%. 40%는 공간 하한이며 읽기 부담도 별도로 본다. |
| 한 부분 선택·닫기 | 지도와 상세의 대상이 일치하고 임의 재배치 없이 전체 맥락을 유지한다. 겹침 패널이 가리는 공간도 비교한다. |
| 짧은 설명→필요한 상세 | 기본은 역할·현재 설명, 원문과 기록은 필요할 때 접근한다. 상세가 다른 대상·출처로 바뀌지 않는다. |
| 명시 편집 시작 | AgentFlow는 읽기와 실제 편집 대상을 구분하고 관련 없는 값에 영향을 주지 않는다. Dify 설정 편집과 인계 성공은 대응 항목으로 세지 않는다. |
| 읽던 자리로 복귀 | 배율·위치·선택·펼침·호출 초점을 유지하며 업무 변경은 남긴다. Dify에 없는 기능은 비교 불가로 표시하고 우리 목적에 맞게 판단한다. |

채택할 것은 지도 중심 공간과 선택한 부분에 맞춘 상세·설정/기록 분리다. 전체 지도에 긴 기록을 기본 나열하지 않는다. 겹침 패널·400px 고정 폭·실행 노드 분류·닫기 후 BODY 초점은 그대로 채택하지 않는다. AgentFlow는 기존 지도 옆 패널과 호출 초점 복원을 유지한다.

4. 원본 범위와 잘린 출력, 최소 근거 포인터, 실패한 대응을 짧게 남긴다. 자기 프로젝트의 도구 혼합 기록은 입력 형태 시험이며 일반 제품 구상 전체를 대표하지 않는다.
5. 결과 직후 재사용할 형식, 부족한 정보, 제품의 포함 모델 결정을 한 번 정리한다. 이때 다음 자동 정리 실험의 최소 범위도 선택한다.

총괄은 자료 선택·해석·제품 반영 판단을 맡고 Astra High가 의미 대응을, Sol High가 원본 범위와 도구 관측 구분을 보조한다. Opus의13 구현과 Cloud의 후보 검증을 취소하거나 새 범용 엔진 배정으로 바꾸지 않는다.
