# PC 지도 공간13 — 좁은 조사·제품 개선 범위

2026-10-16 작성. 제품12의 수용 흐름을 유지하면서, PC에서 지도와 선택한 부분을 더 쉽게 읽는 다음 단계다. 현재 배정은 [ACTIVE](../ACTIVE.md), 직전 수용은 [제품12 결과](../2026-10-16-product-reading-return-12/RESULT.md)를 본다.

## 해결할 문제

제품12는 실제 제품의 영역 읽기·명시 이어가기·수동 편집·지도 복귀를 연결했다. 그러나 큰 상단 설명과 상태·보고 영역이 지도 위 공간을 차지한다. 사용자가 돌아와 프로그램의 부분·관계·변경을 파악해야 하는 목적에 비해 기본 화면이 작업 기록 관리 화면으로 보일 위험이 남는다.

**1280×720와1440×900에서 지도 → 한 부분 이해 → 필요한 경우 명시 조정 → 전체 복귀를 한 화면 흐름으로 읽기 쉽게 만든다.** 현재 저장소에 없는 변경/미결을 만들어 넣지 않는다. 지도 첫 화면의 가용 공간, 읽어야 할 기본 문장 수, 선택·편집 대상의 명료함을 함께 비교한다. 지도 면적 하나만 키워 맥락을 숨기는 것도 실패다.

## 고정 입력과 비교

- 제품 소스 [9613208f](https://github.com/tlsee0813-cmd/agentflow-studio/tree/9613208f40f1f7f8506504ac6025f06e421edd4d/app/continuity).
- [최종 독립 검증과 정적 MOCK 실행물](https://github.com/tlsee0813-cmd/agentflow-studio/tree/398a91adf918113bd77dfbd3454fc3c85b00cc3d/docs/transfer/pc-reading-return-12/independent-fix2). PNG는 기능 회귀용 합성 장면이며 완성 디자인·사용성 증거가 아니다.
- 기존 cycle11의 FLOW091/PowerToys 두 입력은 읽기·관계 이해 대조에 재사용하되, 아직 이 전체 구조가 제품 저장소에 들어간 것으로 표현하지 않는다.
- Dify는 공간 배치와 대상 상세를 여는 기준 참고다. 목적·업무 모델을 복제하지 않는다. 그 밖의 기존 조사 또는 공식 오픈소스 최대1개를 필요한 기제에 한해 대조한다.

## 역할과 첫 산출물

Pro A는 지도/선택 상세/전역 조작의 공간 배분과 상하 높이를, Pro B는 짧은 기본 읽기와 상세 공개·명시 편집 대상의 표현을 각각 맡는다. 각자 최대2후보, 추천1개와 손실·반례, 정확한 공식 근거를 제출한다. 문서·고정 코드·정적 화면·직접 조작을 구분한다. 총괄이 현재 제품 실제 화면과 대조해 하나의 변경 범위를 고른 뒤 Opus에 구현을 맡긴다. 기능 목록이나 거대한 범용 엔진을 만들지 않는다.

구현 전 실제 조작 비교가 필요한 핵심 기제1개를 고른다. 공개 데모나 사용자가 이미 연 Dify에서 가능한 읽기·탐색 조작을 별도로 배정한다. 계정 설정·배포·전송·공개 변경은 이 비교에 포함하지 않는다. 접근 불가면 문서 분석으로 축소했음을 기록한다.

## 유지할 조건과 종료선

- 단순 읽기는 현재 작업/미전송 보고/수동 편집을 바꾸지 않는다.
- 영역 구상과 작업 기록을 같은 대상으로 섞지 않는다. A를 읽고 R을 편집하는 차이는 행동명·제목에서 드러낸다.
- 원문·긴 수동 전문에 접근할 수 있고 내용 일부만으로 금지·예외를 삭제하지 않는다.
- 지도 출발 위치 복귀와 명시 편집 보존을 유지한다. 설명을 숨기려고 사용자가 해야 할 새 관리 일을 만들지 않는다.
- 스키마·실제 AI·자동 기록 변환·큰 층위 엔진·공개 배포를 포함하지 않는다. 현 평면 구조는 최종 방향 확정이 아니다.
- 제품 한 후보의 두 PC 폭 실제 비교와 독립 회귀 뒤 수용/수정/보류를 결정한다. 모바일은 최소 접근만 확인한다. 사람 이해도 결과가 없으면 AI 사전 평가로 명시한다.
