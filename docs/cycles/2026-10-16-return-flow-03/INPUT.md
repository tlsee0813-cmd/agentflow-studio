## 기본 화면 요약 초안

> **목적 정정은 별도로, 작업 지시는 그대로**
>
> 개발 기록에는 목적을 바로잡아도 직접 쓴 작업 지시와 현재 요청은 유지하도록 바꿨다고 적혀 있습니다. 정정 내용은 홈·작업문에 보이고 다음 AI 정리 요청에도 포함됩니다. 저장된 이전 정정을 복원할 때도 작업 지시는 유지합니다.
>
> 관련 영역: 홈 · 작업문 · 다음 AI 요청 · 저장 복구
>
> 기록의 한계: 실제 AI 준수는 미검증이며, 사용자 원요청과 인계 결과는 이 기록에 없습니다.

‘목적 정정은 별도로’는 보고된 동작 설명이지 사용자의 새 목적 문장 자체가 아니다. 위 요약을 현재 운영 제품의 실시간 상태로 표시하지 않는다. 기준 표시는 **‘이 개발 기록에서 보고한 변경’** 정도로 짧게 두고 기술 식별자는 상세로 보낸다.

## 하나의 흐름과 내용 경계

**돌아와 변경 확인 → 목적 정정 영역 이해 → 필요하면 인계 준비 제안 확인 → 전체 복귀**만 대상으로 삼는다. 기본 공간은 위 짧은 요약과 관련 영역을 보여 주고, 선택한 부분에서 F2~F6의 관련 내용만 더 읽게 한다. 홈·작업문·다음 AI 요청·복구는 문서가 기술한 **변경 영향 영역**이다. 프로그램 모듈이나 부모·자식 포함 관계를 입증한 것이 아니므로 지도에서 묶을 경우 ‘변경 영향을 살펴보기 위한 연구 배치’로 밝힌다. 연결선을 쓰더라도 포함·실행 순서·자동 영향 분석 결과로 읽히게 하지 않는다.

**초기와 변경 후:** 초기 화면은 방문자의 진입 화면이고, AI055는 앞선 동작 설명이다. 둘을 같은 뜻으로 쓰지 않는다. 필요할 때만 ‘앞선 개발 설명 / FIX058 변경 보고’를 비교한다. 사용자가 목적을 실제로 고친 전후 화면이나 마지막 방문 이후 자동 수신된 기록처럼 연출하지 않는다. 후속 AI 응답·새 저장 성공·인계 수락 장면을 합성해 채우지 않는다.

**판단과 인계:** 이 기록에는 지금 프로젝트 주인이 선택해야 할 실제 결정이 제시되어 있지 않다. 승인·정정 입력·담당 선택을 필수 숙제로 만들지 않는다. 인계 항목을 둔다면 **‘이 부분을 이어 맡길 내용 보기 — 준비 제안’** 같은 명시적 제안으로 한정한다. 제안 내용은 목적 정정과 작업 지시의 분리, 관련 영역, 미확인 범위를 재진술할 수 있으나 가상의 요청자·수신자·기한·승인·전달 결과를 만들지 않는다. 버튼을 누른 상태도 인계 완료가 아니다.

**기본에서 제외:** QA 수치, H1/E09, 해시, 내부 필드명, 전체 원문, 검사 목록은 기본 지도에 노출하지 않는다. 핵심 불확실성은 위 한 줄처럼 남긴다. 상세 근거는 해당 고정 구간으로 연결하되 큰 원문을 모두 읽어야 전체로 돌아올 수 있는 흐름을 만들지 않는다.

이번 입력은 작은 읽기·복귀 흐름의 내용 계약이다. 자동 병합·새 조정/인계 엔진·모든 저장 호환 기능의 구현 요구가 아니며, 이전 보류 작업(legacy HOLD)의 재개 지시도 아니다.
