# Neo4j Bloom — 집중과 복귀 근거 대조

2026-10-16 · 지정 공식 문서 두 페이지 직접 열람 · 문서 기반 재구성. 실제 Bloom UI·소스·테스트는 실행하지 않았다. `/current/` 문서이므로 고정 제품 버전의 관측은 아니다.

## 확인과 범위 수정

[Scene interactions](https://neo4j.com/docs/bloom-user-guide/current/bloom-visual-tour/bloom-scene-interactions/)는 선택 대상과 가까운 이웃을 함께 선택한 뒤 나머지를 Scene에서 제외하는 흐름을 설명한다. Expand는 직접 이웃을 추가로 시각화하며 조회 제한의 영향을 받는다. Reveal은 **선택된 노드 사이에 이미 존재하지만 현재 보이지 않는 직접 관계**를 드러낸다. 노드 하나만 선택했다면 자기 관계가 있을 때만 가능하다. 따라서 단순히 ‘존재 관계 표시’라고 쓰면 전체 Scene의 숨은 관계를 모두 찾는 것처럼 넓어질 수 있다.

[Scenes and sharing data](https://neo4j.com/docs/bloom-user-guide/current/bloom-tutorial/export-data/)는 Scene 복제·전환과 필터·그래프·시각화·스타일 변경의 자동 저장을 설명한다. 다중 Scene과 공유는 Bloom plugin 배포에서만 가능하다고 명시한다. Scene은 노드·관계 ID에 의존하며, 백업·복구 등으로 **ID가 재사용될 경우** 저장된 Scene이 잘못 표시될 수 있다고 경고한다. 모든 DB 변경이 곧 표시 오류라는 주장은 아니다. 선택·키보드 초점·확대율 각각의 정확한 복원 계약은 이 두 페이지에서 확인하지 못했다.

## 의미 확대 두 가지

1. **자동 저장은 집중 전 보기의 자동 보존과 다르다.** 같은 Scene에서 나머지 노드를 제외하면 그 변경도 저장 대상이다. 문서의 Scene 전환 설명만으로 ‘집중을 닫으면 출발 상태로 되돌아간다’를 보증할 수 없다. 먼저 Scene을 복제해 별도 보기에서 범위를 줄이고 원본으로 전환하는 조합은 문서상 가능한 재구성이나, 직접 조작해 검증한 경로는 아니다. 필터 문서의 ‘Scene을 비우면 필터도 사라진다’는 설명 역시 모든 상태의 영구 보존으로 확대하지 말아야 한다.
2. **그래프 이웃은 제품의 포함 관계가 아니다.** Bloom의 관계 기반 범위 선택을 참고해도 FIX058의 홈·작업문·다음 요청·복구를 실제 모듈 트리로 만드는 근거가 되지 않는다. 원문이 보고한 영향 관계와 연구용 묶음을 유지해야 한다. 화면에서 제외된 영역을 실제 삭제·폐기된 구성으로 읽히게 해서도 안 된다.

총괄 가설인 **‘집중은 관련 범위 보기, 복귀는 출발 보기 복원’**은 유효한 연구 방향이다. 다만 앞부분은 Bloom의 문서상 메커니즘을 참고할 수 있고, 뒷부분의 선택·펼침·위치·초점 보존은 우리 시안에서 별도로 관측할 조건이다. Bloom 엔진·다중 Scene 관리 UI를 채택하거나 사용자에게 보기 복제·저장을 숙제로 요구할 이유는 없다. 아직 오지 않은 cycle03 HTML의 성공·결함은 판정하지 않는다.
