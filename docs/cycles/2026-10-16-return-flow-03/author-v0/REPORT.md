## 무엇을 만들었나

`return-flow-study.html` 단일 파일(41,476 B, 외부 리소스·라이브러리 없음). 흐름은 **기본 지도 → 목적 정정 선택 → 읽기 공간(제자리 근거 미리보기) → 인계 준비 제안 → 전체 지도로 돌아가기** 하나입니다.

- **기본 지도:** 왼쪽에 INPUT 요약 초안(제목·세 문장·관련 영역·한계 한 줄)과 "방문 이력이 없어 FIX058 항목 시점 기준", "지금 결정을 요청하는 항목 없음" 한 줄. 오른쪽 지도에 ‘기록이 바꿨다고 보고한 동작’ 3개(목적 정정·작업 지시·사용자 결정 표시)와 점선 틀의 **영향 영역 4곳(연구 배치, 모듈 구조 아님)**. 영역은 각자 접힘/요약/자세히 3단 깊이를 따로 가집니다(초기: 홈 요약, 작업문 자세히, 다음 AI 요청 접힘, 저장 복구 요약).
- **선택:** 부분을 고르면 문서에서 함께 언급된 영역으로 선이 그려지고(1440) 또는 영역에 표시가 붙고(390), 나머지 영역은 흐려질 뿐 펼침·위치·배율은 바뀌지 않습니다. 선은 ‘함께 언급됨’이며 포함·순서·자동 분석이 아니라고 틀에 적었습니다.
- **읽기 공간:** 목적 정정의 4문장 + ‘작업 지시와의 경계’ 1문장. 각 문장 끝 `근거`는 **문장 바로 아래 제자리 미리보기**(문서 보고 발췌 / 이 설명이 읽은 방식 / 이 기록으로 알 수 없는 것 / 외부 원문 위치 링크)를 열고, 닫으면 DOM에서 제거·초점·읽던 위치를 되돌립니다. AI055 대비는 요청할 때만 여는 2행 대조(390에서는 같은 행 안에 위아래로 쌓아 비교 상대가 남음). 커밋·행·검증 방식·없는 것(원요청, 승인, 인계 수신·수락)·FIX059/061 제외는 접힌 ‘기록의 출처와 경계’에만.
- **인계 준비:** "이 부분을 이어 맡길 내용 보기 (준비 제안)" → 대상·하는 일·범위·기준 기록·지켜야 할 조건·알 수 없는 것. 받을 담당자는 "기록에 없음". 버튼은 `닫기` 하나뿐이며 보내기·배정·완료 상태가 없습니다.
- **전체 복귀:** 진입 시 지도 스크롤·창 스크롤·배율·선택을 저장하고 복귀 때 다시 적용, 초점은 선택 부분 노드로. 근거 닫기(문장 단위)와 전체 복귀(공간 단위)는 다른 버튼입니다.

발명하지 않은 것: 모듈 부모/자식, 사용자 원요청·발화, 방문 이력, 인계 수신자·결과, 승인 숙제함, 결정 요청, 후속 AI 응답.

### 고친 실패 (실제로 관측된 것)

1. 390에서 근거를 열 때 미리보기를 보이게 하려고 창을 168px 내렸는데, 닫아도 되돌리지 않아 **읽던 위치가 바뀌었습니다**. 첫 검사 코드는 이 값을 기록만 하고 판정하지 않아 잘못 통과됐습니다. → 열기 직전 위치를 저장해 닫기/Escape 때 복원, 검사를 판정 항목으로 바꿈. 재실행 120→120.
2. 390 읽기 공간의 ‘전체 지도로 돌아가기’ 바가 짧은 상단 영역 안에서만 sticky라 스크롤하면 사라졌습니다(미리보기 스크린샷에서 확인). → 위치 표시줄 전체를 sticky로.
3. 390 인계 준비 시트가 UA 기본 `max-width` 때문에 오른쪽이 비었고, 선택 직후 관련 영역이 화면 아래라 하단 바만으로는 관계를 알 수 없었습니다. → 폭 수정, 하단 바에 ‘함께 언급: …’ 표시.
4. 390 안내문이 존재하지 않는 ‘선’을 말함 → 폭별 문구 분리.

## 작성자가 본 읽기 부담 (스크린샷 기준, 사람 관찰 아님)

- **영향 영역 틀의 설명문 3줄**이 영역보다 먼저 읽혀 첫 화면에서 가장 무겁습니다. 필요한 경계지만 한 줄로 줄일 여지가 있습니다.
- 관련 영역 이름이 왼쪽 요약과 지도에 **두 번** 나옵니다. 지도 쪽만으로 충분한지 판단이 필요합니다.
- 1440에서 100% 배율이면 부분 열과 영역 틀 사이가 넓어 선이 길고, 세 부분이 같은 무게라 목적 정정이 선택 전에는 두드러지지 않습니다.
- 390의 ‘지도’는 공간이 아니라 세로 목록+표시입니다. 축소 지도보다 누르기는 쉽지만 관계는 선택 후 아래로 내려 확인해야 하며, 공간 이해는 1440보다 약합니다.
- 1440에서는 읽기 공간 본문이 한 화면에 들어가(851/851px) **읽던 위치 보존은 390에서만 의미 있게 시험**됐습니다.
- 터치 후 복귀하면 초점은 선택 노드로 가지만 포커스 링은 보이지 않습니다(브라우저 focus-visible 규칙). 키보드 사용 때만 보입니다.
- ‘사용자 결정 표시’·‘작업 지시’의 읽기 내용은 짧게만 만들었고 흐름 검사는 목적 정정만 대상으로 했습니다.
