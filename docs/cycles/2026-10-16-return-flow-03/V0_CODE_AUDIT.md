# cycle03 v0 — 독립 코드·검사 감사

2026-10-16 · Sol. HTML, REPORT, `check/flow_check.py`, TXT/JSON 로그를 8단계 브라우저 계약에 한정해 읽었다. 실제 브라우저·스크린샷 판독은 이번 감사에서 하지 않았다. 원본 수정·환경 변경·원격 쓰기 없음.

## 조치할 발견

1. **P2 — 단계 FAIL이어도 검사 프로세스가 exit 0으로 끝난다.** `flow_check.py:101–111`은 단언 실패와 조작 예외를 FAIL 레코드로 돌려주지만, `367–389`의 실행부는 이를 저장·출력한 뒤 정상 종료한다. `359–362`의 콘솔 오류·외부 요청도 기록만 하며 실패 판정에 연결하지 않는다. 실패 상태·필수 단계 누락·실행 오류를 종료 상태에 반영해야 한다. 설정/시작 과정에서 밖으로 전파된 예외는 별도로 nonzero가 되므로 모든 예외를 삼킨다는 주장은 아니다. **현재 JSON의 통과 기록을 폐기하는 근거도 아니다.**
   - 최소 정적 반례: 원본의 `Run.__init__/step/chk`만 AST로 추출해 의도적 false 단언 1개와 단계 예외 1개를 호출했다. 둘 다 `FAIL`을 반환하고 예외는 전파되지 않았으며 이 정적 실행은 exit 0이었다. 브라우저나 작성자 전체 검사를 재실행한 결과가 아니다.
2. **P2 — 기록한 HTML 해시와 HTTP에서 실행한 바이트의 결합이 없다.** 검사기 `16–18`은 인자로 받은 로컬 HTML 해시를 계산하고 `306–310`은 별도 URL을 연다. 응답 바이트의 해시 비교나 HTTP 상태의 통과 조건은 없다. 따라서 다른 버전이 같은 선택자를 제공하면 로컬 파일의 해시를 붙인 결과가 될 수 있다. 이번 로그가 다른 버전을 실행했다는 증거는 없지만, Cloud 독립 실행에서는 응답 바이트와 지정 HTML 해시를 먼저 대조해야 한다.

## 코드와 현재 증거가 지지하는 범위

- **다른 깊이·선택·지도 복귀:** HTML `360–361, 393–410`은 영역별 깊이를 유지하고, `414–426`의 선택은 해당 깊이를 초기화하지 않는다. `533–560`은 집중 진입 때 실제 지도/창 스크롤·배율을 저장하고 복귀 때 지도 표시와 배치를 복구한 뒤 같은 값을 다시 적용한다. 선택 노드 초점은 `preventScroll:true`다. 저장된 선택 값은 복귀에서 별도 대입하지 않지만 집중 중 선택을 바꾸는 경로가 없어, 현 작은 흐름의 선택 결함으로 판단하지 않았다.
- **근거 닫힘·반복:** HTML `18`의 전역 hidden 규칙이 있고, 미리보기는 `603`에서 DOM 제거된다. `581, 605–612`는 열기 전 읽기 위치와 출발 버튼 초점을 복구한다. 작성 검사는 `197–223`에서 제거·옛 위치 hit-test·초점·읽기 위치와 재열기/Escape를 확인한다. **위치 비교는 다음 준비 버튼을 찾는 휠 조작(`228`) 전에 한다.** 전체 복귀도 `269–283`에서 조작 뒤 휠 보정 없이 비교한다. 이 두 지점에 검사 보조 스크롤이 복귀 실패를 상쇄하는 순서는 발견하지 않았다. 앱 자체의 미리보기 자동 스크롤(`589–596`)과 복원은 검사 보조 조작과 구별한다.
- **준비 ≠ 송신:** HTML `617–638`은 준비 내용을 구성하고 모달을 열고 닫는다. 보내기·수신자 배정·완료 저장 경로는 없고 실제 사용자/수신자 부재를 명시한다. 외부 리소스 로드 코드 없이 고정 GitHub 원문 링크만 제공한다. 현 코드에서 근거 열람이나 준비를 실제 송신으로 바꾸는 경로는 찾지 못했다.

## 확대하면 안 되는 통과와 남은 관측

- 작성 로그는 1440×900과 390×844에서 각각 **14개 단계 레코드 PASS / FAIL 0**이다. 이는 계약 1–7과 2–7 반복, 반복 대조를 펼친 기록이다. 각 화면의 하위 체크는 110개이며 이를 별도 사용자 사례나 성공률로 합산하지 않는다. JSON/TXT의 화면·브라우저·HTTP200·해시는 REPORT와 일치한다. 데스크톱은 지도 `[32,86]`, 120%가 복귀 전후 같고 모바일은 창 Y=300이 같다. 근거 읽기 위치는 데스크톱 0→0, 모바일 120→120이다.
- 지도 위치 판정은 스크롤 값과 배율 **표시 문자열**의 일치 및 최종 선택 노드의 viewport 진입을 본다(`276–283`). 지도 기준 노드의 전후 실제 좌표·적용 transform 배율 대조는 없다. 깊이는 기본으로 주어진 서로 다른 상태를 유지했으며 사용자가 다른 깊이로 조정한 뒤의 복귀는 실행하지 않았다. 관계도 데스크톱 선 개수만 비교해 끝점·소유의 전후 일치 전체를 검증한 것은 아니다. 코드상 직접 모순은 찾지 못했지만 Cloud 화면 대조가 남는다.
- 닫기·재열기는 p3 근거 한 곳으로 한정된다. 검사 `217`의 ‘첫 줄에 보임’은 실제 viewport 포함이 아니라 존재/상자 검사다. 모바일 관련 표시 4개도 `offsetWidth` 조건으로 세므로 네 개가 동시에 화면 안에서 보였다는 뜻은 아니다. 준비본의 하단 항목은 `inner_text()` 존재 검사(`235–243`)이며 준비 모달 안을 실제로 끝까지 스크롤해 읽은 기록은 없다. 닫기 버튼의 hit-test와 닫힌 뒤 가림 제거는 별도로 검사한다.
- 기록된 순서는 **같은 근거 열기→닫기→재열기/Escape→준비 열기→닫기→전체 복귀**다. 열린 근거를 둔 채 다른 근거/준비로 이동하거나 곧바로 전체 복귀하는 조합, 다른 부분 선택, 비교표 펼침은 이 실행에서 관측하지 않았다. 계약의 작은 흐름을 통과했다는 결과를 모든 조작 순서의 보장으로 확대하지 않는다.
- REPORT의 실제 Chromium 141.0.7390.37/Playwright 1.56, 좌표 클릭·모바일 에뮬레이션 탭·휠은 작성자 실행 주장과 검사 코드가 부합한다. 독립 브라우저 재현·실제 손가락 스와이프·외부 GitHub 원문 왕복·사람의 읽기 부담 평가는 미실행이다. 패키지에는 대표 PNG 3개만 있어 JSON에 이름이 남은 전 단계 화면을 모두 재검토할 수 있는 것은 아니다.
