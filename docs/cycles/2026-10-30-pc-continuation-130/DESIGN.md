## 실제 흐름과 호출 상한

1. 기존 PC 서버를 정상 종료한 뒤 같은4327/같은 저장소로 기존 EnvFile을 선택해 시작한다. 공급자 키는 기존 공개127에서 사용한 키와 동일함만 확인했으며 값은 공개하지 않는다. 시작 자체는 생성하지 않는다. 현재 고정 Codex map 정책은 그대로다. 이 로컬 실행의 공급자 호출 상한은2, 동시1로 둔다.
2. 실제129 프로젝트와 변경 초안 전체가 그대로인지 확인한다. 서버 준비와 AI로 살펴보기 버튼을 확인하고, 기존 정상 UI로 plan1회만 요청한다. 입력 전체와 지침·모델·시간·출력 범위를 먼저 기록한다. 이미 만들어진지도를요약/수선해서넣지않는다.
3. 전달·계약·의미를 나누어 판정한다. 원기록은 과거 구현 지시이며 현재 런타임이 그 요구를 이미 이행했는지는 별도다. 보관된지도에표현된요구를현재완료사실로승격하지않고,읽기개선을기존철회엔진전체재구현으로넓히지않아야한다. 원intent가이미답한대상·이력·판본격리·정확근거왕복을새미결정질문으로돌리지않는다.
4. plan 의미가통과하면 실제선택범위를정하고 scope1회까지 이어간다. 진짜선택사항만총괄이제품목표에맞춰정하며,동일지도를재생성하거나실패응답을수선하지않는다. scope와최종요청문은원intent및불변조건으로독립판정한다. 실패하면추가호출0으로원본보존하고원인을구분한다.

## 보존해야 할 실제 의도

사용자가 철회 내용을 읽을 때 어떤 이전 보고·요청 항목에만 적용되는지와 남는 이력을 쉽게 파악하도록 하는 읽기 개선이다. 다른 항목·판본으로 철회가 번지지 않는 조건과 정확한 근거로 갔다 돌아오는 동작을 유지한다. 기존 데이터·집계·철회 규칙을 임의로 바꾸거나 요청 범위 밖의 새 엔진·연결기·대시보드를 제안하지 않는다. 구체적 화면 표현에서 필요한 실제선택과이미확정된조건을구별한다.
