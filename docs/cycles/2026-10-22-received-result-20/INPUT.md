# 정확한 수신 결과 이어가기20 — 구현 계약
2026-10-22 · 출발 제품 acfafd2d, checkpoint 병합41b6854e. 현재 상태는 [ACTIVE](../ACTIVE.md)만 갱신한다.

## 해결할 한 흐름
B 작업을 보거나 작성하던 중 A의 결과 파일을 가져온다 → 짧은 수신 안내에서 ‘이 결과 검토’를 연다 → 정확한 A 보고·소유 부분의 현재 구상·그 인계 당시 작업 조건을 구분해 읽는다 → 필요하면 명시적으로 다음 요청을 만든다 → 원래 보기로 돌아온다. 읽기만으로 현재B·draft·지도·완료 상태를 바꾸지 않는다. 동일 current 작업 자체에 결과가 올 때의 기존 placeReturn 수신 정책은 유지하며, 별개B에 늦게 온 A와 구분한다.

현재 acceptResultFile/receiptLine은 선택적인 영역설명이 있어야 위치 입구가 생기고 일반 return.1은 수신한 보고의 직접 입구가 없다. 중복 확인도 실제 해당 보고 선택 대신 안내만 갱신한다. 기존 reader/origin/수동편집/정확한 인계 연결을 재사용한다.

## 수용 조건
1. return.1/return.2 모두 실제 일치한 반환 task와 root request, 실제 H_ 인계ID를 구분한다. 최신작업/마지막배열원소를 출처 추정의 fallback으로 쓰지 않는다. 불일치 파일은 기존처럼 거절한다.
2. 신규 수신은 짧은 안내+명시 ‘이 결과 검토’ 입구를 제공한다. 자동으로A나지도에 이동하지 않는다. 정확 duplicate는 새 기록·시간·변경을 꾸미지 않고 원래 같은 report로 연결한다.
3. 읽기 화면은 보고 원문 앞부분과 소유 부분의 사용자 구상을 구분한다. 조건 전문·원문·기준은 필요할 때 펼친다. 현재 taskWorkDetails를 과거 조건으로 표현하지 않고 정확한 ExportRecord.work를 ‘이 결과를 요청했을 때’로 연결한다. 당시 snapshot이 없다면 없음을 표시한다.
4. 별개 B의 currentTaskId·전역 draft·부분별 미저장 입력·지도 좌표/카메라·읽기 상태는 수신/열람만으로 바뀌지 않는다. 출발work/task/space/area의 실제 보기 복귀를 정의한다. 명시 새 요청으로 current가 바뀐 뒤 복귀는 화면만 복원하며 새 current를B로 롤백하지 않는다.
5. 읽기/확인은 승인·완료·현재설명 채택이 아니다. 기존 held/미검증/저장실패 의미를 유지한다. 메모리에만 남은 결과를 브라우저 저장 완료라고 표시하지 않는다. 다른프로젝트전환/새입력 후 오래된 receipt가 엉뚱한 대상을 열지 않는다. 저장 await가 끝났다는 이유로 사용자가 옮긴 새 화면을 다시 work/reader로 끌어오지 않는다.
6. 보관 영역의 정확한 보고와 당시 작업문은 읽을 수 있다. 다른 활성 영역으로 대신 이동하거나 보관 해제하지 않는다. 불가능한 새 작업 행동은 기존 정책을 따른다.
7. PC1280×720·1440×900에서 수신 안내·보고 제목/행동·긴본문을 읽고 복귀한다. 본문은 필요한 구역만 스크롤한다.390은 접근/닫기/가로넘침 최소만 확인한다. 사이클19 지도높이·records origin·목적읽기 회귀를 유지한다.
8. 두 입력을 같은 renderer로 적용한다. A수신/Bcurrent, 동일 인계 여러 보고, 이전 인계 대 늦은 보고, exactduplicate, return.1/no-understanding, held/archived, memory-only, 새요청 후 복귀를 실제 ID/원문으로 검증한다. author와독립Cloud, 정적검토, 양OS CI, 총괄 화면대조를 구분한다.
