# 현재 설명 다시 기록27 — 명시적 새 판본으로 이어가기
2026-10-23 KST. 현재 배정은 [ACTIVE](../ACTIVE.md). [25 결과](../2026-10-23-correction-reading-25/RESULT.md)에서 발견한 공백을 다룬다. 정확 제품689c와 같은 app을 가진 checkpoint b24e790333318d97b1ab713a136a96f2bd6ece98에서 격리 구현한다.

## 해결할 사용자 흐름
사용자가 설명의 표시 오류를 고치고, 그 설명에 맞춰 작업문을 수정하면 이전 설명은 오래된 참고가 된다. 현재는 이를 다시 읽고 지금 상황에 맞는 설명으로 기록할 경로가 없다. 기본 화면에 관리 항목을 늘리지 않고, 기존 설명 편집 안에서 현재 정보를 대조한 뒤 필요한 내용을 기록하고 다음 인계로 이어간다.

## 총괄이 선택한 최소 범위
기존 planStamp의 네 직접값·조건·구상·포함 맥락 비교를 유지한다. 자동 재유효화, 특정 필드의 일괄 제외, 의미 충돌 판정은 하지 않는다. 오래된 설명의 stamp를 덮어쓰지 않는다.

최신 적용 판본이 있는 영역에서 기존 편집을 연다. 유효 설명의 기존 정정 흐름은 유지하고, 오래된 설명에는 ‘현재 상황과 대조해 설명 고치기’를 제공한다. 이전 설명이 채워진 입력을 읽고 필요하면 고친 뒤 ‘현재 설명으로 기록’한다. 문장이 같더라도 새 사용자 판본이며 revision을 올리고 corrects는 직전 판본, stamp는 대조한 현재 맥락으로 남긴다. 외부 보고가 새로 검증한 설명으로 귀속하지 않는다. 보류 기록만 있는 영역·보관 영역은 이 경로로 채택하지 않는다.

오래됨 안내와 인계 제외 문구는 구상·조건뿐 아니라 직접 쓴 작업문 또는 포함 맥락의 변화도 정확히 말한다. 해시 차이만으로 범위·정책 변경이나 의미 모순을 추론하지 않는다.

편집 안에서만 ‘현재 구상·조건 보기’와 ‘관련 작업문 보기’를 제공한다. 실제 stamp 관련 작업을 찾아 현재 네 값을 읽게 하며, 현재 작업이 B여도 A의 설명을 B로 복사하거나 current를 바꾸지 않는다. 여러 작업은 이름·소유 부분별로 펼쳐 읽는다. 미지정 작업은 구별하고, 직접 쓴 값과 생성값은 기존 표현을 재사용한다. 과거 네 값은 stamp에 없으므로 가짜 전후 표를 만들지 않는다. 긴 기술 식별자는 기본 표현에 넣지 않는다.

## 저장 경계
실제 편집을 열 때 project/area/latest revision/current stamp를 포착한다. 무수정 저장도 이 맥락에서 실행한다. 저장 시 다시 검사하고 달라졌으면 초안을 보존한 채 거절한다. 리렌더가 맥락을 자동 갱신하여 검사를 우회해서는 안 된다. 취소 후 최신을 다시 읽고 여는 명시 경로를 유지한다. 영역·프로젝트별 초안을 섞지 않는다.

이 저장은 설명만 추가한다. 네 작업값·사용자 기준·구상·실제 소속·원보고·기존 H는 그대로다. 다음 입력과 인계에는 새 사용자 참고를 전달하되 정책/실행 권한이나 앱 검증으로 승격하지 않는다. 이후 맥락이 다시 바뀌면 새 설명도 정상적으로 오래된 참고가 된다.
