# cycle04 — 메커니즘 조사와 총괄 선택

2026-10-16 · 시안 배정 전 판단. 현재 실행 상태는 [ACTIVE](../ACTIVE.md), 고정 구현 범위는 [BRIEF](BRIEF.md).

## 무엇을 비교하기로 했는가

첫 진입에서 변경 설명을 읽은 뒤 관련 부분을 다시 찾는 부담을 줄이되, 공간과 관계를 잃지 않는 것이 이번 질문이다. **A 관련 범위 먼저 / B 짧은 설명에서 동일 대상 참조 직행**을 같은 사실·관계·상세로 비교한다. Pro가 제안한 가변 상세 시트와 전용 읽기의 전면 비교는 이번에 하지 않는다. 첫 진입 질문을 보려면 이미 검증한 읽기·복귀를 공통으로 유지하는 편이 차이를 분리하기 쉽다.

내부 Astra의 반박은 두 후보의 관계 정보량 비대칭이었다. A에만 세 동작별 관계를 풍부하게 넣고 B에는 네 영역 이름만 남기면 읽기 순서 비교가 아니다. 두 안에서 동일10개 관련 매핑을 비교 가능한 깊이에서 회수하게 한다. 공통 정보 위계 개선이 함께 들어가므로 cycle03 대비 차이를 A/B 방식만의 효과라고 주장하지 않는다.

## 요약의 정보 위계

긴 한계 문장을 모든 자리에 반복하는 대신 **읽는 주장이나 행동의 의미를 바꾸는 짧은 한정은 그 자리에 남긴다.** 기본에는 프로그램 목적·과거 개발보고의 변경 당시 범위·핵심 변경/유지를 둔다. 관련 영역에는 문서의 함께 언급된 범위라는 뜻을, 다음 요청에는 실제 AI 준수 미검증을, 준비 행동에는 준비 제안·보내지 않음을 붙인다. 고정 출처·원대화/승인/수신 부재·MOCK·방문 이력 부재의 정밀 설명은 해당 근거 상세에서 회수한다.

보고 주체를 여러 제목에서 반복하는 문구, 방문 이력이 없다는 긴 운영 설명, 실제 결정 요청이 없다는 상시 안내는 간결하게 만들 수 있다. 프로그램 목적은 변경 요약과 역할이 다르므로 삭제하지 않는다. 직접 쓴 범위와 현재 요청을 유지한다는 조건도 단순화를 위해 지우지 않는다. 요약을 매끄럽게 쓴 것이 검증·사용자 승인·최신 상태의 증거가 되는 것은 아니다.

## Pro 반환을 그대로 채택하지 않은 지점

- OsmAnd의 내려가기 함수는 지원 메뉴 상태 전환이며 원래 전체 보기 복원 증거가 아니다.
- ArcGIS의 다른 위젯 선택→popup은 설정 조건부다. 초기 extent 복귀는 진입 직전 보기 복귀가 아니다.
- Power BI의 제스처 억제는 visual이 선택된 기간이다. 지정 문서만으로 모든 웹 화면은 일반 보기라고 단정하지 않는다.
- Grafana 문서의 변환 데이터 설명과 고정 코드 초기 false는 구별한다. 문서가 변환 기본값=true를 명시했다고 인용하지 않는다.
- Terraform에서 상태/commit이 제공된다는 설명은 sticky·초점·스크롤 보존 보장이 아니다. speculative plan 적용 불가는 별도 공식 연결 문서로 보충 확인했다.

## 관측 방식과 종료 조건

[제품 사전 범위](PRODUCT_SCOPE.md)·[위험 중심 검증](VERIFICATION_SCOPE.md)을 사용한다. 작성자는 비교 산출물과 실행 증거를 반환하며 독립 검토와 합산하지 않는다. 기존 기본 화면은 동일한 Cloud 환경에서 세 크기의 완전한 라벨·의미 단위 노출과 실제 가림을 새 기준 관측으로 남긴다. 과거16단계 회귀를 다시 채우는 작업은 아니다.

두 Pro는 공식 문서·고정 코드로 조사했고 요청 PNG의 직접 시각 열람과 외부 데모 조작은 완료하지 못했다고 명시했다. PNG 관측은 내부 Astra의 실제 열람, Dify 조작은 총괄의 CUA 관측으로 분리한다. 브라우저의 접근 가능성·정확 원본·복귀는 조작 증거이며, AI 내용/이미지 비평과 사람의 이해·사용성은 다른 근거다.

같은 사실과 복귀를 지키면서 초기 의미·연결의 회수 경로를 비교할 수 있으면 이 반복을 정리한다. 차이가 분명하지 않으면 승자를 만들지 않고 공통 개선만 취하거나 보류한다. 같은 과거 변경의 장식 수정으로 다음 연구를 무한히 이어 가지 않는다.
