# cycle04 — 첫 진입 비교 결과

2026-10-16 · 범위: 한 과거 개발보고의 변경·동작·관련 영역을 만나는 순서. 현재 실행 상태는 [ACTIVE](../ACTIVE.md).

## 총괄 판단

공통 정보 위계를 수용하고 **A의 관련 범위 개요를 다음 조합의 후보로 유지한다. B의 긴 설명 열 전체는 보류하고 동일 대상 참조·출발 설명 회수 원리만 보존한다.** 최종 제품 구조나 사람 사용성의 승자를 정한 것이 아니다. 같은 입력의 장식 수정은 이 비교로 정리한다.

A는 미선택 상태에서도 세 동작별 관계를 먼저 훑게 한다. B는 설명의 이름을 기억해 지도에서 재검색하지 않아도 같은 대상을 가리킨다. 그러나 B의 네 문장이 반복되고 좁은 화면의 공간 지도를 뒤로 밀었다. A도 반복 칩과 일부 스크롤이 남아 완성된 다층 지도는 아니다. 초기 영역 깊이가 모두1로 바뀌고 공통 안내도 정리됐으므로 이전 시안 대비 변화를 A/B 순서 하나의 효과로 귀속하지 않는다.

## 보존한 의미와 고친 것

기준 F1~F8, 세 동작·네 영역, 지정10개/미지정2개, 동일 대상 ID, 목적 정정과 직접 지시 보존, 실제 AI 준수 미검증, 준비와 송신의 구별을 유지했다. 네 영역은 문서가 보고한 관련 범위이며 제품 모듈의 포함 구조가 아니다.

독립 내용 대조에서 B의 ‘관계가 기록에 없다’는 문장이 복원 시 작업 지시 보존까지 부정하는 듯 읽힐 수 있음을 찾았다. fix1은 ‘이 지도에서 작업 카드 직접 수정 동작 등과 연결이 미지정’으로 한정했다. 보조 실행 래퍼가 마지막 출력의 성공값으로 끝나던 문제도 고쳐 정확한 정상0/의도한 실패1 쌍만 성공으로 반환하게 했다. 나머지 시안 기능을 다시 설계하지 않았다.

[작성본 독립 검토](AUTHOR_REVIEW.md), [fix1 최소 변경·합성 집계 감사](FIX1_AUDIT.md)에 사실·코드·PNG 판단을 구분했다. 합성 종료값 프로브는 브라우저 UI 검증이 아니다. 공통 도움말/A 범례의 일반적인 미지정 표현은 맥락상 동작 관계를 가리키지만, 다른 표본으로 일반화할 때 더 명확한 명칭이 필요할 수 있다.

## 독립 브라우저 결과

완전히 노출된 실제 노드 이름의 수다. **기준 화면도 설명문에는 네 영역 이름이 있었고**, A390은 관계 칩12개, B390은 문장 속 참조14개의 이름이 모두 보인다. 칩/참조 노출과 실제 영역 카드의 이름·내용 노출은 다르다. A는 관계를 먼저 읽을 수 있지만 그곳에서 무엇이 바뀌었는지는 아래 카드로 가야 한다. A1280의 저장 복구 본문은 여전히 스크롤이 필요하다. 제목·핵심 변경/유지·과거 보고 기준은 여섯 화면에서 완전히 노출됐고,390의 헤더 목적문은 폰트 Range와 자체 경계의 차이로 PARTIAL_LAYOUT이다. 실제 잉크 잘림 결함으로 확대하지 않는다.

조작에서 확보한 범위:

- 두390 읽기에서 실제 창120px의 비초기 위치로 근거를 열고 닫기/재열기/Escape 뒤120px·출발 문장 사각형·근거 버튼 초점을 유지했다. 닫은 직후 측정했고 근거/닫기/링크 노드는 실제로 제거됐다. 근거 본문 자체의 독립 스크롤창은 없다.
- 두1280에서 다른 영역 깊이0/1/2와 실제 transform1.2를 두고 도움말·요약을 열고 닫아도 재선택 없이 선4개의 실제 끝점 대응이 유지됐다.
- A/B×1280/390의 네 전체 복귀에서 세 동작+네 영역 머리의 정확한7개 사각형 변화는0, 선택·깊이·지도/창 위치·실제 배율이 유지됐다. B의 ‘설명으로 돌아가기’는 전체 복귀와 별도 행동이다.
- B에서 작업 지시를 선택한 채 저장 복구를 가리켜도 원래 선택은 유지됐다. 안내는 관련/미지정을 구별했다. 사람이 두 상태를 혼동하지 않는다는 증명은 아니다. A/B 동작 로그에는 서로 다른 경로가 포함돼 클릭·휠 수를 우열 점수로 쓰지 않는다.
- 준비 하단은 A390에서 한 번만 실제 휠57px로 접근해 보존조건·미확인·보내지 않음과 닫기 복귀를 관측했다. 다른 모든 준비 경로까지 재실행한 것은 아니다.

[독립 코드·원본 감사](CLOUD_AUDIT.md)는 측정 JS의 동일성과 문자 Range 결과를 재계산하고, 종료·정확 대상·복귀 수치를 대조했다. 공유21파일의 manifest20/20을 확인했다. 사전 해시 프로브는 서버/브라우저를 열기 전 종료됐으므로 실제 응답 불일치나 UI 결함 재현이 아니다. `run-process.py`의 상위 종료0은 합격 신호가 아니며, 실제 자식 종료/완주/JSON을 기준으로 수용했다. 이 경계 때문에 검증 완료를 뒤집거나 전체 실행을 반복할 이유는 없었다.


## 이번 판단의 범위

Pro의 OsmAnd·ArcGIS·Power BI·Grafana·Terraform 자료는 [원문/고정 코드 대조](SOURCE_AUDIT.md)이고 직접 서비스 조작 결과가 아니다. [Dify 관측](DIFY_OBSERVATION.md)은 총괄이 기존 화면에서 패널 닫기/같은 Agent 재선택만 확인한 별도 근거다. [선택 이유](MECHANISM_REVIEW.md)에 가변 시트를 보류하고 첫 진입 질문에 집중한 판단을 남겼다.

내부 Astra는 초기6PNG와 일부 선택/복귀PNG를 실제 열람해 내용·시각 구조를 비평했고, 총괄은1280에서 A/B 첫 화면과 B 참조를 직접 조작했다. 이는 사람의 처음 이해·실제 손가락 조작·외부 원문 왕복·실제 AI/인계 실행 또는 Dify 대비 우위를 증명하지 않는다.

## 다음 한 일

다음 질문은 **프로그램 구성에서 변경된 한 부분을 골라 상위 맥락·관련 부분·유지 조건을 잃지 않고 필요한 조정/인계 준비와 전체 복귀로 이어갈 수 있는가**다. 구성 수와 변화 수를 좁히되 흐름 자체를 다시 끊지 않는다. cycle01의 혼합 깊이와 외부 관계, cycle03의 정밀 읽기/준비/복귀, 이번의 짧은 기본 설명과 같은 대상 참조를 조합한다. 행렬·긴 설명 열을 제품 문법으로 확정하거나 새 연결기·자동 갱신 엔진부터 만들지 않는다.

입력 후보는 [FLOW091-C의 요청 시점 배경 사본 계약](https://github.com/tlsee0813-cmd/agentflow-studio/blob/5416decfbe9f38a45323de0badc4fc58ec6e4bcd/docs/flow091-background-contract.md#L10)이다. 목적을 요청과 분리된 배경으로 포함하면서, 이미 준비한 요청의 사본·직접 수정을 보존하고 다음 새 요청에만 최신 구상을 쓰는 변경을 다룬다. 이는 과거 개발 계약·MOCK 검사 보고이며 사용자 원대화·실제 AI 준수·인계 수락·확정 모듈 트리가 아니다. 문서3개만 좁게 확인해 후보로 골랐고 새 시안을 구현하지 않았다.

완성된 정답 트리가 없다고 구성 해석 연구를 막지는 않는다. **문서로 확인된 전달·보존 관계**와 **AI가 제안하는 기능 구성**을 구별한 최소 입력을 먼저 고정한다. 제안된 묶음이 상세나 준비문에서 확정된 소유·영향 범위로 바뀌지 않는지가 핵심 반례다. 출처가 없는 이름 변경·실제 사용자 결정·담당 수락을 새로 만들지 않는다. 한 연쇄에서 무엇이 보존·누락되는지 판단하면 그 다음 범위를 정한다.

제품 소스·main·공개 배포·GUIDE107 HOLD는 이번 연구 통합으로 바꾸지 않았다. 최종 UI나 전체 제품 완성 선언이 아니다.
