## 질문과 입력

**처음 들어왔을 때 어떤 프로그램의 어떤 변경을 보고 있으며 어떤 부분들이 왜 관련되는지 읽고, 같은 부분에 들어갔다가 맥락을 이어갈 수 있는가?** 390의 상단 설명 약524px와 1280의 선택 전 관계 노출 부족에서 출발한다. 단순 높이 축소·모든 정보 한 화면 넣기·검사 수 늘리기가 목적이 아니다.

기준 연구 `c0328dcacf4f50541814d7c18801a45ae8a20cb0`의 [cycle03 RESULT](../2026-10-16-return-flow-03/RESULT.md), [INPUT F1~F8](../2026-10-16-return-flow-03/INPUT.md), [전체 제품 목적](../2026-10-15-real-record-02/PRODUCT_LENS.md)을 사용한다. 원본 HTML은 [34b41240의 author-fix1](https://github.com/tlsee0813-cmd/agentflow-studio/blob/34b4124098fe6242b34e16e23532ceb3e0fe91ad/docs/cycles/2026-10-16-return-flow-03/author-fix1/return-flow-study.html), SHA256 `af748df1dfacb7ed6b4ae3709d5ced26ef43f96bc45a9e6c2c05cdc02e9cc77e`다. 같은 폴더의 PNG는 과거 작성자 관측이며 새 후보의 증거로 승계하지 않는다.

FIX058은 과거 개발 변경을 문서가 보고한 표본이다. 원대화·최신 전체 제품·실제 사용자 조작·승인·AI 준수·인계 수락의 증거가 아니다. 네 영역은 변경 영향 범위이며 모듈 포함·실행 순서가 아니다. 정리되지 않은 다른 질문을 이번 구현에 추가하지 않는다.

## 비교할 두 안

단일 자체 포함 HTML에서 동일 사실·대상·관계·상세·준비 내용을 사용해 두 표현을 선택할 수 있게 한다. 비교용 선택기는 작고 명확한 연구 도구로 구분한다. 후보를 바꾸면 깨끗한 별도 시작임을 명시하며, 후보 전환을 제품의 보기 복원/데이터 수정처럼 연출하지 않는다. URL 등으로 각 후보를 독립 실행할 수 있으면 검사에 유리하다.

- **A 관련 범위 먼저:** 짧은 목적·변경 요지·기록 기준 뒤에 동작과 영향 범위를 먼저 훑는다. 미선택 상태에도 무엇이 함께 언급됐는지 읽을 단서를 남기되 이미 사용자가 선택했다고 꾸미지 않는다. 선택하면 해당 범위만 분명하게 강조하고 다른 대상을 무관하거나 삭제된 것처럼 없애지 않는다.
- **B 설명에서 바로 연결:** 같은 변경·유지 내용을 짧게 설명하고 그 문장 속 동작/영역 참조가 기존 동일 대상을 직접 가리킨다. 이름을 기억해 수동으로 찾게 하지 않는다. 참조로 이동한 뒤 현재 부분·어느 변경에서 왔는지와 나머지 관련 범위를 회수할 경로를 남긴다. 설명을 길게 늘려 공간을 아래로 밀어 놓은 뒤 링크만 더하는 안은 피한다.

다른 점은 **설명과 관계를 만나는 순서·참조 연결 방식**이다. 동일 정보가 같은 깊이에서 회수 가능해야 한다. A만 관계를 풍부하게 넣고 B는 이름만 남기는 비교는 하지 않는다. 두 안 모두 같은 공통 정보 위계 개선을 받으므로 cycle03 대비 차이를 A/B 방식 하나의 효과로 귀속하지 않는다. 구체 배치는 구현자가 이 질문 안에서 설계하되 두 안을 같은 카드 목록의 색상 차이로 만들지 않는다.

새 드래그 시트·제스처 엔진은 보류한다. Pro가 제안한 OsmAnd/ArcGIS식 가변 상세는 지도 뒤에 남는 픽셀만으로 맥락을 보장하지 않으며, 이번 첫 진입 질문의 필수 조건이 아니다. 기존 전용 읽기·근거·준비·전체 복귀를 공통으로 재사용하고 실제 결합만 수정한다.

## 동일 데이터·의미 계약

기존 세 동작과 네 영역, 안정된 ID를 유지한다.

| 동작 | 홈 | 작업문 | 다음 AI 요청 | 저장 복구 |
|---|---|---|---|---|
| 목적 정정 | 지정 | 지정 | 지정 | 지정 |
| 작업 지시 | 지정 | 지정 | 지정 | 미지정 |
| 사용자 결정 표시 | 지정 | 지정 | 지정 | 미지정 |

이는 현재 시안의 문서 관련 매핑 10개다. 미지정은 무관함의 증명이 아니다. 전부를 한 부모의 자식이나 연속 실행선으로 만들지 않는다. 동일 대상의 요약 참조는 가능하지만 별도 노드/소유자를 생성하거나 중복 DOM ID를 만들지 않는다.

공통 정보 위계:
1. 기본에서 프로그램 목적, **과거 개발보고의 변경 당시 설명**이라는 기준, 목적 정정은 별도·직접 쓴 작업 지시/현재 요청은 유지된다는 핵심을 읽을 수 있어야 한다.
2. 관련 범위에는 문서에서 함께 언급된 영역이라는 짧은 한정을 둔다. 포함·실행·자동 영향 분석으로 읽힐 선/묶음을 사용하지 않는다.
3. 다음 AI 요청을 설명하는 자리에는 **요청에 포함된다는 보고 / 실제 AI 준수 미검증**을 함께 둔다.
4. 준비 행동에는 **준비 제안·보내지 않음**을 남긴다. 실제 결정 요청이 없는 표본을 승인 숙제로 바꾸지 않는다.
5. 고정 출처·구절, 원대화/승인/실제 수신 부재, MOCK 범위, 방문 이력 부재의 정밀 설명은 근거/출처 상세에서 읽을 수 있게 한다. 기록 기준이 이미 명확하면 기본에서 같은 면책문을 반복할 필요는 없다.
6. 기본에 QA 숫자·내부 식별자·해시·검사 목록을 넣지 않는다. 글자를 작게 하거나 핵심 한계를 숨겨 공간을 얻지 않는다. 자연스러운 한국어·명확한 정보 위계·선택 반응을 우선한다.

Grafana의 동일 참조/제목과 Terraform의 항목별 상세는 요약에서 같은 대상의 근거를 여는 원리만 참고한다. 소스·화면 복제나 새 라이브러리 도입 요청은 아니다. [제품 사전 범위](PRODUCT_SCOPE.md)와 [Dify 실제 관측의 한계](DIFY_OBSERVATION.md)를 함께 읽는다.

## 보존할 조작과 구현 경계

선택은 명시적 동작으로만 바뀐다. 다른 영역의 0/1/2 깊이·대상 정체성·관련 매핑·제공 배율을 유지한다. 참조 직행은 실제 원래 대상을 선택/가리키며, 새 화면에 같은 이름의 별도 데이터를 만들지 않는다. 같은 후보 내부의 상세 닫기/전체 복귀에서는 출발 대상·관련 범위·사용자 깊이·실제 지도/창 위치·배율·초점이 이어져야 한다. B의 참조가 출발점이면 출발 참조와 현재 지도 선택 중 무엇으로 돌아가는지 일관되게 정하고 기록한다. 초점 때문에 저장한 화면 위치가 다시 움직이면 결함이다.

기존 PARTS/AREAS 및 선택·근거·준비 데이터를 재사용한다. layout/drawEdges는 canvas/sizer/parts/frame와 실제좌표·899px 분기에, openPeek/closePeek는 focusCol/rail 및 데스크톱 컨테이너·모바일 창 스크롤에 결합되어 있다. enterFocus/returnAll은 지도 DOM이 남는 구조에 의존한다. 따라서 CSS만 바꿨다는 이유로 복귀 성공을 승계하지 않는다. 기본으로 돌아오면 기존 지도 DOM/상태가 살아 있어야 한다. 필요한 결합 수정은 허용하되 전체 엔진을 새로 만들지 않는다.

제품 소스·main·gh-pages·GUIDE107 HOLD·원격 계정설정·실제 AI/송신은 제외한다. 구현은 연구 산출물 하나에 한정한다. 작업자는 checkpoint에 쓰지 않고 원본 파일을 총괄에게 반환한다.

## 검증과 반환

[좁은 검증 범위](VERIFICATION_SCOPE.md)의 5장면을 후보별 위험에 맞게 적용한다. 작성자 실제 브라우저는 390×844와 1280×720 초기/선택, 1440×900 초기의 완전한 라벨·의미단위 노출을 기록한다. 한 화면에 모든 상세를 억지로 넣지 않는다. 조작/이동거리 감소는 사람 이해 성공이 아니다.

A/B 각각 390에서 관련 범위 접근, 다른 깊이 유지, 읽기 비초기 위치에서 근거 열기→닫기→재열기/Escape, 전체 복귀를 관측한다. 새 요약/도움말을 열고 닫는다면 재선택 없이 선/표시 대상 대응을 확인한다. 데스크톱은 두 후보의 실제 배율·지도 위치 복귀를 한 번씩 확인한다. 공통 읽기/준비 레이아웃에 영향을 주면 준비 하단 접근은 390에서 한 번만 추가한다. 이전16단계 전체 재실행·전체 흐름 반복을 숫자 채우기로 하지 않는다.

브라우저가 받은 최초 HTML HTTP 응답 body SHA256을 해당 파일과 결합한다. 필수장면 FAIL·미완주·pageerror·fatal·cleanup·해시불일치는 실제 nonzero여야 한다. 실행/JSON/로그의 종료를 함께 보존한다. 신규 종료집계를 썼다면 의도한 실패 한 건만 좁게 검증한다. 불가능한 비초기 위치를 DOM조작·가짜여백으로 만들지 말고 미관측 이유를 남긴다.

반환은 경로 구조를 가진 단일 작은 ZIP: orientation-study.html, REPORT.md(채택이유 아닌 설계차이·정확입력·환경·원본hash·성공/실패/미관측·남은문제), 실행 가능한 확인 스크립트와 JSON/로그/실제 종료, 대표 PNG(각 후보390/1280/1440 초기 총6장과 필요한 결함/복귀 장면 최소), MANIFEST.json(파일별bytes·SHA256). 첫 실패가 있으면 최종 결과로 덮지 말고 원인/재현범위를 남긴다. 코드·검증수·AI 의견을 사람 평가로 바꾸지 않는다. 새 라이브러리 설치가 꼭 필요하지 않으면 사용하지 않는다.

완료는 두 안을 실제로 열고 같은 사실/관계와 작은 읽기·복귀를 대조할 수 있는 원본을 받는 것이다. 어느 안을 채택할지, 공통 부분만 취할지, 둘 다 보류할지는 총괄이 독립 내용/코드 대조 후 판단한다.
