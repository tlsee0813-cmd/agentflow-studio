# cycle04 — 첫 화면 비교의 좁은 검증 범위

2026-10-16 · Sol · **사전 검증 설계, 새 실행 결과 아님.** 목적은 첫 화면에서 변경·현재 부분·관련 영역의 의미를 보존하며 다시 찾는 데 필요한 조작을 줄이는지 비교하는 것이다. 레이아웃·새 기능·구체 선택자는 확정하지 않는다.

## 기준과 보존 조건

현재 연구 HEAD는 `c0328dcacf4f50541814d7c18801a45ae8a20cb0`이며 비교 기준 HTML은 별도의 고정 버전이다. 실제 로컬 파일 `work/return-flow03-fix1/return-flow-study.html`을 읽고 SHA256 `af748df1dfacb7ed6b4ae3709d5ced26ef43f96bc45a9e6c2c05cdc02e9cc77e`를 확인했다. 원격 원본은 [34b41240의 cycle03 fix1](https://github.com/tlsee0813-cmd/agentflow-studio/blob/34b4124098fe6242b34e16e23532ceb3e0fe91ad/docs/cycles/2026-10-16-return-flow-03/author-fix1/return-flow-study.html)이다. cycle03 계약·RESULT·Cloud 코드/수령 감사를 읽었다. 기존 [Cloud 16단계 결과](https://github.com/tlsee0813-cmd/agentflow-studio/tree/0201912a2e05ae920337bf25c9e2d116142c94d7/docs/transfer/return-flow-03/fix1)는 역사적 기준이며 cycle04 실행으로 재계산하지 않는다.

다음 조건은 화면 압축과 교환할 수 없다.

- **같은 사실:** 목적 정정과 작업 지시의 구분, 홈·작업문·다음 AI 요청·저장 복구라는 같은 관련 범위, 문서가 보고한 변경이라는 시점/출처 경계. 원요청·실 AI 준수·인계 수신/수락의 미확인은 유지한다. 없는 방문 이력·현재 결정 요청·승인 숙제를 만들지 않는다.
- **같은 의미:** ‘함께 언급됨’은 모듈 포함·실행 순서·자동 영향 분석·담당 소유 변경이 아니다. 요약을 줄여도 이 뜻을 확인할 경로와 필요한 한계는 남긴다. 처음 선택이 없으면 ‘선택 없음’을 사실대로 보여 주며 첫 화면 비교를 위해 목적 정정이 이미 선택됐다고 꾸미지 않는다.
- **같은 보기 연속성:** 명시적 선택만 현재 부분을 바꾼다. 다른 영역의 사용자 조정 깊이, 관계 대상, 지도 위치/제공 배율, 읽기 위치·출발 초점은 해당 닫기/복귀 뒤 유지한다. 새 선택과 복귀를 구별한다. 준비는 송신·배정·수락이 아니다.

## 공정한 비교와 관측값

기준/후보에 같은 FIX058 자료·핵심 설명·근거 접근·한계와 같은 읽기 과제를 둔다. 기본에 정보를 덜 보여 줬다는 이유만으로 승자로 만들지 않고, 빠진 의미와 추가 상세 이동을 함께 적는다. 조건은 **1440×900·390×844, 브라우저 확대 100%**, 같은 브라우저·글꼴 환경·초기 선택/깊이다. 각 후보의 깨끗한 시작과 의도적으로 조정한 상태를 구별한다. 기준 PNG와 다른 환경의 새 픽셀을 직접 성능 비교하지 않는다.

| 기록할 값 | 해석 한계 |
| --- | --- |
| 변경 설명·현재 선택 상태·관련 범위의 **완전한 이름/설명**이 처음 어느 위치에 노출되는지, 잘림/가림 및 원래 설명까지의 경로 | 일부 픽셀·색점·아이콘이 보이는 것과 의미를 읽을 수 있는 것은 다르다. 모든 상세/네 영역이 한 화면에 들어와야 한다는 새 정답도 만들지 않는다. |
| 같은 목적 정정과 관련 범위 설명을 확인하기까지 필요한 클릭/펼침, 실제 이동 거리(화면 높이 단위), 되돌아간 방향 전환·재탐색 | 정해진 경로의 기계적 탐색 비용이다. 휠 이벤트 수는 입력 장치에 따라 달라 단독 순위 지표로 쓰지 않는다. 자동 스크롤을 쓰면 수동 조작 감소와 자동 이동 거리를 구분한다. |
| 선택 후에도 원래 변경 맥락과 현재 부분/관련 범위의 대응을 확인할 수 있는지, 추가로 열어야 하는 화면/설명 | 이름 목록의 존재와 관계 의미의 이해는 다르다. 의미 검토는 고정 자료와의 내용 대조이며 사람 이해 관측으로 쓰지 않는다. |
| 닫기/복귀 직후 실제 기준 노드 좌표·적용 배율·사용자 깊이·선택·출발 초점·읽기 위치의 전후 차이 | 같은 후보 내부의 복귀 연속성이다. 서로 다른 레이아웃끼리 좌표가 같아야 한다고 요구하지 않는다. |

사람 관찰이 없다면 결과는 ‘필요 조작/이동이 줄었다’, ‘의미 문구/대응이 보존됐다’, ‘읽기 복귀가 관측됐다’까지만 쓴다. **사람이 더 빨리 이해했다/부담이 줄었다는 성공 판정은 하지 않는다.** 추후 실제 사람이 자기 말로 설명한 변화·현재 위치·관계 해석과 오해/막힘을 관찰할 때만 별도 근거가 된다. AI 비평과 자동 검사 소요시간은 그 대체물이 아니다.

## 위험 기반 5장면

전체 16단계를 다시 펼치지 않고 다음 장면을 한 번씩 연결한다. 1–3은 첫 화면/배치 변경의 직접 위험이라 두 크기에서 비교하고, 4–5는 실제 변경 영향에 맞춰 좁혀 수행한다. 각 장면에는 전후 화면 또는 기하 기록·조작·판정 사유만 남긴다.

| 장면 | 실제 조작·핵심 증거 | 실패 또는 범위 제한 |
| --- | --- | --- |
| **1. 새로 연 첫 화면** | 스크롤/선택 전 변경 설명, 실제 현재 상태, 관련 영역과 의미를 확인할 경로를 기록한다. 완전한 라벨·핵심 문장, 가림/잘림, 필요한 추가 조작을 기준/후보로 비교한다. | 의미·출처 한계를 지워서만 공간을 얻음, 없는 선택/방문/결정 요청을 만들어 냄, 닫힌 상세의 DOM 텍스트를 첫 화면 노출로 셈. ‘첫 화면에 보였다’는 사람 이해 통과가 아니다. |
| **2. 현재 부분과 관련 범위 찾기** | 같은 시작에서 목적 정정을 실제 선택하고 관련 범위를 확인한다. 클릭/이동/되돌아감과 선택 전후의 다른 영역 깊이·대상 대응을 남긴다. 좁은 화면의 표시/관련 이름은 실제 클립과 가림을 확인한다. | 선택 때문에 전 영역 맞춤/펼침이 생김, 관련 참조를 새 포함/소유로 바꿈, 이름을 찾았지만 무슨 관계인지 확인할 경로가 사라짐. 네 표시의 DOM 개수를 가시성으로 대체하지 않는다. |
| **3. 선택을 유지한 배치 변화** | 사용자가 한 영역 깊이를 바꾼 뒤 목적 부분을 선택한다. 새 요약/도움말/접힘 조작이 있으면 한 번 열고 닫고, **재선택 없이** 그려진 선 또는 관련 표시의 대상 대응·가림과 실제 좌표를 본다. | 재선택이 선을 고친 뒤 성공으로 보고함, 바뀐 높이로 대상/조작이 가려짐, 다른 영역 깊이/선택이 같이 바뀜. 해당 새 조작이 없으면 이 장면의 토글만 비해당으로 기록하고 새 조작을 발명하지 않는다. |
| **4. 비초기 위치에서 근거 닫기** | 우선 390에서 같은 설명의 근거 하나에 실제 휠로 접근해 **창 또는 실제 읽기 컨테이너의 비초기 위치**를 만든다. 출발 문장/버튼·위치·초점을 기록하고 근거 열기→닫기→같은 근거 재열기/Escape를 한 번 수행한다. 다음 휠 전에 닫힘/링크 제거·출발 가시성과 위치를 비교한다. | 이전 0→0 관측을 비초기 성공으로 옮김, 닫은 뒤 먼저 스크롤해 대상을 복구하고 성공 처리함. 내용이 해당 조건에서 스크롤되지 않으면 그 크기의 비초기 관측은 **미관측**이며 DOM 조정·가짜 여백으로 만들지 않는다. 공통 읽기/초점 코드가 바뀌면 데스크톱도 이 장면을 확인하고, 그대로면 기존 증거와 변경 대조를 인용한다. |
| **5. 전체로 돌아와 이어보기** | 진입 전 사용자 깊이·선택·관계 대상·지도 스크롤/실제 배율과 몇 개의 의미 있는 기준 노드 좌표를 기록한다. 근거를 닫고 전체 복귀 후 **어떤 보조 스크롤도 하기 전** 같은 후보 내부 전후를 비교한다. 데스크톱은 제공 배율을 한 번 바꾼 상태, 390은 비초기 지도/창 위치를 사용한다. | 초점만 맞고 지도 위치는 초기화됨, 축소/선택 표시만으로 실제 좌표 복원을 대신함, 관계/소유가 늘어남. 준비 화면·공통 헤더/버튼·모달 크기에 영향이 있는 변경이면 이 장면 안에서 준비 열기/하단 접근/닫기를 **390에서 한 번만** 끼워 넣어 송신 아님·원래 읽기 초점을 확인한다. 영향 없으면 준비는 코드 대조와 cycle03 증거를 인용하며 반복하지 않는다. |

장면 5의 기준 노드는 새 레이아웃의 핵심 기준점으로 정하며 이전 7개 전부를 자동 승계하지 않는다. 다만 관계가 유지된다는 판정은 선 개수만으로 대신하지 않는다. 다른 깊이·현재 부분·관련 대상을 식별할 만큼은 남긴다. 새 장면 4의 닫기 반복 외에 작은 흐름 전체를 다시 한 번 반복할 필요는 없다. 상태 누적·복귀 로직이 실제로 바뀌면 그 위험에 한정해 반복을 추가하고 이유를 적는다.

## 작성자 검사에 필요한 최소 신뢰 조건

- 후보별 파일 SHA256·고정 버전/입력·실제 URL·브라우저/viewport를 기록하고, **브라우저가 받은 최초 문서 응답 body의 SHA256 및 HTTP200을 기대 HTML과 직접 비교**한다. 로컬 파일 해시나 별도 전후 fetch만으로 실행 바이트를 대신하지 않는다.
- 이번에 선택한 필수 장면의 FAIL·미완주·pageerror·fatal·cleanup 오류·해시 불일치는 nonzero로 끝나야 한다. 실제 프로세스 종료와 JSON 판정을 함께 남기고 finally/마지막 출력이 실패를 0으로 덮지 않게 한다. 기존 종료 경로를 그대로 재사용하면 음성 실행 전부를 반복하지 않는다. 종료 집계를 바꿨다면 의도한 실패 한 건의 원인과 nonzero만 좁게 확인한다.
- 장면 4에는 비초기 출발값과 닫은 **직후** 값·출발 문장 위치를 남긴다. 장면 5도 복귀 직후 실측을 먼저 저장한다. 앱의 자동 이동과 검사의 접근 보조를 구분한다. 필요 장면을 못 읽거나 실행하지 못했으면 사유/미관측·미실행으로 남기며 PASS로 채우지 않는다.

이 문서는 구현·새 검사군·브라우저 실행·환경 작업을 요청한 결과가 아니다. 기존 16 PASS와 새 장면 수/하위 조건을 합산하지 않으며, 탐색 거리 개선이 사실 경계·복귀 연속성의 퇴행을 상쇄하는 종합 점수를 만들지 않는다.
