## 실패 증거와 종료의 경계

- **합성 프로브는 사전 파일 해시 실패다.** `verify.py:107–110`은 `--probe`에서 기대 SHA를64자리0으로 바꿔 **서버/브라우저 시작 전** ValueError를 낸다. probe JSON은 stages/initial/actions/server가 비어 있고 executed0·complete=false·setup fatal, 실제 자식1/JSON1이다. 실제 UI 실패·잘못된 브라우저 응답·17장면 실패를 관측한 결과가 아니다. 브라우저가 다른 바이트를 받은 음성 경로를 실행했다고 쓰면 틀린다.
- 정상 실행은 계획17개 ID/상태를 완주하고 actual0/JSON0, fatal=null/pageerrors=[]/cleanup_errors=[]다. `verify.py:129–135`는 FAIL·미완주·pageerror·fatal·cleanup·해시 불일치를 nonzero로 연결한다. 다른 오류 경로의 실제 음성 실행은 없다. 파일/출력 오류가 try 밖에서 나면 최종 JSON 없이 자연 nonzero가 될 수 있다.
- **`run-process.py`는 종료 수집기다.** 자식 반환값과 JSON 일치를 기록하지만 그 불일치/잘못된 자식 결과를 자신의 최종 nonzero로 집계하지 않는다. 상위 runner exit0을 합격 신호로 쓰지 않는다. 이번에는 보존된 **자식 actual0/JSON0·합성 actual1/JSON1**이 맞으므로 현재 증거를 폐기하거나 재실행할 이유는 아니다.

## 별도 회수·이미지 감사와 총괄 판단

수령 담당이 직접 부모165c1520과 지정 경로21파일 추가만 확인했다. manifest20/20 크기·SHA256이 일치했고 전체2,111,597bytes다. 초기PNG6장을 실제 열람해 위 라벨 집계와 큰 모순이 없음을 확인했다. 이 파일의 코드·JSON 재계산과 별도이며 새 브라우저 재실행으로 합산하지 않는다.
