# cycle07 — 실제 변경을 목적·공간·시점으로 읽기
2026-10-16 시작 범위. 기준 연구 d17667c1c519492f6edf8ea064a9f87b5d51fc12. 현재 상태는 [ACTIVE](../ACTIVE.md).

## 이번에 판단할 하나의 문제
**추정 가능한 업데이트 남은 시간을 알려 준다는 목적 아래, 두 화면과 공통 계산에서 무엇이 바뀌었고 무엇은 아직 확인되지 않았는지를 긴 검토문 없이 구별할 수 있는가?**

cycle06의 목적→부분 역할→지킬 조건, 필요한 상세 읽기, 준비 편집과 지도 복귀를 재사용 후보로 둔다. 초기 구상 N01과 이번 VS Code 사례는 별도 프로젝트다. 이전 합성 사례의 구성·사건·성과를 새 입력에 이식하지 않는다.

## 실제 입력과 제한
[입력](INPUT.md)과 [고정 patch 감사](STRUCTURE_AUDIT.md). 사람의 목적 요청, 후속 공통화 지시, Copilot Bot의 고정 코드 변경·답변이 있는 공개 기록이다. 이후 두 파일 변경의 되돌림 요청과 PR 미병합 종료도 남는다. 실제 되돌림 완료·실행 성공·CI·제품 반영·다른 AI 세션 인계는 확인되지 않았다.

두 메뉴는 원래부터 공통 계산을 호출했다. 이번은 새 연결 생성이 아니라 입력 검사·경과 시간 계산의 책임을 기존 공통 부분으로 옮긴 변경이다. 보이는 선을 새로 만들거나 공통 계산이 두 화면을 포함/실행한다고 그리면 입력을 왜곡한다. 같은 상태 형식을 넘긴다는 사실을 같은 객체/시점 공유로 바꾸지 않는다.

이번 고정 변경의 읽기 단위는 두 표시 소비부와 공통 계산이다. 이름·보기용 묶음은 해석이며 전체 VS Code의 확정 제품 계층이 아니다. 되돌림 요청은 파일 변경에 대한 요청이지 화면 역할의 삭제가 아니다.

## 병렬 연구와 총괄 통합
- Pro 공간 표현: 서로 다른 분야의 공식 메커니즘 두 개를 확인하고, 동일 대상·기존 관계를 유지하며 책임 이동을 읽히게 하는 의미가 다른 두 대안을 비교한다.
- Pro 시간/출처: 고정 변경, Bot의 보고, 나중 요청을 현재 구현 상태 하나로 합치지 않는 두 대안을 비교한다. 시간순 보고서·상태 배지 확대를 기본 답으로 삼지 않는다.
- Astra High: 확보한 원문을 작은 사실표와 최소 장면으로 구성한다.
- 6.1 Sol High: 관련 세 부분의 고정 patch만 감사한다. 환경 담당은 기존 미리보기·GitHub 접근만 확인한다.
- 총괄: 원문과 적용 추론을 대조하고 같은 입력의 비교 장면을 고른 뒤 Opus에 좁은 구현을 배정한다. 추천의 일치는 사용성 검증이 아니다.

연구는 현재 공식 원문/고정 코드에 근거하고 직접 조작 여부를 따로 남긴다. Dify는 품질 참고이며 실행 흐름을 복제하지 않는다. 설계도구의 버전 비교나 코드 검토 화면에서 유용한 메커니즘만 가져온다.

## 비교 장면
1. 전체에서 목적, 두 화면, 공통 계산을 보고 이번에 바뀐 책임을 짧게 찾는다. 선이 추가되지 않았다는 사실도 유지한다.
2. 한 부분에서 관련 상대와 변경 전후를 살핀다. 사람 요청·코드 변화·Bot 보고는 필요할 때 대조하며 전체 지도를 긴 기록 목록으로 바꾸지 않는다.
3. 이후 되돌림 요청과 미병합 기록을 확인하고, 선택한 범위의 다음 확인/조정 준비를 편집한 뒤 원래 지도 보기로 돌아온다. 과거 요청 사본·현재 준비 편집·지도 보기 상태를 서로 덮어쓰지 않는다.

표현·기록 범위·준비의 의미가 정해진 다음에 조작 합격 조건을 좁게 고정한다. 새 수집기/연결기/실제 AI 실행·대규모 제품 재설계·전체 기능 목록은 이번 범위가 아니다. 이 작은 자료로 큰 지도 조망·혼합 깊이·사람 사용성을 통과 처리하지 않는다.
