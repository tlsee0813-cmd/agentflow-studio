## 조사와 두 축의 비교
[Pro 공간 연구](https://chatgpt.com/c/6ad11f6e-f728-83e8-9d0a-55ba32028487)는 Onshape의 두 이력 비교와 GitHub의 선택 범위 diff를 대조했다. A는 같은 대상 자리에서 책임의 전후를 비교하고, B는 기존 관계가 전달하는 입력의 차이를 비교한다. A를 추천했다.
[Pro 시간/출처 연구](https://chatgpt.com/c/6ad11f92-7fd0-83ec-b658-da441d3df6b5)는 Onshape의 버전/작업공간 구별과 GitHub의 조건부 오래된 승인 해제를 대조했다. A는 확인된 1월16일 변경을 두고 후속 요청을 붙이며, B는 나중 요청을 먼저 보여 준다. A를 추천했다.

모두 현재 공식 문서 조사이며 직접 서비스 조작·사람 사용성 결과가 아니다. [공간 원문 감사](SPATIAL_SOURCE_AUDIT.md), [시간 원문 감사](TIME_SOURCE_AUDIT.md)로 원문의 기능과 우리 적용을 구별했다. Onshape 형상 비교가 코드 책임 이동을 자동 판별하지 않는다. GitHub 승인 해제는 설정과 코드 변경 조건이 있는 승인 처리이며 일반 댓글·과거 관측 전체의 무효화가 아니다.

## 총괄 선택
**공간 A＋시간 A의 시안 하나**를 만든다. 같은 세 부분과 기존 두 호출 관계를 유지하고, ‘변경 전 / 1월16일 변경’에서 내부 역할의 차이를 비교한다. B의 인자 차이는 필요할 때 상세로 읽는다. A/B 구현 비교를 이미 끝냈거나 사람에게 A가 우수하다고 검증한 것은 아니다.

이유는 이번 patch의 핵심이 새 연결이 아니라 이미 연결된 부분 사이의 처리 책임 변화이기 때문이다. 입력 값을 기본 화면에 펼치면 코드 설명이 중심이 되기 쉽다. 다음 행동을 찾는 데 후속 요청이 중요하지만, 요청만 앞세워 실제로 확인한 변화를 숨기는 것도 피한다. **1월16일 코드에서 본 변경이라는 범위와 이후 되돌림 요청의 존재를 기본 화면에서도 짧게 남긴다.**

목적은 ‘추정 가능할 때 다운로드 남은 시간을 알리기’다. 사용자에게 보이는 두 메뉴의 표시 역할과 기존 공통 계산은 전후에 모두 남는다. 옮긴 것은 진행 정보 누락 검사와 경과 시간 계산이며 표시 문구·분기 전체가 아니다. 새 선·새 부품·메뉴 삭제·동작 완전 동일·성능 개선으로 표현하지 않는다.

뒤의 요청과 미병합 종료는 사건 기록이다. 1월21일의 되돌린 구현 지도를 만들어 채우지 않는다. 같은 세 대상을 함께 보는 바탕은 읽기용 묶음이며 파일 트리나 공통 함수가 소유하는 확정 포함 계층이 아니다.

## 부분 조정과 복귀
선택한 부분의 조정 준비는 목적·선택 범위·고정 변경·확인되지 않은 후속 상태를 보존한다. 관련된 다른 부분을 자동 수정 대상으로 확장하지 않는다. 반대로 ‘다른 부분은 맥락’이라는 말로 영향이 없다고 보장하지도 않는다. 공통 계산을 선택하면 두 화면의 표시 영향을 살필 필요는 남는다.

비교 시점 전환은 읽는 내용을 바꾸는 행동이며 코드 복원·과거 요청 재작성·준비문 초기화가 아니다. 준비문 편집과 진입 전 지도의 선택·위치·배율·비교 보기를 따로 보존한다. 후속 기록 안내는 시점을 바꿨다고 사라지지 않는다.

## 선택을 다시 볼 조건
A가 두 메뉴를 없애 새 계산 기능으로 합친 것으로 읽히면 B 또는 표시 방식을 다시 비교한다. 기본 문구가 ‘공통화 완료’로 끝나 최종 상태로 오해되면 기록 범위 표현을 고친다. 입력 검사/경과 계산 외의 모든 판단이 이동한 것처럼 읽히면 이동 영역을 좁힌다. 새 배지를 늘리는 것으로만 해결하지 않는다.
