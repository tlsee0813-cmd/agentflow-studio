새 WORK41 `workspace41_browser.py:158–164`는 이 경로를 세 번 반복하며 매번 복귀 버튼, 6..9 선택 범위/입력 초점, 같은 지도 transform, 마지막 저장 원문 bytes를 검사한다. 정적 원인 수정과 회귀 단언 추가를 확인했으며, 이 문서에서 해당 검사의 실행 통과를 주장하지 않는다.

**초기 보고 정정:** 보존한 `SOURCE_REVIEW_7CB.md`에는 대체 `place-space`가 `sheetOpen=false`로 돌아가므로 “선택 패널을 닫는다”고 적었다. 별도 독립 실행 결과, 해당 PC 조건에서는 `sheetOpen=false`여도 CSS에 의해 패널의 실제 표시가 유지됐다. 초기 결함의 정확한 영향은 **출발 지도 복귀 행동과 원래 sheetOpen 상태를 잃는 것**이다. PC에서 패널이 실제로 사라진다고 단정한 부분은 이 문서로 정정하며 기존 보고 파일은 수정하지 않았다.

## 작업 메모와 카메라 보존

- **작업 메모의 일회성 복원:** `app.ts:331–332`는 work view가 다시 표시되면 전역 `workMemo`를 폐기한다. `resumeWork`는 그 전에 `const memo=workMemo`로 보관하므로 이번 복원의 초점·커서를 잃지 않는다. 다른 경로로 작업 화면에 들어온 경우에는 오래된 펼침 상태가 나중에 재생되지 않는다. 다른 작업으로 `continueTask`하는 경로는 새 작업을 렌더링하면서 오래된 메모를 비우고, 실제 복원에도 project/epoch/task 일치 검사가 남아 있다.
- **PC12 지연 파일 선택과의 관계:** 초기 후보에서는 오래된 workMemo가 나중의 history → work 왕복에서 재적용되어 새로 연 결과 파일 패널을 다시 닫을 수 있었다는 작성자 진단이 전달됐다. 위 폐기는 그 원인 경로를 차단한다. `pc12_browser.py`의 `test_12_delayed_file_reveal_respects_view_departure`는 이번 delta에서 바뀌지 않았다. 실제 UTF-8 선택 bytes, 지연 중 이탈 뒤 focus/scroll/open/entry 보존, 저장 project 불변, 명시 확인 전 비수락 단언을 그대로 유지한다. 따라서 이 실패를 단언 삭제나 숨긴 filepicker를 억지로 클릭하는 변경으로 피한 것은 아니다.
- **선택 pan 후 패널 닫기:** `app.ts:1591`은 자동 이동 전/후 뷰를 탭 메모 `autoPan`에 남긴다. 이동은 x/y만 바꾸고 s는 유지한다. `app.ts:2038`은 닫을 때 현재 카메라가 기록된 자동 이동 결과와 같은 경우에만 이전 뷰를 복원하고 메모를 지운다. 현재 카메라가 달라졌다면 복원하지 않는다. 비교의 구체 조건은 x/y 차이 각각 0.5px 미만, 배율은 정확히 같음이다. project 전환에서는 `resetEphemeral`이 이 메모도 초기화한다. 이 변경은 workspace 저장 위치/배치/관계나 자동 전체 맞춤을 추가하지 않는다.
- 기존 `markOrigin` / `restoreOrigin`의 지도 카메라·선택·접힘·패널 읽기 상태 스냅샷은 유지된다. 새 `fromMap` 진입은 해당 기존 계약을 사용한다. 카메라의 실제 복귀와 사용자가 수동 이동한 뒤 닫기의 결과는 실행 담당의 검증과 구분한다.

최종 `workspace41_browser.py:100–104`는 작업 위치·편집란·복사·저장 요소의 시작이 0 이상이고 **하단도 viewport 안**인지 검사한다. 편집란에는 교집합 높이 **160 CSS px 이상**을 추가해 초기의 “시작 y만 화면 안” 조건을 강화했다. 입력 텍스트·커서 범위·초점·저장 bytes와 다른 부분의 미전송 요청 text/kind/draftTarget/currentTaskId 단언도 남는다.
