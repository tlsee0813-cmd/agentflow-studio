# 31 · 접힌 부분의 기록을 바로 읽기
2026-10-23 KST. 입력·실험 범위이며 제품 수용 선언이 아니다. 현재 실행 순서는 [ACTIVE](../ACTIVE.md), 조사와 실제 Dify 비교는 [다음 흐름 판단](../2026-10-23-viewport-return-30/NEXT_FLOW_REVIEW.md)에 둔다. 29·30의 검증과 병렬로 후보를 준비하되 각각의 실패를 섞지 않는다.

## 사용자 흐름
전체 지도에서 한 부모 아래에 기록이 있음을 봤으면, 그 표시로 해당 범위의 기록을 바로 읽고 필요한 원문이나 작업을 선택한 뒤 같은 전체 지도에 돌아온다. 지금은 부모 카드의 기록 요약이 span이고 별도 정보 패널을 연 뒤 하위 기록을 다시 찾아야 한다.

새 기록 집계나 우선순위를 만들지 않는다. 기존 subtreeSignals와 subtreePanel을 연결한다. 기록된 질문에는 답변한 질문도 있으므로 미답·미결 개수로 바꾸지 않는다. 현재·이전 기준·보류 설명과 이번 탭 갱신은 기존 의미를 유지한다. 표시가 없다고 개발 문제가 없다는 뜻이 아니다.

## 후보
기존 branch-signals 텍스트를 네이티브 버튼으로 만들고, 선택한 부모의 기존 정보 패널 안에서 정확한 이 부분과 하위 기록을 펼쳐 보여준다. 제목·집계·부모 범위·목록은 기존 자료를 재사용한다. 영역 안으로 들어가거나 현재 작업·요청 대상·프로젝트 내용을 바꾸지 않는다. 기존 카드 크기·좌표·접힘·카메라를 유지한다.

기록 버튼을 누른 경우에만 패널의 옛 읽기 위치보다 명시 진입을 우선한다. 기존 렌더·메모 복원 뒤 해당 disclosure를 열고 패널 내부만 움직여 첫 기록과 소유자를 읽게 한다. 닫기·Escape는 살아 있는 해당 호출 버튼으로 초점을 돌린다. 원문이나 작업 읽기에 들어간 뒤의 복귀는 기존 출발점 기록 기능을 재사용한다.

Dify에서 확인한 선택 노드 이동은 명시 동작이며 줌을1로 바꾼다. 이를 그대로 복제하지 않고, 이 후보는 기록 패널 진입과 지도 카메라 이동을 구분한다. Dify 사용성 비교는 동작·표현 비교이며 사람 연구 결과가 아니다.

## 반드시 반증할 조건
- 같은 부모의 패널을 깊이 읽고 해당 기록을 닫아 기억한 뒤 신호로 다시 연다. 옛 memo.open=false/anchor가 새 명시 열기를 덮지 않아야 한다.
- 기존 work/records 출발점이 있는 상태에서 다른 부모 신호로 이동한다. 기존 정보 버튼과 같은 탐색 종료 정책을 적용해 새 부모의 보고가 옛 출발점에 묶이지 않아야 한다. 신호의 닫기 호출자는 origin/located와 별도로 취급한다.
- P 신호→Q 정보/관계/기록→닫기, 프로젝트 전환, 신호 소멸을 확인한다. 오래된 P 호출자로 돌아가지 않는다. 살아 있는 해당 부분 정보 버튼·제목 등 가까운 대체점을 쓰되 카메라 이동·접힘 해제로 호출자를 다시 만들지 않는다.
- 질문·현재·보류·이전 기준·갱신이 함께 있는 부모와 두 단계 아래 소유 기록, 같은 제목의 다른 부모를 구분한다. 실제 report/task 선택 뒤 복귀에서도 소유자와 읽던 줄이 맞아야 한다.
- 1280×720·1440×900에서 실제 pointer와 Tab/Enter/Space로 접근하고 제목·기록 표시·접기 버튼이 겹치지 않아야 한다. 숫자 DOM 존재만으로 가시성·클릭 가능을 통과시키지 않는다. 접근성 이름에 보이는 집계 문구를 포함한다.
- 클릭 전후 현재 작업·요청 대상·수동 네 값·과거 전달·원보고·좌표·소속은 불변이다. 허용한 정보 패널 선택만 따로 확인한다. 작은 지도 배율에서 표시가 실제로 읽히지 않으면 해당 한계나 보류를 명시한다.

## 범위와 종료
