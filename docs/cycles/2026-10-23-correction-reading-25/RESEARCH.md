# 정정 작업문25 — 관측 전 선택
2026-10-23 KST. 현재 배정은 [ACTIVE](../ACTIVE.md), [관측 계약](INPUT.md).

23은 설명 정정을 다음 입력에 전달했으나 기존 수동 작업값은 그대로 보존한다. 이것은 보호 동작이다. 따라서 ‘정정 설명이 있다’와 ‘지금 전달할 작업문을 필요한 만큼 고쳤다’를 사용자가 구별할 수 있어야 한다.

## 코드로 확인한 재료와 가설
6.1 Sol은 정확689c를 읽었다. 소속영역과 작업 읽기 화면에서 현재 설명·사용자 정정 표시·전문/근거/이전 설명을 볼 수 있다. 직접 편집 disclosure에는 네 값을 고치는 기존 입력이 있으며 재정리를 해도 수동값은 우선 보존한다. 현재 작업 카드에는 별도 현재설명 패널이 없다. 설명 정정만으로 stale 안내는 생기지 않는다.

전체 인계 digest가 바뀌면 ‘내보낸 뒤 수정됨/수정한 작업문 복사’가 나올 수 있다. 전체 전달문이 달라진 사실과 일치하므로 문구 자체를 거짓으로 판정하지 않는다. 다만 네값도 고쳐졌다고 읽히는지는 관측이 필요하다. 코드에는 ‘사용자 구상을 바꾸지 않고 이 설명만 고쳐요’와 참고 경계가 있어 새 정책 자동 승격을 명시 주장하지 않는다.

[정정·인계 권위 전용 Pro](https://chatgpt.com/c/6ad9e4e7-e8b4-83e8-b1f4-aebabc8d27b4),3분43초. 코드/문서 조사이며 제품PNG·외부데모 직접 조작은 아니다. 기존 재료로 과업을 관찰하고, 부족할 때만 직접편집 네입력 위에 기존 현재부분 설명의 짧은 읽기 전용 맥락을 재사용하는 후보를 제안했다. 과거H를현재로치환하지 않고 원문·출처는 필요할 때 펼친다.

총괄은 [GitHub의 리뷰 당시 판본](https://docs.github.com/en/pull-requests/how-tos/review-pull-requests/viewing-a-pull-request-review)과 [GOV.UK details](https://design-system.service.gov.uk/components/details/) 공식 원문을 직접 확인했다(2026-10-23 KST). GitHub는 리뷰 당시 판본을 보존하는 원리, GOV.UK는 필요한 핵심과 선택적 상세를 구분하는 원리만 참고한다. 두 자료가 AgentFlow의 특정 한 줄 추가를 증명하지는 않는다.

Pro가 제안한 ‘경로를 알려주지 않는 과업’도 이미 제품을 아는 AI에게 맡기므로 초행 사용자 실험이 아니다. 총괄은 알려진 UI 조작 관측으로 범위를 바로잡았다. 설명30과명시동작7이공존할수있는반례를넣어, 새표현이설명을조건으로승격시키는지확인한다. 수동값자동변경·보고전체제외·새경고는 채택하지 않았다.
