# 84 — 변경 구상의 작성 맥락
## 판단
기준 e39f6697142e891943604883281745c1ff9fb5a0(app=f93b095). UI75·76·78·80·83 수리를 유지한다. 공개73이며 첫 지도77/79/81/82의 실패를 반복하지 않는다.

총괄은 Pro af-authoring-context84의 B안을 아래 경계로 채택한다. native 읽기 검토와 실제 저장 micro PC 왕복에서 초안·커서는 보존되지만 projectInput/PlanAsk에는 작성 당시 선택·보던 범위가 없음을 확인했다. 이는 입력 정보의 공백이며 실제 AI 오답이나 개선 효과를 관측한 결과가 아니다.

## 제품 계약
1. 새 초안의 **첫 본문 편집**에 작성 맥락을 고정한다. 입력 전에는 고정될 선택/범위를 보인다. 단순 열기·탐색·재열기·원문 왕복은 확정 맥락을 바꾸지 않는다. 본문을 비워도 같은 초안의 맥락을 다시 잡지 않는다.
2. 편집기 한 줄에 '작성 맥락: 선택 X · 보던 범위 Y'와 현재 화면 맥락으로 바꾸기/없애기를 둔다. 맥락 없는 작성도 허용한다. 작성 맥락은 지시어 해석을 돕는 참고이며 변경 대상/요청 범위가 아니다. 다른 부분이나 전체 변경을 쓰면 본문의 명시 의도가 우선한다.
3. 기존 초안은 '작성 맥락 미기록'으로 유지한다. 현재 화면에서 소급 추정하지 않는다. 사용자 명시 지정만 새 맥락이 된다. 제거 후 편집으로 재생성하지 않는다.
4. 프로젝트와 선택/범위의 안정 ID, 당시 이름, 시점·자동/명시 지정 방식과 상태를 초안에 저장한다. self는 실제 범위 ID다. 요청별 P01 alias는 영구 ID로 저장하지 않는다. 동일 ID 이름 변경은 이름 변화를 표시하며, 삭제/다른 프로젝트/동명 재생성은 미해결로 남긴다. 복사/가져오기도 ID를 검증해 다른 객체로 재연결하지 않는다.
5. 별도 작성 맥락 요청 필드를 버전 있는 계약으로 보낸다. 기존 studio.plan.1 네 키는 호환 지원하고 새 요청은 studio.plan.2를 명시한다. user evidence/INTENT/제품 사실로 섞지 않는다. 전체 parts는 유지하며 카메라는 보내지 않는다. 안정 ID는 요청 alias로 대응시켜 전송하며 미해결은 명시한다. 기존 바이트·문자·참조 검증을 약화하지 않는다.
6. 분석은 실제 사용한 본문/맥락 스냅샷과 연결한다. 맥락 변경·제거/참조 부재는 결과를 보존하되 이전 기준으로 표시하고 최신 결과의 생성/적용/지도 조작으로 오인되지 않게 한다. 분석 중 변경 후 도착한 응답도 해당한다. 단순 지도 이동은 분석을 오래된 것으로 만들지 않는다.
7. 기존 계획/요청문/반환 관측·원자료·프로젝트와 키를 보존한다. 저장/내보내기 형식 변경은 명시 버전 및 구형 읽기·무손실 보존을 갖춘다. 기존 자동 분석·추가 모델 호출은 만들지 않는다.

## 수용 증거
- 서로 다른 실제 부분에서 같은 '이 부분' 문장: 저장·전송 맥락은 다르고 scope=self의 실 ID를 유지.
- 작성 후 탐색/닫기/근거 왕복/재열기: 본문·커서·고정 맥락 보존.
- A에서 B 또는 전체를 명시: 본문·전체 parts 유지, 범위 제한을 추가하지 않음.
- 분석 중 변경/제거, 늦은 응답: 이전 기준 표시·실행 차단; 제거 지속.
- 기존 초안 편집: 자동 소급 없음.
- 이름 변경/삭제/동명 다른 ID/복사: 동일성 오연결 없음.
- 1280/1440 PC에서 긴 이름·범위·메모가 읽히며 기존75/83 선택·근거 복귀 보존.

코드/오프라인 요청 계약과 실제 모델 효과를 분리한다. 독립 검증 후 새 실제 모델 실험이 필요하면 입력·기준·횟수를 먼저 고정한다. 이 문서는 구현이나 전체 수용의 증거가 아니다.
