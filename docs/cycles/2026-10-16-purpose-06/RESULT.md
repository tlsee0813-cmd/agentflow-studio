## 총괄 판단
**목적 → 선택한 부분의 역할 → 지킬 조건을 짧게 읽고, 관련 위치를 확인한 뒤 읽던 곳으로 돌아오는 표현을 다음 시안의 재사용 후보로 유지한다.** 이번 작은 입력에서는 긴 검토 보고서보다 프로그램 구상으로 진입하기에 적합하다고 판단했다. 이는 총괄과 AI의 사전 평가이며 사람 사용성의 우승안·최종 제품 문법 확정은 아니다.

기본 화면은 ‘소개글을 다시 입력하는 일을 줄인다’는 목적, ‘소개글 재사용’이라는 부분 후보, 담당자의 내용 확인·게시 선택이라는 조건을 앞에 둔다. 정밀한 원문 읽기와 준비문 편집은 다음 단계에 있다. 준비문의 첫 요청도 재입력을 줄일 작은 작업의 정리이며, 조건 검토만 하는 요청으로 바뀌지 않는다. 실제 기본문 PNG를 추가 확보해 이 점을 확인했다.

**입력에 정보가 없다는 것과 실제로 결정되지 않았다는 것을 구별하도록 수정했다.** v0의 ‘아직 정하지 않은 것/방식은 정해지지 않았다’는 단정은 fix1에서 ‘이 입력에서 알 수 없는 것/제시되지 않았다’로 바꿨다. 미결·변경을 보여 주는 제품일수록, 기록에 없는 문제를 만들어 표시해서는 안 된다.

이번에는 새 하위 기능을 억지로 나누지 않았다. 입력이 지지하는 프로그램 부분 후보는 하나이며, 출연자 소개글은 업무 자료, 행사 홈페이지는 옮길 대상이다. 두 맥락 연결은 실행 순서·자동 연동·구현 완료의 증거가 아니다. 이 작은 예시의 성공을 혼합 깊이 또는 큰 지도 조망의 해결로 확대하지 않는다.

## 조사에서 채택한 것과 보류한 것
Pro 두 세션에 목적/역할과 좁은 화면 탐색을 나눠 맡겼다. [의미 원문 감사](PURPOSE_SOURCE_AUDIT.md)와 [탐색 원문 감사](NAVIGATION_SOURCE_AUDIT.md)를 거쳐 ‘이용 장면 속 역할＋지킬 조건’과 ‘맥락을 남긴 단일 지도/읽기 왕복’을 선택했다. 목적 기여 가설은 성과처럼 쓰지 않고, MiniMap·새 SDK·제스처 엔진은 추가하지 않았다.

C4·Miro·Impact Mapping·React Flow·tldraw를 문서/코드로 대조했다. 이번 사이클에서 그 서비스들을 직접 조작해 비교한 연구는 아니다. Miro의 릴리스 우선순위, tldraw의 실제 API와 폭 전환 맥락 등 원문의 범위와 우리 설계 정책을 구별했다.

Pro에는 실제 PNG 3장을 첨부했다. 상단 목적·중앙 역할·보존 조건이 구별되고 작은 구상도로 읽힌다는 정적 AI 평가를 받았다. 반면 편집된 준비문 PNG로 기본 요청을 판단할 수 없다는 지적은 수용하여, 독립 검증에서 **편집 전 기본 준비문**을 별도로 남겼다. Astra의 실제 이미지 검토와 총괄의 GUI 확인도 조작 검사·사람 사용성 결과와 구별한다.

## 독립 관측이 실제로 지지하는 범위
- **원래 지도 보기:** computed matrix의 배율 1.15, P1/X1/X2의 원시 화면 좌표·크기, 지도/본문 스크롤을 기록했다. 두 폭×두 번의 전체 복귀에서 세 대상의 x/y/폭/높이 차이가 모두 0이다. 진입 지도 스크롤은 1440에서 [138,0], 390에서 [24,137]이었다. P1 선택도 유지했다. 출발 초점은 저장 원시값 대조로 확인하며 해당 지도 비교 함수의 별도 단언은 아니다. 화면 밖 좌표 보존은 모든 대상을 한눈에 읽는다는 뜻이 아니다.
- **맥락 대상 접근:** X1→X2→X1을 실제 클릭으로 찾고 대상의 조상/화면 잘림과 표본 hit를 확인했다. 다만 첫 독립 실행의 이 왕복은 읽기 스크롤 0이고 행 좌표를 측정하지 않았다. 이를 뒤의 근거 창 검사와 섞지 않고, 위 별도 addendum을 요청했다.
- **근거 창 반복 왕복:** 실제 휠로 읽기 119px/160px에 도달한 뒤 근거를 열고 버튼으로 닫았다. 창의 실제 제거, 출발 초점, 읽기 스크롤과 조건 상자의 y를 확인했다. 같은 근거를 다시 열어 Escape로 닫았을 때도 창/링크/닫기 버튼 부재와 초점 복귀를 확인했다. Escape 뒤 스크롤 119→119·160→160은 원시값의 별도 파생 관측이며 39단언에 더하지 않는다. **Escape 뒤 조건 상자 y는 측정하지 않았다.**
- **준비문:** 편집 전 값과 실제 기본문 PNG를 남겼다. 작은 작업 요청·담당자 확인/게시 선택·운영 직접 배포 금지의 의미가 유지된다. 독립 검사는 요청 칸 하나를 실제 키 입력으로 편집하고 닫기/재열기·전체 왕복 뒤 보존을 확인했다. 나머지 두 칸의 편집이나 실제 송신·수락은 검사하지 않았다.
- **검사 방식:** 제품 함수나 내부 상태를 호출·변조하지 않았고 실제 휠/클릭을 사용했다. 전체 overflow 조상의 축별 교집합과 viewport를 계산하고 3개 지점의 hit를 기록했다. 이것은 모든 글자의 읽힘·모든 점의 무가림·사람 이해 성공이 아니다. textarea의 실제 값과 PNG를 문자 Range 측정과 구별한다. favicon 404 리소스 기록은 pageerror와 구별해 보존했다.

### 추가 맥락 왕복 감사
고정 addendum은 **16파일 95,659 bytes**, manifest의 payload 15개 bytes/SHA가 일치한다. 기존 증거 변경 없이 새 경로만 추가됐다. Sol이 별도 실행 코드·JSON·로그·종료를 대조했다.

실제 휠로 읽기 위치 100px에 도달한 후 X2 위치를 보고, 390에서는 ‘읽던 곳으로’를 누르며 1440에서는 남아 있는 읽기 영역을 측정했다. 복귀 직후 측정 전 추가 휠이나 위치 보정은 없다.

| 화면 | 읽기 위치 전→후 / 최대 | X2 행 x/y/폭/높이 전=후 |
|---|---|---|
|1440×900|100→100 /119|1063 /503.234375 /355 /80.0625|
|390×844|100→100 /183|16 /514.484375 /358 /80.0625|

행의 네 값 변화는 모두 0이고 출발 X2 버튼 초점·P1 선택·실제 대상/버튼의 잘림 및 표본 hit도 확인했다. 별도 한 실행 **2경로·16 PASS/0 FAIL**, 실제 child/wrapper/launcher exit 0이다. 최초 HTTP body와 파일 전후 SHA도 동일하다. 첫 실행은 변수 이름이 import를 가린 검사 오류로 서버·브라우저 전 0장면/exit 1이었고 원본을 보존했다. 수정은 변수 이름뿐이며 제품·판정 조건 변경은 없다.

따라서 비초기 맥락 왕복의 빈칸은 **X2·100px·두 지정 화면** 범위에서 보완됐다. X1·다른 읽기 위치·폭 전환 전체로 일반화하지 않는다. 새 PNG나 준비/근거 창/전체 복귀 재검사를 추가하지 않았다.

작성자 코드·표현·측정 한계는 [AUTHOR_AUDIT](AUTHOR_AUDIT.md)에 따로 남겼다. 특히 작성자의 배율/중심 측정은 dataset과 계산값이며 computed 렌더 실측으로 부르지 않는다. 작성자 118/182px 행 좌표 관측, 독립 근거 창 119/160px 관측, 별도 맥락 왕복 관측은 서로 다른 경로다.

## 다음에 확인할 하나의 문제
이 입력은 **개발자 합성 초기 구상 N01**이다. 실제 요구 변경·AI 수행/인계 수락·일반 업무 대표성은 확인하지 않았다. 저장소의 기존 평가 패킷 일부에서도 그 출처를 입증하지 못했으므로 실제 기록으로 이름만 바꾸지 않았다.

대신 Pro가 찾고 Astra가 원문 네 종류로 대조한 [외부 실제 기록 후보](NEXT_RECORD_CANDIDATE.md)를 다음 입력 후보로 둔다. 사람이 Copilot에 두 화면의 중복 처리를 모으라고 요청하고, Bot이 고정 변경과 답변을 남긴 짧은 구간이다. 이후 되돌림 요청과 미병합 종료가 있으므로 성공·최종 수용으로 정리하지 않는다. 두 독립 사업 기능의 변경이나 다른 AI 세션으로의 인계를 입증하는 사례도 아니다.

다음 질문은 **‘추정 가능할 때 업데이트의 남은 시간을 알려 준다는 목적을 유지하며, 한 요청이 닿은 두 화면과 공통 부분에서 무엇이 바뀌었고 무엇이 아직 확인되지 않았는지를 긴 검토문 없이 구별할 수 있는가’**다. 사람 B의 공통화 요청은 사업 목적을 바꾼 요구가 아니라 구현 방식에 대한 후속 지시다. 요청·실제 patch·Bot의 완료 주장·나중의 되돌림 요청을 시간과 출처가 다른 기록으로 나눠 먼저 입력을 구성한다. 다음 시안은 그 대조가 필요한 최소 범위로 제한한다. 실행 순서 화살표나 확정 모듈 트리를 새로 만들어 채우지 않는다.

실제 손가락/핀치, 폭 전환 중 상태 유지, 큰 지도 조망, 사람 사용성, 실제 AI 송신·수락과 전체 제품 품질은 남은 한계다. 제품 소스·main·공개 체험판은 이번 연구로 변경하지 않았으며 GUIDE107 HOLD를 유지한다.
