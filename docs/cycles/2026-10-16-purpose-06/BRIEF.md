# cycle06 — 목적에서 한 부분의 역할을 읽기
2026-10-16 · 기준 연구9b4a422f4e46085acb0841e9d9201c7ff86d6b81. 현재 상태는 [ACTIVE](../ACTIVE.md).

## 판단할 질문
코드 이전의 작은 구상에서 사용자가 전체 목적, 선택한 부분이 필요한 이유, 그대로 지킬 조건을 이해하고 확인·조정 준비로 이어갈 수 있는가? 전체 위치 복원과 전체 의미 이해를 구별한다. 좁은 폭에서는 현재 부분과 바깥 상대를 찾는 방식을 함께 비교하되, 모바일을 이유로 큰 화면의 공간 중심 구상을 버리지 않는다.

cycle05의 지도 선택·혼합 깊이·실제 관계·근거 닫기·준비 편집·진입 전 보기 복귀 계약을 재사용 후보로 둔다. 이전 표본의5묶음·6관계·C32 변경 이벤트를 새 자료에 복사하지 않는다. 시안 전체 재설계·제스처/연결기/수집기/실제AI 기반 구축은 이번 범위가 아니다.

## 입력
[입력 분류](INPUT.md). 원본 [QUALITY024 N01](https://github.com/tlsee0813-cmd/agentflow-studio/blob/9b4a422f4e46085acb0841e9d9201c7ff86d6b81/docs/research/quality024/NEW_INPUTS.md#L1-L7): 공연장 출연자 소개글을 홈페이지로 옮길 때 재입력을 줄이되 담당자 확인·게시 선택 뒤 공개하는 조건은 유지한다. 코드/파일 구조는 없고 먼저 만들 작은 작업 정리를 요청한 **개발자 합성 입력**이다. 실제 사람 발화·업무 대표성·요구 변경 기록·실제 AI 수행/인계를 입증하지 않는다.

N02는 별도 독립 프로젝트여서 N01의 변경 후로 연결하지 않는다. 이번은 초기 구상 표본이다. 시간·변경 이력·실행 완료·담당 AI·확정 모듈·자동 연동을 만들어 채우지 않는다. 실제 변경 기록 검증은 별도 남은 한계이며 합성 비교로 완료 처리하지 않는다.

## 나눌 일과 선택 순서
- Pro 목적/역할: 공식 자료2~3개의 목적·사용자 성과·기능 연결 메커니즘을 비교하고 의미가 다른 최대2대안을 제안한다. 원문 사실/AI 해석/미확인 영향의 구별과 맞지 않는 조건을 남긴다.
- Pro 좁은 화면: 공간 개요·선택 상세·외부 상대의 탐색을 최대2대안으로 비교한다. 전체맞춤은 새 보기이고 복귀는 이전 보기임을 구별한다. minimap이 있다는 사실을 이해 성공으로 쓰지 않는다.
- Astra: 입력 출처/범위 확인 완료. 목적과 보존 조건을 사실로 읽되 구성 이름/포함은 제안으로 둔다.
- Sol: 기존 엔진의 재사용 경계 확인. 조사 결과가 오면 필요한 공식 원문/고정 코드만 감사한다.
- 총괄: 자료 대조→공통 내용과 비교 장면→잠정 선택. 그 뒤에만 Opus에 작은 시안을 배정한다. 모델 간 동의는 검증이 아니다.

## 비교에서 보려는 세 장면
1. 첫 구상: ‘무엇을 덜 하려는 프로그램인가’, 어떤 부분이 그 목적에 연결되는가. 모든 기능을 구현 목록으로 바꾸거나 지도 관리를 숙제로 만들지 않는다.
2. 한 부분: 맡길 범위와 유지할 조건을 함께 읽고 원문/해석을 필요할 때 확인한다. 관련 상대를 실제 영향·구현 완료로 확대하지 않는다.
3. 준비와 복귀: 직접 고친 준비문을 유지하면서 들어오기 전의 선택·깊이·위치·배율로 돌아온다. 좁은 화면에서도 목적/부분 역할/보존 조건에 실제 접근할 수 있는지와 한눈에 이해 여부를 구별한다.

표현 두 개가 필요하면 같은 입력과 대상/관계를 공유하게 한다. 구현 전 합성 조건과 기대 정보를 먼저 고정한다. 사람 사용성은 사용자의 후속 참여와 별도이며 AI 역할 평가와 실제 조작 관측을 분리한다. 연구 기준·작성자 산출물·실패·독립 증거는 GitHub 고정 링크로 공유한다.
