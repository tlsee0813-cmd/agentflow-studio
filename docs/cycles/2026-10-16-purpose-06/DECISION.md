## 조사와 총괄 판단
[Pro 목적/역할](https://chatgpt.com/c/6ad11f6e-f728-83e8-9d0a-55ba32028487)은 C4의 바깥 맥락, Miro의 이용 장면, ImpactMapping의 목적 기여 가정을 비교했다. A ‘목적←기대 행동←기능 후보’와 B ‘이용 장면 속 역할＋지킬 조건’을 제시했고 B를 우선 추천했다. 모두 문서 조사이며 직접 조작 결과가 아니다.
[Pro 좁은 화면](https://chatgpt.com/c/6ad11f92-7fd0-83ec-b658-da441d3df6b5)은 A 위치윤곽 동시 제공과 B 맥락을 남긴 단일 지도/본문 왕복을 비교했다. N01은 작고 구조 정보가 제공되지 않았으므로 B부터 추천했다. 문서/코드 조사이며 직접 조작을 하지 않았고 이전390 PNG 열람도 실패했다. 두 추천의 일치는 사용성 검증이 아니다.

총괄은 **B 역할 설명＋B 명시 왕복의 시안 하나**를 먼저 만든다. A를 동시 구현하지 않는다. 목적 기여 가설은 필요할 때 제안 이유로 읽으며 성과로 주장하지 않는다. MiniMap·새 SDK·제스처 엔진은 지금 추가하지 않는다. 공식 메커니즘을 복제한 것이 아니라 [의미 원문 감사](PURPOSE_SOURCE_AUDIT.md)와 [탐색 원문 감사](NAVIGATION_SOURCE_AUDIT.md)의 경계를 지킨 적용이다. Miro는 릴리스 우선순위를 실제 다루므로 ‘개발순서와 무관’이라고 쓰지 않는다. tldraw의 실제 API는 zoomToFit 등이며 우리 native scroll/선택 보존 규칙은 그 소스가 보장하지 않는다.

## 입력 때문에 줄인 구성
Astra 검토를 수용해 **프로그램 부분 후보는 ‘소개글 재사용’ 하나**로 둔다. ‘받은 글 다루기/옮길 내용 준비’ 자식을 억지로 분리하지 않는다. N01에 없는 접수·저장·편집 구현을 암시하거나 혼합 깊이 성과를 만들기 쉽기 때문이다. 깊이를 포기한 제품 방향이 아니라 단일 작은 입력에 적정한 해상도다. 혼합 깊이는 앞선 표본의 별도 증거로 남는다.

중심 후보의 역할: 홈페이지로 옮길 때 받은 소개글을 다시 쓸 수 있도록 돕는 부분을 제안한다. 줄이려는 일은 재입력이다.
- 출연자가 낸 소개글: **업무 자료**. 프로그램 부분·수신 연동이 아니다.
- 행사 홈페이지: **옮길 대상**. 구현 모듈·자동 게시 연결이 아니다.
- 두 맥락 연결: ‘활용할 원자료’ / ‘내용을 옮길 대상’. 실행 순서·데이터 통신 성공이 아니라 제안의 관계를 설명한다.
- 담당자의 내용 확인＋게시 선택 뒤 공개: **유지할 업무 조건**. 구현된 승인 모듈/새 승인 절차가 아니다.

이 구별을 카드 종류·공간·짧은 문장으로 드러낸다. 모든 상자에 같은 기능 모양을 쓰거나 접수→처리→승인→게시 순서도로 만들지 않는다. 요구/제안/모름 배지를 모든 줄에 반복해 해결하지 않는다.

## 잠정 선택을 바꿀 조건
역할 설명이 자동 실행 흐름으로 읽히거나, 목적과 보존 조건을 찾는 데 긴 보고서를 읽어야 한다면 문구·배치를 수정한다. 실제 큰 지도에서 동시 위치 비교가 필요하고 현재 왕복이 이를 방해한다면 위치윤곽 후보를 다시 비교한다. 이번 작은3대상 배치의 접근 성공을 큰 지도 조망 해결로 확대하지 않는다.

## 세 비교 장면
1. 첫 구상: 전체 목적과 제안 부분의 역할, 자료/대상 구별. 실제 변경·완료·효과가 없는 입력이라는 경계.
2. 부분 읽기: 유지할 게시 조건과 아직 정하지 않은 적용 방식을 읽고, 좁은 폭에서 맥락 대상 위치를 명시적으로 확인한 뒤 읽던 곳으로 돌아오기.
3. 작은 계획 준비: 자신의 문장을 편집·보존하며 운영 배포/자동 게시 지시로 바뀌지 않고 진입 전 지도 보기로 돌아오기.
