# 보고·현재 구상 연결16 — 실제 제품 구현 계약
2026-10-16. 현재 배정은 [ACTIVE](../ACTIVE.md). 제품 기준 a5a48a715c41d1f8ea928af48a33d264c295a128. [표본 구분](INPUT.md), [독립 실패 기준](ACCEPTANCE.md).

## 채택 흐름
지도/영역에서 요청을 연다 → 그 영역의 현재 사용자 구상을 확인한다 → 해당 요청에 연결된 보고를 직접 고르고 필요하면 전문을 펼친다 → 필요한 경우 이 영역의 새 요청을 준비하거나 기존 입력을 이어 쓴다 → 출발 보기에 돌아온다.

기존 renderTaskView를 보완한다. 별도 보고 전용 화면/큰 편집 대시보드를 신설하지 않는다. 보고를 읽는 것, 기존 작업을 편집하는 것, 새 요청을 쓰는 것을 구분한다. 보고 수신은 구상 변경·채택·성공·외부전송을 의미하지 않는다. 자동 요약기가 없으므로 'AI가 읽은 변화/권장 수정' 같은 생성 결과를 만들지 않는다.

## 처음 읽는 정보와 상세 단계
- 영역 이름/선택 요청을 짧게 식별한다. TASK 번호와 검사 배지를 제목 주인공으로 삼지 않는다. 기존 상태/출처 사실은 보조 위치에 보존한다.
- **현재 영역 구상**: 실제 Area.note를 기존 areaIdea로 재사용한다. 당시 요청 구상 사본과 혼동하지 않도록 현재 구상이라고 표기한다. 긴 구상은 기존 앞부분+전체펼침; 빈 구상은 빈 것으로 표시한다. 첫 화면에서 직접 편집칸을 늘리지 않는다.
- **읽을 보고**: 해당 요청의 실제 반환 경로에 속하는 보고 목록을 짧은 선택 컨트롤로 표시한다. 기존 taskTitle/출처종류/시각을 활용해 구분하고 추론 요약은 만들지 않는다. 0개는 간결한 빈 상태, 1개도 명시 선택, 여러개는 선택한 한 건만 전문 접근. 제목이 같을 때 시각/순서 등 실제 정보로 구별한다. 원문 전체를 전부 쌓아놓지 않는다.
- **선택한 보고**: 선택된 것의 실제 출처와 '외부 원문 · 앱 미검증'을 낮은 강조로 표시한다. 짧은 보고는 실제 전문, 긴 보고는 앞부분 최대6줄 정도를 기본 표시하고 '위는 앞부분'임을 밝힌 뒤 전문을 명시적으로 펼친다. 의미 요약/핵심 변화로 부르지 않는다. 현재 구상과 보고를 동시에 읽을 수 있도록 PC 본문에서 나란한 구성을 우선하되 글씨를 줄여 맞추지 않는다. 연결 경로·이전 보고/요청 원문·작업문·기준 등은 필요할 때 연다. 이미 '확인할 일'에서 특정 보고를 골라 들어온 경우 그 선택을 유지한다.
- **다음 동작**: 새 요청 준비/기존 미전송 입력 열기의 실제 행동 하나를 명시한다. 기존 작업 편집은 별도 보조 행동으로 유지한다. 정보 설명을 긴 경고문으로 쌓지 말고 상태가 필요한 자리에서 짧게 알린다.
PC1280×720·1440×900에서 현재 구상/고른 보고/다음 동작의 관계를 먼저 파악할 수 있도록 맞춘다. 읽기 폭·여백·상세 접기는 기존 PC12/13 스타일을 재사용한다. 홈15 3열 비율을 훼손하지 않는다.

## 보고 선택의 정확성
선택 단위는 반환 Task다. 그 Task의 모든 유효한 sourceIds에 출처 종류별 전문 접근을 제공한다. pointedSection의 sourceIds[0]만 읽는 구현을 그대로 확대하지 않는다. 누락 source를 다른 source로 대체하거나 조용히 생략하지 않는다.

pointedReturn/returnPath의 실제 소속 검증을 사용한다. 요청→중간보고→선택보고 사슬을 유지한다. 후속 보고를 직접 반환이나 최신 보고로 바꾸지 않는다. 없는/foreign 보고는 부재·불일치를 알리고 임의 보고를 대신 선택하지 않는다. 오류 후 사용자가 다른 실제 보고를 명시 선택할 수는 있다. 보고를 고르거나 원문을 접고 펼치는 동안 원래 지도 origin을 덮어쓰지 않는다. 보기 메모리는 기존 정책을 따르되 프로젝트 저장 모델을 추가하지 않는다.

## 버튼이 실제 결과를 말하기
미전송 입력이 없고 유효한 활성 영역이면 '이 영역에 새 요청', 보조로 실제 영역 대상을 알린다. writeInArea의 기존 request 준비를 재사용한다. 새 Task 생성·송신·보고 복제·current 작업 전환은 하지 않는다.

미전송 입력이 있으면 버튼부터 '작성 중인 요청 열기/보고 열기/관찰 열기'처럼 실제 종류를 말한다. 옆에서 기존 대상/연결 예정 유지 사실을 짧게 알린다. 클릭 후에만 다른 영역 입력을 열었다고 알리는 UX로 끝내지 않는다. 입력 text/kind/target 및 selectedReturnTaskId를 그대로 유지한다.
- draftTarget null은 현재 작업을 따르는 것, {area:null}은 명시적 영역 없음이다. 이를 같은 문구로 합치지 않는다.
- 보고/관찰 대상은 기존 returnPreview/returnChoiceRequired 판정과 일치시킨다. 선택 보고를 새 입력의 연결 대상으로 몰래 대입하지 않는다.
- 보관된/없는/미지정 영역에서 유효한 새 영역으로 대체하거나 보관을 해제하지 않는다. 기존 미전송 입력이 있으면 그 입력 열기는 가능하되 영역 새 요청과 구분한다. 새 요청을 만들 수 없을 때 간결한 이유를 제시한다.
- 같은 영역에 쓰는 새 요청을 '이 보고에 답장/이 보고에 연결해 재요청'이라고 부르지 않는다. 이번 범위는 저장된 보고↔새요청 관계를 추가하지 않는다.
- continueTask의 기존 정책(A 읽기, 현재 R이 A의 직접 보고인 경우 R 유지, 다른 현재 작업이면 명시 A편집)을 변경하지 않는다. 주 행동과 혼동되지 않게 구분한다.

## 복귀·저장 경계
origin이 있으면 기존 returnToOrigin을 사용해 view/selection/pan/zoom/disclosure/호출초점과 읽던 위치를 되찾는다. 새로 저장한 초안·수동편집·current 선택을 과거 스냅샷으로 되돌리지 않는다. origin 없는 직접 진입은 일반 '전체 공간으로' 이동을 제공하며 출발점 복원이라고 약속하지 않는다. 저장대기/이탈보호/다른탭 변경 보호를 유지한다. 사용자 실제 자료를 fixture로 바꾸지 않는다.

## 범위·산출·검사
실제 app/continuity 제품 코드와 좁은 검사만 변경한다. app.ts/styles.css 및 필요 검사 파일이 예상 범위다. 기존 UI/타입/선택 함수 재사용. 데이터schema·provider/server·새 의존성·홈재설계·관계/계층/자동입력엔진·GUIDE107 실제 AI 실행은 제외한다. 범위상 필수 수정이 있으면 근거와 함께 보고한다.

[ACCEPTANCE](ACCEPTANCE.md)의 실패 중심 장면을 구현·검사한다. 기존 spatial102/PC12 검사에서 의도적으로 바뀐 표시 계약은 좁게 갱신하고, 보존해야 하는 대상/출처/복귀 보호를 느슨하게 바꾸지 않는다. 작성자 검사·독립 검사·시각 판단을 분리한다. 작은 diff, 정확한 기준 SHA/변경파일 목록, 실제 종료코드·재현법, PC 대표PNG 최대4, SHA256 manifest를 ZIP으로 전달한다. 원본·실행증거는 GitHub delivery의 새 경로로 게시하고 총괄이 제품 branch/PR/CI/통합을 담당한다. 로컬 ZIP만으로 완료하지 않는다.
