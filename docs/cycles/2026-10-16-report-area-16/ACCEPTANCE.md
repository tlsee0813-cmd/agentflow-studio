# 보고·현재 구상 연결16 검증 기준
2026-10-16. 구현 전 독립 기준. 작성자 통과와 독립 실행 결과는 별도로 기록한다. 현재 상태는 [ACTIVE](../ACTIVE.md).

PC1280×720와1440×900에서 핵심 왕복을 검사한다. 데이터 오류의 모든 변형을 양폭에서 기계적으로 반복할 필요는 없다. 390은 접근 가능한지 최소 확인한다. 실제 사용자 데이터 대신 격리 fixture를 쓴다.

1. 과거 요청 구상과 현재 Area.note를 다르게 설정했을 때 현재 구상을 정확히 표시한다. 자동 note 변경이 없다.
2. 다른 currentTask, 서로 다른 수동 필드·미전송 종류/본문/대상을 설정한다. 구상 읽기·보고 선택·원문 펼치기만으로 persisted project/current/manual/draft/target이 바뀌지 않는다.
3. A의 R1/R2를 명시 선택한다. 선택 전 최신 보고를 자동 선택하지 않으며 선택 뒤 다른 보고를 섞지 않는다. report Task의 모든 sourceIds에 접근 가능하다.
4. 없는 ID와 다른 요청 B에 연결된 실제 RB를 각각 선택한 stale/foreign 경로에서 오류를 알리고 다른 보고로 대신하지 않는다. source 누락도 조용히 숨기지 않는다.
5. 긴 구상·긴 보고 끝의 구별 문장이 실제 펼친 화면에서 읽힌다. 접으면 실제 본문·공간이 닫힌다. 단순 open 속성/textContent만으로 판정하지 않는다.
6. 입력이 비어 있고 활성 영역이 있는 경우 새 요청을 그 영역에 준비한다. current 자동전환/Task 생성/보고자동삽입/외부송신/AI실행이 없다.
7. 다른 영역 B의 미전송 요청이 있으면 클릭 전 B 대상 유지 안내를 보여주고 본문·종류·대상을 유지해 원래 입력을 연다. null(현재 작업 따라감)과 {area:null}(영역없이)을 구별한다.
8. 미전송 보고/관찰 입력과 연결 예정 작업을 유지한다. selectedReturnTaskId를 포함해 강제 request 전환/재대상화/본문 삭제가 없다.
9. A를 읽되 현재 R(parent=A)인 경우 기존 편집 continue는 R 유지, 다른 RB인 경우 기존 규칙대로 A를 선택한다. 새 요청 동작이 이 정책과 섞이지 않는다.
10. 보관된 영역/영역 미지정 요청에서 새 요청 대상이 임의 활성 영역으로 대체되지 않는다. 보관을 자동 해제하지 않는다.
11. 지도에서 비초기 배율·팬·선택·펼침·스크롤을 만든 뒤 보고 읽기→입력 준비→복귀한다. 실제 matrix, 카드 rect, 호출초점/viewport위치, disclosure를 추가 focus/scrollIntoView 전에 측정한다. origin 없는 직접 진입은 허위 복귀를 약속하지 않는다.
12. 영역 화면의 긴 구상을 펼친 뒤 아래 요청에서 출발해 초안/명시 수동편집을 저장하고 복귀한다. 호출 위치를 되찾되 저장한 새 값/current를 과거 값으로 롤백하지 않는다. 출발 영역 소실 시 명시 fallback, 다른 영역 자동선택 없음.

시각 판단은 검사 수와 분리한다. 현재 영역 구상·선택한 보고·실제 다음 동작을 먼저 읽을 수 있어야 하며 긴 원문/연결 경로/작업문 조건이 첫 화면을 덮지 않아야 한다. source 배지·검사 숫자를 주인공으로 삼지 않는다. 실패 수집 뒤 child 종료는 비정상이어야 하며 pageerror/필수경로 미완주를 통과로 포함하지 않는다.

표본은 실제 보고 재서술+합성 사용자 조건임을 fixture/결과에서 구분한다. 이 검사는 PowerToys 실행 성공이나 실제 인계 수락, 사람 사용성 연구를 입증하지 않는다. Dify 비교와 AI 역할별 사전 평가는 사용자 지시에 따른 검토 방법으로 별도 이름을 쓴다.
