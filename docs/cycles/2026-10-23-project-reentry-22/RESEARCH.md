# 재진입 관문 — 선택 근거
2026-10-23 KST 사전 조사. 구현 결정이나20/21 수용 선언이 아니다.

전체목적 검토(Astra High)는 재진입 위치 판단, 잘못된 결과의 후속 인계 권위, 상세에서 다음 행동 선택의 세 후보를 비교했다. 총괄은 홈/공간지도/변화/후속요청을 한 흐름으로 다시 확인하는 재진입 관문을 우선한다. 정정 권위는 남은 중요한 후속 후보이며 긴 상세의 읽기 부담은 실제 관측에서 함께 기록한다. 단순 버튼의 fold 안팎만으로 전체 경험을 판정하지 않는다.

[주제별 Web Pro](https://chatgpt.com/c/6ad9e588-d3e0-83e8-bdd6-660ab76650a7)의 제안을 총괄이 공식 원문과 대조했다.
- [Figma Compare changes](https://help.figma.com/hc/en-us/articles/15023193382935-Compare-changes-in-Dev-Mode)는 마지막 열람 이후 수정 여부와 선택한 버전 사이의 차이, 바뀐 레이어의 위치를 연결한다. 우리 제품에서 무엇과 비교하는지 없는 변화 표시를 새것으로 읽게 해서는 안 된다는 참고다. Figma의 유료기능을 사용/구매한 것은 아니다.
- [Linear Inbox](https://linear.app/docs/inbox)는 읽음/미읽음을 개별 이슈의 상태와 별도의 알림에 둔다. 우리 질문/보류/후속없는 보고 수를 unread 수로 바꾸지 않는 기준이다. 새 알림함을 복제하기로 한 결정은 아니다.
- [VS Code Source Control](https://code.visualstudio.com/docs/sourcecontrol/overview)는 바뀐 파일, 버전 diff, 파일 이력을 각각 다룬다. 원문에서 제공하지 않는 열람 기준을 추정하지 않는다. 코드diff를 사용자 프로그램 의미의 자동차이로 바꾸지도 않는다.
- [Dify Quick Start](https://docs.dify.ai/en/quick-start)는 AI 실행 workflow의 구성·시험 흐름이다. 목적과 실행 상태를 우리의 프로그램 부분·사용자 판단/미결과 동일하게 취급하지 않는다. 공간 맥락을 유지하는 패널의 비교 기준만 계속 사용한다.

이번 비교는 공식 문서/코드 대조이며 새 외부서비스 조작 완료를 뜻하지 않는다. 직전21의 Dify 제한 노드추가 메뉴 조작을 재진입 실험으로 재명명하지 않는다.

총괄은 Pro의 홈 이탈 중 B/C를 넣는 제안을 그대로 쓰지 않는다. 현재 다른탭live는 남은 공백이므로 정상 UI 준비 후 홈왕복을 쓴다. 모든부분순회=실패나 B/D우선순위 강제도 채택하지 않는다. 오래된 미결이 실제로 더 중요할 수 있다. 판단 이유와 현재/보류/시간기준 구별, 반복재구성 부담을 관측한다. 정직하게 새것인지 알 수 없다는 응답은 기능오류가 아닌 제품경험의 한계로 분류한다.
