# 99 화면 연결 밖의 작업 소유권

**판정: 현재 실행 경로는 내구 비동기 작업을 지원하지 않는다. 다음 구현의 소유자는 기존 PC 로컬 Node로 한정한다.** 브라우저는 프로젝트와 명시 반영을 맡고, Node는 별도 작업 기록·실행·취소·결과 보관을 맡도록 설계한다. 이는 새 구현 방향 선택이며 구현·실제 장기 생성·제품 수용 결과가 아니다. [최소 증거](MANIFEST.json).

## 왜 다음 범위인가

97은 entry별 요청·취소·화면 이동·ready 반영을 구현했지만 슬롯과 원 MapInput/응답은 메모리에만 남는다. 창을 새로고침하면 회수할 작업 ID가 없다. 기존90초 실험의 실패를 지우지 않고, 화면 응답성과 생성 완료 예산을 별도 제품 계약으로 다룰 수 있는지 확인했다.81 Pro 기록은90초를 당시 새 제안이라고 명시한다. 제공 근거에 사용자 직접90초 요구는 없지만 이를 모든 과거 한도의 최초 기원이라고 단정하지 않는다.

## 확인한 경계

| 경계 | 현재 코드 | 다음 책임 |
|---|---|---|
| 접수 | map-run의 메모리 슬롯과 단일 POST | 내구 기록 후 operation receipt |
| 실행 | Node res.close→Request.signal→provider abort | 접수 연결과 실행 controller 분리 |
| 새로고침 | 작업·ready 재조회 없음 | 원 귀속의 같은 작업 조회, 재생성 없음 |

| 서버 재시작 | 호출·ready 복구 없음 | ready 복구, 진행 중은 interrupted·자동 재호출 금지 |

총괄은 `server/app.mjs:26,35`, `server/studio.mjs:109,204`, `client/map-run.ts:61,92`, `shared/storage.ts:225–233`, Worker와 배포 bindings를 직접 대조했고, 독립 SolHigh는 진입점·launcher·저장/적용까지 추적했다. 읽기 전용 소스 근거이며 실제 장애 주입 또는 플랫폼 능력 검사가 아니다.

## 선택한 구현 경계

기존 Node launcher는 브라우저와 별도 프로세스를 시작하므로 외부 서비스·계정·머신 없이 작업 소유자를 구체화할 수 있다. 현재에 journal이 있다는 뜻은 아니다. 공개 Worker는 fetch passthrough이며 배포 구성에 작업 저장/실행 binding이 없다. 플랫폼 자체의 지원 가능성은 조사하지 않았다. Worker에 같은 기능을 제공한다고 표시하거나 전역 Map으로 내구성을 대신하지 않는다.

다음100은 로컬 작업 프로토콜과 journal을 단일 작성자가 구현하고 독립적으로 검증하는 범위다. 원자료·ask와 entry/project/lifecycle·prompt/model/hash·안정 reading ID를 결속한다. JS Map을 가진 MapInput을 무작정 JSON 복사하지 않으며, 복구한 입력으로 기존 인용·지도 변경·seq 관문을 유지한다. 접수 응답을 잃어도 같은 작업 ID를 조회하고 중복 provider 요청을 만들지 않아야 한다.

명시 취소는 먼저 내구 terminal 상태를 기록하고 실행 abort를 시도한다. 늦은 완료가 취소를 덮을 수 없다. 원격 연산·과금 중단을 보장한다고 표시하지 않는다. 프로젝트 저장 후 ack를 잃으면 저장된 reading ID+hash+귀속으로 이미 반영됨을 판정하고, 두 저장소가 원자 transaction이라고 주장하지 않는다. ready 결과는 확인 전 삭제하지 않는다.

Node 재시작에서는 ready 회수와 진행 중 interrupted 처리를 보장할 대상으로 삼는다. PC가 꺼진 동안 계산이 계속된다는 약속은 하지 않는다. 보관 경로·원자 기록/복구·회수 권한·용량/보관 한도는 구현 전 계약에서 고정한다. 키와 private 원자료를 공개 증거/백업에 섞지 않는다.

## 변하지 않는 관문

이번 선택은 시간 한도 확대가 아니다. 기존90초/model/token 설정을 유지한 채 합성 공급자로 접수·취소·재시작·결과 회수·명시 원자 반영부터 확인한다. 새 모델·provider·CLI 경로·자동 재시도·계정 전환·환경 재설치는 선택하지 않았다. 별도 장기 생성 예산은 그 후 근거를 갖고 사전 결정해야 한다.

89/92/96의 기존 실패는 그대로이며,90초 이후 완결 시점이나 의미 품질은 미관측이다. 작업이 오래 살아 있거나 결과가 회수된다는 것은 첫 지도 Q02/Q06 의미 수용이 아니다. 전체 map.6·핵심 조건/부정/예외·원자료 보존 및 인수인계5/8 관문을 유지한다. 공개73·UI75/693d0c7·97·98과 기존 작업 보존, 목표active.
