## 선택

- 홈은 제목·실제 프로젝트·시작 행동이 먼저 읽히도록 정렬한다. 빈 상태는 약560~640px의 간결한 시작 영역 안에 새 프로젝트/예제 둘러보기의 정렬된 두 행동을 둔다. 백업 불러오기는 보조 행동이다. 실제 프로젝트가 있으면 카드 grid와 보조 예제 진입을 사용한다. 장식용 큰 hero와 가짜 프로젝트는 추가하지 않는다.
- 지도는 탐색 영역, 연속된 canvas, 붙어 있는 선택 패널로 구성한다. 지도 바깥의 중첩된 둥근 상자를 제거한다. 기존 220px 탐색/300px 패널과 240×180 노드 좌표 계약을 우선 보존한다. 정확한 화면 비율은 실제 표시로 판단한다.
- 작업은 소유 작업·제목·편집 행동·본문 순서로 읽히게 한다. 반복 안내와 큰 빈 입력 상자가 화면의 주인공이 되지 않도록 한다. 초안, caret, 출발 지도·페이지 위치 복귀를 보존한다.
- 글자 역할과 간격을 공통 토큰으로 묶는다. 본문 약14/22, 작업문15/24, 이름16/24, 보조13/20을 출발점으로 실제 한글을 확인한다. 작은 글자와 낮은 대비로 정보를 숨기지 않는다.
- 흰 내용 면과 중립 배경, 한 가지 절제된 강조색을 사용한다. 고정 셸과 붙은 패널은 평평하게, 조작 요소와 내용 카드는 작은 radius를 사용한다. 기본 그림자는 줄이고 떠 있는 메뉴 등 필요한 층에만 사용한다. 아이콘은 동일한 SVG 크기·획·정렬을 사용한다.
- CSS 말미에 또 override를 추가하지 않는다. 실제 제품인 `app/continuity`의 기존 규칙을 통합한다. 원문·미검증·예제 비저장 사실은 보조 위계로 남긴다.

## 수용 판단

색만 바꾼 후보, 큰 빈 공간과 잘린 구조가 함께 존재하는 지도, 옅고 작은 안내가 핵심 정보를 대신하는 화면, 편집 위에 반복 안내가 쌓이는 후보는 반려한다. 같은 데이터·선택·카메라의 홈/선택 지도/편집 전후를 1280과 1440 PC에서 직접 본다. 1280의 복귀 안내가 지도를 밀어내는 반례와 실제 초안·caret·예제 저장0을 독립 확인한다. 보기 좋은 캡처를 위해 카메라나 데이터를 바꾸지 않는다.

작성자 결과, 독립 실행, 총괄 화면 판단, 미실행을 분리한다. 최종 통합 SHA의 양OS CI 성공과 공개 표시 확인 전에는 수용본으로 배포하지 않는다. 이후 정확 SHA·검증·남은 한계를 별도 짧은 수용 기록에 적는다.

첫 working-tree 후보의 홈/지도/편집 원본 PNG를 총괄이 직접 읽었다. 지도는 연속 표면과 글자 위계가 개선되어 방향을 채택했다. 홈의 넓은 빈 상자와 이름 없는 네 사각형 미리보기는 반려했다. 작업의 반복 소유 안내는 핵심 한줄과 접근 가능한 상세로 정리하도록 후속2를 전달했다. 이 화면에는 아직 고정 SHA가 없으므로 실행 수용 증거로 사용하지 않는다.
