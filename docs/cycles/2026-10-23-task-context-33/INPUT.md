## 합격·반증 장면
PC1280×720를 먼저,1440×900을 별도 반복한다. 읽는 요청02·현재04·다른 부분의 draft를 유지한 채 reader를 읽고, 명시 이어가기 뒤만 대상이 바뀌어야 한다. 같은 요청의 현재 보고를 유지하는 양성 경계도 검사한다.

바로이동 뒤 실제 N 입력과 기존 저장 동작에 접근한다. 섹션 제목만 보이거나 focus만 옮기고 입력이 가려지면 실패다. N만 명시 수정하며 U/S/C·다른 작업·draft·원문·과거H가 같아야 한다. 일반 복사와 파일 결과용 인계는 구별돼야 한다.

파일 선택만 한 순간의 current/draft/보고/과거H는 변하지 않아야 한다. 정확 파일 대상과 H·선택 상태를 볼 수 있고, 당시 인계를 펼쳤다 돌아와도 선택을 반복하지 않아야 한다. 명시 가져오기 후 기존 수신 정책을 유지한다. 비동기 중 다른 프로젝트/화면 전환, 오류 파일, 오래된 선택, 긴 보고의 접근·초점 가림을 실제 경계로 점검한다.

원본에도 같은 신규 검사/관측을 적용해 무엇이 실패했는지 남긴다. 클릭 수나 문서 높이 감소만으로 사용성 통과를 선언하지 않는다. 작성자 static·독립 브라우저·AI 역할 사전 점검·정확 최종CI를 구분하며 사용자의 기준은 목적 차이를 지킨 Dify 비교다.
