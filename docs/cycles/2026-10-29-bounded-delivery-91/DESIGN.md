# 91 제한 시간 안의 첫 완결 지도

기준은4a30e485/app7beb, runtime2999다. 공개73과 UI75 수리, 기존 저장·키·미커밋 작업을 유지한다.89의 micro 판정 정정과76의 비차단 API 표현 한계를 그대로 적용한다. 보류한90 API 경계 초안을 재개하는 작업이 아니다.

## 목적과 차이

76의 DeepSeek는 실제 지시에서 미완결,89의 Codex CLI는 Zephyr에서 시간 초과였다. 서로 다른 시점의 관측이므로 성공 확률이나 동시 실행 성능을 뜻하지는 않는다. 다만 같은90초 동안 두 경로를 각1회 시작해 먼저 완결·계약·적용 전 검사를 통과한 응답 하나만 선택하는 전달 가설을 검토할 근거는 된다.

사례별 경로를 고르거나 사용자가 자료 종류를 분류하게 하지 않는다. 두 응답의 의미를 투표·비교·부분 결합하지 않고, 실패 출력을 고치거나 재호출하지 않는다. 시간 한도도 늘리지 않는다. 빠른 형식 유효 응답의 의미가 나쁘면 그대로 실패다. validator는 의미 검토자가 아니다.

## 고정 조건

- 같은 원자료·동일 ask·기존map6 FIRST 지침. DeepSeek 기본 enabled/low/16384/90초, CLI 기존 Sol High wrapper를 그대로 쓴다. CLI scaffold 차이는 별도로 기록한다.
- 공통 monotonic90초. 시작·완결 확인·JSON/계약 검증·private 적용 가능성 판단까지 포함하고 어느 경로에도 새로운90초를 주지 않는다.
- 두 경로 최대 각1 invocation. CLI 내부 전송 재시도·취소 후 원격 과금을 이 수와 같다고 주장하지 않는다.
- 빠른 실패/무효는 다른 경로를 취소하지 않는다. 첫 적격 응답을 선택한 뒤 loser에 취소를 전달한다. terminal 뒤 응답은 무시하고 선택·저장 사본은 하나만 남긴다.
- caller취소·공통timeout·둘 다 실패는 winner 없이 끝낸다. 구조유효해도 현재 고정 프로젝트에 적용할 수 없는 응답은 선택하지 않는다. 이것은 의미 필터나 실패 출력 수선이 아니다.
- CLI는빈임시폴더/read-only/사용자config미로딩/shell·web비활성,도구event시반려. 최종file의원본UTF8바이트·크기·fataldecode와이번완료event를대조한다. DeepSeek키/Studio접속코드는CLI자식환경에서제거하고기존CLI인증은읽거나복사하지않는다.
- winner 결정 뒤 로컬 프로세스/요청 정리를 확인한다. 원문/source가바뀌거나정리실패면후속저장사본을수용하지않는다. 작은정리대기시간은새모델시간을부여하는것이아니다.

## 순서와 반증

독립 Astra는 별도 전달 메커니즘의 좁은 검증을 권고했고, Sol은 현재 로컬 Node의 optional map executor 경계와 원본/시간 가드를 검토했다. 우선 private 하네스의 동작을 확인한 뒤 기존 실제지시를한번실행한다. 선택된전체응답을기존수용해석으로총괄·독립대조한다. 선행통과일때만micro,그다음Zephyr를각한번진행한다. 어느단계든전달·의미·보존실패면중단하고다른winner로바꿔성공처리하지않는다.

실제 동시 winner의 성공을 과거76/89 단독 결과로 대신하지 않는다. 세 자료가 통과해야 정상 제품 생성 API 연결을 진행할 근거가 생긴다. 현재는 제품 코드/API통합·Cloud worker 변경·배포가없다. 제품연결후에는실제UI생성버튼→단일적용→저장→재열기/내보내기→원문왕복과문단/배치반례를별도로확인해야한다.

공개할것은결정·최소검사/실행메타데이터와필요한화면이다. 실제지시원문·전체모델응답·키·CLI eventstream은비공개Ops에보존한다.
