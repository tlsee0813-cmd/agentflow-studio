## 프로젝트 사본과 수신 경계

[project manifest](project-manifest.json)의 기존 합성 fixture는 r36, 작업6·영역6·handoff3·anchor3이다. 고정 사본의 해시가 원본과 같고 준비4a→수용c732 사이 fixture/domain/validation diff도 없다. 실제 JSONL과 같은 project/task/export라는 연결 근거는 없었다. 실사용 project 사본을 확보한 것처럼 표현하지 않는다.

따라서 수신 dry-run은 **NOT_RUN**이다. 거절·설명 보류·영역 미배치·적용 모두 실행 관측하지 않았다. 원본 project revision·보고·설명·anchor를 바꾸지 않았고 가짜 returnId/과거 anchor도 만들지 않았다. 정적 코드상 target 미존재 거절, 유효 handoff의 anchor 없는 설명 보류, 영역 없는 설명 미생성은 구별하되 이번 표본의 실행 결과로 세지 않는다.

## 다음 제품 범위와 완료 조건

1. 한 기록의 명시 선택 구간에서 최대3개 연결 대기 제안을 만든다. 원문 위치·범위·누락·출처 역할과 제안 해석을 함께 보존한다. 기본 프로젝트 홈을 긴 보고서로 바꾸지 않는다.
2. 제안의 이름/담당/기능 표현을 기존 부분·작업 ID와 자동 병합하지 않는다. 실제 연결 근거가 없으면 미연결로 남기고 후보를 제외·분리·다시 검토할 수 있게 한다. 원문이 같다는 사실과 의미가 같다는 추측을 구별한다.
3. 제안 검토와 기존 return.2 수신을 분리한다. 실제 export/target 연결이 입증되기 전에는 기존 보고·구상·설명을 쓰지 않는다. 유효 연결이 있는 다음 표본에서만 실제 사본 수신을 관측한다. 사람 기록 제출을 선행 관문으로 요구하지 않는다.

다음 완료 조건은 출처에서 제안으로 왕복 가능, 사용자 결정/총괄 해석/배정 예고/실행 관측 구별, 같은 표본 재검토 때 중복 후보 식별, 미연결 후보가 기존 프로젝트를 바꾸지 않음이다. 자동 동일성 병합·새 기능 노드 생성·일반 수집기·스케줄러·범용 실행 엔진·return 키 확장은 제외한다. Q02의 개명/분할/별칭 자동화는 근거가 생길 때 별도 선택한다.

공유물은 이 결과와 독립 검토, 정제3후보, 출처/프로젝트 manifest뿐이다. 큰 원본과 기존 워커 설치·키는 로컬 원래 위치를 보존하며 사본을 늘리지 않았다.
