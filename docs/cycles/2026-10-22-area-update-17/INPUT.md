## 사용자가 끝낼 흐름

정리된 반환 정보 한 번 수신 → 같은 구성부분의 현재 이해 갱신 → 전체 지도에서 달라진 부분 찾기 → 사용자 구상과 받은 설명을 짧게 읽기 → 필요하면 설명 정정·근거 확인·다음 요청/인계 → 원래 전체 보기로 복귀.

기존 제품의 홈·지도·영역상세·보고 원문·입력 보호·복귀를 재사용한다. 새 연구용 별도 화면을 만드는 대신 제품 후보에서 이 접점을 구현한다. PC1280×720·1440×900 중심이다.

## 입력 전제와 의미 한계

외부 정리 담당이 이미 대상과 의미를 대응한 입력을 전달한다고 가정한다. 입력의 설명은 **해당 보고만의 요약이 아니라 명시된 기준까지 반영한 영역의 현재 이해**를 뜻한다. 자동 추출·범용 동일성·자연어 모순 탐지·실제 완료 검증을 이 사이클에서 구현하거나 수용하지 않는다.

설명용 해석과 사용자 의도 변경 제안은 다르다. 기존 의도와 양립하는 설명은 승인 없이 반영하고, 제안은 별도 미채택 상태로 읽는다. 제안이 있다는 이유만으로 설명 전체를 승인 대기로 묶지 않는다. 외부 evidence도 앱 미검증이며, 입력에 적힌 완료/검증 표현을 앱의 판단으로 승격하지 않는다.

형식과 연결이 맞아도 본문 해석이 틀릴 수 있다. 이를 매번 확인해야 할 사용자 업무로 돌리지 않는다. 기본 화면에서 **사용자 구상 / 전달 기록에서 정리한 설명**의 역할을 구별하고, 근거와 사용자 정정 경로를 제공한다. 검사 통과의 이름은 대상·기준·보존·귀속 검증이며 의미 충돌 검출 성공이 아니다.

## 좁은 구현 선택

- 기존 결과 파일 가져오기 한 번에 선택적 정리 블록을 붙인 return.2 경로를 사용한다. 기존 return.1은 계속 읽는다. 새 정리 입력용 수동 관리 화면이나 두 번 가져오기를 기본 절차로 만들지 않는다.
- stable Area ID와 기존 task/return/export 소속을 대조한다. 현재 선택·최신 보고·같은 이름으로 대신 연결하지 않는다.
- 현재 설명은 사용자 Area.note/name·Basis·Task.manual·Background와 별도 저장한다. 새 필드에 맞는 project.6 및 v1~v5 migration을 구현하고, 과거에 없는 정리/기준을 소급 생성하지 않는다.
- **Background는 요청 당시 사본이다.** markHandoff가 copy(t.background)를 보존하므로 이를 전달 시점의 현재 기준으로 재해석하지 않는다. return.2의 실제 전달 시점 기준을 별도로 캡처하고, 반환 파일이 주장한 기준·앱의 실제 export 기록·현재 상태를 대조한다.
- 기준에는 대상·사용자 구상·현재 설명의 버전과 의미에 영향을 주는 사용자 기준 변경을 식별할 정보가 필요하다. 단지 파일이 최신 번호를 써서 보냈다는 이유로 최신으로 인정하지 않는다.
- 구조적으로 유효한 보고와 부적합한 정리의 영향을 분리한다. 정리의 대상/기준 불일치는 파생 반영을 보류하되 정상 보고는 보존하고 읽을 수 있어야 한다. 잘못된 JSON/바이트/보안 형식의 거절은 기존 원칙을 따른다.
- 보류된 설명을 단순 채택 버튼으로 최신 기준 검사 없이 현재로 올리는 우회 경로는 넣지 않는다. 보류는 필수 숙제나 전역 승인함이 아니다.
- 정확한 재전송은 무변경이다. 같은 반환 ID의 수정된 해석과 정확한 중복을 구별하고, 원문·이전 설명을 잃지 않는다.
- 사용자가 자동 설명의 오류를 고치기 위해 본인의 목적(note)을 바꾸게 하지 않는다. 별도 설명 정정은 이전값·근거와 함께 남으며 옛 입력이 되살아나 정정을 덮지 않는다. 사용자 정정도 앱의 직접 검증 완료는 아니다.

## 표시와 다음 행동

기본 화면은 짧은 현재 설명, 핵심 변화, 필요한 판단을 우선한다. 사용자 구상과 외부 정리의 역할 구분은 접지 않는다. 출처·이전 설명·긴 원문은 펼쳐 읽는다. 검사 수·내부 ID·긴 경계 설명·숫자 배지를 추가하지 않는다. 표시하는 변화는 직전 정리와의 차이이며 열람 추적 없이 “지난 방문 이후”라고 부르지 않는다.

현재 설명의 근거 읽기와 명시 보고 선택은 다른 동작이다. 읽기만으로 이어갈 작업·작성 대상·선택 보고를 임의 변경하지 않는다. 새 설명이 왔다고 지도 전체를 맞추거나 다른 부분을 움직이지 않는다.

유효한 현재 설명을 다음 인계에서 완전히 제외하면 사용자가 다시 원문을 조합해야 한다. 사용자 목적·조건을 우선 보존하면서, 유효한 설명을 **전달 기록을 정리한 참고 맥락 · 앱 미검증**으로 귀속해 포함한다. 설명·의도 변경 제안을 실행 지시나 사용자 확정으로 승격하지 않는다. 기준 변경 뒤 낡아진 값은 현재 설명으로 내보내지 않는다. 실제 외부 세션 실행·수락은 이번 성과가 아니다.

## 합격 장면

1. [RESEARCH의 두 표본](RESEARCH.md#표본과-한계)을 같은 코드에 적용한다. 수신→지도 변화 위치→짧은 상세→원문→다음 요청/인계→출발 복귀를 두 PC에서 완주한다. 작성자 검사와 별도 Cloud 검사를 구별한다.
2. 한 입력에 양립한 구체화와 의도 변경 제안이 공존한다. 구체화는 반영되고 제안은 사용자 값이나 인계 명령으로 채택되지 않는다.
3. 정확한 재전송, 같은 returnId의 수정된 해석, 오래된 기준, 사용자 설명 정정 뒤 옛 입력, 정상 형식의 잘못된 영역 본문을 각각 다룬다. 마지막은 자동 탐지 성공을 기대하지 않고 출처·역할·정정 가능성을 검증하는 명시 합성 반례다.
4. 사용자 note/name/Basis/manual/Background, 다른 영역·관계·지도 위치, 미전송 입력의 종류/대상/본문·영역 편집 버퍼를 보호한다. 원문과 이전 설명이 남아야 한다. 기존 importResultFile의 placeReturn 동작은 별도 기존 계약이며 정리 부가 기능이 임의로 추가 변경하지 않는다.
5. v1~v5→v6, return.1 호환, 내보내기/복구 왕복, 불일치 참조 방어, 기존 교차 탭 저장 거절을 확인한다. 다른 탭 live 반영은 미해결 기존 한계다.
6. 인계의 사용자 현재 기준·귀속된 외부 설명·미채택 제안·낡은 값 제외를 실제 텍스트와 브라우저 복사에서 확인한다. 단순 속성만 보지 않고 실제 표시/닫힘, 필요한 좁은 휠 왕복과 출발 위치 복귀도 확인한다.
7. 고정 소스·실제 종료값·실패 원시 결과·수정 후 결과·대표 화면을 GitHub에서 회수할 수 있어야 한다. CI는 후보의 정확한 커밋에서 확인한다. 반례를 숨기거나 미실행을 통과로 바꾸지 않는다.
