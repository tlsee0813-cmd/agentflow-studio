# 28 · 지도 카드의 이름·소속·기록 읽기 비교
2026-10-23 KST · 실험 착수 시점의 계약. 현재 배정은 [ACTIVE](../ACTIVE.md). 제품 채택 문서가 아니다.

## 사용 흐름과 질문
프로젝트로 돌아와 지도를 훑고, 바뀐 부분 하나를 찾아 이해한 다음 필요한 작업을 이어 간다. 24에서 작은 글자와 패널에 가린 카드, 26에서 자동 첫 배치의 반례를 확인했다. 좌표를 다시 계산하기보다 기존 카드 안의 이름과 실제 소속을 먼저 읽게 하는 것이 도움이 되는지 비교한다. 설명 갱신27과 독립적인 표현 실험이다.

## 기준과 좁은 후보
기준은 27 fix1 `6b96543fdf980ff45f0e1b67f83e8a0a561a1542`. 후보는 같은 소스의 두 파일만 바꾼 격리 연구 복사본이다. 아직 제품 통합하지 않는다.
- 제목은 원래 이름 순서 그대로 24px/27px, 최대 두 줄. 이름 앞뒤 조각을 이어 붙이거나 별도 이름을 생성하지 않는다.
- 실제 직접 부모 한 줄, 더 위의 경로가 있으면 생략 사실을 표시한다. 패널의 기존 전문 경로와 긴 이름 펼침을 유지한다.
- 구상 문장·구상 미기재 안내·일반 요청/결과 집계를 카드에서 숨긴다. 구상과 기록 자체는 바꾸지 않는다.
- 현재 작업, 설명 갱신, 기록된 질문, 현재 설명, 보류 설명, 이전 기준 신호와 기존 버튼은 의미·조작을 유지한다. ‘기록된 질문’을 ‘미결’이라고 바꾸지 않는다. 부모 집계 신호가 모든 잎에 이미 존재한다고 가정하지 않는다.
- 카드 240×180, 좌표, 관계, 실제 포함, 카메라 맞춤, 선택과 키보드 순서를 유지한다. 연구 복사본의 명시 클래스만 사용하며 자동 배율 전환이나 사용자 설정을 새로 만들지 않는다.

제목에 실제 쓸 수 있는 폭은 약148px이며 여러 신호를 함께 표시하면 높이가 부족할 가능성을 정적 검토에서 이미 확인했다. 이는 숨길 실패가 아니라 이 비교에서 확인할 반례다. 잘림을 발견해도 즉석 레이아웃 알고리즘·표현 축약을 추가하지 않는다.

## 비교 장면
두 PC 1280×720·1440×900에서 같은 제품 입력과 renderer를 쓴다. 정상 UI로 준비한 4/6/8 영역 사례를 기준과 후보에 적용한다. 기존 UI 백업/복구를 쓰면 그 사실을 기록하고 저장소 직접 주입과 구분한다.
1. 전체 맞춤과 한 부모 펼침에서 이름·직접 소속·원래 영역의 기록 존재를 읽는다.
2. 긴 공통 접두사에 중간 단어만 다른 두 이름, 같은 직접 부모 이름이 다른 가지에 있는 경우를 포함한다. 두 줄만으로 구별되지 않으면 실패로 남기고 기존 전문 읽기까지의 동작을 기록한다.
3. 현재 작업·설명 갱신·질문·현재 설명·보류·이전 기준이 많은 카드에서 실제 표시/잘림/겹침/누르기를 확인한다. 각 신호를 정상 UI로 만들 수 없거나 동시에 성립하지 않으면 미실행/불가능 이유를 구분한다.
4. 카드가 무관한 부모 프레임 안에 보이는 반례는 실제 소속 라벨과 패널 경로가 무엇을 설명하는지 확인한다. 좌표 정책을 고쳤다고 하지 않는다.
5. 정보 읽기 → 관련 작업 읽기 → 지도 복귀 한 경로에서 대상·현재 작업·카메라·선택·과거 기록을 대조한다.

고정 이름·글자 수에 유리한 시안으로 다시 만들지 않는다. 정상 준비 경로가 지나치게 크면 작은 대표 반례부터 검사하고 미실행을 명시한다. 실패 후 합격 수를 늘리기 위해 조건을 바꾸지 않는다.

## 수용 판단
제목이 커졌다는 사실만으로 채택하지 않는다. 실제 소속의 혼동이 줄고 핵심 기록 신호/버튼 접근이 악화되지 않아야 한다. 읽을 수 없는 신호·핵심 버튼 잘림 또는 구별에 필요한 이름을 숨기면 후보 보류다. 성공한 작은 부분과 실패한 전체 조합을 구분한다. 이 사이클은 기존 제품 읽기 흐름을 개선할 근거를 얻는 것이며 범용 자동배치기나 지도 엔진을 만들지 않는다.
