## 사용자 흐름과 정보
왼쪽 프로젝트 탐색 → 중앙의 생성한 프로젝트 카드 → 카드 선택으로 해당 프로젝트 공간 → 프로젝트 목록 복귀. 프로젝트가 어떤 프로그램인지 알아보고 들어가는 홈이다. Dify의 스튜디오 구성·밀도를 참고하며 실행 워크플로/Agents/지식/과금 메뉴는 옮기지 않는다. 보고 해석·구상 갱신 연구14의 별도 구현은 이번에 섞지 않는다.

카드는 실제 프로젝트 이름(최대2줄), 실제 목적 space.brief.text(최대2줄), 정확한 최근 활동 보조 정보가 우선이다. 마지막 요청을 프로젝트 목적이라고 표시하면 실패다. 목적이 없는 프로젝트는 간결하게 부재를 표시한다. 활동 시각은 기존 lastActivity의 범위(원문/내보내기)를 넘겨 ‘모든 수정 시각’으로 부르지 않는다. 요청·보고·검사 건수와 관리 버튼들을 카드 본문의 주제로 삼지 않는다. 영역 수는 필요하면 낮은 강조의 보조 하나로만 쓴다. 완료/진행 등 추론 상태를 만들지 않는다.

## 관찰한 문제와 PC 배치
총괄이 실제 Dify 스튜디오1280×720을 관찰했다: 좌측248px, 콘텐츠 시작x280(간격32px), 제목y17.2, 첫 카드x280.8/y102.8/폭314.4/높이164.4. 화면 생성물 하나도 단정한 카드 폭을 유지한다. 이는 참조 관측이며 제품에 Dify 로고·문구·기능을 복제하는 계약이 아니다.

현재 AgentFlow1440×900 홈은 좌측222px, 상단72px, 중앙960px 제한과129px 추가여백, 첫 카드y231.55/폭960/높이166.25이다. 중앙이 큰 단열 행이고 부차적 설명·버튼이 넓게 퍼진다. 공간13 내부 CSS 개선과 달리 홈 구성 자체를 바꿔야 한다.

홈 전용 목표:
- 좌측224~240px의 안정된 탐색 폭. 브랜드와 ‘프로젝트’ 활성 항목을 짧게 배치한다. 홈에서 이전 프로젝트의 ‘첫 작업을 기다림’ 같은 부정확한 설명·교육 문단을 크게 보여주지 않는다. 프로젝트 내부 탐색은 기존 의미를 유지한다.
- 중앙은 좌측 탐색 뒤24~32px에서 시작한다. 불필요한 MY PROJECTS/내 프로젝트/상단 내 프로젝트 반복을 없애고 제목 한곳, 우측 새 프로젝트 CTA를 같은 상단 영역에 둔다. 첫 카드 상단 목표100~160px. 경고/저장오류가 있으면 숨기지 않으며 정상 화면 목표와 구분한다.
- 1280×720·1440×900에서6프로젝트는3열, 간격16~20px, 카드폭280~360px를 목표로 한다. 열이1개라고 카드가 전폭 행으로 늘어나지 않는다. 본문 여백18~20px, 이름16~18px, 목적13~14px, 낮은 강조의 활동 정보12px 정도. 고정 숫자보다 두PC에서 읽힘·질서·정보 위계가 우선이며 이탈 사유를 기록한다.
- 카드 높이 대략170~210px로 정돈하고 긴 제목/목적은 의미있는 줄 제한과 상세 진입으로 처리한다. 빈 공간을 가짜 프로젝트·큰 안내 배너로 채우지 않는다.
- 카드 본문 클릭과 명시적 키보드 열기를 제공한다. 중첩 button/link를 만들지 않는다. 휴지통은 독립된 더보기 동작으로 분리하고 메뉴 클릭이 프로젝트 진입을 일으키지 않게 한다. 실제 삭제/복원 경로·기존 보호는 유지한다.
- 백업 불러오기·예제는 보조 도구로 접근 가능하게 유지한다. 저장/실행 모드 사실을 숨기지 않되 중앙 주인공으로 만들지 않는다. 불필요한 태그/작성자/유형 필터·새 상태는 추가하지 않는다.

## 진입·저장 의미
기존 projectCard/openOnClick/openEntry/workspace/leaveProject를 재사용한다. 공간이 있는 프로젝트의 카드 열기는 해당 프로젝트 공간으로 진입하고, Task/currentTaskId·수동 필드·미전송 내용은 바꾸지 않는다. 이전 work/task 화면을 복원하는 현재 recallPlace와의 차이를 명시적으로 처리한다. 지도 위치/배율 기억이 있으면 재사용하며 자동 fit으로 덮지 않는다. 공간이 없는 새 프로젝트는 기존 시작 경로로 간다. 목록으로 돌아올 때 해당 카드의 키보드 초점과 가능한 목록 위치를 되찾는다.

새 프로젝트·불러오기 새사본·휴지통/복원·읽기 오류/저장불가·저장 완료 대기와 이탈 보호를 유지한다. 사용자 실제 자료로 테스트하지 않는다. 데이터 schema·AI/provider/server·영역/관계 의미는 변경하지 않는다. 프로젝트 내부 공간13/읽기12의 배치를 홈 CSS 때문에 바꾸지 않는다.
