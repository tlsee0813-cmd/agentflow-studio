## 바꾼 것

  - CLI/GUI처럼 실제 사용 경험이 달라지는 미상은 적을 수 있다. 다만 모든 구현 세부를 전제나 승인할 항목으로 늘리지 않는다.
  - 원문에 없는 새 기능·명령 예시·구현 방식을 대안으로 더하지 않는다.
- **plan.1/plan.2 지침**: 바이트 그대로다(sha 9b856ef8…, c7c0228a…).
- **scope 지침**: 같은 판단 경계를 6번 규칙으로 더했다.

  - 지도 strip 버튼: `지킬 것 N · 확인할 것 M`
  - strip 펼침 창과 넓은 비교의 접힌 조건
  - 0건 화면: 구판 이름은 "아직 확인하지 않은 것"
  - 요청문 읽기의 구역 이름: 구판 이름은 "미정"
  - 목록 위에 한 줄 설명을 붙였다: "분석이 남긴 미정·확인 사항이에요. 모두 직접 정해야 하는 결정이라는 뜻은 아니에요." 원본 문장은 분류·필터·수선·삭제 없이 그대로 표시한다.
- **요청문 생성**(`src/shared/change-plan.ts`, `request-reading.ts`):
  - 새 문서의 구역 제목은 `전체 구상에서 확인할 것 (임의로 정하지 않음 · 선택 범위 추가가 아님):`이고, 빈 줄은 `- 제공된 확인할 것 없음`이다.
  - 읽기 검증은 구판 정확 제목 `전체 구상의 미정 (선택 범위 추가가 아님):`과 새 정확 제목, **이 두 값만** 해당 구역으로 허용한다. 나머지 span·원문·자료 무결성 검사는 그대로다.
  - 구판 문서의 text·reading offset은 재작성하지 않는다.
- **바꾸지 않은 것**: wire·plan/저장 schema(change-plan.1, studio.plans.4, file.4, request-reading.2), unknowns의 `string[]` 형태, frozen·stale 보호, scope 요청문 경로.

## 미확인

- 잠긴 TS 5.8.3 check/build, 관련 검사, 외부 CI, 1280 정상 UI 1경로는 root가 맡는다. 브라우저 확인은 하지 않았다.
- 프롬프트 검사는 문구 존재만 본다. 새 지침이 실제 모델 응답의 unknowns를 개선하는지는 별도 판본 관측이 필요하다. 105를 소급 수용하지 않는다.
- 제목 교체는 화면과 요청문이 모든 항목을 사용자 결정으로 단정하던 문제만 고친다. 이미 저장된 105 응답의 잘못된 문장은 그대로 남고, 그대로 보인다.
- **롤백 경계**: 106 이전 앱은 106이 만든 요청문이 든 묶음을 읽지 못한다. 기존 규칙에 따라 읽을 수 없음으로 표시하고 raw를 보존한다. 버전 번호는 올리지 않았다.
- `client/digest-source.ts`는 plan unknowns를 '변경안의 유지 범위와 미정'이라는 제목으로 돌아와 읽기의 모델 입력에 넣는다. 이 부분은 바꾸지 않았다. 모델 입력 바이트와 digest 지침이 이 제목을 직접 가리키기 때문이다. digest 지침은 이미 미정 항목을 모두 사용자에게 넘기지 말라고 구별한다.
