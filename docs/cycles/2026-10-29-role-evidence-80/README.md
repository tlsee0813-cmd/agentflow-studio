# AF80 · 역할 설명의 근거 접근

**범위:** 부분의 현재 역할 설명이 읽힌 원문(`PartUnderstanding.roleBasis`)으로 가는 입구만 추가한다. 최종 첫 지도 생성이나, 사람이 역할을 오독하지 않음을 증명하지 않는다. 기준 `work/experience78-response-failure` `e20d7d5ca99a2d6406ca05af69c9fc0a57293e78`(app `d12009e…`), 브랜치 `work/experience80-role-evidence`.

**문제:** 저장된 역할 근거(정확 인용)가 선택 읽기면과 전체 읽기에 연결되지 않았다. 현재 주장의 근거는 역할의 근거를 대신하지 못한다(예: 76 micro eval의 넷째 역할 근거 `return self._to_python(result)`는 어느 현재 주장의 인용과도 다르다).

**바뀐 행동**

- 현재 표시된 역할 설명 바로 아래에 접힌 `설명 근거 N`(실제 개수)이 생긴다. 선택 읽기면과 전체 읽기 모두 같다. 기본은 접힘이고 근거 1개도 같은 모양이다.
- 펼치면 각 근거가 기존 짧은 인용 칩 패턴으로 보인다(칩 글자만 짧게, 여는 원문은 전체·정확 위치). 같은 문장이 다른 위치에 있으면 둘 다 따로 남고 글자만으로 합치지 않는다.
- 칩을 누르면 기존 원문 표시가 그 위치를 강조하고, 돌아오면 같은 부분·같은 버튼 초점·펼침·스크롤·카메라로 온다(기존 `data-claim-focus` 복귀를 쓰며, 키는 부분·근거 순번·기록·위치).
- 근거는 현재 역할의 `roleBasis`만이다. 최신 주장의 종류·인용을 역할에 대입하거나 역할 전체의 구현 증거로 올리지 않는다. 사람이 바로잡은 설명에는 옛 AI 근거를 붙이지 않는다(입구 없음). `roleReplaces` 없이 나중에 읽힌 다른 설명은 현재 설명과 그 근거를 바꾸지 않고, 명시 대체일 때만 바뀐 근거가 나온다. 위치를 저장하지 않은 이전 판본의 인용에는 위치를 만들어 붙이지 않는다.
- 전체 문장·현재 주장·관계 순서, 지도 배치, 카드 표시, 근거 이력, 후보·복귀 경로는 바꾸지 않았다. 역할의 현재형 서술은 그것만으로 구현 완료 주장이 아니며, 새 roleKind·schema·prompt·provider·저장 변경은 없다.

**코드:** `src/client/role-evidence.ts`(어떤 근거를 어떤 순서·키로 보일지, DOM 없음), `src/client/app.ts`(렌더와 펼침 기억), `public/styles.css`(`.role-basis` 몇 줄).

**검사:** `tests/role80.test.mjs`(역할 근거만 있고 주장 없음·넷째 근거 정확 위치, 같은 문장 두 위치, 요구 역할과 좁은 작업 보고 공존, 사용자 정정 시 숨김, 나중 설명 무대체/명시 대체, 이전 판본 위치 미생성). DOM·초점·펼침 복귀는 `tests/studio_browser.py`의 `role80_flow`(작성자 미실행). 실제 micro/Zephyr 정상 백업은 root와 Cloud 브라우저에서 확인한다(새 모델 호출 없음).

**표준 합성 백업:** `role-evidence-synthetic-backup.json`은 `tests/role80-fixture.mjs`가 쓰는 같은 합성 기록과 작성된 응답의 프로젝트다(실제 소스·보고·AI 응답이 아님, 키 없음). 홈의 가져오기로 열 수 있다.
