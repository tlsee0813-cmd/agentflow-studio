2026-10-16 총괄 배정. 현재 상태는 [ACTIVE](../ACTIVE.md)에만 갱신한다.

## 목적과 기준
연구 화면을 더 늘리지 않고 기존 제품에서 **영역의 짧은 현재 구상 → 선택한 작업 맥락/필요한 원문 → 명시 이어가기·수동 편집 → 출발 지도 보기**를 한 흐름으로 잇는다. PC1280×720·1440×900을 우선한다.

정확한 결정은 [cycle11 PRODUCT_INTEGRATION](https://github.com/tlsee0813-cmd/agentflow-studio/blob/93f95855b56466ae93dffc184b725889b177c03e/docs/cycles/2026-10-16-two-change-record-11/PRODUCT_INTEGRATION.md)이다. 해당 네 단계와 완료 기준을 이 계약과 함께 적용한다.
제품 기준 USE106 `618d9bd2b99ad433df35107d8902b15f45e30000`, 구현 후보 브랜치 `product/pc-reading-return-12`. 기존 GUIDE107 후보는 가져오지 않는다. 연구 엔진·fixture·자유문 저장형식도 이식하지 않는다. 기존 저장 모델과 API를 유지하는 좁은 UI 연결이다.

## 반드시 지킬 상태 의미
- 영역 읽기와 작업 열람은 currentTaskId, 초안 종류/대상, manual4필드를 바꾸지 않는다. 사용자가 고른 Task의 currentWork를 읽는다. 최신 작업/보고를 임의 선택하지 않는다.
- 현재가 요청 A의 직접 보고 R이면 A의 이어가기는 R을 유지한다. 화면은 읽는 A와 실제 편집할 R을 구별한다. 현재가 다른 요청 B의 보고 RB라면 A로 전환하고 A의 오래된 보고를 자동 선택하지 않는다.
- 명시 이어가기 후 실제 currentTaskId의 기존 수동4필드 저장 경로를 쓴다. 서로 다른 Task 수정값을 섞지 않는다. 새 요청/보고 초안의 기존 종류·대상 보존 규칙도 유지한다.
- 복귀 상태는 탭 내 출발점 하나다. 프로젝트·실재하는 보기/선택/좌표/배율/읽기 위치/호출 초점을 돌려준다. 명시 변경한 이어갈 기록·저장한 수정은 되돌리지 않는다.
- 삭제·보관·다른 프로젝트 전환 등 출발점 무효 시 안전하게 상위 보기로 가되 다른 대상을 임의 선택하지 않는다. 기존 view 상태에 없는 새 상태 체계를 만들지 않는다.
- 사용자 구상, 수동 수정, AI/MOCK 제안, 제외된 낡은 문구를 구별한다. 빈 내용은 빈 내용이며 가짜 미결·자동 작업·요약을 만들지 않는다.
- 이름/현재 구상은 읽기 기본, 편집은 명시 진입. 긴 원문/보고/조건은 필요할 때 확인한다. 요청 사본과 현재 목적·영역의 차이를 코드 변경/방문 이후 변화로 표현하지 않는다. 필수조건과 원문 접근성을 잃지 않는다.

## 구현·검증 경계
제품 코드 변경은 이 흐름에 필요한 app/continuity UI와 직접 관련 테스트로 제한한다. shared domain 저장 스키마, provider/backend/AI 의미, 의존성, 공개 배포, main, GUIDE107는 바꾸지 않는다. 불가피한 추가 파일은 이유와 영향으로 설명한다. 새 범용엔진·커넥터·방문 추적·임의 깊이·전체 모바일 최적화는 제외한다. 층위 목표는 유지하지만 이번 저장 경계를 최종 모델로 확정하지 않는다.

작성자는 실제 소스/기존 검사를 읽고 구현한다. 작성자 검사와 독립 검사는 분리한다.
1. PC 두 폭의 읽기만 경로: 영역→사용자 선택 작업→긴 원문 열기/닫기→지도 복귀. currentTask/초안/manual 전후 동등.
2. PC 두 폭의 명시 편집 두 경로: A/R 유지와 RB→A 전환. 실제 대상별 서로 다른 manual4필드값, 다른 Task 불변, 지도 시야/읽기 위치/초점 복귀와 편집 보존.
3. 빈 구상·작업 없음, 긴 구상·보고, 사본 없음/차이 있음, stale 제외, 유효하지 않은 출발점의 필요한 실패 경계. 새 기능 목록이 아니다.
4. 기존 타입/빌드/도메인 검사와 영향을 받는 기존 browser 회귀를 실행한다. 실행 실패를 코드 결함/검사기 문제/환경 문제로 구별한다. 새 흐름의 최초 실패와 수정 원본을 보존한다.
5. actual UI click/key/wheel, 실제 숨김/노출과 focus, 좌표/배율/scroll을 확인한다. 속성만 보거나 state를 강제 대입해서 제품 흐름 통과로 세지 않는다. 합성 fixture 설치는 분리해 표시한다.
6. 390은 접근/닫기/넘침만 최소 확인. 사람 사용성·실제 AI 수행·공개 적용으로 확대하지 않는다.
