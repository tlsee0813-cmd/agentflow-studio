# 실제 기록 1건 — 병렬 연구 회수와 총괄 판단

2026-10-15 최초 기록 · 2026-10-16 후속 조사 반영 · 상태: 조건부 A/B로 좁힘, 읽기 비교와 새 구현은 미실행

## 범위

[동결 INPUT](INPUT.md)의 E01~E10만 사용했다. 합성 도서관 예제를 개발한 실제 AI 작업 기록이며, 실제 도서관 고객 기록은 아니다. 이후 UI02 fix3의 성공이나 새 환경 검증을 이 입력의 과거 상태에 덮어쓰지 않는다. 이 사이클은 기존 지도 전체를 재설계하기 전에, 선택한 부분의 기록을 읽을 때 근거와 상태가 왜곡되지 않는지 검토한다. 구조·작업·세션을 같은 계층의 자식 노드로 섞지 않는다.

Pro 두 세션에 서로 다른 좁은 질문을 병렬 배정했다. 하나는 통과 범위와 잔여 미결, 하나는 자료별 이름과 변경 지시의 차이다. 내부 Astra High가 공식 원문 네 개를 독립 대조하고 결합 제안을 반박했다. 총괄은 아래처럼 범위를 다시 좁혔다. 이 문서는 구현 배정표가 아니다.

## 초기의 목록＋선택 근거 후보 — 제안 기록 보존

당시에는 전체 지도의 부분별 펼침과 외부 관계를 유지하고, ‘확인할 부분’ 목록과 선택한 항목의 근거 읽기를 기본 후보로 제안했다. 모든 범위표와 사건을 한꺼번에 붙이는 결합안은 채택하지 않았다. 아래는 초기 제안의 기록이며 현재 실행 지시가 아니다. 후속 조사에서 목록이 사용자의 숙제·배정처럼 읽힐 위험을 검토한 뒤 [최신 메커니즘 검토](MECHANISM_REVIEW.md)의 두 읽기 표현 A/B로 좁혔다. 목록안을 영구 폐기한 것은 아니며 세 안을 동시에 구현하지 않는다.

초기 목록 가설은 다음 두 종류를 처음 읽는 자리에서 구별하려 했다. 이 의미 구분은 후속 A/B에서도 유지한다.

- **확인된 누락:** H1의 지정 화면 위치에 미결 참조가 없음. 어떤 위치·어떤 버전·어떤 방식의 검사인지 연결한다.
- **아직 확인하지 않은 것:** 독립 브라우저 미실행, 이름 변경 지시 미확인, 읽기 효용 미검증. 실패나 실행 지시로 바꾸지 않는다.

H1의 기존 독립 Node 5개 통과는 같은 자리에서 그 범위와 함께 보존한다. 작성자 단언 수·독립 사례 수·이미지 수를 합산한 점수나 전체 완료 배지를 만들지 않는다. 상세에서는 선택한 판단을 설명하는 자료만 연다. 원문, 전달 발췌, 검토 요약을 구별하며 해당 근거를 읽었다는 사실을 승인·수신·이해 완료로 바꾸지 않는다.

명칭은 자료명을 주어로 병기한다. 화살표·‘이전/현재’ 열로 정정 사건을 만들어 내지 않는다. 이번 A3의 같은 식별자는 병기의 근거지만, 다른 프로젝트에서 비슷한 이름을 자동으로 병합할 근거는 아니다. 비교를 닫으면 읽던 대상·펼침·위치를 보존한다. 기존 UI03 넓은 본문은 이 과업에 도움이 되는지 시험할 후보로만 유지한다.

## 초기 제안에서 보존할 반례

1. ‘실패 알림 정책 미정’은 합성 사례의 내용이고 ‘미결 표시 누락’은 실제 시안의 결함이다. 예제의 정책을 결정해야 표시 결함을 닫을 수 있는 것처럼 읽히면 실패다.
2. 비슷한 두 이름이 서로 다른 기능 범위를 가리킨다고 밝혀졌을 때 자동으로 합치거나 정정 전후로 고정하면 실패다.
3. 목록 순서를 우선순위·의존성·이미 승인된 작업 배정으로 읽거나, 미실행을 실패로 읽으면 목록 후보를 줄이거나 결과표 후보로 돌아간다.
4. 근거를 읽고 돌아오려면 전체 지도를 다시 탐색해야 하거나 원래 선택을 잃으면 집중 공간의 이점이 없다.

## 다음 읽기 비교의 경계

2026-10-16 추가 사용자 지시에 따라 [전체 제품 목적 대조](PRODUCT_LENS.md)를 실시했다. 현재 표본의 정확한 검증 읽기는 제품의 일부다. 프로젝트·선택 대상·관련 영역의 이해, 불필요한 사용자 개입 방지, 근거를 읽고 판단·원래 보기로 돌아가기를 함께 본다. 표본에 없는 프로젝트 목적이나 실제 인계 성공을 정답으로 채우지 않는다.

후속 Pro 두 세션의 공간·탐색 및 기록·근거 메커니즘 조사와 독립 원문·코드 대조를 회수했다. [MECHANISM_REVIEW.md](MECHANISM_REVIEW.md)는 그 근거와 적용 가설·미확인 조작을 나누고, 현재 조건부 후보를 다음 둘로 정리한다. 조사한 서비스의 실제 사용성이나 AgentFlow의 우위를 검증했다는 뜻은 아니다.

- **A: 판단 본문＋문장별 근거 미리보기.** 확인·미확인 범위를 서술하고 필요한 근거를 출발 문장 옆에서 읽는다. 본문이 자료보다 강한 결론을 만들거나 인용 수가 검증을 대신하면 후보를 재검토한다.
- **B: 자료·검사범위별 중립 대조.** 자료명·관측 위치·검사 방식과 범위를 주어로 대응 가능한 내용만 대조한다. 다른 범위를 같은 측정으로 정렬하거나 열 순서·빈칸을 시간·승인·실패로 읽게 하면 후보를 재검토한다. ‘중립’은 설계 의도이지 입증된 효과가 아니다.

같은 E01~E10, 요약·출처 설명·근거 접근 범위와 공통 공간 조건을 둔다. 두 안의 차이는 읽기 표현이며 A만 넓은 본문, B만 별도 패널로 두어 공간까지 동시에 바꾸지 않는다. 공통으로 보존할 것은 프로젝트·선택 대상·관련 영역·소유·반영 범위·돌아갈 위치이며 모든 패널의 상시 동시 노출이 아니다. 좁은 화면에서 맥락과 읽기가 서로를 가린다면 전용 집중 공간은 후속 비교 후보로 다시 검토한다.

동결 입력의 같은 기록을 두 표현에 놓고 다음을 관찰한다. 무엇이 어느 범위에서 통과했는지, 무엇이 실패이고 무엇이 미확인인지, 두 이름 사이의 변경 지시가 확인됐는지를 답할 수 있어야 한다. 질문은 정답을 포함해 유도하지 않는다. 답하지 못함·잘못 읽음·실행하지 않음을 따로 남긴다.

작성자 단언·독립 사례·이미지 수는 서로 다른 목적·환경·범위의 관측이므로 합산 점수나 같은 측정의 승패로 만들지 않는다. 같은 H1이라도 대응하지 않는 대조 셀은 ‘이 범위의 비교 대상 아님’일 수 있고 미실행·실패와 구분한다. 현재 표본의 이름 차이나 검사 범위 차이를 상충 주장으로 꾸미지 않는다.

두 안 모두 제자리 근거 미리보기와 실제 원문 이동을 구분한다. 미리보기는 원문 전체·최신판 열람이나 해석 검증을 보장하지 않으며 전달 발췌를 원문으로 표시하지 않는다. 문장·행에서 미리보기를 닫는 복귀와 외부 원문에서 원래 대상으로 돌아오는 복귀를 별도로 관찰한다. 필요한 판단의 근거를 여는 것이 목적이며 사용자가 문장별 인용·대조 셀을 전수 검수해야 하는 기본 절차로 만들지 않는다.

[읽기 관찰표](READING_TRIAL.md)의 기존 다섯 비유도 질문과 미실행·못 읽음·상태 오류 구분을 유지한다. 내용·요약·근거 접근·장식을 더 준 안이 정보량 때문에 승자가 되지 않게 하고, AI의 텍스트 읽기를 사람 사용성·실제 조작 성공으로 보고하지 않는다. **이 읽기 비교와 실제 화면 구현은 아직 실행하지 않았다.** 조건부 A/B는 최종 제품 채택이 아니며 이번 연구만으로 전체 수집기·실행 워크플로·새 데이터베이스 개발로 넓히지 않는다.
