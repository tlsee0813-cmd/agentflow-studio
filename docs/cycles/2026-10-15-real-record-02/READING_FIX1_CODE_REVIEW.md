# 읽기 비교 fix1 — v0 대비 좁은 코드·검사 감사

2026-10-16 · 코드·원본 결과 감사 완료 · 작성자 정적 검사 1회 재실행 · 독립 브라우저·사람 관찰 미실행

대상 HTML SHA256: `9add34fc341db08e6ef54e6e99d1fbfac6b39e7de61f5d8bd6415b32fa28ed1d`. v0 SHA256: `500e0021045ae035beca9244d2f7ee59b048f969137777cf3e766655005c9da0`. 원본 반환물·로그는 수정하지 않았고 새 검사군·브라우저·서버를 만들거나 원격 쓰기를 하지 않았다.

## 판단

**넓은 화면에서 닫힌 미리보기 본문이 남는 결함과 f15/f16의 자기 식별을 보완하는 좁은 수정으로 볼 수 있다.** HTML diff의 범위가 맞고, 실제 렌더링에 기반한 추가 검사와 정확한 v0 음성 대조가 이전 속성값 검사 공백을 검출한다. 이 수정 수용을 막을 새 코드 결함은 이번 범위에서 발견하지 못했다. 다만 작성자 실행 근거를 감사한 결과이며 독립 브라우저·전체 의미 동등성·사용성 승인으로 확대하지 않는다.

## 실제 HTML 차이

v0와 원본 파일을 직접 diff했다.

- 전역 `[hidden]{display:none !important}`와 그 이유를 적은 CSS 주석 추가.
- A의 f15/f16 문장에 H1·해당 위치를 명시하고, 두 사실의 `keys`에 자기 식별 문자열 추가. B 행·숫자·사건·출처는 그대로다.
- 바닥글에 fix1 버전 표시 추가. 머리글의 v0 이름은 유지된다고 REPORT도 밝힌다.

따라서 ‘CSS와 f15/f16만’이라고 축약할 때에는 바닥글 버전과 검사 키 변경도 함께 밝히면 정확하다. **HTML의 실행 JavaScript·복귀 알고리즘·외부 링크·공통 요약·나머지 사실은 변경되지 않았다.**

## 실제 렌더링 판정은 좁은 결함에 충분한가

이번 목적에는 **속성 검사에서 실제 렌더링 검사로 보완한 정도가 적절하다**.

- 새 `JS_PANEL`은 computed display, `checkVisibility`, 본문·닫기 버튼의 실제 크기, `elementFromPoint`, 실제 `focus()` 가능성을 함께 기록한다. `hidden` 속성만 true인지 보는 기존 검사는 상태값 검사로 이름을 바꾸었다.
- `PANEL-INIT`, `PANEL-OPEN`, `PANEL-CLOSED-BTN/ESC/KEY`가 첫 화면·열림·버튼/키보드 닫힘을 구분한다. 넓은 화면에서는 본문/닫기 버튼의 박스 0·표시/클릭/초점 불가와 빈자리 안내를, 좁은 화면에서는 부모 시트의 display none을 확인한다.
- 같은 검사기로 정확한 v0를 실행한 결과, **1440×900과 1280×720에서 각 6개, 합계 12개 닫힘 관련 실패**만 기록되었다. 좁은 화면에서는 부모 시트가 이미 숨겨져 실패하지 않았다는 결함 설명과도 맞는다. fix1은 같은 전체 검사에서 308/0이다.
- hidden 수정만 제거한 m6도 넓은 화면의 동일 `PANEL-*` 실패를 검출한다. f15/f16 내용 변경과 CSS 수정의 효과를 모두 섞어 닫힘 수정이라고 설명하지 않는다.

검사 helper는 조작 가능성 확인을 위해 닫기 버튼을 잠깐 focus한 뒤 원래 요소로 돌린다. 이는 사용자 키보드 전체 흐름·화면 판독기 평가가 아니다. 대표 PNG 2장은 해시만 감사했으며 이 역할에서 직접 시각 판정하지 않았다.

## 실패 처리와 검사 보완

**링크 0건 false pass는 보완되었다.** 파일 없음은 exit 2, 링크 0개는 exit 1, 기본 기대 개수 11과 다르면 FAIL을 남긴다. 기대 12개의 음성 로그에서는 raw 11개가 모두 200이어도 추출 수 실패를 유지한다. 검사 개수를 고친 것이며 실제 GitHub 페이지 표시를 새로 검증한 것은 아니다.

**변형 실패 원인 구분도 좁게 보완되었다.** 원본 기준선이 먼저 통과해야 하며 각 변형에 예상 실패 ID와 viewport를 정의한다. exit 1·요약 존재·예상 ID의 예상 화면 실패가 있어야 DETECTED다. timeout, traceback, 요약 없음, 비정상 종료, 교체 지점 불일치는 FATAL이고 다른 실패만 있으면 MISSED다. m1~m6 로그는 복원·새 탭·전환 출발·시트 가림·미리보기 내부 스크롤·hidden 재정의와 대응한다. m2/m4의 ABORT는 별도 출력되고 검출 근거로 쓰이지 않는다. 다만 현재 패키지는 개별 변형의 전체 JSON이 아니라 분류 요약 로그를 제공한다. FATAL/MISSED 분기를 일부러 유발한 별도 음성 실행까지 제출되었다고 주장하지 않는다.

`browser_check.py`는 viewport 예외를 ABORT FAIL로 기록하고 nonzero로 끝내며, setup/launch 등의 바깥 예외를 exit 0으로 덮는 finally 구문은 없다. `run_all.sh`는 정적·브라우저·링크 종료 코드 세 개를 저장해 모두 0일 때만 성공한다. 변형 검사는 별도다. 기존 출력 폴더 덮어쓰기·오래된 JSON 재사용 위험을 막는 실행별 출력 폴더 계약은 추가되지 않았으므로 원본 폴더에서 무심코 재실행하지 않아야 한다.

## 남은 경계

- 미리보기/전환 복귀의 JavaScript가 그대로여서 이전 감사의 **열린 상태 resize 뒤 옛 화면 좌표 복원 위험**은 해소·재현한 것으로 세지 않는다. 선택 사실이 화면 밖이면 다른 가시 사실을 위치 기준으로 삼는 전환 동작도 그대로다.
- 실제 GitHub 요청은 브라우저에서 계속 스텁이다. 확인한 것은 새 탭 고정 URL과 읽기 페이지 상태 보존이며 원문 실제 표시·그곳에서의 사용자 복귀는 미실행이다. 알려진 제한으로 보존한다.
- B 모바일에서 비교 상대 행을 동시에 남기지 못하는 조건, 상태 14종, QA 중심 부담, f07/f08/f10/f17/f20의 문단 맥락 의존은 REPORT가 명시한 잔여 관찰이다. 이번에 고쳤거나 수용했다고 쓰지 않는다. 선택 유지는 근거 버튼으로 고른 사실을 남기는 동작이며 열기 전 다른 선택을 복원하는 기능이 아니다.
- 출처 버전은 기존 고정 커밋을 유지하며 새 외부 실행 의존은 없다. 정적 24 PASS는 모든 출처 지지·A/B 정보 밀도 동등성·사람 이해도를 증명하지 않는다.

별도 허용에 따라 기존 127.0.0.1:8765 서버 root를 확인하고 새 이름 `reading-study-fix1.html`로만 임시 복사했다. `http://127.0.0.1:8765/reading-study-fix1.html`은 HTTP 200이며 응답·복사본·원본 SHA256이 모두 `9add34fc…ed1d`와 같다. 새 서버·프로세스는 실행하지 않았다. 이 HTTP 확인을 브라우저 렌더링 검사나 GitHub 공유의 대체 증거로 세지 않는다.
