# reading-study 독립 브라우저 최소 동작 계약

2026-10-16 · **화면 수신 전 작성한 사전 계약 원본**. 아래의 미실행 표현은 작성 당시 상태이며 최신 실행 결과는 [fix1 통합 판단](READING_FIX1_RESULT.md)에서 읽는다.

**fix1 실행 전 해석 명시:** 실제 구현의 선택은 근거 버튼으로 고른 사실의 강조다. 총괄은 Cloud 배정 전에 R3를 ‘클릭한 사실 유지 + 출발 초점·읽기 위치 복귀’로 적용한다고 명시했다. 미리보기 전 다른 선택 복원 기능을 구현했다고 주장하지 않는다. 아래 원래 문구를 소급해 고치지 않고 이 차이를 남긴다. 또한 B 모바일에서 비교 상대 행이 함께 남지 않는 것은 나란히 대조 후보의 한계이며, 실제 클릭·근거 내용·복귀 오류와 따로 판정한다.

현재 `2026-10-15-real-record-02/INPUT.md`, `MECHANISM_REVIEW.md`, `READING_TRIAL.md`를 읽고 정리했다. 대상 `reading-study.html`의 화면·코드·정확한 커밋은 아직 받지 않았다. 아래는 작성자 검사와 별개로 독립 실제 브라우저에서 확인할 7개 계약이며, 구현 결과나 사람 읽기 효용의 판정이 아니다. selector·버튼 명칭은 발명하지 않고 실제 전달물에서 대응시킨다. 새 코드·하네스·브라우저 환경 변경을 하지 않았으며, 실행 시 기존 확보된 Cloud 환경을 사용한다.

## 공통 실행 조건

- 전달받은 정확 commit·파일 SHA256을 먼저 고정한다. 다른 시안·과거판으로 대체하지 않는다. 원본은 수정하지 않고 정적 HTML을 임시 HTTP 서버로 제공해 실제 Chromium이 `http://...`로 접속하게 한다. 메모리 HTML·fetch/DOM 대역은 실제 접속·조작 증거로 세지 않는다.
- **A와 B 각각 `1440×900`, `390×664`, `390×844`**, 총6조건을 따로 기록한다. 같은 자료·시작 대상·E09 읽기 시작점·공통 공간 조건을 쓴다. 작성자 검사 통과 수와 합산하지 않는다.
- 독립 결과는 계약별·조건별 관측을 남긴다. 이 문서 자체는 기대 결과만 제시하며 현재 판정은 모두 `NOT_RUN`이다. 공통 조건을 만들 수 없으면 그 원인부터 남긴다.

## 7개 계약

### R1. A/B의 사실·출처 경계가 같은가

실제 화면의 A 문장과 대응 B 셀/행을 읽어 **같은 E01~E10·역할·산출물/버전·출처 설명·확인/미확인 경계**가 접근 가능한지 대조한다. 한쪽만 정답 요약·경고·근거를 추가하거나 생략하면 차이를 기록한다. 동일 정보의 조직 차이까지 동일 DOM으로 요구하지는 않는다. 공간 배치·글자 크기·대비·시작 맥락의 차이도 표현 방식의 우위와 분리한다.

최소 사실 표식: 실제 AI 개발·검증 기록이며 고객 기록이 아님; H1의 E10 동결점; E01 표기 차이와 정정 지시·승인·시각 미확인; 기존 독립5개 통과와 E09~E10의 다른 위치별 누락 공존. fix2/fix3·후속 Cloud 성공으로 동결 상태를 바꾸거나 84·36·5·10·13/90을 총 완료율로 합치지 않는다. 합성 A2 정책 미정과 실제 UI 표시 누락도 다른 층위다. 브라우저에 이런 문구가 있다는 관측은 사람이 정확히 이해했다는 판정이 아니다.

### R2. E09의 같은 근거에 문맥을 유지하며 도달하는가

A에서는 E09 관련 문장, B에서는 대응 질문·비교 상대가 있는 셀/행을 출발점으로 삼아 표시된 근거 조작을 **실제 클릭**한다. 두 안에서 같은 제공 발췌와 S01/S03/P02 출처 설명을 읽을 수 있어야 한다. 자료명·버전·관측 범위와 발췌/전달 설명/검토 요약의 수준이 남아 있어야 하며, 원문 전체를 읽었다는 표시로 승격하지 않는다. 다른 근거나 대응 항목이 열리면 실패다.

여는 동작 자체가 선택 대상·필터·사건 또는 읽기 위치를 뜻밖에 바꾸는지도 전후로 기록한다. A의 출발 문장, B의 출발 행과 비교 상대가 어떤 방식으로 유지되는지 확인한다. 좁은 화면에서 둘이 동시에 보이지 않는 것만으로 실패시키지 않고, 출발 문맥을 식별하고 복귀할 수 있는지를 본다.

### R3. 임시 미리보기 닫기는 출발 초점·선택·읽기 위치를 복원하는가

출발 트리거의 식별값·키보드 초점, 구현에 존재하는 선택값, 실제 읽기 스크롤 주체와 위치를 먼저 기록한다. 긴 본문/표에서는 가능한 비영 위치까지 실제 스크롤해 두고 미리보기를 연다. 미리보기 안에서도 스크롤한 뒤 표시된 닫기 조작으로 닫는다. 출발 트리거에 초점이 돌아오고, 원래 문장/행·선택·본문/표 스크롤이 복원돼야 한다. 스크롤은 주체별 실측값과 화면상 출발 위치를 함께 비교하며 수치 허용 오차는1 CSS px로 둔다.

Escape 같은 추가 닫기 경로가 실제 제공되면 별도 관측하고, 제공되지 않은 경로를 임의 요구로 만들지 않는다. 초점만 돌아온 것을 선택·스크롤 전체 복원으로 세지 않는다. 선택 모델이 없다면 ‘선택 없음’으로 명시하고 새 상태를 발명하지 않는다. 내용이 짧아 비영 위치를 만들 수 없으면 최대값을 기록하고 그 조건의 비영 스크롤 복원만 미실행으로 남긴다. DOM scroll 대입을 사용했다면 물리 휠/터치 입력 검증과 구분한다.

### R4. 미리보기와 실제 원문 이동·복귀가 구분되는가

같은 근거에 대한 임시 미리보기와 ‘원문 위치로 이동’이 다른 동작으로 식별돼야 한다. 실제 원문 링크를 눌렀다면 최종 URL·원본 위치 또는 명시된 한계를 기록하고, 새 탭 닫기/브라우저 뒤로가기 등 실제 제공 경로로 돌아온 뒤 대상·선택·펼침(있다면)·읽기 위치·초점을 다시 대조한다. 링크 문자열을 찾았거나 미리보기를 연 것만으로 원문 이동 성공을 주지 않는다.

P02 같은 전달 설명에 원문이 제공되지 않았거나 원문 접근이 막혔다면, 이유와 읽을 수 있는 자료 수준이 표시되는지 확인한다. 원문 이동·왕복은 `NOT_RUN`과 사유로 남긴다. 깨진 것으로 제공된 링크, 잘못된 대상 이동, 원문 없음에도 열람 완료라고 표시하는 경우는 실제 관측된 실패다. 차단을 해결하려고 새 환경·네트워크 정책을 바꾸지 않는다.

### R5. 세 화면 크기에서 필요한 조작을 실제로 할 수 있는가

각 조건에서 A/B 전환(제공되는 방식), E09 근거 열기, 닫기, 원문 조작의 제공 여부를 확인한다. 필요한 제어를 실제로 보이게 스크롤하고, viewport·스크롤 컨테이너·sticky header의 가림과 포인터 hit 지점을 확인한 뒤 정상 클릭한다. 가로 페이지 넘침은 document scrollWidth≤실제 innerWidth를 기준으로 하고, 표 자체 가로 스크롤이 의도된 경우 문서 넘침과 구분해 읽기·조작 가능성을 기록한다. 긴 내용이 한 화면에 모두 나와야 한다는 조건은 아니다.

force click, 직접 핸들러 호출, 제품 DOM/CSS 변경으로 접근 성공을 만들지 않는다. 자동 DOM 스크롤로 가림을 피했다면 처음 가림·이동 방법·최종 hit/click을 남기고 일반 조작 무가림으로 확대하지 않는다. 실제 wheel·touch·키보드 중 수행한 입력만 기록하며 touch context가 아니면 터치 성공을 주장하지 않는다.

### R6. 같은 조건 안에서 반복·왕복이 다른 기록을 덮어쓰지 않는가

E09 미리보기 열기→안쪽 읽기→닫기를 두 번 수행해 다른 근거·이전 선택·미리보기 안쪽 위치가 출발 문장/행의 위치와 섞이지 않는지 확인한다. 실제 원문 왕복을 했다면 이 임시 미리보기 왕복과 분리한다. A/B 전환은 두 안의 같은 의미적 E09 출발점으로 비교하되, 서로 다른 표현의 픽셀 스크롤값을 억지로 같게 요구하지 않는다. 전환 때 읽기 위치를 새로 시작하도록 설계됐다면 그 규칙과 관측을 명시한다. 닫기/복귀로 사건의 사실·미결 상태나 통과 주장이 바뀌어서는 안 된다.

### R7. 독립 결과가 실패·미실행·한계를 보존하는가

성공은 실제 수행한 지정 동작과 기대 관측이 일치한 경우에만 준다. 시도 후 불일치/가림/잘못된 복귀는 `FAIL`; 시작하지 않았거나 원문 미제공·접근 불가·필수 실행조건 부재로 수행하지 못한 경로는 `NOT_RUN`과 사유로 남긴다. 다른 검사는 성공했더라도 실행되지 않은 항목을 통과로 채우지 않는다. 필수 검사 중 오류로 중단되면 fatal·단계·실행/기대 항목수·프로세스 nonzero를 기록하고 부분 성공으로 완주를 가장하지 않는다.

최소 반환물은 exact commit/HTML hash, browser 경로·버전·실제 viewport·HTTP URL/응답, 계약별 실제 조작/관측/판정, 전후 초점·선택·scroll 주체/값, 오류·skip 사유, 대표 원본 PNG와 실행 코드/JSON/프로세스 로그다. JSON과 실제 프로세스 종료코드도 대조한다. 대표 화면은 A/B의 E09 출발·근거 열림·닫은 뒤 위치가 무엇인지 연결해 식별한다. 반환 파일은 내구 공유 경로에 고정하고 원본 실행 이력과 재시도 결과를 덮어쓰지 않는다.

## 이 계약으로 판정하지 않는 것

자동화가 사실 표식과 클릭 경로를 확인해도 Q1~Q5 사람 이해도·부담·선호의 성공이나 A/B 승자를 만들 수 없다. ‘지금 할 일 없음’, 정확한 ‘모름’, 중단은 사용자 오답으로 채점하지 않는다. 사람 관찰의 첫 답변/도움 후 답변·제시 순서·학습 효과는 READING_TRIAL의 별도 기록이다. 기존 Cloud 환경은 사용 가능하지만 새 작업 복원, 전체 제품 기능, 실제 모델 호출·인계·수신·수락은 이 계약의 범위 밖이다.
