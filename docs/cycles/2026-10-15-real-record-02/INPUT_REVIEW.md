# 실제 AI 작업기록 후보 — 근거 검토와 통합 권고

2026-10-15 · 다음 좁은 연구 사이클용 검토 · 구현·최종 설계·원격 공개 없음

## 판단

이 표본은 **조건부 채택**할 수 있다. 현재 프로젝트에서 AI가 시안을 만들고, 다른 검토가 검사 범위와 결함을 지적하고, 수정 결과를 좁게 수용한 실제 개발 기록이다. 도서 대여 서비스와 A1~A6은 그 개발에 사용한 합성 입력이다. 실제 고객 로그나 실제 도서관 업무 기록으로 소개하면 안 된다.

세 목표의 충족 정도는 같지 않다.

| 목표 | 판정 | 표본으로 검증할 수 있는 것 | 주장할 수 없는 것 |
|---|---|---|---|
| 명칭 변경 | 부분 충족 | 의미 시안의 A3 ‘내 목록’과 캔버스의 ‘내 대여 목록’을 나란히 보존하고, 입력 계약과 작성자 설명의 관계를 읽기 | 누가 언제 이름을 바꾸라고 지시했는지, 수정 발화의 선후, 승인된 요구 변경 |
| 미결 | 충족 | 독립 브라우저 재검증, 읽기 효용, INPUT 합격 기준 9의 미검사/보완 대기를 서로 다른 미결로 유지하기 | 상태 검사 통과로 브라우저 검증·사람 이해도·새 보완의 완료까지 승격하기 |
| 엇갈린 완료 주장 | 범위 차이 사례로 충족 | 84/37 통과 기록, 37 집계 정정, 목록 복귀 실패·수정, 기존 독립 5 통과와 남은 INPUT 9 누락을 함께 읽기 | 어느 작성자가 ‘모든 요구 완료’라고 말했다는 허구의 발화, 서로 다른 검사 수의 합산, 과거 5개 통과의 소급 취소 |

사용자의 ‘명칭변경’ 목표를 확정 변경 사건으로만 정의하면 이 한 표본은 부족하다. 그 부족 자체를 입력에 남기는 편이 낫다. 다음 좁은 사이클은 **표기 차이와 명시적 변경을 화면이 혼동하지 않는지**를 시험할 수 있다. 진짜 변경 지시의 처리까지 검증했다고 보고하지 않는다.

## 초안에서 바꿀 부분

1. **명칭의 근거 상태를 갱신한다.** 총괄이 직접 열람하여 전달한 작성자 발화는 다음 한 문장이다. “INPUT 원문 표기(A3 내 대여 목록,D2 대여 확정 후 알림)를 따랐습니다. 기존 prototype.html의 축약 표기와는 다릅니다.” 이는 작성자가 계약 표기를 따랐다고 설명한 근거다. 정정 요청 원문·시각·의도를 확보한 것은 아니다. 기존 초안의 ‘명칭 원 발화 전혀 없음’은 너무 넓으므로 ‘작성자 설명은 있음, 변경 지시·정정 발화는 미확인’으로 고친다. 검토자는 원 대화를 독립 열람하지 않았고, 이 발췌는 총괄 전달 근거로 표시한다.
2. **INPUT 9 누락을 마지막 결함/범위 사건으로 추가한다.** 계약 초안의 위치별 근거는 현 fix1 코드와 대응한다. 접힌 A 요약과 그 실제 끝점 A2 행에는 A2 소유 미결 참조가 없고, B 상세의 끝점 A2 행에는 변경·미결 참조가 없다. B 상세 자체에는 미결 내용과 소유 A2가 이미 있으므로 ‘B에 미결이 없다’고 쓰면 틀린다. B 미결 구역의 직접 A2 이동이 별도 공백이다.
3. **‘새 기준’으로 부르지 않는다.** INPUT 합격 기준 9는 이미 존재했다. 새로 작성한 것은 그 기준을 위치별로 확인할 검증 계약이다. 기존 독립 I1~I5는 끝점 수·복귀 상태·인계문 등을 검사했으므로 해당 위치의 참조 노출까지 검사한 것은 아니다. ‘5개 통과’와 이 누락은 양립한다.
4. **통과 주장보다 강한 완료 발화를 만들지 않는다.** 실제로 확보된 것은 검사 로그와 수용 문서다. 화면용 사건 제목은 ‘초기 검사 반환’, ‘좁은 수정 수용’ 정도로 한정한다. ‘전체 완료 선언→거짓으로 판명’은 근거가 없다.
5. **화면 분류는 연구 제안으로 둔다.** 산출물·작업·세션·변경·미결을 입력에 정리하는 것은 가능하지만 원 대화에 그 모델이 있었다고 말하지 않는다. 이번 입력은 특정 정보 구조·화면 배치를 정답으로 고정하지 않는다.

## 근거 확인 범위

검토자는 후보 문서, 입력·두 시안, 초도 독립 검토, fix1 독립 보고서, 수용 범위, 환경 상태, UI-03 연구, INPUT 9 검증 계약 초안과 후속 H1 위치별 상태 검사 결과를 읽었다. 코드의 표기와 누락 위치를 대조했다. 브라우저 실행이나 새 검사 실행을 하지 않았다. 기존 로그의 실행 시각과 대상 바이트 연결을 소급 인증하지 않았다.

검토 중 후속 위치별 검사 결과가 도착했다. H1의 사례 13개는 3 통과·10 실패였으며, 단언 90개는 72 통과·18 실패였다. 이는 Node 대역/생성 마크업 검사다. 초기 계약의 ‘미실행’은 그 문서 시점의 상태로 남기고, 입력 마지막 사건에는 실행 후 실패와 후속 수정 대기를 반영했다. 390 구조 목록의 직접 미결 경로 부재는 선택적 관측으로 필수 실패 집계에서 제외됐다. 실제 브라우저는 미실행이다.

소스 버전은 H0(초도 캔버스)와 H1(fix1)로 분리한다. H0의 SHA256은 `d0f3b7d378563b620aaa0ebfec34397f416b5d62b8d2f9d14df576b4f507840a`, H1은 `869c76a45f16042ec0a5063c81d1e638d21a2a3e87ce079b6bc5a60843632157`이다. 반환 파일의 동일성과 과거 실행 증명은 별개다.

현재 검토 기준 고정본의 문서 링크는 다음 입력의 출처 목록에 모았다. 두 새 문서는 기존 원문의 계정·대화 ID·로컬 경로·환경 식별자를 옮기지 않는다. 다만 링크 대상 원문까지 비식별되었다는 뜻은 아니다. 공개용 독립 표본을 만들 때는 원문 링크를 그대로 노출할지 별도로 결정해야 한다.

## 좁은 연구 질문 3개

**Q1 — 표기 차이와 변경 사건의 경계:** 이 10개 사건만 읽는 사람이 A3의 두 이름을 같은 대상의 다른 산출물 표기로 이해하면서, ‘누군가 정정 지시했고 승인됐다’고 추론하지 않도록 할 최소 표현은 무엇인가? 두 표현 대안 이하로 비교하고, 각각 오해를 드러내는 읽기 질문 하나를 제안하라. 변경 시각·원문·승인을 보충하지 말라.

**Q2 — 통과와 잔여 미결의 병치:** H1의 독립 5개 통과, INPUT 9 위치별 누락, 독립 브라우저 재실행 미완료를 한 산출물에서 읽을 때 사용자가 현재 할 수 있는 결론을 정확히 제한하는 최소 표시를 비교하라. 검사 수 합산·단일 완료 배지로의 축약·새 요구로의 오해를 어떻게 반증할지 답하라. 새로운 대규모 검사 체계는 제안하지 말라.

**Q3 — 다음 담당자에게 넘길 읽기 흐름:** ‘왜 초기 통과 후 보완이 남았는가’를 확인하고 직전 사건으로 돌아오는 한 경로에서, 반드시 보존할 근거·버전·미결은 무엇인가? 현재/과거 주장과 검증 범위를 놓치지 않는 최소 읽기 과업 2개를 제시하라. 화면 구조 확정·제품 구현·새 도구 조사는 하지 말라.

질문은 같은 표본을 공유하되 별도로 답하게 하면 쟁점을 분리할 수 있다. 답을 취합하기 전 ‘집중 읽기’ 등 특정 배치가 우월하다고 결정하지 않는다. 이번 검토에서 Pro에게 실제로 질문을 전송하지 않았다.

## 통합 권고

다음 입력의 10개 사건을 연구용 후보로 채택한다. 첫 문장에 ‘합성 도서 대여 예제를 구현한 실제 AI 개발·검증 기록’이라고 밝힌다. 명칭 정정 검증은 부분 충족으로, 미결과 검사 범위 차이 검증은 가능으로 보고한다. 최근 INPUT 9 계약과 후속 H1 실패 결과는 고정 저장소 문서와 다른 출처 단계임을 유지한다. 입력은 E10의 H1 누락 확인까지 동결한다. 관련 구현·재검증 결과가 나중에 도착하면 별도 후속 기록에 두고 이 원본을 덮어쓰지 않는다.
