# 전체 제품 목적 대비 현재 연구의 범위

2026-10-16 · 기준 `5a1f81454eac677d0b2473e9dc5157270594b871` · 독립 방향 대조 메모

이 메모의 기준·관측은 작성 당시 기록이며, 최신 조건부 후보는 이후의 [MECHANISM_REVIEW.md](MECHANISM_REVIEW.md)에 따른 A 판단 본문·인용 / B 자료·검사범위 중립 대조로 구분해 읽는다.

## 판단

현재 지도 연구는 **혼합 깊이의 포함·관계와 전체/부분 왕복**, 실제 기록 연구는 **검사 범위·미결·자료별 이름의 정확한 읽기**를 다룬다. 필요한 기반이지만 최종 제품 경험의 일부다. 검사 수와 증거 연결을 정교하게 만드는 일이 계속 중심이 되면, AgentFlow가 사용자의 개발을 이해·조정·인계하는 공간에서 검사 보고서 열람기로 좁아질 수 있다. 고정 여섯 자식 장면과 실제 AI 개발 기록 한 건 역시 서로 다른 입력이지만, 둘 다 같은 시안의 개발·검증에 연결되어 있다. 독립된 여러 제품 맥락을 포괄했다고 볼 수 없다.

최종 목적은 사용자가 평소 AI와 개발하는 동안 프로그램 구상과 변화를 이해하고, 필요한 부분만 조정하거나 이어 맡기며, 긴 대화 재독과 수동 보고를 줄이는 것이다. 아래의 ‘미검토’는 이번 작업의 결함이나 일괄 착수 목록이 아니다. 다음 선택이 전체 목적을 축소하지 않도록 보는 7개 축이다.

## 일곱 축의 범위 대조

| 축 | 현재 다룬 부분 / 아직 다루지 않은 부분 | 제품 경계 | 보존할 원칙 | 다음 좁은 비교에서 확인할 항목 |
|---|---|---|---|---|
| **1. 진입과 프로그램 목적** | 준비된 장면 안의 탐색은 다룸. 막연한 구상으로 시작, 기존 대화·저장소에서 시작, 프로젝트 재발견은 미검토 | 프로젝트 입구를 이번 시안의 고정 장면 선택기로 확정하지 않음. 연결기 완성은 연구 선행 조건이 아님 | 기존 AI에서 한 설명을 사이트에 다시 입력시키지 않음. 빈 부분을 억지로 채우거나 폴더를 목적의 정답으로 삼지 않음 | 선택한 기록을 읽기 전에 ‘무엇을 만드는 프로젝트이며 지금 어느 부분인가’를 알 수 있는가. 자료를 준비한 연구자가 아는 배경을 사용자도 안다고 가정하지 않는가 |
| **2. 구성 정체성과 관계** | 포함/외부 관계, 세 끝점, A3 자료별 이름을 다룸. 실제 분할·병합·폐기·공유 대상, 여러 목적의 지도는 미검토 | 이름 병기는 별칭·병합 엔진 확정이 아님. 산출물·검사·작업·세션을 프로그램 구성의 자식으로 만들지 않음 | 같은 대상의 연속성과 자료별 표현을 구분. 관계 미확인을 없음으로 바꾸거나 상위 관계를 자식에 복제하지 않음 | 근거 상세에 들어가도 대상의 종류와 소유가 유지되는가. 합성 정책 미정과 실제 표시 결함을 별개로 이해하는가 |
| **3. 전체와 집중의 역할** | 펼침·선택·보기 복귀와 집중 읽기 후보를 다룸. 깊거나 혼잡한 임의 배치, 다수 대상 비교, 실제 초보자/숙련자의 효과는 미검증 | 넓은 본문·캔버스·목록 중 하나를 제품 전체의 정답으로 고정하지 않음 | 확대축소와 상세 층은 별개. 읽기 후 선택·맥락·위치를 잃지 않음. 모든 정보를 동시에 보여 주는 것을 목표로 삼지 않음 | 같은 정보에서 이해에 필요한 왕복이 줄어드는가. 상세에 들어가야만 현재 대상과 관련 부분을 알게 되거나 돌아올 때 다시 찾게 되면 후보를 재검토 |
| **4. 자동 정리와 사용자 조정** | 근거가 없는 추정을 피하는 읽기 원칙은 다룸. 사용자 이름·묶음·결정 수정과 새 외부 기록의 만남, 필요한 확인만 묻는 흐름은 미검토 | 수동 입력·승인함·지도 관리가 기본 사용법으로 굳어지지 않음. 지금 추출 형식·모델·동기화 엔진을 확정하지 않음 | 기본 정리는 자동, 조정은 필요할 때. 화면 취향 변경과 작업 기준 변경은 영향이 다름 | ‘확인할 부분’이 모두 사용자의 숙제로 보이지 않는가. 미확인 이름·미실행 검사·실제 결함에 같은 경고나 일괄 승인 요구를 붙이지 않는가 |
| **5. 지속 갱신과 재방문** | E03 열람/E04 반영과 H1 동결 기록의 현재 상태 구분을 다룸. 반복·지연 수신, 동시 작업 충돌, 최신 기록 일부 누락, 갱신 뒤 배치 안정성은 미검토 | 동결 연구 입력의 수동 재생을 최종 제품의 보고 절차로 삼지 않음. 이번 읽기 비교를 전체 갱신 엔진 검증으로 확대하지 않음 | 작성 시각·반영 범위·열람 범위는 다름. 늦은 기록과 새 성공이 과거 판단을 덮지 않음 | 사용자가 보는 ‘현재’의 기준을 알 수 있는가. 과거 H1 미결과 최신 프로젝트 상태를 섞지 않으면서, 돌아온 사람이 관련 변화만 찾을 수 있는가 |
| **6. 이해에서 위임·교체로 연결** | 합성 인계문의 목적·범위·미결과 후보/미전달 의미는 다룸. 실제 담당 교체, 여러 구성에 걸친 작업, 결과 소속 정정, 외부 반영 확인은 미검증 | 외부 개발 도구의 전체 실행 기능을 다시 만들지 않음. 근거를 읽었다고 전달·수락·수행 완료로 바꾸지 않음 | 프로그램 대상은 세션 교체 뒤에도 이어짐. 맥락과 기준 버전은 인계의 핵심이며 중요한 조건을 축약해 지우지 않음 | 선택한 부분에서 필요한 다음 판단을 할 수 있는가. 이번 표본에 실제 인계가 없으면 ‘인계 성공’을 추가하지 말고, 무엇이 다음 담당자에게 필요한지의 읽기만 평가 |
| **7. 기존 해결책 탐색과 채택** | 기존 도구 메커니즘을 출처와 반례로 검토함. 제품 사용자가 선택한 영역에서 해결책을 찾고 채택·제외하는 흐름은 아직 다루지 않음 | 연구 중의 반복 Pro 조사와 향후 제품 내 추천 모듈은 별개. 검색 DB·수집 서비스 구축을 현재 UI의 선행 조건으로 두지 않음 | 발견·채택·실제 사용은 다름. 기존 좋은 메커니즘은 재사용하되 도구 목적·노드 체계를 통째로 이식하지 않음 | 상세가 기록 열람만의 막다른 공간으로 고정되지 않는가. 추천을 나중에 연결할 자리와 대상 맥락은 보존하되 이번 두 안에 근거 없는 추천 결과를 추가하지 않음 |

## 다음 한 비교를 넓히지 않고 보완하는 방법

이 메모 작성 당시의 초기 후보는 **동일 기록의 범위표와 ‘확인할 부분’ 목록**이었다. 이후 조사와 [MECHANISM_REVIEW.md](MECHANISM_REVIEW.md)에 따라 **A 판단 본문·문장별 인용과 근거 미리보기 / B 자료·검사범위별 중립 대조**로 조건부 변경했다. 초기 후보를 최신 실행안으로 유지한다는 뜻은 아니다. 위 일곱 축과 아래 세 경계는 새 A/B에도 유지하며, 일곱 축을 모두 별도 화면이나 구현 항목으로 만들지 않는다.

1. **대상 이해:** 사용자가 검사 결과에 앞서 프로젝트 목적·선택 부분·관련 영역을 설명할 수 있는가. 현재 입력에 없는 목적이나 관계를 정답처럼 채우지 않는다.
2. **과도한 개입 방지:** 미실행·미확인·확정 결함을 구별하고, 확인 목록이 사용자에게 모든 정리를 떠넘기지 않는가. 목록 순서를 작업 우선순위나 이미 승인된 배정으로 읽으면 실패다.
3. **행동과 복귀:** 근거를 확인한 뒤 무엇을 판단할 수 있게 됐는지, 기존 대상과 보기로 돌아올 수 있는지 본다. 실제 조정·위임을 수행하지 않았다면 ‘행동 가능성의 읽기’와 ‘실행 성공’을 구분한다.

두 표현이 모두 이 과업을 만족하면 표의 정보량이나 통과 단언 수로 승자를 만들지 않는다. 사용자에게 추가된 읽기·찾기·관리 부담과 보존된 맥락을 비교한다. 차이가 관측되지 않으면 좁은 결과로 종료하고, 같은 기록의 장식 수정만 반복하지 않는다. 다음 조사·표본은 총괄이 선택을 바꿀 미해결 한 가지에 맞춰 정한다.

새 Pro 조사는 이미 알려진 도구 이름을 재확인하는 데 머무르지 않고 **해결한 문제 → 실제 메커니즘 → AgentFlow 적용 조건 → 부적합 조건 → 선택을 바꿀 장면**으로 회수하면 된다. 이는 새 기능 목록을 받기 위한 요구가 아니다. 이번 메모는 추가 사이트 조사·시안 구현·원격 반영을 하지 않았다.
