# 동일 동결 기록의 읽기 비교 — 관찰표 초안

2026-10-16 · **사전 실험 설계 / 미실행** · 조사 회수 후 조건부 A/B로 좁힘 · 구체 UI·최종 채택은 미확정

기준: [동결 INPUT](INPUT.md), [RESEARCH](RESEARCH.md), [PRODUCT_LENS](PRODUCT_LENS.md), [최신 메커니즘 검토](MECHANISM_REVIEW.md). 비교 대상은 같은 E01~E10을 읽는 아래 두 표현이다. 이전의 범위표·확인할 부분 목록은 역사적 제안으로 보존하며 세 안을 동시에 비교하지 않는다. fix2/fix3·후속 브라우저 결과로 동결 시점의 상태를 갱신하지 않는다.

## 이번 두 후보

| 후보 | 비교할 읽기 방식 | 선택을 바꿀 위험 |
|---|---|---|
| **A: 판단 본문＋문장별 근거 미리보기** | 대상의 짧은 맥락과 확인·미확인 범위를 서술하고, 필요한 문장의 근거를 제자리에서 읽는다. | 유창한 본문이 근거보다 강한 결론을 만들거나, 인용 존재·개수만으로 신뢰를 얻고 범위가 다른 자료를 가리는 경우 |
| **B: 자료·검사범위별 중립 대조** | 자료명·관측 위치·검사 방식과 범위를 주어로 대응 가능한 내용만 대조하고, 선택한 셀의 근거를 읽는다. | 서로 다른 검사 묶음을 같은 측정으로 정렬하거나, 열 순서를 시간·승인 순서로 읽고 빈칸을 실패로 만드는 경우 |

‘중립’은 검증된 성질이 아니라 B의 설계 의도다. 한 안만 더 많은 요약·근거를 갖게 하지 않는다. 현재 표본의 이름 차이·검사 범위 차이를 양립 불가능한 상충 주장으로 꾸미지 않는다.

## 같은 조건으로 두기

- 두 안에 동일한 E01~E10, 대상·버전·역할·출처 설명·요약 문구를 제공한다. 근거의 양과 접근 가능한 범위도 같게 한다. A의 문장과 B의 셀이 같은 사실·한계를 담도록 맞추고 한쪽만 정답 요약·추가 경고를 주거나 정보를 생략하지 않는다. 별도 사실을 추가하지 않고 서술·대조의 조직과 읽기·복귀 경로를 비교한다.
- 같은 시작 대상·읽기 위치, 공통 공간 배치, 프로젝트·선택 대상·관련 영역의 맥락, 화면 크기·글자 크기·대비, 질문 문구·순서·도움 규칙을 사용한다. A만 넓은 본문, B만 옆 패널로 두는 식으로 공간과 정보 표현을 동시에 바꾸지 않는다. 좁은 화면에서 모든 패널을 계속 노출하는 대신 대상·소유·반영 범위·돌아갈 위치를 두 안 모두 보존한다. 장식·정보량·공간 차이가 남으면 먼저 기록하고 표현 방식의 우위로 귀속하지 않는다.
- 작성자 84단언·독립 5사례·새 13사례는 버전이 같아도 목적·환경·검사 범위가 다르다. 통과 수를 합산·순위화하거나 하나의 완료율로 만들지 않는다. 대응하지 않는 대조 셀은 ‘이 범위의 비교 대상 아님’일 수 있으며 미실행·실패와 구분한다.
- 가능한 사람 관찰에서는 제시 순서를 A→B / B→A로 나눈다. 같은 사람이 같은 기록을 다시 읽으면 학습 효과가 있으므로 두 번째 결과를 독립적인 첫 이해로 세지 않는다. 한 명만 관찰하면 순서 효과를 분리할 수 없다고 남긴다.
- 아래 다섯 질문만 사용한다. 짧은 말과 사건 ID만으로 답할 수 있고, 전체 기록 재작성·모든 출처 감사·직접 수정·승인을 요구하지 않는다. 문장별 인용이나 대조 셀을 전수 검수하는 일을 사용자의 기본 숙제로 만들지 않는다. 필요한 판단의 근거만 읽어도 된다. ‘모름’, ‘지금 할 일 없음’, 중단도 허용한다. 진행자는 정답·버튼 위치·어느 안이 좋은지 알려 주지 않는다. 도움을 주었다면 도움 전 관찰과 이후 관찰을 나눈다.

## 미리보기와 실제 원문 이동

두 안에서 같은 제공 발췌·출처 설명을 미리 볼 수 있고 같은 원문 접근 조건을 갖게 한다. 미리보기는 출발 문장(A) 또는 질문·비교 상대가 있는 행(B)을 남겨 읽는 동작이며 원문 전체·최신판을 읽었다는 뜻이 아니다. 전달 발췌를 원문으로 표시하지 않는다. ‘원문 위치로 이동’은 별도 조작으로 구분하고, 실제 원문 제공·이동·복귀를 수행한 경우에만 성공을 기록한다.

미리보기 닫기의 문장·행·읽기 위치 복원과 실제 원문에서 돌아올 때의 대상·선택·펼침·위치 복원을 따로 관찰한다. 초점만 돌아온 것을 전체 보기 복원으로 세지 않는다. 원문이 없거나 접근할 수 없으면 그 사유를 표시하고 원문 이동을 **미실행**으로 남긴다. 근거를 읽은 사실을 문장의 정확성·승인·수신·수행 완료로 바꾸지 않는다.

## 질문과 입력 안의 판정 근거

질문은 참여자에게 보여 주되, 오른쪽 판정 근거는 관찰자용이다. 제품 목적에 대한 배경 지식을 정답으로 요구하지 않는다.

| ID | 유도 없이 제시할 질문·과업 | 입력에서 확인 가능한 근거 / 미확인 경계 | 기록할 관찰 |
|---|---|---|---|
| Q1 | 이 기록은 어떤 일을 다루며, 지금 보고 있는 대상과 시점은 무엇입니까? | INPUT의 목적·출처 경계: 합성 도서 대여 예제를 구현한 실제 AI 개발·검증 기록이다. 실제 고객 기록이 아니다. 의미 시안/H0/H1을 구분하고 현재 표본은 H1의 E10까지 동결이다. 프로젝트 전체 목적의 상세·제품 최종 기능은 이 표본만으로 확정하지 않는다. | 검사 숫자를 보기 전에 대상·종류·시점의 맥락을 얻는지, 연구자가 아는 배경을 추정하거나 다시 입력해야 하는지. |
| Q2 | 자료마다 이름은 어떻게 쓰였고, 그 차이에 대해 어디까지 알 수 있습니까? | E01: 의미 시안 ‘내 목록’, 캔버스·INPUT ‘내 대여 목록’. 작성자 설명은 있으나 정정 요청·승인·시각·의도는 미확인이다. 자료 차이를 승인된 변경 전후로 답하면 상태 오류다. | 자료명을 구분하는지, ‘미확인’을 ‘없음’이나 ‘승인됨’으로 바꾸는지. |
| Q3 | 이 동결 시점에 확인된 결과와 남아 있는 것은 무엇입니까? | E04~E07: 목록 복귀 결함과 H1의 좁은 수정, 작성자 브라우저 기록과 독립 Node 5개 통과는 별도다. E09~E10: 지정 위치의 참조 누락과 후속 수정 대기. E08: 독립 브라우저·읽기 효용은 미완료다. 합성 A2 정책 미정과 실제 UI의 미결 참조 누락은 서로 다른 소유·범위다. 84·36·5·10 또는 13사례·90단언을 전체 완료 수로 합치지 않는다. | 통과·확인된 결함·미실행·미확인을 구분하는지, 과거 통과를 취소하거나 뒤의 성공을 끌어오는지, 정책 결정과 표시 수정의 대상을 혼동하는지. |
| Q4 | 지금 자신이 할 일이 있는지, 어떻게 판단하겠습니까? | 입력은 확인된 누락과 미확인 항목을 기록하지만 참여자에게 전부 조사·수정·승인하도록 배정하지 않는다. 다음 판단에 필요한 자료를 짚거나 당장 할 일이 없다고 답할 수 있다. 특정 작업 선택을 정답으로 정하지 않는다. 실제 인계·수신·수락 성공은 표본에 없다. | 문장별 인용·대조 셀을 모두 자신의 검수 숙제로 읽는지, 표시 순서를 우선순위·의존성·승인된 배정으로 읽는지, 추가 입력·관리 부담을 느끼는 이유. 부담 표현 자체를 참여자의 오답으로 채점하지 않는다. |
| Q5 | E09의 근거를 이 자료에서 확인한 뒤, 읽던 곳으로 돌아오세요. 무엇을 확인했습니까? | E09와 이미 제공된 S01/S03/P02의 출처 설명을 연결한다. 원문·전달 설명·검토 요약의 수준을 구분한다. 기존 5개 통과와 별개로 위치별 공백을 다룬다는 판단은 보존된다. 원문을 제공하지 않았다면 출처 설명을 읽은 일을 원문 전체 검증으로 세지 않는다. | 근거에 도달하는 경로, 추가 찾기·도움, 대상·버전·선택·펼침·읽기 위치의 복원, 판단이 달라졌다면 이유. 새 선택과 직전 보기 복귀를 구분한다. |

Q5는 두 안에서 같은 E09 시작 위치와 같은 제공 근거로 수행한다. 근거 미리보기만 열었는지 실제 원문으로 이동했는지, 각각 어디로 돌아왔는지를 분리한다. 원문이나 조작 가능한 표현이 아직 준비되지 않았다면 해당 내용 검증·왕복은 **미실행**으로 남긴다. 이 초안 작성 중 새 출처를 회수하거나 화면을 실행하지 않았다.

## 관찰 기록과 판단

| 관찰자·읽은 주체 / 실제 수행 방식 / 표현·제시 순서 | 질문 | 첫 답변·사건 근거 | 판정과 이유 | 찾기·도움·미리보기/원문 왕복·추가 숙제 부담 | 도움 또는 근거 확인 뒤 바뀐 점 |
|---|---|---|---|---|---|
| 미실행 | Q1~Q5 각각 기록 | 미기록 | 미실행 | 미관측 | 미관측 |

판정은 **일치 / 부분 이해 / 상태 오류 / 기타 오독 / 못 읽음 / 미실행**을 구분한다. 상태 오류는 미확인을 확정, 미실행을 실패, 제안을 배정·완료, 근거 열람을 승인·인계 성공으로 바꾸거나 서로 다른 버전·소유·검사 범위를 섞은 경우다. 못 읽음은 시도했지만 내용을 찾거나 해석하지 못한 경우이며 틀린 상태를 주장한 경우와 다르다. 미실행은 참여·과업·조작 자체를 수행하지 않은 경우다. 모른다고 정확히 답한 미확인 항목은 못 읽음으로 처리하지 않는다.

Q1~Q4의 첫 답변과 Q5 근거 확인 후 답변을 분리하고, 원문 답변을 짧게 남겨 관찰자의 추정을 구분한다. 시도·복귀·도움이 실제 관찰된 경우에만 경로와 부담을 적는다. 주관적 선호와 근거를 잘못 읽은 오류를 합산한 점수는 만들지 않는다.

사람이 수행한 관찰과 AI의 텍스트 읽기·자기평가는 별도 기록한다. AI가 정확히 답했거나 경로를 설명했다고 사람 사용성·실제 클릭·복귀 성공으로 보고하지 않는다. 두 안이 모두 같은 과업을 만족하거나 차이가 관측되지 않으면 승자를 만들지 않는다. 관측된 이해·찾기·복귀 부담과 그 한계만 남기며, 이 한 표본의 결과를 제품 전체·임의 프로젝트·자동화·인계 성공으로 일반화하지 않는다.
