## 현재 판단

v0에서 발견한 ‘닫았지만 근거 본문이 남음’은 실제 표시 규칙을 보완하는 좁은 수정으로 처리했다. A의 f15/f16은 H1·위치를 문장 자체에서 읽도록 바뀌었다. 새로운 사실·동결 이후 결과·비교 기능은 넣지 않았다. 독립 Cloud 실제 조작과 원본 감사를 받아 **이번 좁은 수정과 지정 로컬 동작을 수용한다.** 이 수정으로 A/B 중 하나의 우월성이나 제품 최종 품질을 결정하지 않는다.

총괄은 정확한 fix1을 실제 IAB의 1280×720에서 열고 E09 버튼과 닫기 버튼을 눌렀다. 닫은 뒤 `pvBody.hidden=true`, computed display `none`, 본문 박스 0×0, 초점 `ab-f14`를 확인했다. 기존 v0의 같은 경로에서 남았던 본문은 이 관측에서 사라졌다. 전체 여섯 화면 조건·사람 읽기·원문 왕복을 이 한 경로로 통과 처리하지 않는다.

## 독립 실행에서 판단을 바꾼 이유

Cloud는 A/B 각각1440×900·390×664·390×844에서 실제 HTTP→Chromium으로 수행했다. 미리보기 내부에는 실제 wheel 입력을 했고, 본문 위치 준비의 DOM 스크롤은 별도로 기록했다. 버튼·Escape 왕복12개에서 내부 scroll+240, 본문 변화0, 닫은 뒤 출발 초점·선택 유지와 본문/버튼 위치 차이0을 관측했다. 이를 전체 터치 탐색·모든 크기의 검증으로 확대하지 않는다.

첫 실행의6실패는 표현 전환 전후의 미리보기 scrollTop 숫자를 같게 요구한 검사였다. 두 번째 검사가 이를 비영 값만 남으면 통과하도록 낮췄지만 총괄은 그것만으로 읽기 보존을 인정하지 않았다. 기존54개 확인·내부6개 미검증·외부2개 차단으로 보수 판정한 뒤, **같은 E09 텍스트·줄·가시 구간**을 전후 측정하는 여섯 전환만 추가했다. 모두 동일 텍스트와 보이는 줄이 유지됐고 상대 위치 차이는 최대0.734375 CSS px였다. 출발 인용의 높이가 바뀌며 스크롤 수치가 보정되는 설명과 일치한다. 관측한 읽기 위치의 보존이며 모든 위치나 브라우저 내부 알고리즘을 증명한 것은 아니다.

[첫 실패·두 번째 실행·보수 판정 원본](https://github.com/tlsee0813-cmd/agentflow-studio/tree/ce91a08fe8ff641a491d34bf35de732f85816792/docs/transfer/real-record-02/fix1)과 [추가 여섯 관측](https://github.com/tlsee0813-cmd/agentflow-studio/tree/ce91a08fe8ff641a491d34bf35de732f85816792/docs/transfer/real-record-02/fix1/continuity-addendum)을 함께 보존했다. 실제 종료코드는 첫 실행1, 두 번째0, 오프라인 보수 판정1, 추가 관측0이다. 과거 기록을 마지막 결론으로 덮지 않는다.

외부 GitHub 원문은 실제 새 탭에서 인증서 신뢰 오류로 열리지 않았다. 실제 원문 읽기·왕복은 미실행으로 남기며 스텁·raw 요청·경고 우회로 대체하지 않았다. 원본 전후 해시는 동일하고 fatal/pageerror/cleanup 오류는 없었다.

## 표현 판단에 남는 것

- B의 390폭은 근거를 열 때 비교 상대 행이 함께 남지 않는다. 모바일 나란히 대조 조건은 충족하지 않으며, 행별 읽기·복귀가 가능하다는 것과 다르다. 이번에 별도 비교 기능을 더하지 않았다.
- 선택은 근거 버튼으로 고른 사실을 닫은 뒤 유지하는 동작이다. 미리보기를 열기 전의 다른 선택을 되돌리는 기능으로 부르지 않는다.
- 상태14종과 근거 버튼의 밀도, 나머지 문장의 문단 맥락 의존은 읽기 부담의 관찰 대상이다. 모든 문장을 새 개발 항목으로 만들지 않는다.
- 한 실제 AI 개발·검증 기록을 사용했지만 합성 도서 대여 예제를 개발한 기록이다. 여러 실제 고객 프로젝트나 일반적인 프로그램 변경을 검증한 것은 아니다. [사람 읽기 관찰](READING_TRIAL.md)은 미실행이며 승자를 정하지 않는다.

## 다음 범위의 이유

이번 기록의 모든 모서리를 다듬는 것을 다음 목표로 두지 않는다. 사용자 검토를 수용해 [역할별 AI 사전 평가](READING_ROLE_PRECHECK.md)를 회수했으며, 기본 지도에는 짧은 현재 설명·중요 변화·필요한 판단을 놓고 정밀 근거·범위 대조는 상세에서 활용하는 흐름을 다음 후보로 둔다. 이 평가는 자료를 아는 AI의 비평이며 사람 사용성 결과가 아니다.

[사용자 조정·새 기록의 기존 메커니즘 조사](UPDATE_MECHANISM_REVIEW.md)도 회수하고 공식 코드로 독립 대조했다. Home Assistant·Penpot·Zotero를 비교했지만 특정 제품의 정책이나 소스를 통째로 채택하지 않는다. [FIX058의 비QA 변경 기록 후보](REAL_CHANGE_CANDIDATE.md)는 실제 개발을 보고한 문서로서 입력 폭을 넓히는 데 유용하나, 사용자 원발화·실제 인계 수락은 없다. 다음 흐름에서도 이 빈칸을 만들지 않는다.

main·공개 배포·제품 소스는 이번 읽기 연구의 변경 대상이 아니다. 현재 상태와 후속 연구는 [ACTIVE](../ACTIVE.md)에서 이어 읽는다.
