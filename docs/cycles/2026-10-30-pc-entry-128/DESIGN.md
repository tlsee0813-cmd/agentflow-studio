# 128 — 기존 설치를 쓰는 선택형 PC 시작

## 사용자 문제와 선택

현재 제한 공개127은 기존 지도를 읽고 변경안을 이어 가는 범위다. 원기록뿐인 새 사용자는 첫 지도를 만들 수 없다. 로컬에서도 기본 start-local.ps1는 DeepSeek 서버를 열고, 실제104/122 FIRST 및121 RETURN이 성공한 owned CLI는 cycle102 preview 명령과 private policy로만 실행된다. 123의 첫 지도 중앙 입구 수리는 이미 수용됐으므로 반복하지 않는다.

독립 검토의 A를 좁게 채택한다. **이미 설치·로그인된 Codex가 있는 이 Windows PC에서, 정책 JSON 수작업 없이 명시적으로 선택해 시작하고 자신의 원문을 입력할 수 있는 로컬 입구**를 만든다. 공개127의 map/jobs 차단이나 기본 DeepSeek 실행을 변경하지 않는다. 새 연결기·AI품질 연구·별도 저장체계는 추가하지 않는다.

기준: 제품8a3bf347364e9615f3023d59bf5604835455d3f0, appd5a6be031fb06b925a1511e06c5845f15d56ec14. UI75693 수리와 stash·키·기존 저장을 보존한다.

## 구현 범위

- 기존 start-local.ps1와 구별되는 선택형 PC 실행 명령/입구 및 짧은 한국어 사용 안내. 사용자는 기존 CLI 경로를 선택할 수 있지만 모델·권한·실행인자를 임의 구성할 필요가 없다. 설치·로그인·계정전환·빌드 환경 재설치는 하지 않는다.
- 이미 성공한 121/122 고정 정책을 재사용한다. CLI0.165.0-alpha.1.2, binary SHA256 5c1b55966bf9f757dcbf00065c9a6cb862ead55d34b015f1be1939ff18e43943, gpt-6.1-sol/high, 299초선택/300초판정, 같은 tool/config 격리 인자, scope map7-later(FIRST6 및후속7). 허용하지 않은 바이너리는 설명하고 멈춘다. 자동 업데이트/다운로드/대체 모델/재시도는 없다.
- 기존 createContinuityApp/studio handler/map-jobs/CLI executor를 사용한다. 기존 엔진을 다시 만들거나 기본서버·Worker에 암묵적으로 로드하지 않는다. executor 코드 이동은 필요하지 않다.
- 안정된 로컬 주소·저장소로 돌아온다. 시작만으로 생성하지 않는다. 이미 열린 다른 서버를 성공으로 오인하지 않으며 실행자·scope·정책과 해당 저장소/소유를 구별한다. 타 프로세스를 종료하거나 잠금/lease를 삭제해 시작하지 않는다.
- 기존 실행기 종료·소유권·미확정 차단 계약을 유지한다. 종료와 다시 열기가 사용자가 수행 가능한 행동이어야 한다. 키/원문/인증자료를 로그·명령인자·브라우저 저장에 복사하지 않는다.
- DeepSeek 환경키가 없어도 첫 지도 경로 자체의 준비/미준비를 정확히 알린다. 기존 변경 구상 등 별도 기능의 공급자 제한을 전체 Codex 준비 실패와 혼동하지 않는다.

## 완료 조건과 증거

1. 설치된 고정 바이너리로 정상 시작 → 정확 실행자 확인 → 정상 프로젝트 원문 입력 입구까지 Root 직접 PC 확인. 새 AI 생성0으로 종료한다.
2. 기존 저장된 작업의 읽기·재시작 보존, 다른 포트/서버 오인 방지와 정상 종료. 실행자 미확정 상태를 숨기지 않는다. 정상 사용자 동작과 제어 fixture를 구별한다.
3. 바뀐 실행 경계의 의미 있는 검사와 독립 검토, 정확 SHA의 필요한 CI. 작은 검사 수를 전체 제품 완성으로 세지 않는다.
4. 결과·사용법·최소 증거 GitHub, 기존 공개73/127·기본실행·키·stash 불변.
