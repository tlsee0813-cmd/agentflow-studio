# cycle10 선택 근거와 좁은 구현 계약

2026-10-16 연구 판단 시점의 기록. [범위](BRIEF.md) · 현재 배정은 [ACTIVE](../ACTIVE.md).

## 선택: 실제 수신부가 구별되는 목록 + 간결한 관계 참고

현재 G3의 R2/R3는 같은 출발점과 같은 종류만 보이므로 열기 전 선택 근거가 없다. **묶음 안의 실제 끝을 목록에서 식별하고, 열린 참고에서는 양끝·소속·조건을 짧게 읽는 안**을 구현 대상으로 선택한다. 다섯 공간 역할·원래 여섯 관계·현재 선택/준비 분리·기존 복귀를 유지한다.

Pro A의 DataTables 원리는 목록의 식별 정보를 먼저 두고 상세에서 구조적으로 숨겼던 정보만 추가하는 사례다. 총괄의 실제 공식 데모 조작에서도 이 동작을 관측했다. 그러나 우리 화면에서 다른 위치에 한 번 나왔다는 이유로 끝점 정보를 없애지 않는다. **현재 참고만 읽어도 실제 양끝과 방향을 알 수 있어야 한다.** 기본 지도를 표로 바꾸거나 해당 라이브러리를 도입하지 않는다.

## 무엇을 유지하고 무엇을 줄일지

- G3의 받음 항목은 ‘AI 입력’과 ‘작업문과 미리보기’가 각각 실제 수신부임을 열기 전에 드러낸다. 같은 보내는 곳/요청 사본이라는 사실도 잃지 않는다. R ID와 색만으로 구별하지 않는다.
- C21의 보냄 항목은 이미 C31/C32가 구별되므로 수신부 문구를 무조건 추가해 중복시키지 않는다. 선택된 세부, 선택된 묶음, 받음/보냄을 구분한다. 이번 원래 여섯 관계만 구현·검증하며 없는 내부 관계를 새 표본으로 발명하지 않는다.
- 열린 참고는 실제 양끝 이름·방향, 필요한 소속·접힌 대표 차이, 해당 관계 조건을 보존한다. 큰 양끝 카드와 같은 소속 설명을 반복하는 면적은 줄인다. 조건이나 실제 끝을 ‘앞에서 봤음’으로 생략하지 않는다.
- 읽기 전용·지도 선택 유지·준비문 불변은 짧게 알린다. 버튼/Escape 닫기와 명시 이름을 가진 지도 이동은 구분한다. 원문 링크와 관계 ID는 필요한 상세 근거로 남기며 기본 목록의 주된 정보로 올리지 않는다.
- 390에서 목록의 구별 문구와 참고의 핵심 조건이 실제로 읽혀야 한다. 글자 축소·말줄임으로 핵심을 숨기지 않는다. 참고의 모든 내용과 전체 지도를 동시에 한 화면에 넣을 필요는 없지만 닫기·원래 항목 복귀 경로는 찾을 수 있어야 한다.
- 기존 G3 준비 불가/세부 선택, C32 등 세부의 네 준비 필드, 사본 유지·빈값 처리·직접 편집 우선 조건을 그대로 둔다.

R3 조건은 명시 새 요청 시 고정한 그 요청의 사본이며 최신 지도 구상으로 덮어쓰지 않는다는 뜻이다. 없거나 비면 별도 배경 블록을 생략한다. R5의 일치하는 반환 식별자와 R6의 정확히 연결된 대상 작업 조건도 서로 합치지 않는다. 입력 FACTS/RELS/준비 기본값을 새로 쓰는 작업이 아니다.

## 보류: 선 방향촉과 갈래 변경

Pro B가 찾은 JointJS의 선 몸통 방향촉은 대표점 원과 방향을 나누는 유효한 후보지만, 75% 배치는 예제 값이다. 실제 우리 코드에서 접힌 수신 끝은 화살촉을 **생략**하며 단순 가려짐만은 아니었다. 투명 클릭 경로14px와 양끝 제외도 이미 있다. React Flow의 클릭 영역 분리 원리를 새로 만들 필요가 없다.

이번 문제인 G3 목록의 R2/R3 구별에는 선 기하 변경이 필요하지 않다. 따라서 **cycle10에서는 방향촉·곡선 경로·클릭 폭·배치 엔진을 바꾸지 않는다.** 짧은 선/집계 숫자와의 충돌을 실제로 비교할 별도 방향 연구 후보로 남긴다. 조사 목록이 전부 개발 목록이 되는 것을 피한다.

## 실제 관측과 근거 수준

[DataTables 공식 Class control](https://datatables.net/examples/responsive/column-control/classes.html)을 총괄 IAB에서 조작했다. 390×844에서 Name/Position 열의 Airi Satou 행을 펼치면 Office(Tokyo)·Salary·Extn만 추가되고 Name/Position은 반복되지 않았다. 열린 채 1280×720로 바꾸자 Office/Salary는 본행으로 복귀하고 상세는 Extn만 남았다. 넓은 쪽은 DOM의 실제 innerWidth/Height도 확인했다. 확대 후 기존 스크롤이 다른 위치를 가리켜 행을 닫고 재열어 실제 넓은 화면을 관측한 절차는 최초 자동 resize 관측과 구분한다. 좁은 화면의 가로 넘침도 있었으므로 모든 픽셀 가독성 보장이 아니다.

현행 페이지는 Responsive4.1.1 CDN 링크를 표시한다. [고정3.0.3 코드](https://github.com/DataTables/Responsive/blob/935c1f4efc8aa7b8c63e83921a693fe806279e36/js/dataTables.responsive.js#L1556-L1632)와 동일 실행 버전이라고 쓰지 않는다. ‘all’은 Responsive breakpoint 포함 규칙이고, listHidden은 구조적 숨김 기준이다. tableAll도 앞 단계에서 never/control이 제외된 columns 범위를 출력한다. 자세한 코드 예외는 [목록 출처 감사](LIST_SOURCE_AUDIT.md)에 있다.

[JointJS4.1 문서](https://docs.jointjs.com/4.1/learn/features/customizing-shapes/relative-position-on-links/)도 총괄이 방문해 양끝 원/0.75 방향촉의 공식 예제 코드를 읽었다. 내장 preview는 관측 당시 화면 아래에 있었고 직접 조작하지 않았다. 사이트 실행 실패로 판정하지 않는다. React Flow 실행 데모도 미조작이다. Pro의 문서/고정 코드/정적 그림, 보조 세션의 브라우저 표면 미제공, 총괄의 실제 DataTables 조작을 구분한다. [방향 출처 감사](DIRECTION_SOURCE_AUDIT.md).

## 필요한 검증과 전달

기준 fix1 54,524B/SHA90141c4c…53173에서 차이를 남긴다. 1280×720·390×844에서 G3와 C21의 R2/R3 목록을 열기 전 실제 글자로 구별하고, 각각 올바른 실제 양끝/조건의 참고로 연결되는지 확인한다. 참고를 바꿔 읽기·반복 버튼/Escape 닫기·명시 이동의 선택/깊이/초점과 실제 본문 제거를 확인한다.

C32의 네 준비 필드 중 실질 문장 E를 편집한 뒤 새 참고를 왕복하고 재진입해 값 보존을 확인한다. 다른 세부의 준비로 섞이지 않아야 한다. 비초기 깊이·배율·스크롤 복귀와 초기 무선택→선택의 카드/선 변화를 관측하되, 선 기하는 정확 문자열 동일 대신 기존 허용차와 원시 차이를 기록한다. R1–R6의 종류도 이번에는 기대 문자열과 명시 대조한다.

실제 브라우저/소스 HTTP·전후 hash·필수 완료 장면·child/collector 종료를 남긴다. 문자/clip/hit와 실제 viewport를 분리하고, DOM 스크롤 보조를 썼다면 명시한다. 검사기 오류·첫 제품 실패를 보존하고 바뀐 검사 코드는 해시별로 남긴다. PNG는 마지막 대표4장 정도와 중요한 실제 결함 장면만 남겨 중복 보관을 줄인다. 검사 수를 사용자 장면 수·사람 이해 결과로 확대하지 않는다. 작성자 결과 뒤 독립 검증을 별도로 수행한다.
