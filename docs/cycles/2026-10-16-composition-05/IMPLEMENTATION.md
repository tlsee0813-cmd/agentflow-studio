# cycle05 클릭 시안 계약
2026-10-16 · [입력](INPUT.md) · [선택 이유](DECISION.md). 담당: Opus, 연구용 독립 HTML. 현재 배정 상태는 [ACTIVE](../ACTIVE.md).

## 사용자 장면
AgentFlow의 과거 기록에서 ‘요청에 배경을 함께 담되 이미 맡긴 일은 당시 배경을 지킨다’는 변경을 살핀다. 기본 화면에서 프로그램의 기능 일부와 바뀐 부분을 찾고, 한 부분의 상위/외부 맥락을 이해한 뒤 필요한 확인·조정의 준비문을 편집하고 전체로 돌아간다. 이 표본은 개발 계약/MOCK 보고이며 실제 원대화·새 AI 실행을 흉내 내서 사실처럼 보이지 않는다.

## 의미·구성 계약
- 보기용 기능 묶음5개: **구상과 목적 / 요청 맥락 / 전달할 내용 / 결과 연결 / 저장·복구**. 이는 AI가 제안한 기능 구성안이다. 실제 코드 모듈 포함/소유/자동 실행 순서가 아니다.
- 필요한 부분만 세분화: 요청 맥락 안 ‘새 요청의 배경 고정’·‘요청 범위 구분’; 전달할 내용 안 ‘AI 입력’·‘작업문과 미리보기’; 결과 연결 안 ‘일반 보고 연결’·‘파일 반환 연결’. 나머지는 큰 구상으로 남긴다. 혼합 깊이를 사용자가 개별적으로 바꿀 수 있게 한다.
- 기본 변경 소유는 F1의 **작업문과 미리보기**(목적을 별도 배경에 포함)로 한정한다. 관련 기능을 모두 변경 완료로 강조하지 않는다. 접힌 부모는 ‘안에 바뀐 부분’이라는 집계이며 모든 자식의 변경이 아니다.
- 명시 관계6개만 사용: 구상과 목적→배경 고정(명시 새 요청 때만), 배경 고정→AI 입력(요청 사본), 배경 고정→작업문과 미리보기(요청 사본), 작업문과 미리보기→저장·복구(내보내기 기록의 사본), 저장·복구→파일 반환 연결(일치하는 반환 식별자), 배경 고정→일반 보고 연결(정확히 연결된 대상 작업의 사본). 각 관계는 원문 사실을 요약한 것이며 구현 실행 순서가 아니다.
- 접힌 대상에 집계 표시를 하더라도 원래 관계 ID·양끝·종류가 남고 눌러 실제 대상들을 확인한다. 관계6개 또는 양끝의 수를 UI 품질 점수로 쓰지 않는다. 미지정 부분을 무관함으로 바꾸지 않는다.
- 기능 지도와 작업/요청 예시는 구별한다. 요청·세션을 기능의 자식으로 두거나 실제 담당자를 만들지 않는다. 소유/포함 제안이라는 의미는 선택 설명·집중·준비에도 유지한다.

## 표시와 조작
기본 화면은 짧은 목적, 핵심 변경과 유지 조건, 기능 공간을 우선한다. 검사 수/코드 ID/긴 경고/연구 보고서를 전면에 두지 않는다. 제안·과거 기록이라는 한정은 읽을 수 있게 짧게 두고 정밀 출처는 펼쳐 본다. 색은 변경 소유와 관계를 혼동시키지 않게 쓴다. 비어 있는 버튼·가짜 완료·출처 없는 미결 배지는 넣지 않는다.

지도에서 선택하면 배치를 흔들지 않는 짧은 설명을 제공하고, ‘이 부분 보기’로 집중 읽기를 연다. 집중은 상위 묶음 한 줄과 바깥 실제 연결을 남긴다. 전체를 새로 자동배치/전체맞춤하는 것으로 복귀를 대신하지 않는다. desktop/mobile의 구체적 CSS는 작성자가 판단하되 작은 화면에서도 관계·준비·전체 복귀를 실제로 접근할 수 있어야 한다. 새 bottom-sheet/gesture 엔진은 만들지 않는다.

집중의 핵심 내용은 F1~F10을 해당 기능에 맞춰 연결한다. 요청 당시 사본과 지금 구상을 구별하고, 기존 작업문 재생성/재내보내기도 사본을 바꾸지 않음을 바로 읽을 수 있게 한다. 보존 조건을 기술 부록 뒤로만 숨기지 않는다.

검사 문서의 A→변경→B→늦은 A를 짧게 보여줄 경우 ‘문서의 MOCK 검사에서 재구성한 예시’라고 밝히고, 사용자 발화/날짜/실제 승인/실제 담당자를 만들지 않는다. 예시 값이 필요하면 별도 합성값으로 명시한다. 예시를 실제 AI가 잘 지킨 증거로 쓰지 않는다. null을 미결이나 최신값으로 채우지 않는다.

‘확인·조정 준비’는 대상 기능/선택 범위, 꼭 지킬 조건, 필요한 근거, 미확인 사실을 담은 편집 가능한 짧은 준비문이다. 직접 고친 문장이 닫기/재열기로 사라지지 않는다. 지도 구성 제안은 이해용 맥락이고 실행 범위는 준비문에서 따로 표현한다. 실제 전송/수락/완료로 바꾸지 않는다. 처음 준비의 범위는 선택한 작업문 배경 분리 동작에 한정하되 다른 기능을 모두 구현하라는 자동 지시는 만들지 않는다.

## 재사용과 실행 증거
cycle03/04의 근거 닫기·준비·복귀 계약은 재사용 후보이나 cycle01의 수동 좌표와 같은 상태 엔진이 아니다. 새 조합에서 검증한다. 선택·깊이·배치·지도/창 위치·실제 배율과 비초기 읽기 위치/출발 초점을 보존한다. 집중에서 편집한 준비문은 전체 복귀로 되돌리지 않는다.

산출물: 독립 `composition-study.html`, 짧은 README(사실/제안/합성 경계와 실제 실행/미실행), 실제 실행 검사 코드·로그·결과, 필요한 대표 PNG, bytes/SHA256 manifest. 계획한 핵심 장면만 실행하고 안내 문구/중복 단언을 검사 수로 부풀리지 않는다. 최초 실패가 있으면 이전 코드/결과를 보존한다. 정상 실행과 의도한 실패를 구분하고 실제 자식 종료를 기록한다. 실행하지 못한 것은 미실행이다.
