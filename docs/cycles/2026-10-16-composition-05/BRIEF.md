# cycle05 — 구성에서 변경과 다음 행동까지
2026-10-16 착수 · 고정 입력 기준 `571e7a7030039b4d4354757949cdabc8533c70aa`. 현재 배정·실행 상태는 [ACTIVE](../ACTIVE.md)에만 갱신한다.

## 이번에 판단할 것
프로그램의 기능 구성을 먼저 보고 변경된 한 부분에 들어가, 상위 맥락·관련 부분·보존 조건을 잃지 않고 조정 또는 인계 준비와 전체 복귀까지 이어갈 수 있는가?

cycle04의 공통 정보 위계와 A 관계 개요, B 동일 대상 참조를 재료로 삼되 그 행렬·긴 설명을 제품 문법으로 고정하지 않는다. cycle01의 혼합 깊이/외부 관계와 cycle03의 근거 읽기/준비/복귀를 조합한다. 부품 수와 변경 수를 작게 하되 흐름을 또 단편으로 나누지 않는다. 기본 화면은 짧은 현재 설명·변경된 부분·다음 행동을 앞세우고 코드 식별자·검사 수·정밀 근거는 상세에 둔다.

## 입력과 장면
[입력 사실·경계](INPUT.md)는 FLOW091-C의 실제 프로젝트 개발 계약과 MOCK 검사 보고다. 사용자 원대화나 실제 AI 협업의 관측 표본으로 부르지 않는다. 문서에 없는 기능의 포함 트리는 AI의 **해석 제안**으로 만들 수 있지만, 문서가 확인한 전달·보존 관계와 구별해야 한다. 폴더 구조를 정답 지도나 사용자 승인으로 치환하지 않는다.

1. **전체에서 찾기:** 목적이 작업문과 분리된 배경으로 포함되도록 바뀐 부분과, 그대로 지킬 요청 범위를 짧게 읽는다. 일부 구성만 펼쳐도 관련 부분을 찾을 수 있다.
2. **한 부분 이해:** 새 요청의 배경 사본 고정과 이후 구상 변경의 관계를 읽는다. 검사 보고에 있는 A→변경→B→늦은 A 순서를 재구성한다면 반드시 MOCK 예시로 표시하고 새로운 실제 사건이나 시각을 만들지 않는다.
3. **준비하고 복귀:** 관련 부분의 확인/조정 요청을 준비한다. 구성 제안이 승인된 범위가 되거나 배경이 지시·새 결정으로 승격되지 않는다. 준비는 실제 전달/수락/완료가 아니다. 돌아오면 펼침·선택·배치·배율·읽던 위치를 보존한다.

빈 값은 빈 값이다. 근거 없음, 아직 결정하지 않음, 실제 AI 미검증을 같은 경고로 만들지 않는다. 이 표본에 없는 미결 사항을 기본 지도의 관심 표시 수를 채우려고 발명하지 않는다. 필요할 경우 별도 합성 경계 사례로만 명시한다.

## 작은 배정
- Pro 구성 해석: 모델과 뷰를 구별하는 실제 메커니즘 2~3개와 최대2개 기능 구성 후보. 구성 분할의 의미를 비교한다.
- Pro 탐색: Dify와 다른 분야의 접힘/집중/복귀 메커니즘 2~3개. 실제 끝점과 집계된 관계, 초점 복귀와 지도 전체 복원을 구별한다.
- 내부 Astra: 명시 사실·제안의 경계와 의미 왜곡 반례. 내부6.1 Sol: 기존 코드 재사용 계약/의미 있는 회귀 범위, 전달 체계 보조.
- 총괄: 원문·반례를 대조해 구성 후보를 선택·조합하고 클릭 시안 계약을 확정한다.
- Opus: 총괄의 좁은 계약 뒤 시안 구현. 독립 실행은 기존 Cloud에 분리한다. 아직 구현/검증 배정이 시작됐다는 뜻은 아니다.

공식 자료·고정 코드 조사와 실제 서비스 조작은 구분한다. 3개라는 수를 채우거나 같은 대안을 모델들이 동의했다는 이유로 채택하지 않는다. 결정에 영향 없는 추가 조사는 늘리지 않는다.

## 완료 기준과 경계
