- **실제 변경 일치:** HTML 차이는 10줄의 문자열 변경뿐이고 제공 `overview-v0-to-fix1.diff`와 일치한다. 카드·요약·상세표·390 설명에 “누락 확인”을 복구하고 표시 조건·분기 유지 표현을 분명히 했다. `prepDefaults`, 배치·배율·맞춤·선 그리기·위치 찾기·읽기/지도 복귀·준비 함수는 v0와 동일하다. 원본은 42,025B/SHA256 `85f07ee4159a6db825be2fa3163142b70b27c4fb56f090c934b3b41f1fe0eb81`다.
- **좁은 단일 실행 정합:** 새 `wording_check.py` 결과는 1280×720·1440×900·390×844 완주, **24 PASS/0 FAIL**이며 raw log의 판정 수도 같다. 세 최초 HTTP는 200·42,025B·위 SHA, 파일 전후 SHA도 동일하다. fatal null, 세 오류 목록은 비었다. `exit.json`의 실제 child 종료 0, 상위 shell이 기록한 collector 종료 0이다. 수집기는 검사 대상 파일명·설명 두 줄만 바뀌었고 상위 shell은 바이트가 같다. v0의 78개 흐름 검사를 다시 실행한 결과가 아니며 수를 합산하지 않는다.
- **167/167의 정확한 범위:** `wording_check.py:72–85`는 after(1월 16일)로 돌아온 뒤 P1과 P3를 선택한다. 이때 390 panel의 `scrollHeight=clientHeight=167`, `.strip-c`의 문구·전체 박스 clip·5점 hit와 부분 읽기 표의 셀 박스/hit를 검사했다. “전체 선택 설명 텍스트의 잉크가 모두 보인다”는 검사는 아니다. 미선택·변경 전·P2 선택 설명의 별도 열독 성공으로 확대하면 안 된다. 여유 0은 미래 문구/글꼴 변화에 여유를 보장하지 않는 경계이며 현재 결함의 증명은 아니다.
- **기록의 한계:** 가시성 함수는 raw rect와 hit를 계산하지만 성공 JSON에는 대체로 텍스트·실패 요소 목록·카드 scroll/client 높이만 남긴다. 외부에서 전체 rect/hit를 재계산할 수 있는 기록으로 표현하면 안 된다. 5점 hit는 문자 전체 가독성·사람 이해의 증거도 아니다. 배율·왕복·편집 보존의 새 실행은 없으며 v0의 raw 전후 쌍, 실제 상세 열기 전후, 맞춤 뒤 내용 hit 공백을 해소했다고 주장하지 않는다. 해당 독립 Cloud 관측은 별도 진행 범위다.
