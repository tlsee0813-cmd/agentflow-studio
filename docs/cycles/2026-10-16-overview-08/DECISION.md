# cycle08 — 정보량·탐색 통합 선택
2026-10-16 구현 전 판단. 현재 상태는 [ACTIVE](../ACTIVE.md). [범위](BRIEF.md).

## 조사에서 확인한 것
[정보량 Pro](https://chatgpt.com/c/6ad11f6e-f728-83e8-9d0a-55ba32028487)는 Bforartists의 명시 접기와 React Flow의 Contextual Zoom을 비교해 명시 상세를 추천했다. [탐색 Pro](https://chatgpt.com/c/6ad11f92-7fd0-83ec-b658-da441d3df6b5)는 전체맞춤/찾기/복귀를 모두 공통 도구줄에 두는 안과 필요한 문맥에 두는 안을 비교해 후자를 추천했다. 이는 설계 후보 비교이지 구현 A/B나 사람 사용성 결과가 아니다.

[정보량 원문 감사](DENSITY_SOURCE_AUDIT.md): BFA의 노드 헤더 접기 그림을 실제 읽었으며 현재 머리말은5판이다. React Flow 예제의 배율0.9 조건은 같은 노드의 표시 내용을 바꾸며 데이터 계층 생성/축약이 아니다.
[탐색 원문 감사](NAVIGATION_SOURCE_AUDIT.md): Node Search 기본 선택＋맞춤은 우리의 선택/배율 보존 정책과 다르다. 총괄이 공식 Save and Restore에서 저장→노드 추가→복원을 직접 조작해 노드2→3→2를 관측했고 App.jsx에서 nodes/edges/viewport 복원을 읽었다. 따라서 내용까지 되돌리는 예제를 보기 복귀에 통째로 적용하지 않는다.
[Dify 실제 관측](DIFY_OBSERVATION.md)은 작은 노드/별도 상세, 선택 강조, 맞춤 메뉴·미니맵 존재까지다. 패널 뒤 노드 가림도 있었으며 Dify의 맞춤·복귀·층위 기능을 실행했다고 하지 않는다.

## 총괄 선택
**간결한 기본 지도＋명시 상세, 문맥별 위치/복귀**를 한 시안으로 만든다. 배율은 공간 크기만 조절하고 정보 수준을 자동 변경하지 않는다. 처음부터 모든 책임/인자를 넣는 cycle07 지도와 비교할 다음 후보이며 최종 제품 확정은 아니다.

기본에는 목적, 고정1/16 비교 범위·후속 요청 존재, 세 역할과 두 기존 호출, 책임 이동의 핵심만 남긴다. 누락 확인·경과 계산은 해당 비교 시점에 실제로 맡은 부분에만 표시한다. 없던 책임을 회색 행으로 채우지 않는다. 다만 이 변화가 삭제/신설로 읽히지 않도록 ‘두 메뉴의 확인·경과 계산을 기존 공통 계산으로 옮김, 표시 역할·호출 유지’를 짧게 함께 읽힌다.

선택한 부분에서 두 책임의 개별 내용과 전달 인자, 남은 역할을 푼다. 근거/준비는 필요할 때 이어 간다. 카드 안을 펼치며 다른 두 카드를 밀지 않는다. 세 부분의 이름을 단순 목록으로 바꿔 두 호출을 숨기지도 않는다. 작은 화면에서도 두 메뉴가 각각 같은 계산을 사용함을 구별한다. 가짜 부모·하위 노드나 실행 순서선은 추가하지 않는다.

## 탐색과 보존
전체맞춤은 현재 지도를 다시 맞추는 명시적인 새 보기다. 사용자가 한 선택·근거 시점·편집 내용을 바꾸지 않는다. 위치 찾기는 관련 부분을 보여 주는 문맥 행동이고, 전체 복귀는 **상세 진입 때 저장한 보기**로 돌아온다. ‘마지막 전체맞춤을 취소’하는 전역 명령이 아니다. 지도 좌표/배율/선택/비교 보기와 준비 편집 보존은 별개다.

필요하면 상세 패널 공간을 빼서 지도를 배치한다. 처음부터 전체 역할과 관계 양끝이 보이지 않는 것을 자동 축소만으로 해결하지 않는다. 좁은 화면은 별도 요약 배치를 쓸 수 있지만 역할·관계·이동 의미는 유지한다.

## 선택을 다시 볼 조건
축약 후 변화가 삭제/추가처럼 읽히거나, 공통 카드의 부재가 ‘상세를 접어 숨김’과 혼동되면 표현을 고친다. 이름만 남아 관계를 상세 문장으로 재구성해야 하면 부적합하다. 명시 상세의 조작 부담이 자동 밀도보다 낫다는 사람 결과는 아직 없다. 이번에는 새 SDK/자동 의미 줌을 도입하지 않고 작은 흐름으로 검증한다.
