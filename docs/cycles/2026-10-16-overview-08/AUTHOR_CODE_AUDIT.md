최종 HTML은 41,912B/SHA256 `624a6e70082e2cca377080b5f4a67e1f29b3f8ed4f7aac8eda1cb3b07c32154b`. 세 HTTP 응답은 200·동일 bytes/SHA, 파일 전후 해시도 같다. 최종본의 위 한 줄을 역변환하면 run-01/02가 보고한 41,911B/SHA `307877ef49c42d0486ded00c14a06776c836d7e8465a809008a2bf719c2fdfe4`가 정확히 재현된다. 과거 전체 HTML/검사 스냅샷은 없고 제공 diff로 차이를 추적한다. 로그 판정 수는 각 JSON과 맞으며 최종 fatal null·오류 목록 3개 모두 비었다. collector는 child returncode를 그대로 반환하고 상위 shell이 그 코드를 별도 기록·전파한다. 상위 shell 자체를 외부에서 수집한 실제 종료 기록은 아니다.

초기 노출은 카드 전체 inPane/자체 세로 잘림, 선끝과 라벨 기하에 더해 이름·역할·이동 단서의 5점 hit를 검사한다. **맞춤 뒤**는 `all_exposed()`의 카드·선끝·라벨 기하와 자체 세로 잘림만 검사하고 이름/역할/단서 hit는 다시 검사하지 않는다(200–203행). VIS의 overflow clip은 변환 배율과 축별 차이를 일반 처리하지 않으며, Range로 문자 잉크 전체를 측정하지 않는다. 선끝 역시 computed scale로 환산한 위치와 pane 비교이고 가림 hit가 아니다. 초기/맞춤의 긍정 판정을 문자 전체 가독성이나 사람 이해 성공으로 확대하지 않는다. 독립 Cloud는 기존 두 흐름 안에서 초기/선택/맞춤/복귀의 raw 쌍과 맞춤 뒤 내용 hit만 보완하면 된다.

복귀·편집의 코드 경계는 유지됐다. HTML 432–474행은 진입 snapshot과 위치 탐색의 임시 mapView/readTop을 분리하고 전체 복귀 때 진입 배율·scroll·선택·비교 보기만 복원한다. `prepDefaults()`(506–520행)는 cycle07 fix1 함수와 바이트가 같고, per-target 편집 저장·근거 닫기 함수도 동일하다. 이번 실행은 P1의 수정 요청 전체 값 유지와 맞춤 이후 유지까지 검사하나 다른 대상 편집이나 peek 반복은 재실행하지 않았다. 최종 비초기 진입은 1280 115%/scroll81,0, 1440 130%/50,0, 390 115%/24,33이다. reader는 160/124/160으로 이동하고 출발 행 raw rect 전후 동일·loc-P3 초점 기록이 있다. 맞춤은 새 보기이며 배율 1.019/1.205/0.994를 만들고 다음 진입 snapshot이 그 보기를 복원한다.
