## 좁은 수정 필요 1개

**옮겨진 책임인 ‘진행 정보 누락 확인’에서 ‘누락’이 기본과 상세 모두 빠졌다.** HTML 252·255행 카드, 259–260행 변화 요약, 349·353행 상세 표가 모두 ‘진행 정보 확인’이다. `C-1440-selected-detail.png`에서도 상세 표에 동일한 축약이 보인다. 짧은 칩 하나의 축약이라면 주변의 정확한 설명으로 보완할 수 있으나, 지금은 부분 읽기 역시 같은 표를 사용한다(401행). 실제 이동은 필요한 진행 정보가 없는지 확인하는 책임이며 모든 진행 정보 검사·상태 판단의 이동이 아니다. 표시 조건·분기 등은 메뉴에 남는다.

최소 정정은 상세 표와 기본 변화 설명에 ‘누락’을 복구하는 것이다. 칩도 길이가 허용되면 같은 이름을 쓰면 된다. 다른 확인까지 공통화했다고 명시한 것은 아니므로, 이 문제를 새 기능 생성이나 전체 구조 오류로 과장하지 않는다. 근거 대조(420행)와 준비 범위(510행)의 ‘누락 확인’은 이미 정확하다. 레이아웃 재설계 사유는 아니다.

## 실제 이미지에서 확인한 개선·유지

- **A-1280-initial:** 이름·역할·이동 단서가 있는 세 카드와 두 호출의 양끝·라벨이 한 화면에 보인다. 이전의 책임행 반복을 줄이고, 메뉴에는 표시 역할과 공통 계산으로의 이동 설명, 공통에는 기존 추정과 옮겨온 책임을 둔다. 목적·고정 과거 시점·후속 요청/미병합 경계도 기본에 남는다. 큰 근거 보고서를 먼저 읽어야만 연결을 찾는 구성은 줄었다는 정적 판단이 가능하다.
- **B-390-initial:** 두 메뉴가 각각 공통 계산으로 이어지고 세 역할이 함께 보인다. 모바일을 단순 세 항목 목록이나 순차 실행 흐름으로 바꾸지 않았다. 역할 문장은 줄바꿈되지만 화면에서 잘린 새 핵심 문구는 발견하지 못했다. 아래 선택 설명에도 기존 계산으로 이동·표시와 호출 유지가 남는다. 실제 사람의 식별 속도나 글자 가독성 성공은 측정하지 않았다.
- **D-1280-before-view:** 공통 카드에는 실제 맡았던 추정만 책임 칩으로 표시한다. 회색 문장은 두 메뉴가 담당했다는 설명이며 공통 책임 행이 아니다. 두 호출은 그대로 있고 전달 라벨이 세 숫자로 바뀐다. 삭제·신설이 아닌 책임 이동이라는 맥락이 유지된다.
- **C-1440-selected-detail:** 두 책임·전달값의 전후 표, 남는 표시 역할, 이후 요청과 실제 반영 미확인이 보인다. 왼쪽 카드 잘림은 README가 공개한 130% 확대·이동 장면이다. 초기 조망 실패로 세지 않으며, 이 한 장만으로 복귀 동작이 성공했다고도 판단하지 않는다.

## 코드 대조와 증거 한계

HTML 186·188행의 고정 시점/후속 안내, 403–410·425–429행의 관련 부분≠자동 수정 범위·Bot 보고≠승인·되돌림 완료 미확인은 유지된다. `prepDefaults` 함수는 cycle07 fix1과 문자열 전체가 동일함을 읽기 전용 비교로 확인했다. 새 준비문 선결정은 없다. 이번 PNG에는 준비창이 없으므로 준비문 노출·편집 보존은 코드 대조와 작성자 보고를 넘어 독립 주장하지 않는다.

README의 세 폭 검사 결과는 작성자 검사이며 본 감사의 실행 결과가 아니다. 초기 전체 조망은 이번 세 부분 표본에서 시각적으로 개선됐으나, 맞춤·왕복·편집 유지의 독립 성공, 큰 프로그램 일반화, 실제 AI 인계, 사람 이해 개선은 입증하지 않는다. 390의 130% 카드 폭 초과·화면 폭 변경 시 상태 보존 미보장·준비문 내부 스크롤은 작성자가 공개한 잔여 한계로 유지한다. 추가 전면 수정 목록으로 확대하지 않는다.
