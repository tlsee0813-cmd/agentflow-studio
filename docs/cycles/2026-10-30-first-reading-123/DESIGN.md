# 123 — 첫 지도 시작과 현재 이해를 바로 읽기

122에서 실제 배치 사본의 의미와 생성 중 다른 작업·결과 회수 흐름을 수용했다. 이제 같은 완료 자료로 PC의 시작·읽기 부담을 줄인다. 새 AI 생성이나 과거 실패 실험은 하지 않는다.

## 확인한 문제

- 지도 실행기가 준비된 122에서 중앙의 빈 지도 카드는 여전히 서버 연결 안내만 보였다. 돌아와 읽기 안에서는 정상 생성이 가능했다. 현재 main의 비동기 status 응답은 상태 칩·계획·선택 패널을 갱신하지만 renderMapEntry/refreshUnderstood를 호출하지 않는다. 지연 응답 뒤 실제 시작 입구를 다시 그리는지 확인한다.
- 1280×720 Display 렌즈는 설명→관계→현재 주장 순서다. 현재 주장 시작은 화면 y483.8, 목록 끝은 y807.8로 본문 아래(y663.2)를 넘는다. 이는 읽을 수 없는 데이터가 아니라, 같은 부분을 이해하는 중간에 다른 부분의 연결이 끼어드는 문제다.
- 전체 읽기도 같은 344.8px 패널이며, 현재 이해를 관련 부분보다 먼저 배치한다. 넓은 독서 화면으로 잘못 안내하지 않는다.

## 선택한 변경

1. 상태 응답 뒤 현재 열린 프로젝트의 빈 지도 카드와 지도 이해 줄을 갱신한다. 기존 mapRun.can/input/blocked를 재사용하고 별도 실행 가능 판정을 만들지 않는다. 정상 map-only, 키 없는 서버, 접속 코드 필요, 준비 중·도착 결과의 실제 의미를 유지한다. 자동 생성·자동 적용·화면 이동은 추가하지 않는다.
2. 렌즈의 영역 순서만 설명→현재 주장 전체→관계→기존 요청 대응·안쪽 연결·내부 구성으로 바꾼다. claimList의 정렬·종류·판본 조건·본문·인용 identity를 그대로 쓴다. CSS order로 시각과 키보드 순서를 다르게 만들지 않는다.

지도 배치·저장·스키마·프롬프트·검증기·실행 정책은 그대로 둔다. 새 넓은 UI나 요약·접기·키워드 우선순위를 함께 넣지 않는다. 직접 사용 결과에서 필요성이 남으면 별도로 판단한다.

## 수용 조건

- 지연된 실제 형태의 status 응답으로 초기 접근과 빈 프로젝트 새로고침을 확인한다. ready map-only 첫 지도 입구가 자동으로 나타나고, 연결 불가·코드 미입력·부적합 입력은 실행 가능으로 과장하지 않는다. 응답 도착 때 다른 프로젝트의 편집·선택·카메라·초점을 훼손하지 않는다.
- 기존122 Power/Display의 실제 저장 자료를 재사용한다. 모든 주장·후행 always-on/절전 불가·두 화면 대응이 원문 그대로 연속 노출되고, 공급·제어 관계의 방향과 note도 찾고 따라갈 수 있어야 한다. 관계를 찾는 부담까지 개선됐다고 미리 주장하지 않는다.
- 주장 근거 왕복과 관계 방문 복귀에서 같은 선택·범위·근거 버튼·스크롤·카메라를 유지한다. 긴 관계 note/8개 초과 등의 UI75 계약은 코드 경계와 필요한 집중 검사로 보존한다.
- 작성자 검사와 총괄의 1280×720·1440×900 실제 화면, 독립 delta 검토, 정확 커밋 CI를 구분해 기록한다. 전체 생성 품질/전체 출시 수용으로 확대하지 않는다.
