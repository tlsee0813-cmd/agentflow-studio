1. trusted Worker 정책으로 map6 first/later·map7·legacy·jobs를 제공자/실행기 전에 거절한다. 기존 plan3/scope/digest/ask 계약·권한·CORS는 유지한다. 일반 Node/선택된 CLI 미리보기의 수용 경계를 바꾸지 않았다.
2. Root 정상 UI에서 구판11/.2→현재14/.4 사본 가져오기, 첫 편집, reload, backup, 빈 origin 재가져오기까지 정확히 보존됐다. 4013자 과거 요청과 철회·인용·소유를 소급 변경하지 않았다. 구주소 보존과 구reader의 안전한 거절은 확인했지만 다운그레이드 성공이 아니다.
3. 완료된 실제107 plan과109 scope의 messages가 전체 일치하는 저장 응답 재생 2회로 동일 Worker/assets의 요청 생성·회수 경로를 확인했다. 새 16202자 요청과 다른 프로젝트의 기존 bundle까지 reload 후 같았다. 새 AI 품질 검증이나 실패 실험 재실행은 0이다.
4. 최종 패키지에서 실제 Zephyr 지도 → Display 주장 → 원문 표 → 복귀 → 변경안·동결 요청 회수와 늦은 status의 새 이름·직접 부분 두 입력 보존을 Root가 확인했다. 저장된 보고·철회 읽기는 유지한다. 독립 P2인 불가능한 대조 유도는 네 곳을 수리했고, Sol 최종 검토에서 추가 P1/P2는 없었다. P2 두 특수 조건의 UI 실행은 작성자 6개 flow로 구별했다.

## 공개할 범위와 계속 보류할 범위

별도 origin에서 전달할 범위는 기존 지도 읽기·수동 편집·근거·변경 구상·요청·저장된 반환 읽기다. 서버와 브라우저를 한 세트로 전달해야 한다. UI만 공개73 Worker에 올리거나 전체 새 Worker에서 생성 기능을 열지 않는다. 첫 지도·새 지도 갱신·새 요청/보고 대조 AI는 이번 후보에서 보류한다.

실제 패키지 prefix agentflow.studio.preview: 를 채택한다. 선택 검토의 browser-demo:는 예측 오차였다. manifest의 Worker agentflow-studio-existing-map-124는 검토용 이름이지 이미 배포된 주소가 아니다. 다음 출시 행동은 대상 존재·소유, 실제 설정, 업로드 bytes 동등성과 공개 smoke를 확인하는 별도 구체 결정이다. 원주소 교체·스키마 다운그레이드·자동 이행은 선택하지 않았다.

일반 AI 표시·붙여넣기 안내의 지도 정리 언급·status 도착 전 짧은 기본 첫 지도 안내는 남은 표현 한계다. 명시 제한 신호 뒤 실행 입구와 서버 거절은 유지된다. 화면 밀도와 첫 사용자의 전체 성공은 계속 실제 자료에서 판단한다.
