# 124 — 기존 지도 작업용 제한 출시 후보

123의 첫 지도 입구·읽기 순서·초안 보존을 마감한 뒤, 수용된 제품 경험이 계속 미병합 후보에만 쌓이는 문제를 다룬다. 완료105의 공개 전달 검토를 재사용하며 새로운 모델 연구나 실패 재실험을 하지 않는다. 이 단계는 배포 가능한 후보의 구현·검증 선택이며 공개 배포 허가가 아니다.

## 선택할 사용자 경험

기존 지도 또는 예제를 열어 현재 설명과 근거를 읽고, 바꿀 일을 구상해 요청문을 만들며 이미 저장한 보고와 대조를 읽는다. 첫 지도 생성과 새 보고의 지도 반영 AI 대조는 이 후보에서 제공하지 않는다. 요청/보고 자료 보관과 기존 대조 읽기를 새 map7 생성 가능으로 표현하지 않는다.

공개73 원주소는 그대로 두고 별도 고정 origin의 제한 작업용 후보를 준비한다. 새 origin은 공개73의 localStorage에 접근하거나 쓸 수 없고 자동 자료 전송·교차 origin 동기화를 만들지 않는다. 현재 사용자는 정상 백업 내보내기→사본 가져오기로 들어오며, 처음 보는 사용자는 예제로 먼저 읽을 수 있다. 새형식 백업을 공개73에 되돌리면 열린다고 약속하지 않는다. 원파일과 원주소가 보존되는 사본 사용 경계다.

## 제품·서버·패키지

1. 같은 커밋의 Worker와 assets를 한 세트로 고정한다. accepted plan3/scope/digest/ask 계약을 유지하고 API·프롬프트·검증 의미를 얇게 되돌리지 않는다.
2. 명시적인 제한 출시 설정에서 map capability를 제공하지 않고, /map 모든 schema/intent와 jobs 직접 호출도 공급자/실행기 접근 전 거절한다. 구탭·수작업 HTTP 요청에도 같다. 일반 Node/선택된 CLI 미리보기 동작은 유지한다.
3. 화면은 ‘기존 지도 작업용’의 가능한 일과 제한을 짧게 안내한다. AI가 연결돼 있어도 map이 보류된 경우 ‘AI 서버 연결하면 지도 가능’처럼 틀린 처방을 주지 않는다. 첫 지도 중앙·돌아와읽기·보고대조 버튼을 같은 정책으로 다룬다. 예제와 백업 import를 기존 정상 UI에서 바로 찾게 한다.
4. dry-run 패키징에서 source/app SHA, 모든 browser asset과 전체 Worker module closure SHA, 적용 policy와 API endpoint를 남긴다. CLI/Node filesystem·private policy·키는 공개 묶음에 포함하지 않는다. 기존 deploy 스크립트를 확장하더라도 이 작업에서 실제 업로드·deploy는 하지 않는다.
