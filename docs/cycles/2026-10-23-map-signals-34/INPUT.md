# 34 지도에서 읽을 부분 찾기
작성 시점 2026-10-23 KST. 현재 배정은 [ACTIVE](../ACTIVE.md), 본 문서는 이 후보의 판단 계약이다.

## 목적
돌아온 사용자가 지도를 훑고 ‘어느 부분에 어떤 기록이 있어 한 번 열어볼지’를 정한 뒤, 기존 기록을 읽고 같은 지도로 돌아온다. 32의 사실표와 실제 관측에서 말단 카드의 질문/설명 상태가 빠져 있음을 확인했다. 카드의 미적 완성이나 새 줌 모드보다 이 선택 이유의 노출 한 곳을 개선한다.

## 한 후보
기존 카드의 기록 신호를 말단까지 연결한다. 부모는 자기+포함 후손, 말단은 자기만 센다. 관계선은 소유 범위를 늘리지 않는다.
1. 질문 전체 기록 수 N은 기존 subtreeSignals.questions 집계와 일치시킨다. 그 집계에 남는 이전 기준/적용 미확인/원래 실제 요청 질문의 시험 답변을 새로 버리지 않는다. 최초 시험 문맥 또는 시험 재정리에서 생겨 기존 H18 검사104/118에 따라 제외되던 질문을 이번에 다시 넣지 않는다.
2. 그중 기존 적용 상태 active이고 answered=false인 M을 구별한다. 문구는 ‘답변 기록 없음’의 사실이며 해결 의무·미해결 전체·새 알림·완료를 뜻하지 않는다. 세부 분류는 기존 패널에 남긴다.
3. 현재 설명·이전 기준 설명·보류의 존재를 서로 합치거나 동시 상태를 말줄임으로 숨기지 않는다. 상세 원문은 기존 기록에서 읽는다.
4. 정확한 기존 openBranchRecords로 들어가며 원호출·카메라·선택·미전송 값을 보존한다. 카드 이름/소속/구상/기존수/기존행동을 새 신호 때문에 숨기지 않는다.
5. 180px 높이·좌표·기존 글자 크기는 유지하는 첫 후보다. 같은 정보를 반드시 같은 독립 줄에 둘 필요는 없고, 카드 안에서 기존 정보/배지/접기 행동을 재배치할 수 있다. 긴 제목·혼합 상태에서 들어맞지 않으면 불필요한 새 표현을 먼저 덜고, 필수 존재가 가려지면 보류한다. 자동배치/프레임 확대/새 상태엔진으로 확장하지 않는다.

## 검증 관문
- 정확 T2의 미리보기(답변 기록 있음), 오류행 처리(현재 답변 기록 없음), 내보내기(이전 설명+보류)를 입력 그대로 비교한다. 내보내기의 외부 CSV/XLSX 주장은 사용자의 현재 CSV 조건으로 승격하지 않는다.
- 같은 renderer의 긴 제목·현재/이전/보류 공존·다른 적용 상태/시험 답변 작은 경계 입력에서 전체 기록 존재와 소유/표시를 확인한다.
- PC1280×720,1440×900에서 기존과 후보의 실제 지도 첫 모습·선택 전 읽기·정확 기록 열기·닫아 복귀를 비교한다. 32의 알려진 정답을 재사용한 관측을 최초 발견성 실험이라고 하지 않는다.
- 신호 누락/잘림·기존 내용 가림·중첩 버튼·잘못된 소유 영역·불필요한 저장·위치 이동이면 수정하거나 보류한다. 검증 숫자 대신 대표 실제 화면으로 판단한다.
- 독립 원자료/코드 검토와 정확 최종 CI 후에만 checkpoint 통합한다. 후보 자체 실행 가능 여부는 Cloud에서 확인하며 로컬 실행 차단을 우회하지 않는다.

별도 최신상태 엔진, 새 배지 체계 전체 개편, 상단 체크 수 재정의, 실제AI 추론, 모바일 최적화·공개 배포는 이 한 후보에서 하지 않는다. 좋은 결과는 사용자에게 읽을 문서를 더 주는 것이 아니라 다음 부분을 고르는 부담을 줄이는 것이다.
