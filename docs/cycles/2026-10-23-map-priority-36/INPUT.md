# 36 기본 지도와 상세의 정보 우선순위
2026-10-23 KST · 35 체험본 검증과 병렬로 진행하는 한 후보. [34 보류 결과](../2026-10-23-map-signals-34/RESULT.md)를 되돌려 수용하지 않는다.

## 질문
사용자가 지도로 돌아와 어느 부분인지, 무엇을 하는 부분인지, 왜 읽어볼 만한지를 구별할 수 있는가? 작은 카드 안에 보고서를 넣는 방향을 피한다. 35의 체험본 검증/공유는 이 작업에 종속하지 않는다.

## 이번에 바꾸는 계약
34의 기존 수량까지 전부 기본 카드에 동시에 보존한다는 조건을 철회한다. 요청/결과 수·질문 전체 수·세부 본문은 **같은 소유자의 기존 상세**로 명시적으로 옮길 수 있다. 이 때문에 수량 비교에 상세를 한 번 더 여는 비용이 생긴다. 정보 삭제나 우연한 overflow로 숨기는 것을 허용하는 뜻은 아니다. 기본 카드에 원래 이름·소속·부분의 짧은 역할/구상 설명을 우선하고, 읽을 이유의 존재를 작은 별도 영역으로 둔다. 경고만 나열하는 작업 목록으로 만들지 않는다.

기존 전체 지도 좌표·카드 폭/높이·포함관계와 글자 크기는 유지한 첫 후보 하나를 비교한다. 내부 행의 우선순위와 제목 줄 수는 바꿀 수 있다. 실제 고정 사례에서 이 조건이 목적을 충족하지 못하면 반례를 공유하고 보류한다. 숨은 줄을 검사에서 제외하거나 예외 CSS를 끝없이 더하지 않는다. 새 줌/레이아웃 엔진·새 기록 모델·자동 요약/AI/마이그레이션은 범위 밖이다.

## 보존할 의미와 행동
- 현재 답변 기록 없는 질문은 기존 `active && !answered`다. 이전 기준 질문/시험 답변을 현재 미답으로 바꾸지 않는다. 부모의 자기+포함 후손과 말단 자기 범위는 유지하며 관계 상대는 포함하지 않는다.
- 설명 보류, 이전 기준 **설명**, 이번 탭 설명 갱신을 구분한다. 네 종류가 겹칠 때 하나/‘외 N개’로 숨기지 않는다. 탭 갱신은 새 변화/안 읽음/완료를 뜻하지 않는다. 아무 문제가 없더라도 현재 설명과 과거 기록에 접근할 수 있어야 한다.
- 부모 집계이면 하위 포함임을 읽을 수 있게 한다. 기본에는 존재만 두고 정확한 수량은 상세에 둘 수 있다. 34의 순수 집계 논리는 재사용 가능하지만 보류 배치 전체를 가져오지 않는다.
- 부분 이름이 긴 공통 접두사일 때 구별할 부분을 실제로 읽을 수 있는지 확인한다. 원문 DOM/tooltip 존재만으로 기본 식별 성공이라고 하지 않는다. 원래 이름을 데이터에서 바꾸거나 짧은 별칭 모델을 만들지 않는다.
- 현재 작업 표지와 기존 부분 진입/정보/하위 접기/기록 진입을 보존한다. 현재 표지는 버튼이라고 가정하지 말고 실제 코드를 확인한다. 새 입구를 추가한다면 무엇으로 이어지는지 명시한다.
- 기존 상세가 옮긴 정보와 정확한 소유 기록을 실제로 보여주는지 대조한다. 부모 기록 검사에서 비어 있지 않은 부분집합만 확인하지 말고 해당 입력의 정확한 소유자/기록 집합을 확인한다. 닫은 뒤 원래 선택·카메라·접힘·초점 복귀와 저장본 보존을 유지한다.
