## 사용자 흐름과 문제
사용자가 한 부분을 읽거나 직접 수정한 뒤 전체 공간으로 돌아오면, 지도 자체의 아래쪽이 PC 화면 밖으로 밀리지 않아야 한다. 카드가 현재 카메라 밖에 있는 일과 지도 컨테이너가 화면 아래로 넘치는 일은 구분한다.

[28 결과](../2026-10-23-map-reading-28/RESULT.md)의 같은 입력 비교에서 기존 제품과 연구 후보 모두 1280×720의 6/8카드 지도 top268.89, height704, bottom972.89가 관측됐다. 일부 정보 버튼이 y720보다 아래에 있었다. 4카드와 1440의 다른 결과를 모든 진입 경로의 합격으로 확대하지 않는다. 28의 큰 제목 후보는 계속 보류한다.

## 고정 기준과 가설
원관측 제품은 6b96543fdf980ff45f0e1b67f83e8a0a561a1542, 28 원자료는 delivery의 c6b3b224532aacea5c8834271beceb2cc3be8c53 / docs/transfer/map-reading-28/independent-a/v0 이다. 29 후보709e402b2e44a4864139eda03201e186f5761c6f는 작업 옆 읽기만 추가하며, 해당 지도 진입 순서는 동일하다. 실행 시 실제 checkout·원문 해시를 다시 기록한다. 29 검증과 섞어 제품 회귀라고 부르지 않는다.

정적 검토에서 openSpace는 render가 높이 측정·최초 fit·패널 읽기 복원을 마친 뒤 페이지 스크롤을 복원한다. 이전 작업의 깊은 스크롤이 남으면 측정 top≤0에서 720−0−16=704가 된다. 그 뒤 재측정이 없으면 원관측 수치와 맞는다. 이는 아직 원인 확정이 아니다.

반증 요인도 함께 확인한다. PC에서 숨은 area-list의 기본 open은 최초 4카드에서 true, 6/8에서는 false이며 후행 toggle이 높이를 다시 잴 수 있다. 이전 open 기억값에 따라 경계는 달라진다. 비동기 저장 완료의 renderStatus, resize도 재측정하므로 우연한 회복을 한 원인으로 몰지 않는다. 문서·코드 검토는 실제 사건 순서 관측을 대신하지 않는다.

## 먼저 할 관측
기존 Cloud에서 같은 6영역 자료와 같은 저장 상태를 정상 UI로 복원하고, 작업 화면 스크롤0/깊은 위치에서 동일한 전체 공간 버튼으로 진입한다. 양 PC 1280×720,1440×900에서 최종 scrollY, 지도와 레이아웃 rect, inline height, 카메라 행렬, 최초 카메라 유무, 목록 open을 기록한다. 저절로 회복되면 toggle·저장 완료·resize와 시간 순서를 구분한다.

같은 실패 상태에서 명시적 모두 보기만 누른 경우와 실제 창 크기를 바꾼 경우를 별도로 비교한다. 4영역 표본은 목록 기본 열림/이미 기억된 열림 상태가 차이를 설명하는지 확인하는 대조군이다. 관측을 위해 데이터·DOM·응답을 대신 넣거나 제품을 먼저 수정하지 않는다. 사건 추적용 계측이 필요하면 원본 실행과 분리해 계측 방식·타이밍 영향을 표시하고 원본에서 재확인한다.

## 수정으로 넘어가는 조건과 범위
원인 순서가 확인된 경우만 지도 진입의 스크롤 복원→최종 높이 측정→카메라가 없을 때만 최초 fit→패널 읽기 복원 순서의 최소 변경을 검토한다. render 뒤 size 한 번만 덧붙여 이미 잘못 저장한 최초 카메라를 남기는 안은 피한다. 기존 restoreOrigin 흐름은 별도로 보존한다.

전체 카드 자동배치, 카드 크기·글자 변경, 매번 자동 fit, 새 엔진, 문서/프로젝트 의미 변경은 범위 밖이다. 원인이 다르면 가설을 폐기하고 관측에 맞는 최소안을 다시 판단한다.

## 합격 경계
- 같은 입력의 스크롤0/깊은 위치 진입에서 최종 지도 높이가 최종 top과 PC 가용 높이를 기준으로 계산되고, 정상 공간이 충분한 표본에서 지도 아래가 뷰포트 안에 놓인다. 실제 정상 UI 정보 버튼 진입도 확인한다.
- 최초 카메라는 최종 지도 크기를 기준으로 만들어진다. 기존 사용자의 이동·배율·선택·접힘 상태는 재맞춤하지 않는다. 화면 밖 항목 안내가 최신 가용 범위와 맞아야 한다.
- 작업에서 지도 복귀, 영역을 거친 복귀, 기존 명시적 이전 화면 복귀를 구분한다. 열어둔 패널 읽기 위치와 포커스는 최종 높이 뒤 복원되며, 작은 중간 높이 때문에 읽기 기억이 잘리지 않는다.
- 저장한 영역 좌표·부모 관계·수동 작업 네 값·설명·과거 전달 기록·원보고는 바뀌지 않는다. 화면 상태와 프로젝트 데이터 불변을 따로 검증한다.
- 원본 실패/후보 결과를 보존하며 실제 클릭·보이는 본문·가림을 확인한다. 숫자상 rect만 통과한 결과로 끝내지 않는다.

## 증거와 종료
제품/검사 작성자와 Cloud 독립 관측을 구분한다. 실행·수정 없이 원인이 부정되면 그 결과로 닫을 수 있다. 후보가 생기면 정확 커밋의 독립 PC 검증·필요한 회귀 검사·CI·코드 검토 후 checkpoint 통합 여부를 판단한다. main·공개 체험판은 변경하지 않는다.

자료는 delivery의 새 viewport-return-30 접두사에 공개 GitHub로 회수 가능하게 남긴다. 작은 결과표와 대표 화면, 원시 수치는 분리하고 큰 JSON은 무손실 압축·원해시 목록을 사용한다. 실제 사람 사용성 연구나 전체 지도 가독성 합격으로 확대하지 않는다. Dify와 비교할 기준은 같은 공간을 떠났다가 돌아왔을 때 공간을 다시 찾느라 드는 부담이며, Dify 실행 엔진 복제는 아니다.
