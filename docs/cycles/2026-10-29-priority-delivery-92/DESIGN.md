# 92 고정 우선 경로 — 비공개 검증 선택

총괄은91 반려 후 회수한 좁은 판단(edc3df8c)을 바탕으로 고정 Sol 우선 전달 후보를 비공개로 검증하기로 했다. 제품 통합과 공개 수용은 아니다. 기준source b3c9edf/app7beb, 원격checkpoint6fa81ae, UI75 최종693과 공개73·stash·키 보존이다.

91의 빠른 DeepSeek 구조유효 응답은 핵심 의미를 잃었다.89의 별도 Sol 두 자료 수용과 Zephyr 미완결은 우선 경로의 완료 기회를 유지하면서 보조 완료를 보관할 제한된 근거다.91에서 취소한 Sol이 성공했을 것이라 추정하지 않는다. 소수 사례로 만든 전역 우선순위이며 일반 품질·성공률을 보장하지 않는다.

같은 고정 원문/ask/map6지침/모델 설정·기존CLIwrapper를 사용한다. 두 경로는 각1회 동시 시작한다. 모든 자료에 Codex Sol High 우선순위를 적용하며 자료 종류·기대 정답·이전 결과로 라우팅하지 않는다. 먼저 완결·전체 계약·private 적용 가능성 검사를 통과한 DeepSeek 응답은 요청 안에 보관하고 적용하지 않는다. Sol이 유효하면 그것 하나를 선택한다. Sol이 terminal 실패한 경우 또는 선택 마감까지 유효 완료하지 못한 경우에만 마감 전에 검증 완료된 DeepSeek를 선택한다. 둘 다 부적격이면 실패다. 선택된 응답의 후속 의미 판정이 나쁘면 후보를 중단하며 다른 보관 답으로 바꾸지 않는다.

공통 실행시계는 첫 경로 시작 전 코어에서 시작한다. 입력 준비 시간과 실패 receipt 파일 저장은 이 실행 시계의 모델 작업 시간이 아니다. 전체 실행 한도90초 안에 검증·선택·정리·private 사본 최종화를 두기 위해 선택 cutoff를 모든 자료89초로 고정한다. 남은1초는 로컬 정리·보존 재검사·private 사본 최종화에만 쓴다. API 자체 기본90초는 그대로여도 코어가89초에 취소하며 새 생성 시간을 주지 않는다. elapsed 최종검사가90초를 넘으면 성공 사본으로 수용하지 않고 실패 receipt에 기록한다. JS timer와 OS는 실시간 보장 장치가 아니므로 실제 elapsed를 증거로 남긴다. 제품 UI/API 전체 대기시간 수용을 이 private 실행으로 주장하지 않는다.
