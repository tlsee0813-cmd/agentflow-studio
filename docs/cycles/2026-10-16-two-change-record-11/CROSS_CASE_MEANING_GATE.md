# cycle11 두 사례 공통 입력·화면 의미 통과 기준

기존 cycle09 입력 감사와 cycle11 PowerToys 출처 감사를 재사용한 사전 기준이다. 현재 화면·코드 실행 결과가 아니며 사람 이해도 판정도 아니다. 같은 화면과 공통 입력 구조로 두 사례를 교체하되, 관계 수·사건 종류·자료 성격을 같게 만들지는 않는다.

## 왜곡 위험과 통과 조건

1. **구성을 사건이나 업무 목록으로 바꾸지 않는다.** FLOW091의 5역할·6관계와 C32 강조는 AI가 제안한 보기이며 과거 계약/MOCK 보고를 설명한다. PowerToys는 편집기 안 두 동작과 외부 공용 훅의 부분 지도다. 같은 부모·자식 수나 6관계를 맞추려고 새 부분·선을 만들면 실패다. PC 기본에서 무엇의 부분 지도인지, 선택한 부분의 역할과 관련 상대가 사례에 맞게 드러나면 통과 후보다. 전체 제품의 완성 구성이라는 표시는 금지한다.

2. **사실과 변경을 분리한다.** 변경 근거가 없는 FACT는 역할·조건·배경으로 남긴다. FLOW091의 모든 보존 조건을 변경점으로 칠하거나 PowerToys의 모든 파일을 각각 기능 변경으로 만들면 실패다. 변경 정보가 없는 항목/사례도 기본 설명·선택·상세가 성립해야 한다. C32 변경을 부모 전체에 귀속하지 않고, PowerToys 두 수정은 각각 자기 요구와 patch에 연결되어야 한다.

3. **관계의 뜻과 실제 끝을 보존한다.** FLOW091은 명시 새 요청의 사본, 내보내기 사본, matching returnId, 정확히 연결된 작업이라는 서로 다른 조건을 유지한다. PowerToys의 두 문제는 같은 리뷰·후속 커밋에 함께 있어도 직접 인과·호출 관계가 아니다. ManagedCommon의 실제 연계는 외부 공용 부품 의존이며 편집기 소유 자식으로 바꾸지 않는다. 포함·참조·호출·사건 대응을 하나의 ‘영향’ 선으로 통일하면 실패다. 접힌 대표와 실제 끝점은 상세에서도 구별되어야 한다.

4. **자료 부재를 새로운 미결로 생산하지 않는다.** changes 없음은 변경 미확인/미변경을 일괄 선언할 근거가 아니며, 자동 unknown·승인 필요·담당자 숙제를 만들지 않는다. FLOW091의 옛 사본 null은 계약상 없음으로 유지한다. 실제 검사·인계 증거 부재는 자료의 확인 범위로 설명하고, 진행 중 업무 상태로 승격하지 않는다.

5. **후속 상태와 준비 범위를 과장하지 않는다.** PowerToys의 검색 답변은 User 계정 주장이고 AI 참여 메타는 전체 AI 대화·인계 수락 증거가 아니다. PR 병합은 배포·실제 동작 검증과 구별한다. 현재 PR 본문을 최초 요구로 쓰지 않는다. 준비는 선택한 부분의 확인/조정 제안이며 두 수정·외부 훅을 자동 작업 범위로 합치거나 병합된 수정을 재지시하지 않는다. FLOW091도 보기 선택을 새 요청 생성·과거 사본 갱신으로 취급하지 않는다.

## 교체 검증의 완료선

PC에서 ‘기본 조망→한 부분→실제 관련 상대 참고→선택 범위의 준비→전체 복귀’를 두 입력으로 각각 확인한다. 사례를 바꾼 뒤 이름뿐 아니라 자료 성격·조건·변경 귀속·관계·준비 대상까지 바뀌고 이전 사례의 선택/편집이 새 사례의 것으로 잘못 섞이지 않아야 한다. 외형 일치나 검사 통과 수만으로는 위 기준을 충족하지 않는다.

두 사례에서 같은 표현 원리가 어디까지 재사용되고 어디에서 별도 설명이 필요한지 기록하면 이번 판정은 끝난다. 이를 제품 최소 체험 범위 결정의 근거로 쓰되, 임의 자료 자동 해석·전체 프로그램 조망·사람의 쉬운 이해가 검증됐다고 확대하지 않는다.
