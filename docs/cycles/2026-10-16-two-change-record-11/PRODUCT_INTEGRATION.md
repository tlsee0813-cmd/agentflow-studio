## 채택할 공통 경험

PC에서 전체 공간의 한 부분을 고르면 **그 부분의 현재 구상을 짧게 읽고 → 필요하면 연결된 작업 하나의 맥락/원문을 읽고 → 명시적으로 이어서 다듬고 → 출발한 지도 보기로 돌아온다.** 아무 작업도 선택하거나 작성하지 않고 돌아갈 수 있다. 프로그램의 부분이 첫 탐색 단위이고, Task는 거기에 연결된 작업 기록이다. 작업을 기능의 자식으로 그리지 않는다.

cycle11의 두 입력은 같은 화면이 성격이 다른 기록을 다룰 수 있다는 작은 근거다. 수동 구조화한 두 표본을 임의 기록 자동 지도화의 성공으로 확대하지 않는다. 연구의 층위/외부 공통부 표현을 보존할 가치는 있으나 이번 제품 연결에서 저장 구조 전체를 교체할 이유는 없다. **기존 평면 모델은 이 연결의 현재 저장 경계이지 최종 지도 모델로 확정한 것이 아니다.**

## 한 번에 체험할 최소 변경

1. **선택 영역을 먼저 읽는다.** 현재 areaPanel은 이름·구상 편집과 보고 발췌가 앞선다. 영역 이름과 사용자가 적은 현재 구상을 읽기 기본으로 바꾸고 편집은 명시적으로 연다. 구상이 길면 원문에 연결된 발췌임을 밝힌다. 빈 구상/작업 없음은 그대로 두며 AI 요약·자동 작업·미결 숙제를 만들지 않는다. 영역 선택만으로도 읽을 가치가 있어야 한다.
2. **한 작업을 골라 짧은 맥락부터 읽는다.** 기존 관련 요청 목록에서 사용자가 고른 Task의 이름/종류·영역 소속을 보여 준다. 이미 있는 currentWork의 짧은 이해/범위는 사용자 수정·AI/모의 제안·제외된 낡은 문구를 구별해 재사용할 수 있다. 값이 없으면 생성하지 않는다. 요청 원문·반환 보고·긴 기준은 필요할 때 펼쳐 읽으며 보고는 앱 미검증 표기를 유지한다. 모든 기록을 기본 화면에 연속 출력하지 않는다.
3. **명시적 이어가기와 기존 편집을 잇는다.** 작업 읽기는 이어갈 Task와 요청 대상을 바꾸지 않는다. ‘이어가기’를 눌렀을 때만 기존 continueTask를 사용하고 Task.id별 manual4필드를 기존 저장 경로로 편집한다. 이미 쓰던 새 요청/보고의 종류·대상 보존도 기존 writeInArea 정책을 따른다. 연구용 자유문을 네 필드에 자동 배분하지 않는다.
4. **‘출발한 지도 보기로’ 돌아온다.** 프로젝트·보기·선택 영역·지도 좌표/배율·열람 위치·호출 초점은 탭의 출발 상태 하나로 기록한다. 현재 존재하는 보기 요소만 저장하며 없는 패널 탭 같은 상태를 새로 만들지 않는다. 돌아올 때 명시적으로 선택한 currentTaskId나 저장한 manual 편집을 되돌리지 않는다. 삭제·보관·다른 프로젝트 전환으로 출발점이 유효하지 않으면 같은 프로젝트의 안전한 상위 보기로 이동하고 다른 대상을 임의 선택하지 않는다.

이는 후보 A(기존 경로 연결)에 꼭 필요한 짧은 읽기를 포함한 범위다. B의 별도 변화 요약 화면은 추가하지 않는다. 기존 backgroundPreview는 필요한 상세에서 요청 사본과 현재 목적/영역 이름/구상 차이만 설명한다. 그 차이를 코드 수정이나 ‘지난 방문 이후 달라진 점’으로 포장하지 않는다.

## 구현 완료 기준

PC1280×720·1440×900에서 두 경로를 분리해 실제 확인한다.

- **읽기만:** 영역 선택→작업 하나 읽기→긴 원문 열고 닫기→지도 복귀. 이어갈 작업·초안 종류/대상·manual값은 바뀌지 않는다.
- **명시 편집:** 같은 출발→다른 Task를 명시 이어가기→서로 다른 Task에 서로 다른 manual값 편집→지도 복귀. 출발 보기와 초점을 보조 이동 전 관측하고, 이어갈 작업·수정값은 새 값으로 남고 다른 Task에 섞이지 않는다.
- 작업 없음/구상 없음에서도 읽기 흐름에 가짜 의무가 없어야 한다. 긴 구상/긴 보고, 요청 사본 없음/구상 차이 있음, 낡은 AI 문구 제외를 기존 실제 데이터 의미대로 확인한다. 내용을 줄였다는 이유로 출처/대상/필수 조건을 없애면 실패다.
- 수정 전 재현 가능한 결함은 동일 검사 old-fail/new-pass로 남긴다. 소스·HTTP 일치, 계획 장면 완주, 실제 종료, 대표 화면을 GitHub에서 회수 가능하게 남긴다. 검사 통과를 사람 이해도 향상으로 말하지 않는다.

핵심 사용자 흐름은 읽기만과 편집 두 경로다. 나머지는 이 흐름의 실패 경계를 확인하는 검사이며 새로운 기능 목록이 아니다. 390은 접근/닫기/넘침 최소 확인만 하고 모바일 배치 최적화를 병렬 목표로 만들지 않는다.

## 보류할 표현과 남은 위험

연구용 긴 자료 경계 헤더·식별자·검사 수를 제품 첫 화면으로 가져오지 않는다. 공통 엔진 자체 이식, 임의 깊이/자동 추출/새 연결기, 코드 변경 자동 추론, 방문 간 변경 추적, 새 문장 생성, 전체 모바일 최적화는 이 연결 범위 밖이다. 사람이 짧은 문맥만으로 충분히 이해하는지와 큰 지도에서 혼합 깊이를 다루는 경험은 아직 남는다. 작업 선택을 강요하거나 단순 보고서 목록으로 돌아가면 작은 구현이라도 실패다.

이 연결을 검증 가능한 한 단위로 삼고 유사 시안을 계속 늘리지 않는다. 제품 소스 반영과 배포는 연구 판단과 별도이며 현재 HOLD를 해제한 것으로 기록하지 않는다.
