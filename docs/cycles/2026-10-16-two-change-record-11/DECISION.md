# cycle11 선택·완료 기준 — PC의 같은 화면에 두 입력
2026-10-16 총괄 판단. 이 문서는 선택 시점 계약이며 현재 진행은 [ACTIVE](../ACTIVE.md). 최신 사용자 검토를 수용해 새로운 사례 전용 시안이 아니라 **같은 렌더러에 두 입력을 바꾸는 작은 검증**으로 조정했다.

## 채택
- 공간: 포함 경계를 남기고 그 안의 실제 부분을 선택한다. 외부 지원부는 밖에 둔다. draw.io의 swimlane 직접 선택은 참고 원리이며 모든 그룹의 기본 동작이라는 주장은 하지 않는다.
- 읽기: PC에서 지도와 짧은 선택 요약을 먼저 보여 준다. 역할 한 문장과 근거가 있는 변경 한 문장, 다음 행동 하나가 우선이다. 요청·코드·작성자 주장 등 세부는 명시한 근거 읽기에서 연다. Grafana의 대상 이름을 유지하는 Inspect/Edit 구분을 참고하되 탭/통계 보고서를 복사하지 않는다.
- 준비: 선택한 부분에서 사용자가 명시적으로 여는 **빈 자유문 ‘내 다음 요청’ 한 칸**을 연구한다. 대상 이름과 참고할 기록은 읽기 전용으로 펼쳐 볼 수 있다. 기존 네 칸을 읽고 수정하도록 강제하거나 과거 수정 작업을 자동 재지시하지 않는다. 초안은 아직 보내지 않음이며 실제 작업 생성/AI 송신/수락이 아니다. 제품 Task.id별 manual 4필드는 유지되며 이번 연구가 이를 대체하지 않는다.
- PC 1280×720과 1440×900을 주 검증 폭으로 한다. 390은 최소 접근·넘침·닫기 확인만 하며 별도 모바일 재설계를 하지 않는다.

## 같은 화면이라는 기술·의미 조건
동일 index.html + engine.js + style.css에 flow091.json과 powertoys.json 두 입력을 넣는다. 선택기는 연구 사례 전환용이다. 사실·이름·구성·관계·변경·근거·초기 보기는 입력에 둔다. 엔진/CSS에 사례명·노드 ID·문구별 분기를 두지 않는다. 데이터의 구조와 optional 필드에 따른 표시는 허용한다. 수동 보기 배치나 순서는 fixture의 보기 제안으로 구분한다. 자동 원문 해석·연결기·범용 그래프 엔진은 만들지 않는다.

공통 입력은 schemaVersion, caseId, 제목/범위/자료 성격/기준 시점, nodes(고유 ID, parent 또는 null, 이름/역할/짧은 설명/근거/선택적 변경), relations(실제 from/to, 종류/짧은 설명/전체 조건/근거), evidence(종류/고정 원문/요약/확인 한계), initialView로 구성한다. 이번 허용 구조는 루트와 직접 자식의 두 층이다. parent는 보기의 포함이며 관계와 별개다. 입력 검사는 누락된 끝점·중복 ID·순환/지원하지 않는 깊이를 오류로 보여 주고 조용히 소속을 보정하지 않는다.

FLOW091은 기존 5역할·세부·6조건 관계와 C32의 근거 있는 변경을 보존한다. 나머지 사실을 변경으로 칠하지 않는다. PowerToys는 편집기 내부 두 동작과 외부 공통 입력 훅, 공통 훅→녹화 판정의 이벤트 종류 전달 관계를 표현한다. 두 수정 사이 인과선과 가짜 인계는 없다. 공통 훅도 실제 코드 변경을 설명할 수 있지만 사용자 변경 두 건과 동일한 별도 요구로 세지 않는다.

각 변경은 실제 근거와 비교 기준을 가진다. ‘마지막 방문 이후’ 자동 추적 기능이 없으므로 ‘이 기록에서 달라진 부분’으로 표기한다. 근거 부재/null에서 미결·승인 필요·숙제를 만들지 않는다. 임의 기록 전체를 자동 지도화할 수 있다고 말하지 않는다.

## 완료선
1. 두 사례가 동일 renderer/style 해시로 열리고 각 자료 성격·구성·관계·변경·정확 출처가 맞는다. ID를 바꾸거나 변경 배열을 비운 시험 입력에서도 사례 전용 문구/빈 가짜 행이 생기지 않아야 한다. 별도 세 번째 실사용 사례라고 부르지 않는다.
2. PC 두 폭에서 각각 전체 부분 지도→변경된 한 부분→역할과 짧은 변경 이해→필요한 근거→닫기→명시 요청 준비→입력→전체 복귀를 실제 조작한다. 관계 참고와 다른 대상 전환도 동작해야 한다.
3. 사례/대상별 초안 격리, 선택·깊이·줌·지도 위치 복귀, 근거 닫은 뒤 내용 제거와 호출 초점 복귀를 확인한다. 사례 전환은 열린 상세를 닫고 각 사례의 보기/초안을 보존한다. 메모리 보존이면 재로드/다른 세션 보존을 주장하지 않는다.
4. 기본은 짧게, 전체 조건·원문 종류·확인 한계는 필요할 때 읽힌다. 긴 문장 숨김으로 필수 조건이 없어지는 것은 실패다. 단순 글자 수·검사 수로 사람 이해 효과를 주장하지 않는다.
5. 작성자와 독립 검증은 실행 소스·HTTP·실제 조작·종료·오류·미실행을 분리한다. 최초 실패·수정 전 코드/검사·최종 대표 화면은 GitHub에 회수 가능하게 둔다. 로컬 경로만 남기지 않는다.

## 종료 후 제품 연결 판단
더 많은 시안으로 자동 연장하지 않는다. 두 입력 결과를 근거로 (a) 제품에 가져갈 공통 흐름 (b) 보류 표현/위험 (c) 기존 제품에서 재사용할 선택·작업·수동편집 경로 (d) 한 번에 체험할 최소 연결 범위를 하나의 판정으로 낸다. 실패한 부분은 그 부분만 수선한다.

제품 후보는 현재 영역/작업의 짧은 역할·변경 읽기→대상별 상세 근거→기존 준비 경로→원래 보기 복귀부터 검토한다. 연구용 계층/초안 형식을 그대로 제품 데이터 구조에 이식하거나 main/공개 체험판을 자동 변경하지 않는다. 기존 제품 제약과 실제 구현 비용을 함께 판정하며, 연구 통과를 제품 반영 완료로 계산하지 않는다.
