**질문 하나:** 키보드 관리 편집기의 서로 다른 두 동작이 수정됐을 때, 사용자가 어떤 부분이 어떻게 달라졌고 공통 입력부가 어디에 관여하는지 공간 지도에서 이해한 뒤 한 부분만 확인·조정할 수 있는가?

cycle10의 수신부 식별·간결 참고는 검증된 연구 후보로 남긴다. FLOW091의5역할·6전달/사본 규칙이나 고정 노드 구조를 PowerToys에 옮기지 않는다. 프로그램 전체가 아닌 근거가 있는 작은 부분을 다룬다.

## 이번 연구에서 비교할 것

- **공간·소속:** 키 검색·선택과 녹화 종료 판정은 같은 편집기 안의 서로 다른 동작이다. 공통 ManagedCommon 훅은 외부 지원부다. 포함과 참조를 구분하며, 파일 경로를 그대로 제품 사용자용 기본 화면으로 만들지 않는다.
- **짧은 현재 설명과 변경:** 기본은 역할·현재 변화·그 한 부분을 이해하는 데 필요한 맥락이다. 긴 리뷰·식별자·검사 수·병합 배지를 기본 화면의 중심으로 두지 않는다. 두 별도 요구가 한 커밋에 들어갔다는 사실을 하나의 변화 전파나 두 기능 사이 인과로 바꾸지 않는다.
- **원문과 조정:** 과거 작성자 주장, 고정 코드, 병합 기록의 증명 범위를 상세에서 구별할 수 있어야 한다. 확인/조정 문서를 만드는 미래 행동과 실제 과거 인계를 구분한다. 실제 AI 송신/수락 기능을 추가하지 않는다.

Pro A는 공간 포함·외부 공통부 참조 표현을, Pro B는 현재 역할·변경 설명과 정밀 근거로 내려가는 표현을 따로 조사한다. Dify의 실행 중첩을 기능 포함으로 복사하지 않는다. 앞선 메커니즘 이름을 다시 나열하기보다 이번 입력에서 작동하는 공개 서비스/오픈소스의 구체 동작1~2개, 손실, 고정 원문, 실제 관측 가능한 공개 데모와 짧은 절차를 제시한다. 문서/코드/정적 그림/직접 조작/사람 평가를 구분한다.

총괄이 입력·원문·실제 화면을 대조한 뒤 최대두 표현 후보 중 좁은 한 흐름을 선택한다. 그 전에는 구현·새 기능·계층 엔진·제품 소스 변경을 배정하지 않는다. 없는 미결·새 담당·인계·검증 성공을 발명하지 않는다. 선 방향은 cycle10에서 보류한 별도 질문이며 자동 구현 목록에 추가하지 않는다.

## 작은 흐름의 후보

전체 부분 지도에서 두 변화 위치를 파악 → 한 동작 선택 → 해당 동작과 공통부의 관계/정확한 변경 읽기 → 필요하면 그 한 부분의 확인·조정 준비 → 전체로 복귀. 이는 평가하려는 사용자 행동이며 원문에서 이미 성공한 기록이 아니다. 혼합 깊이·390 가독성·선택과 참고의 구별·편집 보존은 채택할 UI 계약에서 구체화한다.

실제 관찰 없이 사람 이해가 좋아졌다고 확정하지 않는다. 다음 반복의 입력으로 쓸 수 있는지까지 판단하고, 제품 전체 완성을 선언하지 않는다.
