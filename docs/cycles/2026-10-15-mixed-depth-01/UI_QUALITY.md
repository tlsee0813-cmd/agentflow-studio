# UI-02 화면·사용흐름 평가 틀

기준: `UI_NEXT.md`, `UI_RESEARCH.md`. 대상은 작성 중인 `canvas-study.html`이다. **실제 화면 검사는 아직 하지 않았으므로 아래 전 항목은 미실행이다.** 코드·Node 검사 통과를 이 표의 통과로 옮기지 않는다.

의미 보존 검사는 데이터의 관계 수·소유·버전·인계 내용을 판정한다. 이 평가는 같은 내용을 사용자가 화면에서 구별하고 찾아가며 돌아올 수 있는지를 판정한다. Dify 이상의 완성도 목표를 카드 장식이나 색상 유사성으로 평가하지 않는다. 아래를 통과하더라도 최종 제품 완성도나 Dify보다 우수함을 증명한 것은 아니다.

## 공통 관찰 조건

실행 담당은 파일 버전/해시·브라우저·화면 크기·브라우저 확대율을 기록한다. 1440×900, 확대율 100%에서 시작하고 390폭에서도 별도 수행한다. 같은 S2의 **A4 확인 → A2 결정 변경과 B 참고 확인 → A4 복귀**를 기본 흐름으로 삼는다. 클릭·키보드 조작과 그 전후 화면을 남기며, 자동화 실행과 사람이 읽은 관찰을 구분한다. 적어도 펼친 전체, A2 선택 상세, 내부 집중, 복귀, 좁은 화면의 핵심 동작에 식별 가능한 증거를 남긴다.

| 항목 | 관찰할 동작·화면 | 구체적 실패 기준 | 현재 |
|---|---|---|---|
| 1. 포함 경계와 관계 읽기 | 전체에서 A 경계, 여섯 부분, 바깥 B를 확인한다. 실제 선의 시작·끝을 눈으로 따라가고, A 접기 전후에 표시가 어떻게 바뀌는지 본다. | B가 A 내부처럼 보인다. 포함 경계와 관계선의 모양·접점이 구별되지 않는다. 선이 카드·글자를 가려 끝점을 알 수 없다. 접힌 표시는 숫자만 보여 원래 대상을 여는 조작을 찾을 수 없다. | 미실행 |
| 2. 정보 위계와 밀도 | 1440폭 기본 화면에서 카드 이름·짧은 목적·세분화 상태·변경 종류를 읽고, 선택 상세에서 긴 설명·전후 결정·이유·미결을 찾는다. | 상세를 열자 B나 현재 선택이 가려지고 복구 조작도 없다. 매 선택마다 전체맞춤으로 글씨가 작아진다. 카드 전문이 캔버스를 압도한다. 잘린 이름·정보에 접근할 수단이 없다. | 미실행 |
| 3. 선택·펼침·공간 조작의 예측 가능성 | 카드 선택, 펼침 버튼, 확대/축소를 따로 사용한다. 선택 상세를 열고 닫으면서 위치를 비교한다. 키보드로도 조작의 이름·초점·다음 이동을 확인한다. | 선택만 했는데 계층이 바뀐다. 배율 변경만으로 포함 깊이가 변한다. 패널을 열 때 원하지 않은 재배치·전체맞춤이 일어난다. 이름 없는 핵심 버튼, 보이지 않는 초점, 빠져나올 수 없는 초점 이동이 있다. | 미실행 |
| 4. 공간 기억과 복귀 | A4 선택·관계 목록·펼침 상태·화면 위치/배율을 기록한 뒤 내부 집중으로 들어가 A2와 B 참고를 읽고 이전 전체 보기로 돌아온다. 두 표현 전환도 같은 경로로 확인한다. | 돌아오면 A2가 선택되거나 A4를 다시 찾아야 한다. 펼침·목록·위치/배율이 초기화된다. 현재 경로와 돌아갈 위치를 화면에서 알 수 없다. ‘이전 보기’가 데이터 변경 취소처럼 보인다. | 미실행 |
| 5. 선택과 변경의 구별·찾아가기 | A4가 선택된 상태의 A2 변경 표시를 보고, A2 상세의 전후·이유를 연다. B의 관련 참조에서 변경 소유자를 찾아간다. 색 이외의 이름·문구·형태 표시도 확인한다. | 선택 테두리와 변경 표시를 구별할 수 없다. 색만으로 상태를 알린다. B에서 무엇이 어디에서 바뀌었는지 찾을 수 없다. 관련 참조가 B 자체나 관계 자체의 변경처럼 읽힌다. 변경 정보를 읽으려다 원래 선택 맥락을 잃는다. | 미실행 |
| 6. 390폭 핵심 행동 완주 | 좁은 화면에 맞는 탐색 경로로 A4 → A2 변경·B 참고 → A4 복귀를 수행하고, S3 인계 준비 내용과 미전달 상태까지 찾아 읽는다. 패널·목록을 닫고 캔버스로 돌아온다. | 데스크톱 전체가 단순 축소되어 읽거나 누를 수 없다. 가려진 조작 때문에 흐름이 막힌다. 패널/메뉴에서 돌아갈 수 없다. 가로 스크롤을 반복해도 핵심 내용·복귀 조작이 계속 화면 밖에 남는다. 인계 상태를 읽을 방법이 없다. | 미실행 |

## 판정 규칙

각 항목은 **통과 / 실패 / 미실행**으로 기록하고 수행 경로와 화면 근거를 붙인다. 캡처 한 장이나 작성자의 코드 설명만으로 상호작용을 통과 처리하지 않는다. 실패는 외관 취향과 구별하여 ‘어떤 조작에서 어떤 정보·맥락을 잃었는지’로 적는다. 핵심 행동을 막거나 구조·변경을 오해시키는 실패가 남으면 해당 표현의 수용은 보류한다. 이 틀은 첫 시안의 반복 개선 기준이며 사용자 이해도 검증을 대신하지 않는다.
