# 실제 브라우저 검증 환경 상태

2026-10-15 · 환경 준비와 시안 검증을 구분한다.

## 현재 환경

사용자가 다시 연 `agentflow-studio` 설정 세션에서 내부 보조 담당(6.1 Sol High)이 설치 스크립트와 시작 스킬 초안을 검토하고 저장·게시했다. UI의 ‘환경이 게시되었습니다’와 ‘게시됨’을 직접 확인했다. 나만 접근, 기존 패키지 관리자 범위를 유지했고 시크릿·권한·네트워크 범위를 추가하지 않았다.

Node 22.16.0, Playwright 1.57.0, 시스템 Chromium 154.0.8037.57을 사용한다. 설치/실행 경로는 `/workspace/browser-env`, 브라우저는 `/usr/bin/chromium`이다. 환경 준비 단계에서 실제 Chromium→HTTP 접속→입력·클릭→JavaScript/localStorage→뒤로가기→스크린샷 저장·읽기와 반복 실행을 확인한 보고를 받았다.

**새 Cloud 작업에서 게시본을 복원하는 검증은 미실행이다.** 현재 제공된 앱 도구에는 해당 환경을 지정해 새 작업을 시작하는 경로가 없었다. 기존 setup 세션의 준비된 환경에서 수행하는 아래 시안 검증과 별개다. 게시 자체를 새 작업 복원 성공으로 표시하지 않는다.

## 현재 시안의 독립 실제 화면 실행

대상은 `3847a9b267d43dcc16bd1b999af446ad5cc38c91`의 `docs/cycles/2026-10-15-mixed-depth-01/canvas-study.html`이며 SHA256은 `0AEEDD515E7F80F4B091BA1B395F90E0D19355A9EB3CA6C7E1174AD48FA2898C`다. 단일 HTML을 임시 HTTP 서버로 제공하며 제품 전체 빌드나 임의 소스 변경은 하지 않는다. 1440×900, 390×664, 390×844에서 합격 기준 9의 지역별 노출·이동·복귀와 스크롤을 배정했다.

실행 결과는 [독립 클라우드 근거](evidence/ui02/cloud-fix3/REPORT.md)에서 버전·실행 코드·원본 로그·대표 화면과 함께 읽는다. 이 근거는 작성자 Chromium 결과나 Node 대역 검사와 합산하지 않는다. 사람 이해도, Safari/Firefox, 실제 터치·화면 판독기, Dify 대비 품질 우위는 별도다.

원본은 [전달 고정 커밋](https://github.com/tlsee0813-cmd/agentflow-studio/tree/9afe18444d92cf5930e0af5406ad7efce309d7c7/docs/transfer/ui02-fix3)에 공개되어 다른 세션이 회수할 수 있다. 최종 JSON의 86개 검사 그룹은 모두 실행됐고 최초 완주 85통과·1실패도 보존했다. 목록 스크롤은 DOM 값 설정, 고정 헤더 가림 회피는 DOM 스크롤 후 실제 클릭이다. 휠·터치 입력 검증이나 모든 위치에서 가림이 없다는 보장은 아니다. 각 위치의 단언 범위와 검증기 종료 처리 보완은 감사 보고서에 구분한다.

## 이전 환경 실패 기록

이전 ChatGPT Work 클라우드 작업에서는 Chromium 배포 응답이 정상 ZIP 대신 HTTP 200/text-html 오류 페이지로 반환됐고, 별도 Cloud Chrome도 실행 컨테이너 localhost에 연결하지 못했다. 원격 로컬 파일 접근 정책을 우회하지 않았다. 당시 사용자가 브라우저 검사가 가능한 환경을 확인해 주겠다고 응답했다.

그 환경에서 원본 `5323e022`에 실행한 것은 Node 상태 검사다. 의미 시안 prototype.html fix3의 독립 4개 상태 통과도 실제 DOM·브라우저 검사로 바꾸지 않는다. Opus가 별도 환경에서 반환한 UI-02 작성자 브라우저 결과 역시 과거 Work 환경 문제가 해결됐다는 증거로 쓰지 않는다.

보조 담당의 브라우저 연결이 후속 턴에서 없어져, 총괄이 이미 열린 설정 탭에 준비된 검증 요청을 한 번 전송했다. 환경 진단 반복은 중단했고 보조 담당은 반환 결과의 독립 감사와 근거 정리를 계속 맡았다. ZIP 파일 미리보기의 자동 다운로드가 되지 않아 수동 저장을 요청했으나, 사용자는 GitHub 전달 공간을 제안했다. 연결된 기존 저장소에 전달 전용 브랜치를 만들고 Cloud의 원본 업로드를 해당 경로에 한정해 허용했다. 원본 회수와 감사 결과는 위 근거 문서에 구분한다.
