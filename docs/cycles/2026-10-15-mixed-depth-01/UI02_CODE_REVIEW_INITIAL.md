## 구현 발견 1개

### [P2] 구조 목록에서 상세를 보고 돌아오면 목록의 스크롤 위치가 초기화됨

**근거:** `canvas-study.html:686`은 목록 항목 선택 시 `ST.pane`을 먼저 `detail`로 바꾼다. 이후 536행의 저장 조건은 `ST.pane === "outline"`일 때만 참이므로 떠나는 목록의 스크롤을 저장하지 않는다. 579행의 `innerHTML` 교체로 기존 목록 요소가 사라진다. 다시 목록으로 돌아올 때는 536행이 새로 생성되었던 숨은 목록의 0을 저장하고, 592행이 이를 복원한다. 도구줄의 목록→다른 탭 전환도 696행에서 같은 순서로 처리한다.

**재현:** 390 폭의 S2 구조 목록을 아래로 스크롤 → A4 선택 → ‘← 구조 목록’. 기대는 이전 목록 위치 유지다. 독립 Node 요소교체 대역에서 합성 목록 `scrollTop=120`으로 시작했을 때, 상세 진입 후 `olScroll=0`, 목록 복귀 후 `scrollTop=0`을 관측했다.

**영향:** 상세를 확인한 뒤 탐색하던 목록 위치를 잃어 다시 찾아야 한다. 구조 목록을 기본 탐색으로 쓰는 좁은 화면의 복귀 동작에 해당한다. 의미 데이터나 캔버스의 전체/집중 좌표는 이 결함으로 변경되지 않는다.

**확인 수준:** 제어 흐름 정적 검토 + Node 상태 재현. DOM 요소를 교체하면 스크롤이 초기화되는 동작을 대역에 반영했다. 실제 브라우저의 픽셀 위치를 독립 관측한 결과는 아니며, 브라우저 후속 재현이 필요하다.

## 작성자 자기검사와 근거 품질

### 실제 동작을 검사하는가

`tests/check_canvas.js`는 jsdom에서 HTML의 스크립트를 실행하고 실제 버튼 `.click()` 후 생성 DOM/상태를 비교한다. 단순 소스 문자열 검색만 있는 검사는 아니다. 다만 레이아웃 검사는 아니고, 84는 독립 사용 시나리오 수가 아니라 인계 필드별 문자열 확인 등을 포함한 assertion 수다.

`tests/render_check.py`는 Playwright Chromium에서 클릭·마우스 끌기·키보드를 실행하고 bounding rect/SVG 샘플 좌표를 확인한다. 구조적으로 실제 브라우저 동작 검사다. 이번 검토자는 해당 프로그램을 재실행하지 않았으므로 동봉 로그는 **작성자가 제공한 실행 기록**으로 구분한다.

### 기능결함과 별개인 근거 품질 문제

1. **실패 assertion이 프로세스 실패로 이어지지 않음.** `check_canvas.js:14,169`, `render_check.py:8~13,188`은 실패 수를 늘리고 요약을 출력하지만 이를 종료 코드에 반영하지 않는다. 런타임 예외 없이 assertion만 실패하면 정상 종료할 수 있으므로 자동 수집기가 종료 코드만 볼 경우 실패를 놓친다. 이는 정적 제어 흐름 확인이며 현재 동봉 로그가 실패했다는 뜻은 아니다.
2. **Chromium 통과 수에 정보행 1개가 포함됨.** `render_check.py:97`은 `ok(True, ...)`로 프레임 머리글의 가시성 정보를 출력한다. 실제 가시성은 로그에서 False여도 PASS가 늘어난다. 따라서 동봉 ‘37 PASS’는 조건 검사 36개와 무조건 정보행 1개로 읽어야 한다.
3. **390 대상 가시성 주장이 좁은 검사보다 넓음.** `render_check.py:181`은 `inter(a4,cw)`로 일부 교차만 검사한다. 이것만으로 A4 카드 전체가 잘리지 않는다고 판정할 수 없다. 동봉 `390_S2_canvas_A4.png`의 A4 전체 표시를 읽는 것과 일반 회귀 조건의 충분성은 별개다.

작성자 로그에는 대상 HTML의 바이트 해시와 실행 시각이 없으므로, 이번 대상 해시와의 직접적인 실행 이력을 그 로그만으로 확정하지 않는다. 다시 실행할 때 해시를 함께 남기면 버전 연결이 가능하다.
