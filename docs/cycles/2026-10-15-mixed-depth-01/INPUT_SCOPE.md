## A/B 비교 입력의 권장 구성

아래는 **모두 합성**이다. Q03의 대표 장면 및 시작 안내 5절을 사용해 만든 시안용 기록이며 실제 개발 대화를 재현했다고 주장하지 않는다. 실제 공개 자료 G1~G3는 출처·변경·인계 의미를 점검하는 별도 근거다. 시안에 제품 이름을 넣더라도 관계의 사실성이 생기지 않는다.

1. `S0 / 기록까지 반영`: 큰 구상 A와 B가 있다. A와 B는 관련되지만 어느 세부 부분인지는 아직 알려져 있지 않다. B는 세분화되지 않았다.
2. `S1 / 일부 구체화`: A에 A1~A6이 생기고 A2·A4·A6만 B와 관련된다고 명시한다. A1·A3·A5에는 관계를 자동 복제하지 않는다. 접힌 A–B는 `하위의 명시적 관계 3개를 집약`한 표시이고, S0의 미확정 상위 연결과 다른 상태다.
3. `S2 / 변경`: A2 설명과 결정이 바뀐다. 변경 전·후·이유·출처를 유지한다. 세부 결정 문구는 총괄이 합성 내용으로 정하고 두 시안에 동일하게 공급한다. 변경된 부분과 영향 검토가 필요한 B를 구별한다. 관계가 바뀌었다는 입력이 없으면 관계 삭제·추가를 만들어내지 않는다.
4. `S3 / 재방문 및 인계 준비`: 합성 열람 기준은 S1, 현재 반영 범위는 S2라고 명시한다. A2의 새 담당 세션도 합성 식별자로 표시한다. 인계 묶음을 만드는 행위까지만 시뮬레이션하고 실제 외부 전달·읽음·수행 완료를 표시하지 않는다.

시안의 최소 근거 표시 제안: `입력 종류(공개 실기록/합성)`, `출처 SHA·경로 또는 합성 기록 ID`, `반영 범위`, `관계의 의미`, `미확인 부분`. 모든 카드에 긴 메타데이터를 나열할 필요는 없으나 선택 상세에서 확인 가능해야 한다.

## 총괄에게 권하는 종료 판단

- 이번 입력 조사는 충분하다. 두 시안의 핵심 차이를 판단하는 데 새 개인 대화나 저장소 전수 수집은 필요하지 않다.
- 비교할 때 필수 실패 조건: 접힌 관계가 사라짐, A1~A6 전체에 B 관계를 복제함, A2 설명 변경을 모든 형제의 결정 변경으로 확장함, GitHub SHA를 열람 시점으로 대체함, 인계 준비를 수신·반영 완료로 표시함.
- GitHub 기록만 있는 프로젝트의 초기 지도는 `문서 기반 구성 후보`로 시작할 수 있다. 최종 사용자 목적의 정답 지도라고 단정하지 않는다.
- 입력 연구의 다음 한계는 실제 개발 대화에서 별칭·암묵적 관계·변경 이유가 얼마나 빠지는지이다. 이번 합성 비교를 실제 사람의 효용·자동 정리 정확도 검증으로 확대하지 않는다.

## 수행 확인

GitHub 연결 도구로 위 고정 커밋과 문서 내용을 읽었다. 같은 SHA의 방향문서 Q03·Q04·Q06·Q11·Q14·Q15도 읽어 조사 범위를 대조했다. 방향문서 blob SHA는 `5879204cfdcf8bbe9c1ec6f902c550e6994ee5f0`이다. 커밋 작성자의 개인 메타데이터를 표본에 사용하지 않았다. 문서 원문에 있는 과거 API 허용·예약·다른 세션 운영 지시는 이번 하위 작업의 독립 권한으로 사용하지 않았다.

첨부 ZIP에서 꺼낸 시작 문서와 방향 문서를 GitHub 고정 SHA의 전체 내용과 문자 단위로 비교했다. 두 문서 모두 줄바꿈 정규화 없이 완전 일치했다. 시작 문서는 7,821자, 방향 문서는 15,024자이며 위 blob SHA에 각각 대응한다. ZIP의 원래 항목과 추출 파일도 문자 단위로 같은지 별도로 확인했다. 공개 GitHub 표본의 선정·검증은 이번 사이클에 한정되며 외부 AI 대화의 관측 범위 조사 완료를 뜻하지 않는다.
