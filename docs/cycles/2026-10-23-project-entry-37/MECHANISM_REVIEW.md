# 37 비교 조사와 총괄 판단

2026-10-23 KST · 구현 전 판단 시점. 현재 진행은 [ACTIVE](../ACTIVE.md), 이번 범위는 [INPUT](INPUT.md)이다.

[새 Pro 세션](https://chatgpt.com/c/6adab66c-4428-83ee-aac8-dec9d0914941)의 응답을 [원문](PRO_RESPONSE_KO.md)과 [회수 기록](PRO_RECEIPT.json)으로 보존했다. 모델은 실제 UI5.6 Pro, 완료10분12초이며 다른 지도 세션에 섞지 않았다. Pro는 코드/문서 조사이고 체험본 독립 조작이나35 PNG 판독을 수행하지 않았다고 명시했다.

## 수용

가벼운 프로젝트 선택→같은 프로젝트의 공간→필요한 한 부분과 행동으로 이어지는 연결을 유지한다. 카드에 작업/질문/보고의 모든 상태를 추가하지 않는다. 현재 작업·별도 미전송 초안·원보고의 의미를 구분한다. 재진입 과제는 버튼 순서를 알려주는 대신 '전에 목적과 구조를 만든 프로젝트로 돌아와, 이어갈 작업 한 건을 정해 새 인계가 가능한 상태로 준비'로 두어 다음 판단 때 활용한다.

총괄도 공식 문서를 다시 열었다. [Dify Quick Start](https://docs.dify.ai/en/quick-start)는 Studio에서 빈 workflow 생성 후 그 canvas로 진입한다고 안내한다. [Linear 공식 설명](https://linear.app/docs/initiative-and-project-updates)은 프로젝트 개요에 최신 업데이트를 두고 과거를 Updates로 분리한다. 이는 선택한 대상의 일관성과 현재/과거의 읽기 층 분리에 대한 참고다. 두 서비스의 실행 방식/건강 상태 체계를 우리 제품에 통째로 도입한다는 뜻이 아니다. Dify 카드 소스의 세부 항목은 Pro의 고정 소스 대조이며 이번 총괄이 다시 코드 전부를 검증했다고 세지 않는다.

## 수정해서 수용/보류

Pro의 '실제 미답' 항목에 후속 작업문 없는 보고를 함께 나열한 표현은 수용하지 않는다. 답변 없는 활성 질문과 아직 후속 작업문이 없는 보고는 서로 다른 사실이다. 후자는 처리 의무/실패/미결 질문이라고 단정하지 않는다. 원문은 지우지 않고 이 판단을 함께 둔다.

현재 작업·초안·후속 참고의 근거가 여러 층에 분산된다는 주장은 재진입 관측 가설로 보존한다. 실제 자료 선택 과제 전에는 새 상단 알림/추천/작업 우선순위 규칙을 만들지 않는다. '프로젝트 카드 자체는 적절하다'는 결론은 구조가 이미 있는 프로젝트의 코드 경로에 한정된다. 첫 방문 전체의 사용성 성공으로 확대할 수 없다.

## 이번에 실제로 고칠 것

총괄의 배포35 실제 조작에서는 fresh 방문이 빈 작업 폼으로 시작했고, 예제는 공간 없이 옛 요청을 읽게 했다. Astra와 Sol의 별도 코드 대조는 초기 startNew 분기, 예제의 영역 부재/전체 공간 메뉴 숨김을 확인했다. 이는 Pro가 실제로 관측하지 않은 조건이며 같은 결론으로 뭉치지 않는다.

따라서37은 기존 프로젝트 홈을 정상 첫 입구로 연결하고 작은 비저장 공간 예제로 프로젝트의 목적→포함 구조→한 부분의 기록/작업→전체 복귀를 경험하게 하는 후보 하나를 구현한다. 기존 홈과 지도·reader를 재사용한다. 새 프로젝트 작성/목적 입력을 삭제하지 않으며 유효 세션 복원과 오류 분기는 지킨다.

Dify 수준 이상이라는 전체 수용 선언, 사람 연구 완료, AI 의미 품질 완료는 하지 않는다. 제품에 대한 첫 이해가 개선되는지는 같은PC실제흐름으로 확인한다.36의 미세 카드 검증을 전체 제품 경험 완성으로 대신하지 않는다.
