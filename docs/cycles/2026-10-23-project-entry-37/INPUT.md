## 판단과 근거

별도 비공개35 체험본을 총괄이 실제 로그인 후 조작했다. 첫 방문은 빈 '나의 프로젝트' 작업/목적 폼이었다. '내 프로젝트'를 눌러야 빈 카드 홈에 도달했고, '예제 둘러보기·저장 안 됨'은 옛 미용실 요청 하나이며 영역과 지도 입구가 없었다. 예제 닫기 뒤 빈 작업으로 돌아왔다. 이는 코드의 fresh startNew, 예제 공간 부재/전체공간 메뉴 숨김과 일치한다고 독립 Astra가 확인했다.

사용자가 요청한 기본 경험은 프로젝트 목록에서 하나를 열어 목적과 부분의 관계를 공간으로 읽고 작업을 이어가는 것이다. 기존 홈/공간/부분 읽기/작업/복귀를 재사용한다. 새 엔진이나 추가 보고서가 해결책이 아니다.

별도 [Pro 비교 조사](https://chatgpt.com/c/6adab66c-4428-83ee-aac8-dec9d0914941)는 재진입에서 현재 작업·별도 초안·후속 필요 기록의 선택 근거가 분산될 수 있다는 가설을 냈다. 코드/문서 조사이고35 PNG는 판독하지 않았다. 이 가설을 즉시 새 상태 규칙으로 구현하지 않는다. 이번 첫 입구 결손은 실제 관측+소스가 있는 별도 총괄 판단이다.

## 좁은 변경

1. 유효한 화면 복원 정보가 없는 정상 첫 방문은 기존 프로젝트 홈을 연다. 유효한 세션 복원, 저장 읽기 오류, 복구 안내는 보존한다. 오류를 빈 목록으로 바꾸지 않는다.
2. 홈에서 실제 프로젝트와 명확히 구분되는 '공간 예제 · 저장 안 됨' 입구를 제공한다. 기존 카드 비율과 읽기 위계를 재사용한다. 새 랜딩 페이지/마법사/강제 안내 단계는 만들지 않는다.
3. 비저장 예제는 프로젝트 목적, 작은 포함 구조와 부분의 실제 소유 작업/명시적 합성 보고를 같은 제품 renderer로 보여준다. 적은 상위 부분과 하나의 하위 층위만으로 포함을 이해할 수 있어야 한다. 제품이 지원하는 정상 domain/API로 유효한 자료를 구성한다. 공간·보고·인계의 ID/부모/소유 연결을 임의로 위조하지 않는다.
4. 예제 카드→전체 공간→한 부분 읽기→그 부분의 작업→공간 복귀를 연결한다. 기록 존재를 완료/실행 성공/미결 해결로 표현하지 않는다. 필요하다면 작은 미결 하나를 명시하되 무의미한 테스트 식별자/검사 수를 기본 화면에 넣지 않는다.
5. 예제 닫기는 프로젝트 홈으로, '내 프로젝트 시작하기'는 기존 빈 프로젝트 작성/목적 입력으로 연결한다. 예제는 자동 저장/복제하지 않는다. 예제 편집은 기존 메모리 전용 정책을 따른다. 실제 프로젝트, 현재 작업, 다른 초안, 기존 세션/저장 오류를 덮지 않는다.

문구와 세부 배치는 구현자가 근거를 들어 조정할 수 있으나 위 의미 경계는 유지한다. Dify의 프로젝트 카드→작업공간 일관성은 참고하되 실행 워크플로 목적이나 노드 종류를 복제하지 않는다. PC1280/1440 중심이다.

## 확인할 PC 흐름

- 새 브라우저 저장상태에서 기본 홈과 예제의 비저장 성격이 실제로 보이는가. 사용자 프로젝트가 있는 정상 재방문 및 유효 세션 복원은 기존 계약을 지키는가.
- 예제의 목적/부모와 자식/정확한 소유 기록을 읽고 작업으로 갔다가 공간으로 돌아오는가. 실제 화면에서 작은 글씨·가림·초점·지도 보존을 확인하며 속성값 통과를 가독성 통과로 대신하지 않는다.
- 예제 열기·편집·닫기 뒤 실제 프로젝트 수/저장본/현재 작업/별도 초안이 동일한가. 반복 열기와 취소에도 예제가 목록에 새 사용자 프로젝트로 쌓이지 않는가.
- 내 프로젝트 시작하기가 예제의 보고/인계/기준/현재 작업을 물려받지 않고 기존 목적 입력과 명시 공간 진입으로 이어지는가. 저장 읽기 실패 상태는 빈 정상 홈처럼 표시되지 않는가.

작성자 검사와 독립 Cloud 실제 조작을 구분한다. 새 동작의 의미 있는 검사와 관련 홈/정적/공간 회귀만 우선 수행하며, 전체 최종 CI는 정확 통합 head에서 수행한다. 대표 화면과 재현 가능한 원자료는 GitHub delivery 새 접두사로 공유한다. 사람 사용성 수행이나 Dify 이상 전체 완성으로 과장하지 않는다.
