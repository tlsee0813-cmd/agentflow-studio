# 93 결과 — 요청문을 읽고 원래 자리로 돌아오기

**요청문 읽기와 복귀 수리를 범위 수용한다.** 저장된 요청문을 열면 본문에 키보드 초점이 들어가고, 닫으면 실제로 눌렀던 버튼으로 돌아온다. 요청문을 만들 수 없는 상태에서도 복귀하며, 복사 때문에 읽던 문서나 긴 초안의 위치가 사라지지 않는다. 늦게 끝난 복사는 이미 닫거나 다시 연 문서·다른 세션의 안내와 초점을 바꾸지 않는다.

최종 소스는 `d881b0ae8d892f6d65cfdce63a6924377ec567d7`, app tree는 `81c5a4e6e6428440427d97caa392ba156063e467`이다. [PR56](https://github.com/tlsee0813-cmd/agentflow-studio/pull/56)은 draft·미병합·미배포로 유지한다. 공개 수용본73, 미수용74, UI 범위 수용75를 구별하며 UI75 최종693의 수리를 보존한다.

기준 `bc3a02b`에서는 ‘마지막 요청문’을 닫으면 BODY로 초점이 사라졌다. 첫 수리 `c953621`에서 복귀는 고쳤으나 긴 초안의 스크롤이 200에서 0으로 돌아가는 문제가 남아 총괄이 직접 재현했다. `dc5cf51`에서 같은 텍스트의 스크롤 보존과 비동기 복사의 세션 확인을 추가했다. 최종 `d881b0a`는 검사만 바꿨다. 존재하지 않는 대기 항목을 건너뛰던 검사를 제거하고, 실제 다른 프로젝트의 문서를 연 뒤 이전 복사를 완료하는 순서와 최신 시도 우선 규칙을 확인하게 했다.

총괄은 Windows 1280×720·DPR1.25에서 기존 저장 파일을 정상 UI로 열었다. 표시를 붙인 검사용 초안 1,813자의 역방향 선택 4..15와 스크롤 208.8은 요청문 열기·복사·Esc 뒤에도 같았다. 요청문 본문의 읽던 위치 804.8도 유지됐다. 원래 133자 초안으로 다시 가져온 뒤 ×·하단 닫기·Esc 모두 같은 입구로 돌아왔다. 내보낸 변경안의 전체 묶음은 원본과 같고 내보내기 시각만 달랐다. 복사 직후 클립보드의 4,013자는 동결 요청문과 정확히 일치했다. [직접 관측과 원본 해시](evidence/root-ui-summary.json)

이 자료는 합성 문서 변환기 대화를 과거 실제 모델이 읽은 저장 사본이다. 실제 OSS 개발·실행 기록이나 새 모델 응답은 아니다. 여러 후속 행동 뒤 클립보드를 읽었을 때 936자가 나온 별도 관측도 보존했다. 중간 변경을 배제할 수 없어 이를 제품 복사 실패로 귀속하지 않는다. 정상 복사 직후 대조와 구별한다.

독립 Cloud는 제공한 최종 빌드의 `request93_flow`만 1280×720·1440×900, DPR1에서 각각 한 번 실행했다. 21.829초, exit 0이었다. 합성 초안 1,479자의 역선택과 스크롤 200, 요청문 12,515자의 본문 위치, 세 진입 경로와 닫기, 7개 지연 복사를 확인했다. 지연 복사는 실제 대기 항목을 각각 한 번 완료시키는 테스트 제어이며, OS 클립보드의 쓰기 순서 보장은 아니다. Cloud는 원본 PNG 네 장을, 총괄은 대표 두 장을 직접 열었다. 새 P1/P2는 없었다. 원본 ZIP 640,698바이트의 CRC와 8개 파일 해시를 대조했고, 전체 원본은 비공개 Ops에 보존했다. [독립 원본 결과와 한계](evidence/cloud-result.json)

총괄의 고정 TypeScript 5.8.3 검사·빌드는 최종 소스에서 통과했다. 최종 client와 CSS는 직접 화면 검증한 dc5 빌드와 바이트가 같아 그 범위의 증거를 재사용했다. [빌드 기록](evidence/build.json)과 [독립 코드 검토](evidence/code-review-summary.json)를 남긴다. 정확한 d881 소스의 [CI 40798177122](https://github.com/tlsee0813-cmd/agentflow-studio/actions/runs/40798177122)는 Windows·Ubuntu 모두 성공했다. 실제 AI 의미 품질을 검증한 결과는 아니다.

Cloud 관측기의 필드 이름 충돌로 N01 본문 자체는 추가 증거에 남지 않았다. 이번에는 입구·복귀·목록 위치·URL·카메라만 대조했고, 완료된87의 원문 검사를 반복하지 않았다. 세 스크롤의 동시 스트레스, 복귀 후 별도 Tab 순환, Cloud의 OS 클립보드 내용 대조도 미실행이다. 원본 보고의 판독 오류는 관측 도구의 한계로 남기며 제품 검사 재실행으로 덮지 않았다.

긴 원자료와 반복 Markdown의 읽기 부담은 남는다. 첫 지도 Q02/Q06의 의미 품질·전달 문제와 인수인계5·8의 전체 관문도 미완료다. 이 수리를 전체 제품 완성으로 취급하지 않으며 목표를 계속 유지한다. 새 모델 호출·완료 실험 반복·환경 설치·계정 변경은 없다.
