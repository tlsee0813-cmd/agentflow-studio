# 실제 포함 구조와 PC 작업공간18 — 구현 계약
2026-10-22 결정 시점. 현재 진행 상태는 [ACTIVE](../ACTIVE.md)에만 기록한다.
시작 checkpoint: 0bda82ee12c4a8e3e8b0559aa6c57271b87ba1aa. 제품 기준: e17370e83edccaf954b419054ee4748233752922.
제품의 기존 홈→전체 공간→한 부분→요청·인계→명시 복귀에 연결한다. 새 사례용 HTML은 만들지 않는다.

## 이번 사용 경험
사용자가 큰 구성 A를 A1/A2, A2의 한 부분까지 나누고 B는 큰 덩어리로 둔다. A만 접어도 안쪽에 기록된 질문과 설명 갱신이 있음을 알고, 실제 관계의 끝점을 찾아 그 부분의 현재 구상·설명을 읽는다. 정확한 부분에 요청을 만들어 인계한 뒤 출발 지도와 읽던 위치로 돌아온다. PC에서 긴 근거를 읽는 동안 지도와 다음 행동이 사라지지 않아야 한다.

## 데이터와 권위
1. Area ID는 유지한다. 프로그램 포함은 별도 Space.containment(version/child→parent/revision)로 저장한다. 한 자식의 활성 부모는 하나인 잠정 범위다. Task.parentTaskId는 작업의 이어짐이며 포함이 아니다. Relation은 실제 관계만 담는다.
2. flat project.6 이전 입력은 포함 없는 루트로 마이그레이션한다. project.7과 명시 anchor.2/새 plan stamp 변형을 사용하되 기존 정확 키 검증을 느슨하게 하지 않는다. 기존 anchor.1·return.1/2·원문·설명 이력은 보존한다. 필요한 변경이 이 범위를 넘으면 구현 전에 총괄에게 근거를 보낸다.
3. 수동 ‘하위 부분 추가’와 명시적인 소속 변경을 제공한다. 순환·자기 부모·없는/보관된 부모·타 프로젝트 부모를 거절한다. 활성 자식이 있는 부모 보관은 거절하고 먼저 자식 소속/보관을 정리하도록 설명한다. 좌표 드래그로 소속을 바꾸지 않는다. 공유 부분은 같은 Area와 관계로 연결하고 부모마다 복제하지 않는다.
4. 사용자 note/이름·명시 소속 변경에 단조 증가 revision을 기록한다. 부모 참고는 순서 있는 조상 ID/이름/note/revision으로 인계에 담고 ‘포함 맥락 참고이며 자식 실행 범위로 자동 상속되지 않음’을 밝힌다. 조상 작업의 개별 조건을 자식 실행 명령으로 자동 합치지 않는다.
5. 조상 변경·이동은 이후 자식 설명의 기준 검증에 반영한다. 조상 변경 후 돌아온 늦은 설명은 보류하고 과거 설명은 현재 인계에서 제외한다. A→B→A나 부모 구상 수정→원문 복원도 변경 이력을 지우지 않는다. 입력 수신·현재 표시·정정·다음 인계가 같은 유효성 함수를 쓴다. 단순 재저장으로 오래된 기준을 새 기준처럼 만들지 않는다. 관계 없는 가지·pan/zoom/접기는 유효성을 바꾸지 않는다.
6. 과거 anchor.1에 당시 없던 조상 정보를 소급하지 않는다. 이전 부모 없는 루트 설명은 종전 자기 기준으로 읽을 수 있으나 나중에 부모가 붙으면 조상 기준 미기록으로 현재성에서 제외한다. 과거 원문/보고 읽기는 계속 가능하다.

## 한 지도 안의 서로 다른 깊이
- 가지별 접기/펼침과 배율은 독립이다. 접기는 보기 상태이고 프로젝트 의미 데이터를 바꾸지 않는다. 각 Area의 절대 수동 좌표는 유지한다.
- 기존 평면 뒤에 부모와 자손을 나타내는 경계/경로를 더한다. 프레임 본문은 카드를 가로채지 않는다. 계산된 프레임은 이동 핸들이 아니다. 별도 전체 자동 재배치 엔진은 만들지 않는다.
- 새 하위 부분은 해당 부모 주변의 빈 위치에 놓는다. 임의 기존 좌표의 겹침은 자동으로 고칠 수 있다고 주장하지 않는다. 겹친 프레임 때문에 다른 소속으로 오해되거나 제목·카드·접기 조작이 가려지는 경우는 수용 실패다. 경로/소속 표시와 비차단 프레임으로 해결하고 남는 반례는 기록한다.
- 숨은 끝점은 가장 바깥 접힌 조상으로 투영한다. 묶음 기준은 보이는 from/to+방향+종류다. 직접 관계와 안쪽 관계 수/실제 원관계 ID·끝점·note는 보존한다. 반대 방향이나 다른 종류를 합치지 않는다. 같은 접힌 대표 안의 내부 관계를 가짜 자기 루프로 그리지 않으며 목록에서 실제 끝점을 읽을 수 있다.
- 집약선/연결 목록→실제 끝점 선택은 필요한 조상만 펼치고 그 카드가 읽히도록 최소 이동한다. 전체 Fit이나 배율 변경을 강제하지 않는다. 원래 보기로 명시 복귀할 수 있다.
- 접힌 카드와 연결 목록에서 ‘기록된 질문’과 ‘설명 갱신/보류’를 구분한다. 실제 소유 Area로 이어지는 목록을 제공한다. 기존 checkItems의 질문/보고, areaDescription의 current/held를 재사용한다. 보고 수를 미결 수로 부르거나 부모 완료로 합산하지 않는다. 질문 없음은 일반 개발 미결 없음이라는 뜻이 아니다. 신규 수동 미결 장부·읽지 않음 추적은 이번 제외다.

## PC 작업공간과 읽기
- 1280×720,1440×900 중심. 전체 공간에서는 압축된 상단 맥락 아래 지도와 패널이 남은 viewport 높이를 함께 채운다. 기존 560px 상한 때문에 큰 PC 공간을 버리지 않는다.
- 지도 최소 약2/3, 패널 약300px 기준. 큰 화면의 여유는 지도에 먼저 준다. 패널 리사이저/도킹은 제외.
- 패널은 고정 제목·포함 경로·닫기 / 스크롤 본문 / 고정 행동행이다. 본문만 overflow:auto, min-height:0, overscroll containment. 행동은 영역 열기·새 요청을 직접 노출하고 나머지는 더보기로 접근한다. 행동행은 입력을 덮는 overlay가 아니다.
- 기본 본문은 사용자 구상·받은 설명·중요 변화/판단을 짧게, 요청은 개수와 소수만 보여준다. 전체 근거/이력/긴 요청 목록은 명시 펼침. 권위 표시와 원문 접근은 유지한다.
- 60자 제목,2000자 구상,공백 없는 URL,긴 경로,요청5개에서도 가로 페이지 스크롤이나 사라진 닫기/행동이 없어야 한다.
- 패널 휠/키보드가 뒤 지도·페이지로 새지 않는다. 새 지도 휠 제스처는 추가하지 않는다. 이름 있는 region, 행동으로 건너뛰기, Tab/Shift+Tab/Esc를 제공한다. IME 조합·내부 컨트롤이 소비한 Esc로 패널을 닫지 않는다.
- 닫기는 선택 해제와 해당 카드 초점 복귀이고 카메라 복원이 아니다. ‘위치 찾기 전 보기로’는 전체 출발 상태 복원이다.
- project+Area별 패널 읽기 위치/anchor, 명시 펼침, 가지 접기, 선택·카메라·초점·작성중 입력은 기존 Origin/view memo에 연결한다. 공간→영역→새 요청→인계→명시 복귀도 포함한다. 내용 길이가 바뀌면 숫자 scrollTop만이 아니라 읽던 항목 anchor를 사용한다. 접기/읽기는 탭 수명 보기 상태이며 project schema에 저장하지 않는다.

## 두 입력과 출처
같은 제품 renderer에 두 독립 입력을 적용한다. 아래 층위는 원자료의 명시 제품 계획이 아니라 분석자 재구성이다.
- PowerToys PR51150/a964: editor→검색·선택/기록 종료, common hook 별도 루트. 실제 XAML의 mapping control→KeyDropDownButton→검색 입력·결과를 3수준의 근거로 쓰되 reusable type와 instance를 구분한다. hook의 event 전달은 relation. a964가 두 review요구를 함께 고쳤으므로 ‘한쪽만 해결된 실제 중간본’을 꾸미지 않는다.
- 내부 제품13: SPACE→PURPOSE/MAP/RECORDS/ADD는 기존 분석자 대응, MAP→도구/영역 카드/선택 상세는 renderMap을 근거로 재구성한다. v0 clipping 독립 관측과 fix1 작성자 제한은 다른 출처다. zoom 도구 수정이 clipping 해결을 뜻하지 않는다. ADD→카드 관계의 정밀 대응은 분석자 판단이라고 밝힌다.
- 실제 질문이 없는 곳의 미결 신호, 순환,공유/반대방향,긴문자 등의 검사는 별도 ‘합성 경계 사례’로 표기한다. 두 사례를 새 UI로 따로 만들지 않는다.
