# 35 최신 PC 흐름의 독립 미리보기 준비
작성 시점: 2026-10-23 KST. 34 카드 후보 검토와 독립적으로 준비한다. **공개 배포는 아직 결정하지 않았고, 이 범위는 빌드·격리·실제 흐름 검증까지다.** 현재 배정은 [ACTIVE](../ACTIVE.md)를 따른다.

## 이유
수용된 checkpoint 제품을 최신의 연결된 PC 경험으로 체험할 준비가 필요하다. 또 다른 작은 지도 표시 변경만 반복하지 않는다. 현재 공개 USE106과 연구/제품 소스의 차이를 분명히 한다. 34가 보류되더라도 이미 수용한33의 흐름으로 준비할 수 있다.

## 최소 구현
- 기존 명시 정적 browser MOCK 빌드를 재사용해, 독립 출력 폴더에 최신 미리보기 하나를 만든다. 일반 서버와 기존 정적 데모 빌드 경로는 유지한다. 같은 코드/기능을 통째로 복제하는 별도 앱을 만들지 않는다.
- 전용의 고정 저장 접두사를 사용한다. 현재 runtime-static.ts의 agentflow.studio.browser-demo:와 달라야 한다. local/session/legacy backup/충돌 확인의 모든 저장키에 적용하며 기존 데모를 읽는 fallback·자동 복사를 넣지 않는다. 접두사를 빌드마다 바꾸지 않는다.
- 미리보기와 규칙 기반 MOCK임을 짧고 명확하게 표시한다. 실제 AI나 서버 실행으로 보이게 하지 않는다. 자료 이동은 기존 백업 파일의 명시 가져오기다.
- 출처 commit·빌드도구·산출파일 해시를 기록해 GitHub로 재현·전달한다. 개인정보/키/실사용자 기록을 넣지 않는다. 대형 ZIP과 로컬 경로만의 인계는 피한다.

## 검증
1. 같은 origin의 기존 데모와 미리보기를 왕복하며 각각 저장·새로고침한다. 양쪽 local/session 자료와 기존 legacy 키가 서로 바뀌지 않아야 한다. 다른 프로젝트를 선택하는 per-tab 상태도 격리한다.
2. 기존 하위 경로 모듈 import, 정적 allowlist, connect-src none, API 요청 없음, 명시 백업·복구를 재사용해 검사한다. 원검사의 단언을 낮추지 않는다.
3. PC1280/1440의 한 흐름: 프로젝트 카드→한 부분의 설명/기록→명시 이어가기→N만 수정→정확H 인계→합성 파일 선택/검토/명시수신→출발 지도 복귀. 실제 입구를 사용하며 details를 코드로 여는 검사를 발견성 근거로 쓰지 않는다.
4. 코드·작성자·독립 화면·정확CI를 구분해 수용한다. 준비한 빌드가 공개 게시됐다고 하지 않는다. 대규모 새로운 온보딩/저장 엔진/자동수집·실제AI는 추가하지 않는다.
