2026-10-22. 사용자의 연속 진행 지시에 따라 18의 제품 통합 뒤 이어가는 좁은 개선이다. 현재 상태는 [ACTIVE](../ACTIVE.md)에서만 갱신한다. 이 문서는 착수 당시 판단과 합격 기준이다.

## 선택한 최소 변경
- 지도 화면에서 중복 프로젝트 맥락을 줄인다. 프로젝트 이름은 한곳, 저장 상태는 항상 보이며 관리 동작은 이름 있는 메뉴에서 찾는다. 작업/집중 화면의 공용 헤더 동작을 의도 없이 바꾸지 않는다.
- 목적의 짧은 표시와 전체 원문/고치기 접근을 유지한다. 저장 실패·보류·가져오기 결과를 장식으로 숨기지 않는다. 긴 이름/목적/URL도 가로 페이지 넘침 없이 읽을 수 있어야 한다.
- 기존 우측 300px 읽기 패널을 부분/연결/이어 볼 기록 보기로 전환한다. 제3pane, 도킹/리사이저, 새 기록 모델 없이 기존 checkSection/checkRow와 정확 taskId/returnId를 재사용한다.
- 기록 개수나 펼침으로 지도 위가 길어지지 않는다. 본문만 독립 스크롤하고 제목/보기 선택/해당 보기의 행동은 고정한다. 기록을 읽을 때 이전 선택 영역의 새 요청을 현재 기록의 행동처럼 노출하지 않는다.
- 지도 카메라, 영역별 초안, 각 보기의 펼침/읽기 위치는 별개 탭 메모리다. 보기 전환이 저장된 프로젝트 원문/현재 작업/구상을 변경하지 않는다.

## 복귀 계약
출발 기록 → 부분 → 연결 → 실제 끝점 → 요청/인계의 중간 전환이 최초 명시 출발 보기·호출행을 덮지 않아야 한다. 명시 복귀는 지도 camera/선택/접힘과 정확한 패널 보기/목록 anchor/실제 호출행을 회수한다. 기존18의 최종 펼침·높이 확정 뒤 읽기 memo 복원 순서를 유지한다.
새 요청 때문에 보고행이 이어 볼 목록에서 정당하게 사라지면 가짜 행을 부활시키거나 다른 보고에 초점을 주지 않는다. 기록 보기와 가능한 읽기 위치를 복원하고 짧은 이유와 안정된 목록 머리 fallback을 제공한다. 패널 닫기와 출발 복귀는 다르다. Home에서 원래 초기화되던 모든 미저장 입력까지 보존된다고 확대하지 않는다.

## 합격 기준
1. 양PC 기본·선택·기록 읽기의 지도와 도구가 실제 보이고 클릭/키보드로 작동한다. 기본 mapTop≤230px은 개선 목표이며 실제 안내 상태의 공간을 별도로 측정한다. 핵심은 기록 열림/1→5건 이상 증가가 지도 높이를 바꾸지 않는 것과 지도 실제 가시 면적의 개선이다. CSS 상수를 기대값에 그대로 옮긴 검사는 사용하지 않는다.
2. 5건 이상 기록에서 끝행까지 native wheel/키보드로 접근하고 정확한 보고를 읽은 뒤 실제 호출행으로 돌아온다. record 종류·원문·선택 보고의 의미를 유지한다.
3. 긴 이름/목적 전체를 읽고 미저장 영역 편집을 둔 채 다른 기록/부분을 읽어도 초안과 행동 대상이 섞이지 않는다.
4. 실제 새 요청/인계문 대상은 명시 선택한 정확 영역이다. 원문/사용자 기준은 읽기만으로 바뀌지 않으며 출발 records 보기/카메라/anchor로 돌아온다.
5. 요청 후 사라지는 보고행 fallback, 목록 재열기의 숨은 이전 DOM memo 덮어쓰기, 모드 간 memo 혼입을 검증한다.
6. 패널 휠/키보드가 뒤 페이지·지도에 새지 않는다. 조합 중·이미 소비된·입력 내부 Escape는 보호하며 정상 닫기 초점도 검증한다. 실제 OS IME와 합성/CDP 이벤트는 구분한다.
7. 이전18의 포함/질문/권위/PC 복귀와 홈15/보고16/갱신17 회귀를 유지한다. 구형 화면 구조 검사 수정은 전제 변화와 실제 단언 유지 여부를 분리 기록한다.
8. 정확 최종 head의 Ubuntu/Windows CI와 작성과 분리한 Cloud 실행, 공유 PNG/원본을 대조한 뒤 checkpoint 수용 여부를 판단한다. 중간본 실패도 보존한다.
