# PC 지도와 기록 읽기19 — 착수 판단
2026-10-22 착수 시점의 결정 기록. 현재 상태는 [ACTIVE](../ACTIVE.md). 구현/실제 검사 완료 선언이 아니다.

## 관측한 문제
18 최종 공유 PNG에서 1280 실제 자식 선택은 지도 시작이 약414px, 1440 펼친 기록과 RB-A 복귀는 약525px이었다. 동작 결함은 해결됐어도 맥락·기록이 작업면을 밀어내는 읽기 부담은 남았다. [고정 원본](https://github.com/tlsee0813-cmd/agentflow-studio/tree/479658cc6748b7755b1423a9ef524e0b1b9c922d/docs/transfer/mixed-depth-18/independent-fix4).

## 비교와 선택
A는 기존 우측 읽기 패널에서 부분/연결/기록을 전환한다. 지도 높이는 일정하나 보기별 상태와 최초 출발점 보호가 필요하다. B는 지도 위 기록띠에 높이 상한과 내부 스크롤만 둔다. 수정은 작지만 기록을 읽는 동안 지도 높이를 계속 소비한다.
총괄은 A를 택했다. 상태 보존을 대충 처리하고 공간만 늘리는 구현은 수용하지 않는다. 기록→부분 전환 시 한 번에 읽을 수 있는 내용은 줄지만 명시 기록 복귀와 각 보기 읽던 위치를 보존하여 반복 닫기/다시 찾기를 피한다. 별도 도킹 시스템은 만들지 않는다.

## 외부 메커니즘과 목적 차이
- 총괄은 사용자 Dify 워크플로의 버전 기록을 실제 열어 우측 패널과 남은 캔버스를 확인했다(2026-10-22). 화면에는 보기 전용·복원·종료 버전과 빈 기록 안내가 나타났고 종료하여 기존 캔버스로 돌아왔다. 버전 복원이나 실행·게시를 수행하지 않았다. 빈 목록 관측이므로 많은 기록의 스크롤 품질을 확인했다고 하지 않는다. AgentFlow의 이어 볼 기록은 과거 버전의 복원 화면이 아니다. 공간 분리 원리만 참고한다.
- [Dify 공식 Workflow Studio](https://www.dify.ai/workflows)는 실행과 게시·버전·관측을 연결하는 제품이다. 우리의 구상·변경 이해와 외부 작업 인계 목적과 구별한다.
- [VS Code 공식 Custom Layout](https://code.visualstudio.com/docs/configure/custom-layout)은 중앙 작업면과 보기 영역의 분리, 패널 위치/표시 전환과 배치 기억을 설명한다(2026-10-22 문서 확인). 이것은 AgentFlow에 도킹/최대화/사용자 레이아웃 설정 전체를 도입하라는 근거가 아니다. 지도 높이를 기록 내용에 종속시키지 않는 좁은 원칙으로 적용한다.
- [기존 Pro PC 공간 연구와 같은 주제 후속](https://chatgpt.com/c/6ad9e588-d3e0-83e8-bdd6-660ab76650a7). 새 홈 모델 선택에서는 Pro가 노출되지 않았으나 기존 PC 주제 세션에 5.6 Pro가 표시됐고 좁은 후속 질문을 제출했다. 착수 시점에는 후속 답변 수용 전이다. 앞선 연구와 새 응답을 섞지 않고 후속 판단은 별도로 추가한다.

## 내부 감사에서 수용한 반례
A 선택의 미저장 초안이 남은 B 기록 보기에서 A 새 요청을 B의 행동처럼 노출하면 안 된다. records→부분→연결→정확 끝점의 모드 전환이 최초 출발 Origin을 덮으면 안 된다. 원보고가 다음 요청으로 목록에서 빠졌다면 가짜 행을 복구하지 않고 정직한 이유/안정된 fallback을 써야 한다.
원래 목적/영역 입력 buffer, 숨은 이전 DOM, 공용 헤더 적용 범위, 최종 body 크기 이후 scroll anchor 복원 순서를 기존 코드에서 확인했다. 검사 수가 많아도 실제 호출행 가림을 놓친18의 사례 때문에 새로운 결과도 실제 rect/hit/초점과 PNG를 대조한다.

외부 코드를 도입하지 않는다. 사람 사용성 결과나 Dify 이상 완성으로 표현하지 않는다. 사용자의 Dify 비교 기준을 적용하며 사람 기록 제출을 추가 관문으로 요구하지 않는다.

## Pro 후속과 총괄 대조 — 같은 날 추가
후속 응답은 10분36초 처리 뒤 회수했다. Pro는 고정 PNG 파일/메타데이터에 접근했으나 화면으로 렌더링하지 못했다고 명시했다. 따라서 그 응답의 시각적 판정은 채택하지 않고 총괄의 직접 PNG 관측과 구분한다. 같은 PC 주제 세션을 이어 사용했으며 다른 의미/구조 연구를 한 세션에 합치지 않았다.

Pro도 A를 권고했다. 고정 진입 버튼으로 기록 발견성을 유지하고, 패널 mode가 제목·본문·행동을 함께 소유하며, mapSelected와 행동 대상을 분리하라는 제안을 수용한다. 행이 없어지면 인접한 다른 보고로 가장하지 않고 목록 머리와 가능한 읽기 위치/짧은 이유로 돌아온다는 기존 계약을 재확인했다. '새 요청이 생겼다'는 특정 이유를 확인 없이 단정하거나 '다음 행동 없음'을 개발 미진행으로 일반화하는 문구는 그대로 가져오지 않는다. 저장 실패를 '이 탭의 내용이 보존되지 않았다'고 쓰는 제안도 메모리 보존과 영구 저장을 혼동하므로 채택하지 않는다.

총괄이 [Dify 고정 소스](https://github.com/langgenius/dify/blob/0d06488de5dfc0ae49b28be5ffb19c8b819ef364/web/app/components/workflow/header/header-in-normal.tsx)를 직접 읽어 isRestoring·draft 백업·다른 우측 패널 닫기를 확인했다. 이는 실제 UI의 보기 전용/복원/종료와 일치한다. AgentFlow에서는 기록을 읽기 위해 현재 프로그램 상태를 과거 snapshot으로 바꾸지 않는다. [VS Code References View 원문](https://github.com/microsoft/vscode/blob/main/extensions/references-view/README.md)도 참조 결과를 sidebar tree로 분리하고 결과 사이를 이동하는 기능임을 확인했다. 목록과 목적지를 분리하는 참고이며, 동적으로 목록 자격이 사라지는 AgentFlow의 fallback은 자체 계약이다.

목적 전체 읽기/편집도 지도 위 inline 펼침으로 되돌아가는 위험을 추가 점검한다. 기존 전체 읽기 기능을 재사용할 수 있는지와 편집 중 공간 점유를 구분해 판단하며, 목적 전용 새 엔진이나 도킹 범위로 확대하지 않는다. 총괄은 기존 project-read의 지도 호출/닫기 복귀 분기를 재사용한 전체 읽기를 승인했다. 드문 명시 편집은 기존 inline을 유지한다.
