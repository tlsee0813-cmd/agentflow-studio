# FLOW091-U — 기존 화면·문구·탐색 정리 (후보 `flow090/spatial-workspace`, 기준 `f2111453`)

이번 배치는 이미 있는 화면, 문구, 탐색만 정리했다.
- 새 도메인, AI, 연동 기능은 없다. 저장 형식(`idea015.project.4`), 작업 ID, 부모, 기록은 바꾸지 않았다.
- 공급자 경계와 프롬프트는 그대로다. 사람 대상 사용성 검증이 아니다. 브라우저 검사는 실제 HTTP와 MOCK으로 했다.
- 별도 후속(이번 아님): `space.brief`와 영역 설명은 인계문에 들어가지 않는다. 안내 문구를 늘려 덮지 않았다. → 후속 커밋 FLOW091-C(`flow091-background-contract.md`)에서 배경 사본 계약으로 연결했다.

| 선택 패널의 최근 보고 | 없음(영역 화면에서만 볼 수 있었음) | 그 영역 최신 반환의 원문 앞 140자(‘원문 앞부분’, 날짜, 연결 작업, 미검증), ‘자세히 보기’(영역 화면에서 그 작업의 원문을 펼침), ‘이 보고에서 이어가기’/‘작업 화면으로’(명시 행동). 요약, 판정, 정규식 분류(예: ‘미검사’ 추출)는 하지 않는다 |

## B. 지도와 작업 화면을 주 화면으로
- **위쪽 압축.**
  - 프로젝트 안(환영 화면 뒤)에서는 프로젝트 머리의 영문 소제목과 부제를 숨기고 이름 칸을 줄였다. 이름 편집은 그대로다.
  - 전체 공간 머리는 한 줄이다: ‘전체 공간 · 프로젝트 목적 · 원문(한 줄 말줄임)’. 원문 전체와 고치기는 ‘목적 전체 보기 · 고치기’ 안에 있다. `#space-brief`에는 원문 전체가 들어 있다.
  - 1265×712에서 지도 위쪽 끝은 456px에서 334px로, 작업 화면의 ‘지금 할 일’ 줄은 359px에서 292px로 올라왔다. 빈 여백만 추가하지 않았다.
- **화면 밖 영역.**
  - 지도에서 카드가 보이는 영역 밖에 있으면 왼쪽 위에 ‘화면 밖 영역 n개 · 모두 보기’를 띄운다. 누르면 기존 ‘전체 맞춤’과 같다(보기만 바꾸고 위치는 그대로).
  - 자동 재배치나 배율 자동 초기화는 없다. 이동·확대·맞춤 뒤마다 다시 센다.
- **좁은 화면 영역 목록.**
  - 760px 이하에서는 지도 위에 ‘영역 목록 n개 · 지도 확대와 상관없이 고르기’가 나온다. 지도와 같은 영역 ID를 쓰며(`data-area-id`), 영역이 5개 이하면 펼쳐져 있다.
  - 줄마다 선택 버튼(지도 선택과 같은 동작)과 ‘열기 ↗’가 있다. 열기 버튼은 74×44px다. 맞춤 뒤 지도 카드의 열기 버튼은 42×14px까지 줄어든다.
  - 편집 자료를 복제하지 않았고 별도 페이지도 없다. 넓은 화면에서는 숨긴다.
- **영역에서 지도로 돌아오기.**
  - `openSpace`(경로 ‘전체 공간’, 사이드바)가 설정 시트만 닫는다. 선택 강조와 보기 위치는 그대로다.
  - 저장하지 않은 이름·설명 입력이 있으면 값(프로젝트·영역 키)은 남고, ‘작성 중인 ‘영역’ 설정 다시 열기’ 버튼이 나온다.
  - 선택(`mapSelected`), 시트 열림(`sheetOpen`), 현재 작업(`currentTaskId`)은 서로 다른 값이다. 돌아오기는 현재 작업을 바꾸지 않는다.

## 남은 한계
- 화면 밖 판정은 카드 전체가 보이는지로 센다. 일부만 보이는 카드도 ‘화면 밖’에 들어간다.
- 패널 발췌는 글자 수로 자른 원문 앞부분이다(공백은 한 칸으로 합침). 문장 단위로 자르지 않는다.
- 목표와 원문이 ‘같은지’는 앞뒤 공백을 뺀 문자열 일치로만 판단한다. 비슷한 문장은 접지 않는다.
- 좁은 화면에서 프로젝트 도구 버튼(백업 등)은 여전히 두 줄이다.
- 사람 대상 사용성 확인은 하지 않았다.
