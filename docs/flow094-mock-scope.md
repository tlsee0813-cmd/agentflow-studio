## 재현 (REUSE093-P, Pro가 fd82e964 실제 UI에서 저장한 작업문)
첨부 ZIP sha256은 `e609478f…66465c6`이다. 같은 요청과 구상을 도메인 → MOCK → `handoffText` 실제 경로에 넣어 같은 결과를 재현했다.
- **A (설계 검토, ‘코드·설치·실행·저장소·배포 변경 없이’).**
  - 원인: 어떤 규칙에도 걸리지 않아 기본값으로 떨어졌다. 기본값은 항상 구현을 가정한다.
  - 결과: 다음 작업이 ‘관련 구현 위치를 찾고 요청한 부분만 수정하세요’, 확인할 동작이 ‘관련 검사를 실행해’였다.
- **B (정보확인 분담 설계).**
  - 원인: 장애 규칙이 키워드 `오류`만으로 발동했다. B에서 `오류`는 설계 대상(‘누락·오류·미확인을 어떻게 기록할지’)일 뿐이다.
  - 결과: ‘먼저 현상을 재현하고…’와 기대/실제 사실 질문(‘답변이 필요해요’)이 붙었다.
- 사용자 원문, 기준, 배경 사본, 출처는 원래 바뀌지 않았다. 결함은 앱이 덧붙인 문구에만 있었다.

## 수정 (`src/shared/mock.ts`, 규칙 기반 · 의미 이해 아님)
- **행동 판정은 요청 자신의 말로만 한다.**
  - 다음 조건이면 검토 작업으로 둔다: 변경 동사(수정·고쳐·바꿔·구현·만들어 등)가 없고, 실행이나 변경을 명시적으로 금지했거나(‘…변경 없이’, ‘구현/배포 금지’, ‘고치지 말고’ 같은 목록 포함) 검토·조사·설계·비교·제안·정리를 요청했을 때. 금지 구절 안의 동사는 변경 요청으로 세지 않는다.
  - 검토 작업에는 코드 수정, 명령 실행, 장애 재현, 검사 실행, 배포, 사실 질문을 덧붙이지 않는다. 다음 작업은 ‘요청 원문이 요구한 항목만 검토·정리, 모르는 값은 미확인’이다.
- **장애 단어는 주제일 뿐이다.** 검토 작업에서 재현은 요청이 직접 재현이나 원인 조사를 요구할 때만 남는다. 이때도 코드 수정, 자동 복구, ‘변화가 보이는지’ 검사는 붙이지 않는다.
- **검토 요청에 돌아온 보고**는 ‘필요한 수정 또는 검사를 진행’ 대신 앞선 요청 항목과 대조하고, 확인된 것과 미확인을 나눈다.
- **바꾸지 않은 것.**
  - 일반 구현 요청(기존 기본값), 실제 장애 보고(‘결제가 실패하는 오류가 있어요’ → 재현과 사실 질문), 작은 문구 변경, 대기자 선택 질문.
  - 원문·잠금·배경 사본·출처, 작업 준비 상태(완료로 표시하지 않음).
- **판단 순서.** 변경 동사가 있으면 기존 동작을 유지한다(예: ‘검토해 보고 틀리면 고쳐줘’, ‘수정하고 배포는 하지 마세요’). 불확실할 때 범위를 넓히지 않는다.

## 실제 AI 서버 프롬프트 (`server/prompt.mjs`)
- 같은 확장 경로의 근거가 두 문장에 있었다:
  - ‘변경 금지를 진단 금지로 확대하지 않는다’: 재현을 허용하는 쪽만 있었다.
  - ‘코드·원인이 미확인이면 … 먼저 확인’: 요청 종류와 무관하게 적용됐다.
- 수정:
  - 실행·재현·변경을 명시적으로 금지했거나 검토·조사·설계 산출물만 요청한 경우에는 그 범위를 지키고, 코드나 장애가 언급됐다는 것만으로 수정·재현으로 읽지 않는다는 문장을 덧붙였다.
  - 두 번째 문장은 ‘문제 해결이나 원인 조사를 요청했는데’로 한정했다.
- 실제 AI 호출은 하지 않았다. 실제 AI 품질이 통과했다는 주장이 아니다.
