# NAV103 — 경로·뒤로가기·복원에 적용한 재사용 판단 메모

작성·원문 확인·우리 조건 재검토: 2026-10-15 KST. 실제 예정 과제에 대한 **문서 판단**이며 새 화면/라우터/중첩 계층 구현은 아니다. 이 파일과 [evidence.md](evidence.md)가 외부 검토자에게 줄 전체 패킷이다. 원자료 링크는 근거 추적용이며 파일/브라우저/세션의 자동 공유를 전제하지 않는다.

## 문제와 현재 판단

AgentFlow에서 전체 공간 → 영역 → 더 작은 구상으로 이동해도 위치를 알 수 있고, 되돌아오거나 새로고침해도 이어 보려는 곳을 잃지 않게 한다. 위치 이동으로 기존 수동 초안이나 현재 작업이 바뀌면 안 된다.

**현재 D2: 임의 중첩 탐색의 구현과 재사용 방식 최종 채택을 보류한다.** 직접 주소/브라우저 이력에는 후보 B를 우선 검토할 이유가 생겼지만 채택·설치·구현 승인은 아니다. D1의 기존 메커니즘 A 선택은 당시 좁은 조건의 설계 참고로 남긴다. 과거 선택을 새 조건의 합격으로 올리지 않는다.

현재 수용 소스는 `2931b50938af037a43e20ed7aba69b96ab79843d`(2026-10-15 14:56 KST). 이 커밋을 읽었을 뿐, 그 브랜치나 공개 반영을 수정하지 않았다. 데이터는 `idea015.project.5`; 공간 내부는 전체/영역/작업의 고정 3층이다. ‘더 작은 구상’을 기존 작업과 같은 것으로 치환하지 않는다. Area에 parentId가 없고 검증에도 허용되지 않는다 [E1].

## D1 — 제한된 조건에서 빌릴 부분 선정 (과거 판단, 보존)

판단자: CYCLE103 문서 담당. 조건 v1은 **분석을 위한 축소 가정**이며 고객이 확정한 요구가 아니다. 기존 전체/영역/작업 안에서 같은 탭으로 탐색하고, ‘뒤로’는 경로의 상위 위치 버튼, ‘새로고침 복원’은 화면 종류·대상 ID를 의미한다고 한정했다. 픽셀 스크롤·포커스까지 새로고침 후 유지, 직접 주소, 브라우저 뒤로/앞으로, 임의 중첩은 v1 충족 범위 밖이다.

| 후보 (최대 2개) | 왜 빌리는가 / 빌릴 부분 | 직접 남길 일 | D1 상태 |
|---|---|---|---|
| A. 이미 있는 탭 위치 기억·층별 복귀 메커니즘 | rememberPlace/recallPlace의 대상 확인과 sessionStorage, leaveLayer/openSpace/openArea의 스크롤·포커스 복귀. 현재 작업/요청 대상과 보는 위치를 분리한 경계가 이미 있음 [E2–E4] | 새 중첩 대상 ID/상위 경로/유효성/삭제 의미, 재로딩할 스크롤 범위. layerMemo는 메모리이며 새로고침 보존으로 확대 주장하지 않음 | **설계 참고로 채택.** 현 3층의 경계를 재사용 출발점으로 선정. 새 코드 적용 승인 아님 |
| B. 브라우저 기본 URL fragment + 세션 이력 메커니즘 | URL에 보기 식별자를 표현하고 fragment 이동/브라우저 Back을 화면 이동과 잇는 기반. 패키지나 프레임워크를 추가하지 않아도 되는 후보 [E6] | URL 해석/검증/초기 로드, 저장 위치와 우선순위, 중복 렌더 방지, 포커스·스크롤, 로컬 데이터 찾기, 없어진 대상 처리 | **보류.** v1의 같은 탭·상위 버튼 복귀에는 새 URL 경로 계약을 정할 필요가 아직 불명확 |

A와 B는 모든 역할이 겹치는 제품 대체재가 아니다. 여기서 비교한 경계는 ‘무엇으로 보는 위치를 식별·복원할지’다. B를 쓴다고 A의 보기/작업 분리나 스크롤 기억을 버릴 이유는 없다. 현재 코드에 있는 작은 라우터를 발견한 것은 아니다. 새 OSS 후보를 수집하지 않았다.

D1의 실제 사용 상태: 기존 앱에 A 메커니즘이 이미 존재한다. **이 문서 작업으로 새로 적용한 코드는 없고**, 임의 중첩/URL 연동은 미구현이다. 확인은 소스 읽기뿐이며 기존 시험 파일의 기대를 읽었다고 실행 통과로 세지 않는다.

## D2 — 변경 조건에서 재검토 (현재 판단)

조건 v2는 이번 후속 요청이 명시했다: **중첩 구상에서 직접 주소·브라우저 뒤로가기·없어진 공간을 처리하면서, 기존 수동 초안과 현재 작업을 바꾸지 않음**. v1의 ‘더 작은 구상 제외/상위 버튼만/같은 탭 화면 ID 복원’ 가정으로는 이를 충족할 수 없다.

| 바뀐 조건 | 읽은 근거로 가능한 판단 | 아직 정하지 못해 보류한 것 |
|---|---|---|
| 직접 주소로 중첩 대상을 열기 | A의 sessionStorage만으로 주소 수신자의 목적지를 식별할 수 없음. B를 우선 검토. URL은 데이터를 복제하거나 접근권한을 만들지 않음 | ‘더 작은 구상’의 정체·안정 ID·부모 경로, entryId/project.id와 가져온 사본의 구별, 같은 브라우저 재방문인지 다른 기기/사람 공유인지 |
| 브라우저 Back과 상위 경로 | 방문 이력의 이전 위치와 계층상의 부모는 다름. 현재 경로 버튼은 openSpace/openArea를 호출하며 브라우저 이력 처리는 관찰되지 않음 [E2,E4] | URL vs 저장 위치의 우선순위, 첫 로드/뒤로·앞으로/새로고침의 처리 계약, 정확히 복원할 스크롤·포커스 범위 |
| 대상이 보관/삭제/찾을 수 없음 | 현 recallPlace는 없는 작업→영역→전체 공간의 폴백을 함. areaOk는 존재 여부만 보며 보관 상태까지 거부하지 않음. 중첩 조상 처리의 증거는 아님 [E2,E5] | 사라진 자식/조상, 보관된 영역, 지워진 프로젝트, 현재 브라우저에 데이터가 없는 주소를 구별할 정책. 안내 후 사용자 선택으로 돌아가기 vs 자동 폴백 여부 |
| 수동 초안·현재 작업 불변 | 보기 함수와 continueTask/writeInArea를 구분해야 함. 보존 대상은 project.draft, draftKind, draftTarget, currentTaskId뿐 아니라 task.manual 필드. 저장 대기·실패도 존재함 [E3,E4] | URL에 따라 열린 화면이 요청 대상을 바꾸지 않도록 할 연결 계약. 저장 미완료/접근 불가 상태의 새로고침에 대해 무손실을 약속할 수 없음 |

**D2 결정:** 후보 A만으로 확대 해결했다는 판단은 보류. 후보 B는 직접 주소·브라우저 이력의 **우선 검토 후보로 변경**, 최종 채택은 보류. A의 기존 동작은 유지되며 D1 기록도 그대로다. 두 후보 모두 중첩 데이터의 정체·삭제 의미·초안 보호 정책을 대신 결정해 주지 않는다.

부분 재사용의 선: 브라우저에서 빌릴 것은 주소/이력 이벤트, 기존 코드에서 빌릴 것은 보기와 작업의 분리 및 유효 대상 확인이다. 직접 남길 것은 중첩 대상 해석, 경로 표시, 사라진 대상 안내, 주소와 저장값 충돌 처리, 초안·작업 불변 검증이다. URL로 임의 project.5 객체를 만들거나 parentId를 덧붙이지 않는다.

## 확인·미실행·다음 결정

- 읽은 것: 고정 코드·기존 시험 명세·브라우저 API 문서 [E1–E6]. 소스의 분기 관찰과 확장 설계 추론을 구별했다.
- 하지 않은 것: 설치, 앱 실행/수정, 새 HTML, 라우터 연결, DB/계층 스키마 변경, 브라우저 복원 재현, 배포. D1/D2에 대한 통합시험은 미실행. 기존 CSV 시안의 72개는 HTML 기능 확인이며 이 과제의 효용·복원 성공 근거가 아니다.
- 나중에 구현이 승인된다면 확인해야 할 조건: 같은 문서 안 경로/Back/직접 주소 이동 전후 수동 초안·현재 작업 값이 같음; 주소와 실제 보기가 일치함; 없어진 대상에서 새 초안/작업을 만들지 않음. 새로고침 보존은 저장 완료와 미완료를 나눠 정의해야 함. 지금 실행하지 않으며 이를 별도 새 실험으로 시작하지 않는다.
- **가장 작은 다음 결정 하나:** 첫 직접 주소 지원을 ‘같은 브라우저에 이미 저장된 대상의 재방문’으로 제한할지 총괄이 결정한다. 이것이 정해져도 중첩 대상 정체와 없어진 대상 정책은 남으므로 자동으로 구현을 시작할 수 없다. 이 문서 작업은 여기서 끝낸다.

라이선스 확인 범위: A는 사용자가 작업을 맡긴 동일 저장소 코드의 메커니즘 참고이며 새 코드 복사 없음. 해당 tree의 LICENSE/COPYING 이름 검색에서 라이선스 파일을 찾지 못했으므로 외부 재배포 허가를 추정하지 않는다. B는 브라우저 API 사용 후보이며 구현체·MDN 예제를 복사하지 않는다. MDN 자료의 고정 LICENSE 설명과 확인 한계는 E6에 있다. 코드 복사·배포가 생기면 해당 대상 조건을 별도로 확인해야 한다.
