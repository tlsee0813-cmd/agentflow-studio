## 새 검토자의 출력 원문

읽은 범위는 `navigation/packet.md`와 `navigation/evidence.md` 두 파일뿐이다. 원자료 링크나 코드는 열지 않았고, 실행·설치·브라우저·네트워크 확인도 하지 않았다. 아래의 ‘관찰’은 패킷 작성자가 기록한 관찰을 복원한 것이며, 독자가 원자료를 독립 검증했다는 뜻은 아니다.

## 1. 현재 판단

현재 결정은 임의로 깊어지는 구상 탐색을 구현하거나 재사용 방식을 최종 확정할 단계에 이르지 못했다는 것이다. 기존 메커니즘 A만으로 확대된 요구를 해결했다고 볼 수 없다. 직접 주소와 브라우저 방문 이력을 다루는 부분에서는 브라우저 기본 메커니즘 B를 먼저 검토하되, B를 채택하거나 설치·구현하도록 승인한 것은 아니다. A의 기존 동작과 과거 설계 참고 기록은 유지된다.

근거:

- `packet.md` 「문제와 현재 판단」: “현재 D2: 임의 중첩 탐색의 구현과 재사용 방식 최종 채택을 보류한다.”, “채택·설치·구현 승인은 아니다.”
- 「D2 — 변경 조건에서 재검토」 결정문: “후보 B는 직접 주소·브라우저 이력의 우선 검토 후보로 변경, 최종 채택은 보류.”
- 같은 파일의 현재 데이터 설명과 `evidence.md` E1: 현재 공간 내부는 전체/영역/작업의 고정 3층이며 Area에 `parentId`가 없다. 따라서 ‘더 작은 구상’을 기존 작업이라고 간주하여 중첩 요구가 이미 충족됐다고 읽을 수 없다.

## 2. 과거 판단과 당시 조건

D1에서는 기존 A의 보기 위치 기억과 층별 복귀를 재사용 설계의 출발점으로 골랐다. 이 선택은 같은 탭에서 기존 3층을 이동하고, ‘뒤로’를 상위 경로 버튼으로 해석하며, 새로고침 뒤 화면 종류와 대상 ID를 되찾는다는 좁은 분석 조건에서 이루어졌다. 이 조건은 고객 확정 요구가 아니다. 직접 주소, 브라우저 뒤로/앞으로, 임의 중첩, 새로고침 후 정확한 스크롤·포커스 유지는 당시 충족 범위에 들지 않았다.

그 조건에서는 URL 경로 계약을 새로 정할 필요가 분명하지 않아 B를 보류했다. A의 선택도 설계 참고이며 새 코드를 적용한다는 승인은 아니었다.

근거:

- `packet.md` D1 첫 문단: “조건 v1은 분석을 위한 축소 가정이며 고객이 확정한 요구가 아니다.” 이어서 포함·제외 범위를 명시한다.
- D1 표 A 상태: “설계 참고로 채택”, “새 코드 적용 승인 아님”. B 상태: “같은 탭·상위 버튼 복귀에는 새 URL 경로 계약을 정할 필요가 아직 불명확”.
- `evidence.md` E2: 대상 ID 복원에 쓰는 `sessionStorage`와 메모리에만 있는 `layerMemo`를 구분한다. 이것이 대상 복원을 모든 스크롤·포커스의 새로고침 복원으로 확대할 수 없는 근거다.

## 3. 보류 이유

요구가 중첩 대상의 직접 주소, 브라우저 뒤로가기, 없어진 공간 처리까지 넓어졌지만, 그 대상과 실패 상황의 의미가 아직 정해지지 않았다. 브라우저 기능을 선택하는 일만으로 이 결정을 대신할 수 없다.

- 중첩 구상이 무엇이고 어떤 안정 ID와 부모 경로를 가지는지 정해지지 않았다. 작업을 중첩 구상으로 치환하거나 기존 스키마에 `parentId`를 붙여 해결할 근거도 없다. 근거: `packet.md` 「문제와 현재 판단」 및 D2 표 첫 행, E1.
- 직접 주소가 같은 브라우저의 저장된 자료를 다시 여는 용도인지, 다른 기기나 사람에게 전달되는 용도인지 정해지지 않았다. `entryId`와 `project.id`, 가져온 사본도 구별해야 한다. URL 자체가 데이터나 접근권한을 제공하지는 않는다. 근거: D2 표 첫 행, E3.
- 방문 이력상 이전 화면과 계층상 부모는 다르다. URL과 저장 위치가 충돌할 때의 우선순위, 초기 로드·Back·Forward·새로고침 처리, 스크롤·포커스 복원 범위가 미정이다. 근거: D2 표 둘째 행, E4, E6. E6은 `pushState`/`replaceState` 호출만으로 필요한 이벤트가 모두 발생한다고 가정할 수 없음을 덧붙인다.
- 없어진 자식·조상, 보관된 영역, 삭제된 프로젝트, 현재 브라우저에 데이터가 없는 주소의 대응을 정하지 않았다. 기존의 작업→영역→전체 공간 폴백을 중첩 조상 처리나 보관 대상 거부의 증거로 쓸 수 없다. 근거: D2 표 셋째 행, E2, E5.
- 화면 이동이 수동 초안과 현재 작업을 바꾸지 않도록 연결 규칙과 검증이 필요하다. 보존 대상에는 초안 관련 값, `currentTaskId`, `task.manual` 필드가 포함되며 비동기 저장 대기·실패 때문에 새로고침 무손실을 지금 약속할 수 없다. 근거: D2 표 넷째 행, E3, E4.

## 4. 빌릴 것과 직접 남는 일

A에서 빌릴 것은 보는 위치와 실제 작업·요청 대상을 분리하는 경계, 유효 대상 확인, 기존의 위치 기억·층별 복귀다. B에서 빌릴 것은 주소에 보기 식별자를 담고 브라우저 주소·이력 이벤트를 활용하는 기반이다. 두 후보는 전체 역할이 같은 대체품이 아니므로 B 검토가 곧 A 폐기를 뜻하지 않는다.

직접 정하고 구현해야 할 일은 중첩 대상의 정체·ID·부모 경로·유효성·삭제 의미, 주소 해석과 초기 로드, 경로 표시, 주소와 저장값의 우선순위, 이벤트 연결과 중복 렌더 방지, 스크롤·포커스 범위, 로컬 데이터 탐색과 사라진 대상 안내, 초안·현재 작업 불변 검증이다.

근거:

- `packet.md` D1 후보 표의 “빌릴 부분”과 “직접 남길 일”.
- D1 표 아래: “A와 B는 모든 역할이 겹치는 제품 대체재가 아니다.”
- D2 「부분 재사용의 선」: “브라우저에서 빌릴 것은 주소/이력 이벤트, 기존 코드에서 빌릴 것은 보기와 작업의 분리 및 유효 대상 확인”. 이어 직접 남길 일을 열거한다.
- E6: B는 fragment 기반 브라우저 메커니즘 하나이며 History API 문서는 경계 확인용이다. 별도의 세 번째 라우터 후보나 확정된 URI 문법·구현을 제시한 것은 아니다.

패킷은 고정된 프로젝트 소스, 기존 시험의 기대 내용, 브라우저 API 문서를 읽었다고 보고한다. 프로젝트 소스 기준은 `2931b50938af037a43e20ed7aba69b96ab79843d`이며 문서에 적힌 커밋 시각은 2026-10-15 14:56 KST다. E6의 MDN 자료도 별도 snapshot으로 고정되어 있다. 독자가 여기서 확인할 수 있는 것은 이러한 출처와 관찰·한계가 패킷에 기록되어 있다는 사실이다.

이 작업에서 설치, 앱 실행·수정, 라우터 연결, 새 HTML, DB·계층 스키마 변경, 브라우저 복원 재현, 배포, D1/D2 통합시험은 하지 않았다. A는 기존 앱에 존재한다고 기록되어 있으나 이번 문서 작업으로 새로 적용한 코드는 없다. 기존 시험을 읽은 것과 실행 통과는 구별되어 있다. 다른 CSV 시안의 72개 확인은 이 탐색 과제의 복원 성공 근거가 아니다.

근거:

- `packet.md` D1 「실제 사용 상태」 및 「확인·미실행·다음 결정」의 “읽은 것”, “하지 않은 것”.
- `evidence.md` 머리말: “구현/시험 성공을 뜻하지 않는다.”
- E4의 브라우저 이력 API 검색 부재는 읽은 소스 범위의 관찰이며 모든 배포환경에 대한 동작 실험이 아니다. E5의 기존 시험도 “이번에는 실행 안 함”이다.

향후 확인 조건은 문서 안 이동 전후 초안·현재 작업 값의 동일성, 주소와 실제 보기의 일치, 없어진 대상에서 새 초안·작업을 만들지 않는지 등이다. 이것들은 실행 결과가 아니라 구현 승인 뒤 확인할 조건으로 적혀 있다.

## 6. 가장 작은 다음 결정

총괄이 첫 직접 주소 지원의 범위를 ‘같은 브라우저에 이미 저장된 대상을 다시 여는 경우’로 제한할지 결정하는 것이 다음 한 가지 결정이다. 이 범위를 정해도 중첩 대상의 정체와 없어진 대상 처리 정책은 여전히 남는다. 따라서 이 결정만으로 구현 착수 조건이 모두 갖춰지는 것은 아니다.

근거: `packet.md` 「확인·미실행·다음 결정」의 굵은 문장 “가장 작은 다음 결정 하나”와 바로 뒤의 “자동으로 구현을 시작할 수 없다”. 문서 작업은 여기서 끝낸다고 명시되어 있어 별도 실험이나 구현을 후속 행동으로 추론하지 않는다.

## 문서만으로 알 수 없는 점과 다르게 읽힐 여지

- 중첩 구상의 구체 데이터 모델, URI 문법, 실패 안내와 복귀 방식은 미정이다. 문서의 공백을 특정 구현으로 채울 수 없다.
- ‘같은 브라우저’라는 첫 지원 범위가 새 탭·다른 창·다른 프로필까지 어떻게 나뉘는지는 적혀 있지 않다. E6의 `sessionStorage` 설명만으로 프로젝트 데이터의 가용 범위를 확정할 수 없다. 다음 결정을 내릴 때 경계를 더 구체화할 여지가 있다.
- v2를 명시했다는 “이번 후속 요청”의 원문은 패킷에 포함되지 않았다. 요구를 이 문서가 위와 같이 요약하고 있다는 것은 알지만, 원래 요청의 다른 조건이나 승인 범위를 복원할 수는 없다.
- 총괄이 누구인지, 언제 결정하는지, 구현이 이후 승인될지는 알 수 없다.
- 소스의 기록과 실제 배포 동작이 같은지, 저장 실패 때 어느 입력이 남는지, 정확한 복원 성능·호환성은 실행 근거가 없어 확인할 수 없다.

핵심 여섯 항목을 복원하는 데 필수적인 문장 수정은 발견하지 못했다. 선택적으로 다음 결정 문장의 ‘같은 브라우저’ 뒤에 새 탭·창·프로필의 포함 범위를 추후 정해야 한다는 짧은 설명을 붙이면 범위 해석을 더 좁힐 수 있다. 아직 정하지 않은 범위를 독자가 임의로 확정한 문구로 고치지는 않는다.
