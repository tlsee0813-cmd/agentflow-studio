## 고객 문제와 지금 필요한 크기

공방의 명단 반입 영역을 구상하는 개발자가 CSV 읽기까지 직접 구현하려다가, 라이브러리가 업무 검증까지 해결한다고 오인하는 문제를 고른다. 이는 실제 구현에서 생길 수 있는 구체적 고객 과업을 모델링한 것이다. 특정 고객이 요청했다는 인터뷰 근거는 없다. 선택할 것은 ‘CSV 파서 제품 전체’가 아니라 ‘CSV 문법 읽기를 빌릴지’다.

사용자에게 남길 가치는 후보 숫자가 아니라 **이 조건에서 왜 골랐고, 무엇은 여전히 직접 해야 하며, 무엇이 바뀌면 다시 봐야 하는지**다. 새로운 외부 개발 세션에도 목적·조건·결정 식별자·시험 상태를 함께 넘길 수 있다.

최소 기본 입력은 문제/조건 한 줄, 후보 최대 2개, 선택·보류 이유와 다음 확인이다. 출처 판·라이선스·시험·이력은 접힌 세부에 둔다. 후보를 꼭 두 개 채울 필요도, 영역마다 메모를 만들 필요도 없다. 링크만 남기고 판단할 문제가 없다면 북마크가 더 싸다.

다음은 기능을 쓰지 않는다: 문구·색상 변경, 이미 승인된 의존성의 좁은 수정, 외부 코드 도입이 금지된 작업, 명확한 기존 구현으로 끝나는 일. 단발 프로젝트여서 기억을 재사용할 가능성이 낮으면 저장소의 짧은 메모로 끝낸다. 사용자가 이미 ADR/이슈에 같은 결정을 잘 남기면 중복 입력을 만들지 않는다.

## 기억의 단위와 상태

새 DB 스키마 제안이 아니라 문서 한 절의 논리적 항목이다.

- 연결: 프로젝트 목적 → 영역 목적 → 이 판단이 도움 되는 작업. 현재 보는 위치/이어가는 작업/요청 대상은 별개.
- 조건 스냅샷: 실행환경, 입력, 필요한 결과, 금지. 조건 v1을 고친 대신 v2와 차이를 추가한다.
- 후보: 기준 URL + 정확한 판·파일/절 + 빌릴 부분 + 남길 부분. 유사후보 발견은 동등성·중복 판정이 아니다.
- 결정: 선택/보류/불필요, 이유, 판단자, 당시 조건. 등록→후보→결정→실제 사용→검사는 서로 다른 축이며 자동 승격하지 않는다.
- 확인: 원문 발행/커밋 날짜, 원문 확인일, 우리 조건 재검토일을 분리. 보고 출처와 직접 관찰을 분리. 생략/미실행은 합격 아님.
- 경험: 실패 입력/환경/관찰자/대응/미해결을 남긴다. 한 환경의 실패를 후보 전체의 결함으로 일반화하지 않는다.

MADR의 결정 이유·결과·확인과 재검토 기록을 작게 참고한다. GitAgent의 조건/실패 기억은 참고하지만 검색→설치→실행 자동화는 가져오지 않는다. datasketch·datacontract-cli의 구분은 사용자 제공 기존 조사로만 이어받았다. 코드·프레임워크는 이식하지 않았다.

## 다음 구현 최소 수용 기준

1. **문서 먼저:** 실제 예정 작업 한 건에 선택적 메모를 붙여 팀이 쓴다. 다음 조건 변경에서 같은 기록을 찾을 수 있는지 확인한다. 3개 과업까지 확인하되 후보 수 채우기와 추가 수집을 하지 않는다. 이득이 없으면 UI 구현을 중단한다.
2. **진입 비용:** 영역 구상 안 접힌 한 줄만 추가할 수 있다. 전체 공간을 가리는 상시 판넬·후보 피드·등록 요구가 없어야 한다. 불필요한 일은 메모 없이 완료 가능.
3. **판단 보존:** 후보 2개 비교→선택/보류→조건 v2→새 판단을 표현하고 D1 원문/조건/출처를 보존. 현재 판단과 과거 판단을 혼동하지 않게 한다.
4. **권한 경계:** 열기/닫기/단계 보기/출처 열기로 요청 대상, 이어가는 작업, 초안, 설치·실행 권한이 바뀌지 않는다. 실제 요청에 넣기는 별도 명시 행동과 기존 요청 확인 흐름을 따른다.
5. **근거 표현:** 판·파일/절, 세 날짜, 라이선스 확인 범위, 실제 사용 여부, 미실행/보고/직접 검사를 구별한다. 필수 조건 미확인은 그 적용만 보류한다.
6. **기기·인계:** 390px와 1280px에서 수평 넘침 없이 키보드로 열기/닫기/복귀. 외부 참고문은 목적·조건·결정 이유·남는 일·미실행·출처를 포함하고 권한을 넓히지 않는다.

남은 총괄 결정은 이 작은 문서 실험을 다음 실제 과업에 적용할지다. 앱 저장 위치/스키마/자동 감지/검색 API/실행 연결은 이번에 결정하지 않는다.
