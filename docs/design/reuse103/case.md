# 하나의 문제, 조건이 바뀐 후속 문제

2026-10-15 KST. 아래 고객·판단자·실패 기록은 **시안용 가상 사례**다. 실제 고객 조사나 실제 통합시험 결과가 아니다. 공개 소스에서 관찰한 파서 동작은 sources.md에 따로 적는다.

## P1: 공방 직원이 예약 CSV를 미리 확인하기

공간: 도자기 공방 운영 / 영역: 예약명단 반입 / 작업: 반입 전에 오류 보여주기.

- 목적: 직원의 재입력과 누락을 줄이고 잘못된 예약은 반영하지 않는다.
- 조건 v1: UTF-8(선택적으로 BOM), 2MB 이하·2,000행 이하 (이 사례의 MB는 1,000,000바이트), 현재 데스크톱 Chromium, CSV를 브라우저 밖으로 보내지 않음. 이름/일시/인원 열은 필수. 중복 헤더는 거부. 날짜·인원은 업무 규칙으로 확인.
- 직접 구현 대안: split(',')/줄 단위 분리. 인용부호·쉼표·줄바꿈·열 수 오류 처리까지 늘어나므로 CSV 문법은 기존 파서를 빌리는 쪽이 유리하다는 설계 추론.
- 검색 전에: 기존 가이드 REUSE096과 영역 구상의 금지·완료 조건을 확인. 이 저장소에 실제 고객 CSV 기능을 넣으려는 작업이 아니다.

| 선택에 필요한 것 | Papa Parse | csv-parse |
|---|---|---|
| 재사용 형태 | 라이브러리의 CSV 파싱/파일 읽기 역할 | 라이브러리의 CSV 파싱/열 처리 역할 |
| 브라우저 경계 | 파일 읽기 경로 관찰; 실제 UI 연결은 미시험 | 브라우저 배포 경로 관찰; 실제 입력/번들 연결은 미시험 |
| 중복 헤더 | 자동 이름 변경이 업무상의 ‘허용’은 아님; 원래 헤더를 별도로 거부해야 함 | 열 이름 처리·그룹 옵션은 업무상의 ‘허용’이 아님; 원래 헤더를 별도로 거부해야 함 |
| 공통으로 해결하지 않는 것 | 예약 날짜, 정원, 동일 예약 판정, 미리보기와 복구, 반영의 원자성 | 동일 |
| 라이선스 | 지정 판 MIT 문구 읽기; 제품 결합·번들 고지 미확인 | 지정 판 MIT 문구 읽기; 제품 결합·번들 고지 미확인 |
| D1 (가상 판단자: 영역 담당 개발자) | **시험 대상으로 채택**, 작은 브라우저 파일의 입력 경로가 직접적 | **보류**, 현재 조건에서는 입력/번들 연결 비교를 더 할 이익이 작다고 판단 |

D1은 최종 운영 도입 결정이 아니다. 근거가 문서·소스 읽기에 그치므로 **실제 사용 없음 / 통합시험 미실행 / 설치 승인 없음**으로 남긴다. csv-parse가 브라우저에서 불가능하다는 뜻도, 성능이 나쁘다는 측정도 아니다.

### 작은 시험 제안 T1

다음 구현이 승인될 때만 별도 일회성 샘플에 수행한다. 정상 UTF-8/BOM, 인용 쉼표, 인용 줄바꿈, 누락·중복 헤더, 열 수 불일치 6종과 경계 크기 2MB를 쓴다. 정상 데이터는 예상 값과 같고, 오류 데이터는 행/열 위치가 드러나며 예약 반영 0건이어야 한다. 브라우저 요청 계측으로 CSV 외부 전송 0건을 확인한다. 이 사이클에서는 파서를 설치하거나 이 시험을 실행하지 않았다.

F1 (가상 실패 경험): 과거 시도에서 중복 헤더가 자동 이름 변경된 뒤 필수 열 검사에서 빠졌다. 당시 환경/입력은 v1 중복헤더 샘플이며, 대응은 원래 헤더 단계에서 거부하는 것. 실패 기록 예시를 보여주기 위해 쓴 것이며 실제 사용자 보고·직접 재현이 아니다. 파서 결함으로 분류하지 않는다.

## P2: 거래처 파일도 받고 재반입을 막기

v2에서 행 수 한도, 대상 기기, 시간·메모리 기준과 예약 업무키는 미정이다. 이 항목에 의존하는 합격/확대 적용은 보류한다.

같은 영역의 후속 요청: “거래처가 준 Shift-JIS 50MB 명단도 읽고, 같은 파일을 다시 넣어도 예약을 중복 생성하지 않게 해 주세요.” 조건 v2는 v1을 덮어쓰지 않는다.

| 바뀐 조건 | D1을 그대로 쓸 수 없는 이유 | 다음 확인 |
|---|---|---|
| UTF-8 → Shift-JIS | CSV 문법과 바이트→문자 해석은 별개. 지원 옵션 존재만으로 글자 보존을 보장 못 함 | Shift-JIS로 표현 가능한 일본어·ASCII는 예상 문자열을 확인하고, 표현 불가 문자·잘못된 바이트는 거부/오류 정책을 정해 확인. 조각 경계 문자도 포함 |
| 2MB → 50MB | 스트리밍 API 이름만으로 메모리 상한/반응성 보장 못 함 | 대상 기기에서 최대 메모리·멈춤·취소 동작 측정. 수치 기준은 기기 선택 뒤 정함 |
| 첫 반입 → 재반입 중복 방지 | 구문상 같은 행과 동일 예약은 다름. 파일 해시만으로 거래처가 재정렬한 파일이나 다른 파일의 중복예약까지 해결 못 함 | 동일 파일 재반입의 신규 예약 0건. 업무키·수정예약 정책은 고객 결정 필요 |

**D2 (가상): 두 후보의 확대 적용을 보류.** Papa Parse의 D1을 취소/합격으로 덮어쓰지 않는다. csv-parse는 스트림 대안으로 재검토하되 아직 교체 결정하지 않는다. 문자 해석, 50MB 경계, 재반입 정책을 분리해 확인한다. v1도 실제 통합시험 미실행 상태이므로 이미 운영 중이라고 표시하지 않는다.

시험 제안 T2는 작은 문자 fixture → 한 개 50MB fixture → 같은 파일 2회 반입 순서다. 합격 조건은 문자 일치/정의된 오류, 취소 후 예약 반영 없음, 두 번째 신규 예약 0건이다. 시간·메모리 기준과 예약 업무키가 미정이면 관련 합격 판정을 보류한다. 후보를 더 수집해서 이 미정을 숨기지 않는다.
