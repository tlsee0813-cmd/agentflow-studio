### 두 안 공통 규칙 (시안에서 동작)
- **세 표시를 분리한다.**
  - 경로 = 계층 위치.
  - 미니맵 = 이 층 안에서 지금 보이는 화면 위치. 클릭하면 같은 층 안에서만 스크롤한다.
  - 점선 화살표 = 영역 사이 관계(흐름·먼저 필요). 포함 관계도 실행 순서도 아니다.
- **지도 이동만으로는 아무것도 바뀌지 않는다.**
  - ‘이어가는 작업’은 ‘이 작업 이어서 하기’로만 바뀐다.
  - 빠른 요청의 대상 영역은 사용자가 직접 고른다. 보는 곳과 대상이 다르면 그렇다고 표시한다.
  - 권한, 실행, 요청 내용은 지도 이동으로 생기지 않는다.
- **돌아오면 위치가 복원된다.** 층마다 선택과 스크롤을 기억했다가 돌아올 때 되살린다. 탭 기억이고 프로젝트 데이터가 아니다.
- **판단 필요는 모든 영역을 모아 보여 준다.**
  - 기존 상태 문구 중 ‘제품 선택 항목 있음’(질문)과 ‘구현 보고 도착 · 앱 미검증’(보고)을 모은다.
  - 앱 기록 기준이다. 목록에서 열기는 명시 행동이다.
- **지금 할 일**은 위에 한 줄로 둔다. 최근 변경은 한 줄로만 보여 준다. 지난 기록은 접어 둔다.
- **외부 도구 상태**는 앱 기록과 상자를 나눠 보여 준다.
  - 근거(붙여넣은 보고)가 없으면 ‘알 수 없음’이라고 쓴다.
  - 보고가 있어도 ‘외부 도구의 주장 · 앱이 확인한 것 아님’이라고 쓴다.
- **빈 첫 화면과 빈 영역**은 목적 한 줄 또는 ‘바로 첫 요청’, 그리고 ‘무엇을 요청할지 같이 정하기’ 중에서 시작하게 한다.
- **빠른 입력**: 어느 층에서든 `/`를 누르면 빠른 요청 칸으로 간다. Enter를 누르면 지금 입력창 경로로 넘어간다. 보내기 전 확인은 지금과 같다.
- **키보드**: 방향키는 항목 이동, Backspace와 Alt+↑는 위층, Esc는 선택·정보·서랍 닫기. A와 B의 Enter 차이는 위 표에 있다.

## 6. 추천 조합

1. **B의 뼈대를 쓴다.** 지도는 넓게, 작업은 전용 화면으로 연다. 지금 앱과 같은 방향이다.
2. **카드 클릭은 진입 우선을 기본안으로 시험한다.**
   - 제목·↘ 클릭 한 번으로 들어간다. 정보는 ⓘ로 따로 본다.
   - 확정 전에 시안 두 규칙을 실제 사용자 3–5명에게 같은 과제로 짧게 비교한다.
   - 결과가 나오기 전에는 제품의 지금 규칙(선택 우선)을 바꾸지 않는다.
3. **A에서 가져올 것:**
   - 모든 영역의 판단 필요 목록과 영역 점 표시. 배지와 목록이면 되고, 고정 트리는 필요 없다.
   - 층 표시와 경로를 세 화면 모두에서 같게 한다.
4. **draw.io에서 가져올 것:** 층마다 보기 상태(선택·스크롤)를 복원한다. 들어가기·나오기와 접기·펴기를 다른 동작으로 둔다.
5. **고정 3단 트리는 쓰지 않는다.** 층이 셋뿐이라 경로와 판단 필요 목록으로 충분하다. 하위 구상이 실제로 생기면 다시 본다.

  - 우리 쪽: 우리 영역과 목적, 활용 방법(아이디어·라이브러리·일부 코드·서비스).
  - 검토 근거: 검토한 버전·커밋, 코드·라이선스 링크.
  - 날짜: 원문 확인 날짜와 우리 적합성 재검토 날짜를 따로 둔다. URL이 살아 있어도 설명과 적합성은 낡을 수 있다.
  - 상태: 선택 또는 보류 이유.
- **나중에 앱과 잇는다면.** 영역 정보의 ‘참고 후보’ 접힌 절(시안의 빈 자리)에 연결한다. 등록은 채택이 아니다.
- **검증은 작게.** 실제 예정 작업 3개에 후보를 최대 2개씩만 확인한다. 이번 시안에는 가짜 검색, DB, ‘재사용 검증 완료’ 표시를 넣지 않았다.

## 12. 한계
- 가상 데이터와 정적 시안이다. 실제 저장 데이터, 실제 AI, 외부 도구와 연결되지 않는다.
- 사용성 시험은 하지 않았다. ‘적음’, ‘좋음’은 설계 판단이다.
- 시안의 버튼 일부는 비활성이거나 시연 문구만 띄운다(작업문 복사, 결과 붙여넣기, 답 기록). 실제 동작은 제품에 이미 있다.
- 브라우저 점검은 Chromium 하나로만 했다(1280×860, 390×800).
