# FLOW083 — 첫 사용, 내 프로젝트, 요청 흐름 (후보 `flow083/project-entry`)

근거: DESIGN082-B 카드안 + RESEARCH082-A(제품 문서·공개 화면 관찰, 실사용 생성/삭제 검증 없음). 자동 검사는 배선 확인이며 사람이 도움 없이 쓸 수 있다는 증거가 아니다.

## 고객에게 달라진 점
- **첫 방문:** 무엇을 하는 서비스인지 두 문장, 첫 입력 곁에 한계("AI 연결 없음 · 이 브라우저에만 저장 · 복사·저장은 실행이 아님")를 보여 준다. 이름 단계 없이 큰 입력에서 바로 시작한다. 기본 이름은 첫 요청 앞부분으로 붙고 언제든 바꿀 수 있다.
- **예제 둘러보기:** 메모리에만 만든 예제(정상 도메인 경로 + 명시적 MOCK 규칙)이며 저장·목록 등록을 하지 않는다. 배너에서 닫기/내 프로젝트 시작을 고른다.
- **다시 방문:** 새 탭·새 방문은 ‘내 프로젝트’ 목록(이름, 마지막 요청, 최근 활동, 요청/가져온 결과 수, 이어서 하기)부터 보여 준다. 같은 탭 새로고침은 열던 프로젝트를 유지한다. 휴지통만 남아도 목록을 보여 준다.
- **프로젝트 안:** ‘지금 할 일’ 카드에 단계별 주 행동 하나(작업문 복사 → 결과 붙여넣기, 질문이면 답하기)와 보조 행동(Markdown 저장, 다시 정리, 전체 작업문 보기, 새 요청)을 모았다. 복사 성공·실패, Markdown 저장, 미리보기는 서로 다른 안내와 기록을 남긴다(미리보기·실패는 기록 없음). 복사·저장은 전달·실행이 아니라고 말한다.
- **지난 요청과 결과:** 각 항목이 ‘내 요청’인지 ‘가져온 결과 · 구현 보고/관찰·검사 자료’인지, 어느 요청의 작업문에 대한 결과인지, 몇 번 복사·저장했는지를 보여 준다.
- **관리:** 여러 프로젝트 만들기·전환·이름 바꾸기. 프로젝트 전체를 휴지통으로 옮기기·되돌리기·되살리기(원문·기준·요청·결과 전체, 외부 작업 취소 아님). 백업 파일은 지금 프로젝트를 덮지 않는 새 사본으로 추가한다. 이번 버전에는 영구 삭제·휴지통 비우기·개별 요청 삭제가 없다.

## 저장 (잠정 — Sol 저장 검토 결과로 조정 예정)
- Project payload 형식 불변. 기존 단일 키 `agentflow.idea015.project.v1`은 그 자리에서 slot `legacy`로 목록에 오르며 이동·복사·삭제하지 않는다. 이후 프로젝트는 `…project.v1:W_<uuid>` 각자 키에 저장한다.
- 목록/휴지통 상태만 `agentflow.idea015.workspace.v1` 인덱스에 둔다. 인덱스 쓰기는 항상 저장된 값을 다시 읽고 고친다(오래된 탭이 휴지통을 되살리지 못함). 프로젝트 저장 전 인덱스를 새로 읽어 휴지통에 있으면 저장하지 않는다.
- 새 프로젝트는 빈 키에 먼저 쓰고 그다음 목록에 올린다. 목록 등록이 실패하면 다음 저장에서 같은 키를 다시 올리며 사본을 만들지 않는다. 읽을 수 없는 인덱스나 프로젝트는 덮어쓰지 않는다.
- 백업 사본은 같은 project ID와 내보내기 기록을 그대로 가진다. 일치하는 결과 파일은 그 사본에서도 정확한 반환을 찾는다(두 사본 중 연 쪽에만 들어감).

## 기존 테스트 갱신 (행동 동등성)
- `browser.state()`/정적 `state()`는 이 탭이 연 프로젝트 키를 읽는다(첫 프로젝트는 기존 키 그대로).
- 새 탭·재방문은 목록부터: `open_listed()`로 같은 프로젝트를 열고 기존 단언을 그대로 검사한다(browser test_08/12, ui001 remount, connect039 test_04는 같은 키를 지정).
- 가져오기 확인 문구는 ‘새 프로젝트 사본으로 불러올까요?’로 단언한다(교체 → 사본).
- connect039 test_05 전반부: 가져오기가 더 이상 브라우저 값을 덮지 않으므로 ‘덮기 전 원본 보존’ 대신, 가져온 뒤 기존 바이트가 그대로인지와 그 이전 형식 프로젝트를 열 때 원본 보존 실패 시 저장을 멈추는지를 단언한다.
- 질문 우선(ui02) 등 기존 단언은 바꾸지 않았다. 입력 패널은 출력 카드 아래 그대로 두고, ‘지금 할 일’의 ‘＋ 새 요청’으로 언제든 연다.

## 한계
사람 사용성 관찰 없음. MOCK이라 이해 품질 무관. 영구 삭제·용량 관리·다중 기기 없음. 저장 설계는 Sol 검토 전 잠정.
