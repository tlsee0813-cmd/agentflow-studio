# IDEA-012 · 제품 리허설

설치 없는 클릭형 탐색 시제품입니다. 기존 AgentFlow 제품을 교체하거나 연동한 버전이 아닙니다.

## 열기

ZIP을 풀고 `IDEA-012_Rehearsal/index.html`을 브라우저로 여세요. 패키지 설치, 개발 서버, 로그인, API 키가 필요하지 않습니다. CSS·JavaScript·아이콘은 HTML 안에 있고 외부 라이브러리·폰트·API를 사용하지 않습니다.

선택은 **이 탭에서만** 유지됩니다. 새로고침·닫기·초기화하면 사라집니다. 필요한 기준은 화면에서 Markdown 파일로 내려받을 수 있습니다. 내려받은 기준을 다시 불러오는 기능은 없습니다.

## 한 고객 흐름으로 내린 판단

**첫 사용자:** AI로 실제 회원이 쓸 작은 수업 예약 앱을 만드는 1인 제작자.

**중심 가치:** “자동으로 넣어줘”의 중요한 해석 차이를 고객 결과로 먼저 겪고, 한번 선택한 결과를 개발 뒤와 다음 변경에도 다시 사용한다.

기존 AI 대화보다 나아야 할 장면은 설명을 더 잘 요약하는 때가 아닙니다. “참여 확인 후 예약”을 선택한 사람이 모의 결과의 “추가 수락 없이 예약”을 보고, 원치 않은 변경인지 의도한 변경인지 판단하는 때입니다. 그 판단을 다음 요청에서 다시 쓰지 못한다면 별도 제품의 이점은 약합니다. 효과는 아직 가설입니다.

기준 자료는 첨부 `붙여넣은 텍스트(1).txt`의 IDEA-012 첫 지시입니다. 뒤의 Claude 안에서는 작업 후 결정 대조를, B1·B3·B4에서는 결과를 보며 의도를 구체화하는 신호·기록과 실행의 불일치·추가 조율 부담을 반영했습니다. 자료 속 경험 수를 시장 검증으로 해석하지 않았으며, 자동 권한 확대나 모든 작업의 의무 승인은 채택하지 않았습니다.

## 먼저 눌러볼 경로

`대기예약 만들기 → 두 결과 체험하기 → 각 안에서 빈자리 만들기 → B안으로 정하기 → 기준 복사/내려받기 → 모의 구현 결과 열기 → 같은 장면 재생 → 처음 정한 대로 수정 요청 → 수정 반영 예시 재생 → 다음 변경에서 다시 쓰기 → 이전 결정으로 장면 다시 보기`

마지막에는 예약 방식이 유지된 문구 변경을 **“결정할 것 없음”**으로 통과합니다. 이어서 “배정 순서를 바꾸는 다음 요청”을 누르면, 이전 대기 순서 기준이 다시 사용됩니다. A안도 같은 전체 흐름을 지원하며 어느 안도 추천값으로 자동 선택하지 않습니다.

다른 경로도 실제로 동작합니다.

- **둘 다 아니에요 / 지금은 보류:** 직접 입력을 그대로 남기거나 미정으로 진행합니다. 자유문장을 A/B로 추측하지 않으며 일치·위반으로 판정하지 않습니다.
- **의도한 변경:** 바뀌는 조건을 보고 그 기준만 갱신합니다. 이전으로 돌아가 선택을 바꾸면 관련 비교를 다시 확인하도록 표시하고, 원문과 직접 메모는 유지합니다.
- **차이가 없는 경우 / 근거가 없는 경우:** 시작 화면의 “문구만 바꾸기”는 새 선택 없이 통과합니다. 결과 화면의 “기준대로인 예시”는 승인 없이 진행하고, “요약만 있는 예시”는 가능성만 표시하며 확인 요청으로 이어집니다.

## 모의 체험의 경계

버튼, 상태 분기, 선택 이력, 기준 수정, 전달용 문장 생성, 복사·파일 저장은 구현되어 있습니다. 자유입력은 기록만 하며 **AI 분석을 하지 않습니다.** 기본 불일치 장면은 선택과 다른 결과를 보여주도록 준비한 연출이지, 실제 코드에서 찾아낸 결함이 아닙니다.

저장소·실제 앱·실제 테스트·CLI·실시간 이벤트·고객 데이터·외부 API는 연결하지 않았습니다. 코드 diff와 요약만으로 고객 결과를 확정하지 않습니다. 사용자가 열어 본 **수정 반영 예시**와 실제 수정 적용은 끝까지 구분합니다. 미반영·보류 상태로 다음 단계에 가면 미확인을 유지합니다.

직접 메모와 자유입력 조건의 의미·모순도 자동 비교하지 않습니다. “같음”은 정해진 예시의 예약 방식·배정 기준에 한정됩니다. 정상 참여와 거절을 보여주되, 미응답 시간·오래된 대기의 유효 기간 등은 미정으로 남겼습니다. 수업·이름·장면은 가상의 예시입니다.

기준을 고르거나 자주 승인해도 실제 실행 권한은 늘어나지 않습니다. 수정 요청은 이미 발생한 예약·환불·삭제 같은 외부 일을 되돌리지 않습니다. 실제 안전성, 정확도, 사용자 효용, 절감 효과를 검증한 제품이 아닙니다.

## 이번 환경에서 확인한 것

Linux의 Chromium **144.0.7559.96**, Playwright로 버튼을 클릭했습니다. 주요 14개 경로와 후속 3개 회귀 경로에서 A/B 체험·선택·수락/거절, 직접 입력/보류, 결과 대조, 수정 요청의 미적용 상태, 의도된 변경, 다음 요청 재사용, 기준 수정 후 이전 비교 재검토, 수동 메모 보존을 확인했습니다. HTML 입력의 문자 처리, 실제 Markdown 내려받기, 클립보드 접근 거절 시 수동 복사 창, 초기화 취소/확정도 확인했습니다.

1440px 데스크톱과 390px 모바일 뷰포트의 주요 화면을 캡처해 확인했습니다. 검사한 경로에서 JavaScript 실행 오류와 외부 HTTP 요청은 없었으며, 모바일 5단계에 문서 가로 넘침이 없었습니다. 같은 세션의 자체 검사이며 독립 리뷰나 실제 예약 앱 테스트가 아닙니다.

**검증 제한:** 환경의 브라우저 정책이 `file://` 열기를 `ERR_BLOCKED_BY_ADMINISTRATOR`로 차단했습니다. 정책을 바꾸지 않고 동일 HTML 내용을 브라우저에 직접 로딩해 위 흐름을 검사했습니다. OS에서 파일을 더블클릭해 여는 과정, 실제 기기, Safari/Firefox, 운영체제 클립보드 내용 읽기 검증은 하지 않았습니다.

## 다음에 확인할 것

좋은 AI 대화·작은 시제품·README만 사용하는 방식과 비교해, 이 체험이 중요한 의도 차이를 더 쉽게 발견하게 하는지 확인해야 합니다. 특히 두 번째 실제 변경에서 사용자가 자발적으로 이전 장면을 다시 찾는지, 새 관리 부담보다 효익이 큰지가 핵심입니다. 실제 자료를 도입할 때에는 고객 결과를 뒷받침할 관찰과 “모름” 처리부터 확인해야 합니다. 그 결과가 약하면 기능을 늘리기보다 템플릿이나 기존 도구의 절차로 축소하는 것이 맞습니다.

이번 묶음은 `index.html`, `README.md` 두 파일뿐입니다. 기존 제품 소스·첨부 보고서 원문·교재·비밀정보는 포함하거나 수정하지 않았습니다.
