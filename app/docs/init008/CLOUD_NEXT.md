# 총괄 전달용 — 다음 좁은 Cloud 검증 제안 (아직 배정/실행 아님)

## 먼저 분리할 두 작업

현재 Cloud에 배정된 일은 **기존 INIT007의 p03 deferred 단일 항목 기록, generation0**이다.
그 작업은 기존 검토된 source/원장/입력으로 Cloud가 마무리한다. INIT008 소스를 그 원장에
끼워 넣거나 기존 p01 실패 슬롯을 재시도하지 않는다. 이 ZIP은 그 기록이 끝났다는 증거가 아니다.

INIT008은 독립 검토 전 `review_ready`다. 새 source/runtime/body 지문 때문에 기존 INIT007의
review/acceptance 파일은 새 유료 실행 승인 자료가 될 수 없다. 초기 source hash gate가 막는 것은
의도된 보호다. 기존 고정 run/목적 ID/ledger 파일의 지문을 고치거나 임의 경로를 바꿔 우회하지 않는다.
새 코드를 현행 INIT007 runner로 곧바로 live 실행하는 명령을 제공하지 않는다.

## A. 독립 리뷰와 무상 실행 (총괄/기존 Cloud)

FINAL ZIP의 manifest/source fingerprint를 대조하고 `source/` 하나에서 작업한다.
FULLSOURCE에 patch를 재적용하지 않는다. 비교용 patch는 정확한 입력77파일 기준에서만 적용 가능하다.
리뷰 초점은 실제 ID만 안내하는 prompt(원문을 system 역할로 올리지 않는지), validateResult/상태 guard
byte 불변, 같은 Requirement 객체에서 만드는 결정 요약, 원문/수동값/완료 조건/출처 보존이다.

Node22.16.0/npm10.9.2/TypeScript5.8.3에서 클린 npm ci 후 check/build와 INIT00819검사를 실행한다.
필요 관련 회귀는 VALIDATION.md의73개 또는 리뷰로 영향이 없다고 확인한 범위에서 선별한다.
실제 direct-http 브라우저에서는 신규3개와 입력·미저장 수정·옛 응답·잠금/보류 관련7개를 확인한다.
`BROWSER_TRANSPORT=dom-bridge` 결과를 직접 브라우저 통과로 대체하지 않는다. 브라우저 전체18,
전체178/parity/INIT007 두 단계 CLI를 관성적으로 반복할 필요는 없다.

## B. 실AI 재평가의 작은 별도 작업 계약을 총괄이 먼저 확정

**제안이지 현재 실행 지시가 아니다.** 독립 리뷰와 A 수용 뒤 기존 Cloud에만 새 실험을 배정한다.
새 source와 계측/출력 경로, 기존 실험과의 분리, 예산 예약과 기록 정체성을 명시한 별도 검토가 필요하다.
이 패키지는 새 live runner/원장을 구현하거나 시작하지 않는다. 기존 사용자 키/비용 허용은 Cloud에
유효하므로 사용자에게 재승인 질문을 반복하지 않는다. Pro에는 키·유료 호출 권한이 없다.

목적은 새 prompt의 실제 근거 참조와 보류 표현을 관찰하는 것이지, 소비된 INIT007 슬롯 재시도나
전체6사례 합격 채우기가 아니다. 다음 두 시나리오의 **첫 요청+실제 질문에 대한 후속 각 최대1회**, 
합계 최대4회가 작은 제안 범위다. 새 프로젝트의 정체성과 출처는 정상 상태 함수에서 만들며
다른 프로젝트 ID로 옛 envelope/sourceId를 복붙하지 않는다.

- p01형: 막연한 목표 → 실제 핵심 질문이 고정된 기록/재확인 사실과 맞을 때만 해당 사실로 답변.
  provider200/expected model/stop/usage 뒤 app200인지, 전체 답변 출처로 proposed 요구와 관찰 가능한
  완료 조건을 받는지 검토한다. 누가/언제/사용 습관은 임의로 추가하지 않는다.
- p03형: 첫 실제 질문이 저장 범위라면 unknown→deferred를 같은 Answer ID로 수정한 뒤 후속1회.
  두 출처·deferred/TBD/Claude-only 보존, AI 요약의 확정/보류 분리와 UI 현재 결정 요약을 함께 본다.
  실제 질문에 해당 고정 사실로 답할 수 없으면 skip. 추가 호출로 횟수를 채우지 않는다.

새 본문으로 지원정보/가격/예약을 Cloud가 공식 자료와 현재 설정에서 다시 확인한다. 옛 가격이나
잔여 예약을 새 원장에 자동 재사용하지 않는다. 제안 한도는 동시1·재시도0·15초·출력4096
(제품 기본2048 불변)·본문32KiB·최소12초 간격 및 rolling6/min이며, 총 비용 예약은 총괄이
기존 Cloud 허용 안에서 검토한다. 이 한도는 계정 청구 hard cap이라는 뜻이 아니다.

## C. 좁은 수용/중단 기준

성공 사례에도 sourceIds 존재 여부와 **의미상 근거**를 따로 사람이 확인한다. 모델이 기본 source를
무관하게 인용하거나 중요한 요구를 생략해 오류만 줄였다면 개선 성공으로 보지 않는다.
known_source 거절이 재발하면 해당 슬롯을 보존하고 그 정확한 안전 진단만 기록한다. 새로운 ID
치환/무조건 근거 연결/자동 재시도/rejected raw 보관으로 통과시키지 않는다. 인증·usage·model·
finish·정체성·예산·저장/원장 불확실성은 검토된 gate에 따라 중단하고 원장을 보존한다.

반환물은 새 검토된 source/runtime/fixture 정체성, 실제 질문/선택 효과/권고, 제출한 고정 사실과
적용 요구/완료 조건/status/출처, 거절 시 안전 진단, 호출 수와 skip 이유, 사람이 읽은 품질 판정이다.
상태/프로토콜 통과, 합성 고객 품질, 실제 고객 승인, 직접 브라우저 실행을 각각 구분한다.
p02/p04/p05/p06의 미발생 후속과 전분기·실고객 품질은 그대로 미검증이다.
