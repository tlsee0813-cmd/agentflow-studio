# IDEA015 — 이어서 만들기

기존 AgentFlow Studio 앱 안의 추가 진입점이다. 기존 `app/src`, `app/server`, 평가기, fixture,
gate, 잠금파일을 수정하지 않는다. 큰 앱 재작성이나 준비된 결과만 재생하는 HTML 시제품이 아니다.
입력·상태 전이·문맥 구성·수동 편집·내보내기·저장/복구는 실행 코드이며,
자연어 해석은 명시적인 규칙 mock 또는 별도 DeepSeek 서버 요청으로 나눈다.

## 실행 (`app/` 디렉터리)

```sh
npm ci --ignore-scripts --no-audit --no-fund
npm run build
node continuity/scripts/build.mjs
node continuity/server/index.mjs --mock
```

`http://127.0.0.1:3000`을 연다. API 키가 필요 없다. 원래 `npm run demo`는 원래 INIT009 화면이다.
IDEA015는 위의 별도 시작 명령을 사용한다. 동시에 같은 포트를 사용하지 않는다.

Node 22.16.0 / npm 10.9.2 / TypeScript 5.8.3을 기준으로 한다. 의존성은 기존
`app/package-lock.json`의 TypeScript 한 개뿐이고 추가 설치 패키지는 없다.
`continuity/scripts/`는 설치된 부모 앱의 컴파일러를 우선 사용한다. 없을 때만 정확히 같은
버전의 PATH 컴파일러로 bootstrap하며, 이를 npm ci 성공으로 보고하지 않는다.

## 써 볼 한 흐름

FLOW049의 프로젝트 홈은 출발 요청, 이 작업에서 이어가는 요청, 사용자 기준과 돌아온
원문을 함께 보여준다. 자연어 요청을 보내면 홈을 구성하며 목적 카드를 따로 작성하지 않는다.
‘현재 작업문 보기’로 전달하거나, 필요한 선택만 답하고, ‘방향 수정 / 다음 요청’으로 이어간다.
결과 JSON과 기존 붙여넣기 모두 같은 홈에서 시작한다. 기술 단계마다 돌아올 필요는 없다.

목적 연결은 기존 Task 부모 연결의 첫 request Source ID에서 도출한다. 별도 현재 목적 값을
저장하지 않으며 원문·Basis 현재 값/이력·수동값·project.1/.2/.3 및 return.1 호환을 유지한다.
연결은 의미상 같은 목적·완료·코드 영향 없음의 판정이 아니다. 자세한 범위와 실제 검증은
[FLOW049 인계](../../docs/flow049-outcome-home.md)에 기록한다.

프로젝트 이름과 자유 요청 → 필요한 경우의 질문/직접 답 → 작업문 복사 또는 Markdown 저장
→ 실행 도구에 사용자가 붙여넣기 → 받은 요약/자료를 ‘돌아온 결과’로 붙여넣기 → 다음 변경 요청.
작업문을 복사해도 CLI가 실행되지는 않는다. 결과 보고도 실제 검증 완료로 바뀌지 않는다.

작은 CSV/debounce/문구 수정은 mock에서도 바로 작업문을 만든다. mock의 질문 분기는
예약 성립 방식의 간단한 선택, 문제 현상의 관찰 질문에 한정된 규칙이다.
임의 분야의 자연어를 일반적으로 이해하거나 실제 코드의 원인을 알아낸다고 표시하지 않는다.
DeepSeek 경로는 같은 UI의 서버 API를 사용하지만 이번 제출에서 실제 모델을 호출하지 않았다.

## 선택적 결과 파일 (CONNECT039 후보)

기본은 위의 복사/붙여넣기다. 작업 카드의 ‘결과 파일로 받기 · 선택’을 열면 파일용 작업문
복사/Markdown 저장을 쓸 수 있다. 외부 도구가 만든 JSON을 입력 카드의 ‘결과 파일로 가져오기’에서
선택하고 정확한 원래 작업·내보낸 시점/버전·이후 기준·보고 원문을 확인한 뒤 명시적으로 가져온다.
짧은 보고나 웹 전용 도구에서는 파일 생성/이동이 더 번거로울 수 있다. 별도 연결·감시·자동 실행은 없다.

`agentflow.return.1`은 이 앱의 교환 형식이다. 키는 `schemaVersion, projectId, taskId, returnId,
report, evidence` 여섯 개만 허용한다. report는 비어 있지 않은 문자열, evidence는 같은 조건의
문자열 또는 null이다. 본문 각각 JS 문자열 길이 11,000 이하, 전체 유효 UTF-8 JSON은 128 KiB
이하이며 BOM/제어문자/추가 키/일치하지 않는 ID를 거절한다. ID는 파일용 내보내기 때 채워진다.
자동 파일 수리나 자르기, 최근 작업 대체 연결은 없다. 기존 결과 붙여넣기는 계속 쓸 수 있다.

명시 가져오기는 report와 선택 evidence를 한 결과 Task에 추가하며 작성 중 초안과 수동값·기준을
보존한다. 동일 인계의 동일 필드 본문은 중복 추가하지 않고 변경된 부분 보고는 새 기록이다.
Source에는 Studio가 생성한 연결 표지와 외부 본문을 구분해 넣는다. 전체 JSON 원문은
`Task.resultFile.rawText`에 보존하여 원문 보기/다운로드/복구에 쓰고 AI에 중복 전송하지 않는다.
파일은 인증이나 실행·요구 완료의 증명이 아니다. 가져오기는 AI 호출을 일으키지 않는다.

## 사용자 권한과 문맥

- 실제 요청은 원문 요청으로, 실제 답변은 원래 질문을 포함한 답변 원문으로 보관한다.
  배경·인용까지 확정 정책으로 승격하지 않는다. AI의 출력 계약에는 상태·출처 종류·기준 수정 필드가 없다.
  별도의 ‘잠금’ 기능은 없다. AI가 기준을 바꾸지 못하는 이유는 그런 쓰기 경로가 없기 때문이다.
- 저장한 기준을 직접 고치는 행위가 사용자 결정이다. 별도 재승인을 반복하지 않는다.
- AI 정리는 요청 당시의 기준 revision과 함께 저장한다. 그 뒤 기준이 바뀌거나 이 작업에 답변·기준이
  추가되면 그 AI 문구는 현재 작업문에서 빠지고 화면에 ‘기준 변경 전’으로 표시된다. 직접 쓴 값은 그대로 나간다.
  새로고침·가져오기 뒤에도 같은 판단을 한다. 다시 정리하거나 재승인할 의무는 없다.
- 정확한 `D2의 '30일'을 '60일'로 변경해줘` 또는 유일한 같은 단위 값에 대한
  `D2을 60일로 변경해줘`는 앱의 제한된 결정적 인식으로 그 부분만 바꾸고 이력·ID를 보존한다.
  이 문법을 입력하도록 강제하지 않으며 화면의 ‘직접 수정’이 일반 편집 경로다.
  그 밖의 자유 변경 요청도 재확인 버튼 없이 원문 작업문으로 진행하되, 저장 기준의
  임의 자연어 패치를 자동 확정하지 않는다. 광범위한 자연어 변경 인식은 미구현이다.
- 다음 작업에는 현재 입력/답변, 직전 작업과 연결된 결과 묶음, 보존 기준을 넣는다.
  전체 과거 채팅은 보내지 않는다. 모델의 관련 기준 선택에는 개수 상한을 두지 않으며
  비선택 기준도 작업문의 보존 기준 영역에 남긴다. 무응답은 삭제가 아니다.
- 결과/관찰 자료는 기본적으로 마지막으로 내보낸 작업에 연결한다. 여러 과거 작업 중 하나를
  임의로 골라 연결하거나 자동으로 구현 증거를 읽어 검증하는 기능은 없다.

## 저장·복구

같은 주소(프로토콜·호스트·포트)와 같은 브라우저 프로필의 `localStorage`에 단일 프로젝트를
저장한다. `localhost`와 `127.0.0.1`, 다른 포트는 서로 다른 저장 영역이다.
사용자 요청/답변·기준/이력·수동 작성·내보내기 기록·작성 중 입력을 JSON으로 내보내고 복구할 수 있다.
내보내기 기록은 작업문 전문을 다시 복사하지 않고 시각·방식·당시 revision·글자 수·식별값과 그때의 작업 문구만 남긴다
(원문과 기준 이력은 한 번만 보관하고 ID/revision으로 참조). 저장 형식은 `idea015.project.3`이며
`project.1`/`project.2` 파일과 브라우저 저장 내용은 자동 변환한다. 추가 필드는
`ExportRecord.returnId`와 `Task.resultFile`이며 과거 기록에는 모두 null을 넣는다. 과거 ID를 새로 만들지 않는다.
v1 이전 작업문 전문은 `legacyText`로 남긴다. 브라우저에 이미 저장된 이전 형식 원문은
v3 쓰기 전에 `agentflow.idea015.project.v1.legacy-original` 또는 `v2.legacy-original` 키에 그대로 보관한다.
각 버전의 첫 원본을 유지한다. 사용자가 선택한 복구 파일은 원파일 자체가 있으므로 브라우저 백업 슬롯에
중복 저장하지 않는다. 덮어쓸 브라우저 구형 저장값의 원본 백업 실패 시 쓰기는 차단한다.
복구 전에 파일을 검증하고 프로젝트 교체를 확인한다. 잘못된 import는 기존 상태를 바꾸지 않는다.
복구 파일은 평문이며 인증·서명된 사용자 행동 증명이 아니다. 민감한 정보를 넣지 않는다.

쓰기 실패나 관측한 다른 탭 변경은 조용히 덮어쓰지 않고 입력을 이 탭에 유지한다.
이때 닫기 전에 ‘복구 파일 저장’을 사용한다. 여러 탭의 동시 원자적 편집·자동 병합은 제공하지 않는다.
입력/수동 편집이 바뀐 뒤 도착한 응답은 버리고, 재시도는 원래 입력을 중복 생성하지 않는다.
복구 때 중단된 요청을 자동 재전송하지 않는다.

AI 전송 문맥은 128 KiB 한도를 둔다. 이 한도는 AI 요청에만 적용되며 작업문 복사·저장, 자동 저장, 복구 파일은 막지 않는다.
AI 문맥에는 모든 기준의 현재 값과 출처 ID를 넣는다(이전 값은 개수만). 확정·답변·보류 기준과 수정된 기준은 항상 전문이다.
지금 맥락 밖의, 한 번도 고치지 않은 오래된 요청 기록만 200자 발췌와 `partial` 표시로 보낸다. 전문은 앱과 작업문에 남는다.
자동 저장·복구 파일·가져오기는 같은 압축 JSON 바이트에 같은 8,000,000바이트 한도를 쓴다.
배열 항목 수 상한은 100,000개다. 앱이 만드는 항목은 하나당 80바이트(8MB/100,000)를 넘으므로 실제로는 8MB가 먼저 걸리고,
상한은 손으로 만든 파일만 막는다. 자동 저장도 가져오기와 같은 `parseProject` 검사를 통과한 바이트만 쓴다.

## 검사

```sh
npm run check
node continuity/scripts/check.mjs
node continuity/scripts/build.mjs
node --test continuity/tests/*.test.mjs
python continuity/tests/browser.py
```

브라우저 검사의 선택 의존성은 기존 `tests/browser-requirements.txt`를 재사용한다.
설치된 브라우저를 지정할 때만 `BROWSER_EXECUTABLE`을 사용한다.
기본 검사는 직접 HTTP/실제 브라우저 저장소 경로다. 정책상 차단된 환경에서
`BROWSER_TRANSPORT=dom-bridge`를 명시하면 DOM 검사 + 저장소 대역으로만 검사한다.
이 대체 모드는 직접 브라우저 네트워크·CSP·원래 localStorage·실기기 복구 검증이 아니다.

기존 전체 `npm test`는 유지되어 있다. 이전 live 평가 스크립트를 이번 작업 실행 방법으로
사용하지 않는다. 기존 gate/원장을 열거나 fingerprint를 바꾸지 않는다.

## 실제 코드 재사용

`../server/config.mjs`, `errors.mjs`, `limiter.mjs`, `static-files.mjs`,
`providers/deepseek.mjs`의 `readLimitedBody`를 직접 import한다. 기존 HTTP 서버의
localhost/Origin/CSP 경계를 새 계약 라우트에 작은 구성 코드로 적용했다.
빌드·컴파일러·잠금파일과 브라우저 검사 도구 pin도 기존 앱을 사용한다.
DOM 대체 검사기법은 기존 `app/tests/browser.py`를 적용했다. 새 외부 라이브러리나
Spec Kit/OpenSpec/Promptfoo 등의 프레임워크는 도입하지 않았다.

자세한 제품 판단·검사 범위·Cloud 인계는 제출 ZIP 최상위 문서를 참조한다.
